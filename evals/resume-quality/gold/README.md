# 真实来源脱敏评测集

`v1/` 包含五位不同作者的自述履历与五份 GitLab 官方岗位族定义的脱敏配对。固定来源/完整原文 hash/内容许可见 `sources.mjs`，归属与修改说明见 `v1/NOTICES.md`。这些是构造的评测配对，不是原作者的真实申请或录用记录；公开来源可重新识别，不声称不可逆匿名。

## 使用边界

- `cases/` 是评测器输入，包含独立要求标签、权重、支持范围、STAR 信号与原始来源 URL。**不是模型输入**。
- `materials/` 是脱敏全文条目与原始日期/角色上下文；原个人联系方式、地址、个人链接不进入这一层。保留全部选定专业条目，技能清单与行动证据分开，不通过截短限定语换取分数。
- 模型采样前调用 `goldModelMaterial(case, groups)`。该 allowlist 只返回 JD、脱敏上下文和证据 ID/全文/hash，不返回权重、标准答案、STAR、批准改写或作者/来源 URL。后续必须通过统一 tasks 运行，本文没有模型执行器。
- `mappings/` 以 UTF-16 半开区间、1-based 行号、原片段 hash 记录来源链。解码/标记清洗/替换后，派生偏移与原文偏移不同；映射粒度为完整原始 token/标记条目，不伪称逐字符一一对应。
- `baselines/` 只有三份逐月日期可证的确定性全文抽取。后端的年份日期与前端的矛盾日期字段保留原样，不补 January、虚构月份或 epoch。三份 baseline 不是模型或人工写作成绩，也不是完整求职成稿。

## 生成与验收

原始快照及许可证明按 `sources.mjs` 的固定版本准备在显式目录。原文含公开个人信息，保留在仓库外；生成器只读取数据，不执行来源代码。先核十份原文字节及全部许可证明 hash，再创建新的输出目录。输出已存在、原文/许可变动、PII 或未使用标签规则均失败，不覆盖旧数据。

```sh
node --import tsx evals/resume-quality/gold/build.mjs --sources /explicit/raw-snapshots --out /new/dataset
node --import tsx evals/resume-quality/gold/verify.mjs --dataset /new/dataset --sources /explicit/raw-snapshots
```

不提供 `--sources` 的 verify 只验派生包，不声称验了原始来源。29 个数据文件含完整清单，重新生成的字节应完全相同。首次成功后的修改必须重新生成并通过验收，不能只改清单掩盖数据变化。

四轴报告继续使用上层 README 的命令，将 `cases/`、`baselines/` 和一个新报告目录分别传入。报告实际打印全部 PDF 页，不裁页或缩字凑一页；基线没有的月份不被自动填充。全部回归由根 `test:resume-quality` 和现有 CI test glob 收集。

## 标签与许可

标签在候选生成前由 Codex 对照固定原文审阅，不声称外部人工认证或经历独立核验。147 条所选 JD 要求均留在分母，部分支持单列，不冒充完全覆盖；其余“尚无证据”不表示本人不会。未裁决的 STAR 维度保守不给分，来源未报告结果就保留缺项。规则对未知语义改写需额外复核，不能据此宣称完整幻觉检测能力。

已保留的重要反例：历史 Rails 是部分支持、不是完全缺失；Android 延迟改善不能充当 Web 性能证据；Jest 工具清单不证明编写测试；fictional 项目不充当商业交付；实习、协助、团队贡献与学术项目的边界不能被删掉。
