# 迈向更好 · BetterMe

本地优先的简历与求职工作台，长期方向是以真实经历为基础的职业成长 Agent。
仓库：[github.com/nanfengovo/better-me](https://github.com/nanfengovo/better-me)

2026-10-18首轮功能分批发布见[GitHub分批交付报告](docs/reports/github-feature-batches-2026-10-18.md)；后续119套模板、独立主题和纸张工作室见[模板与主题分批发布记录](docs/reports/github-theme-template-batches-2026-10-18.md)。

当前优先完善非 Agent 功能：**事实库与多份简历 → 119 套版式与版本管理 → PDF / DOCX / Markdown / RenderCV YAML → 岗位收藏与官网公开读取 → 手动投递、实际沟通与跟进队列 → 材料快照与求职资料导航**。已有 AI 导入和 JD 分析仍可选用，日常记录岗位与投递无需模型。职业持续对话、学习规划、契约打卡和自主编排后置；真实机会地图、全站持续同步和自动申请尚未实现。

保留的六套自研模板支持同一份事实切换展示：

- `zh-classic`：经典正式，居中抬头与清晰分节。
- `en-ats`：简洁单栏，无照片和装饰侧栏，链接以文字保留。名称表示设计用途，不代表通过所有招聘系统的解析认证。
- `clean-modern`：现代信息布局，使用分区抬头与重点标签突出项目和技术经历。
- `editorial`：编辑部，大字抬头、侧标分节和书刊风格的留白。
- `sidebar`：左岸，个人资料置于窄栏，正文聚焦经历与成果。
- `compact`：精练履历，横向信息带与紧凑分节，适合信息密集的简历。

另有 113 套来源适配，可在「排版与模板」按来源或名称查找。JSON Resume 覆盖固定官网目录的全部 65 套，RenderCV 覆盖全部 9 套主题，NewFuture 包含基础、flex、block 打印模式；awesome-resume-for-chinese 的 31 个顶层入口逐项核对，19 个具备许可的实际模板来源贡献 39 套（含 NewFuture），其余工具、重复或无授权等入口的原因见完整库存。目录、源版本和逐套许可见 [模板库说明](templates/README.md) 与 [全部版式清单](templates/CATALOG.md)。原版固定栏目分配按现有事实模型适配，不捆绑上游运行时、网络字体、图标或示例人物资料。

模板 ID 不决定输出语言；这份简历的语言通过工具栏「简历语言」中文/英文按钮切换。顶栏「界面 中文 / EN」控制工作台的导航、按钮、编辑标签和弹窗文案，「浅色 / 深色」控制工作台外观；两者与简历语言分别保存。因此可以用英文深色界面编辑中文简历，也可以用中文界面输出英文简历。编辑器「编辑字段」只筛选中英输入字段，不翻译正文。预览缩放与「适应宽度」只改变屏幕显示，排版中的字号、间距和边距则同时影响预览与 PDF。

桌面端可拖动编辑区与预览区之间的分隔线，实时调整两侧占比；比例会在当前浏览器来源记住。双击分隔线或聚焦后按 `Enter` 恢复默认，左右方向键微调（按住 `Shift` 加大步长），`Home` / `End` 到达可用边界。窄屏自动切为上下布局。

预览默认适应实际宽度，拖动分栏时纸张同步缩放；也可以用加减按钮手动调至 20–130%，再点「适应预览宽度」恢复自动。默认开启「跟随编辑」：点击或输入某个字段、滚动左侧经历时，右侧定位并轻标记对应内容。手动滚动或浏览右侧会暂时暂停跟随，继续操作左侧后恢复；关闭「跟随编辑」可独立浏览。定位只移动预览内部，不带动整页；被隐藏的字段不会因此重新出现。

## 快速开始

准备满足 [package.json](package.json) 中 `engines` 要求的 Node.js，并使用 `packageManager` 指定版本的 pnpm。

```bash
pnpm install
pnpm dev
```

浏览器打开 Vite 提示的地址（默认 `http://localhost:5173`）。

首次启动显示演示数据。可先用 [examples/](examples/README.md) 中的样例熟悉操作，再处理自己的简历。

## 使用流程

1. 点击 **导入简历**，上传 PDF、Word、图片或文本文件；检查提取文字，选择 AI 或离线规则解析。图片和扫描 PDF 需要支持图片输入的模型；手机截图可先点 **裁剪简历识别区域** 排除状态栏、登录横幅和工具栏，点击 AI 解析才向当前配置的模型服务商发送图像。
2. 对照原文检查解析结果、警告和未解析项，再确认替换当前文档。导入前可通过 **更多简历操作 → 下载 JSON 备份** 留存现有数据。
3. 在 **内容编辑** 中补充信息，核对每条数字与单位，再确认量化。需要强调某个词时，先选中文字，再用上方工具栏调整格式；加粗/斜体/下划线也支持 `Ctrl/Cmd + B/I/U`。
4. 打开 **排版与模板** 选择模板、调整分节顺序和显示开关。例如把工作经历移到最前、把教育背景放到最后，关闭 **抬头中的学历**；国内投递可以保留照片，海外投递可以用无照片预设。再选择输出语言，检查英文缺失、长链接及跨页效果。
5. 用简历名称下的选择框管理多份简历；可 **新建**、**复制**、切换或删除当前视图。名称可直接编辑。它们共享真实经历，突出重点请使用展示选择，不必复制事实库。
6. 使用 **导出 PDF / 打印**，在浏览器打印对话框选择另存为 PDF；检查 A4、缩放、页眉页脚和分页。需要可编辑文件时点 **下载 DOCX**；也可下载/复制 Markdown，或点 **导出 RenderCV YAML** 并阅读导出说明。
7. 顶部可开关 **自动保存**，旁边的 **自动保存设置** 可选择按回车、停止输入或离开编辑项保存。默认按回车，停顿模式可自定义 1–300 秒；输入法选词回车和 `Shift + Enter` 不触发保存。随时可点 **立即保存** 或 `Ctrl/Cmd + S`。投递前打开 **历史版本**，为完整内容命名并保存检查点；选择旧版查看简历和逐项差异，再用 **恢复为新版本** 切换。`Ctrl/Cmd + Shift + S` 打开历史版本。
8. 点击侧栏 **机会** 打开 **机会与投递**；手动收藏岗位，或用 **导入 JD** 核对正文后收藏。也可展开 **从公司公开招聘页发现机会**，选 Greenhouse/Lever 或腾讯招聘官网，预览并勾选。岗位详情可创建简历、留存材料、记录联系人和实际沟通，保存下一步时间后进入跟进队列。
9. 需要 JD 分析时，使用编辑器下方的岗位入口、机会区的 **导入 JD**，或岗位详情的 **分析 JD**。在 **AI 配置** 设置服务地址、Key 和模型后再分析；结果供人工判断，不会自动改写事实库。侧栏 **资料** 打开求职资料库。
10. 点击 **更多简历操作 → 下载 JSON 备份** 保存事实库与全部简历视图；在机会区另点 **备份** 保存机会、阶段历史、跟进与材料。更换设备时分别恢复，两份文件不能互相替代。

顶部 **内容检查 → 查看明细** 中，双击一条问题，或点击 **定位并修改**（也支持键盘激活），即可切回内容编辑、展开对应经历并聚焦需要处理的字段。修改指引解释原因，并提供可展开的具体步骤；补充有依据的比较基线或因果说明、改写具体正文后，对应提醒实时更新。量化仍须本人核对后勾选 **已核实**；修改相关内容会撤销旧核实状态。定位本身不修改事实，也不改变当前简历的展示取舍。

**恢复** 用于完整 BetterMe 文档 JSON；**导入简历** 用于提取/解析简历。仅含 FactBase 的 JSON 与 PDF/Markdown 不能替代完整备份恢复。确认导入或恢复会替换当前文档，建议操作前备份。

导入结果可以逐段展开核对并下载核对 JSON。确认导入后，完整提取文本、可用的视觉 OCR 转录及待补录内容随本地文档和 JSON 备份保存，在 **导入原文与待补录** 查看和下载；它们不进入对外简历。OCR 转录是未经核实的模型输出，不能代替原图；请自行保留原 PDF / Word / 图片。当前导入会按所选模板重排，不支持对任意原稿进行保持位置、字体和字号的局部编辑。

**DOCX** 在当前浏览器内生成，保留当前语言、展示取舍、分节顺序及基本文字格式，输出可编辑的 A4 单栏文件。所选简历主题的颜色、三种字体角色及可映射装饰会写入 Word 样式。它不含照片，不复刻网页模板的分栏装饰；需要视觉版式时使用 PDF。中英文真实文件已通过 ZIP/OOXML 检查和正文回读；当前验证运行时缺少 LibreOffice，实际中文字体及长文分页尚未逐页验收，投递前请在 Word 或兼容编辑器打开核对。PDF/Word 导入工具首次打开时按需加载，DOCX 生成库在导出时加载。

**RenderCV YAML** 以当前语言和当前可见简历投影为输入，对齐 RenderCV 2.8 的固定 schema。选中任一 RenderCV 版式时映射对应的 9 种原生主题；其他版式回落为 classic 并明确说明。保留可映射内容和分节顺序，颜色、字号、间距、照片及局部文字样式等未完整映射，差异列在导出说明。当前项目不内置 RenderCV 引擎，也未替你生成或验收 RenderCV 引擎输出的 PDF。中文字体需在自己的渲染环境核对，不能把结构化导出当作已经通过中文排版验收。

## 岗位链接与截图

在 **分享链接** 中粘贴 LinkedIn、猎聘、51JOB、BOSS 直聘的官方岗位链接或完整分享消息，然后点击 **提取岗位正文**。动态页面可使用 **浏览器读取**：本地服务打开专用 Microsoft Edge，加载原岗位并自动尝试读取；遇到登录或访问验证时保留当前岗位页，供你自行操作后继续读取。各平台使用独立的固定数据目录，本站登录在本机保留，不接管日常浏览器。创建与导航最多 30 秒，随后另用最多 5 秒请求显示岗位页；单次接续读取最多 45 秒，可以取消。已有会话时点击 **显示岗位窗口** 会请求激活原标签页，保留验证状态；激活完成不保证操作系统已将窗口放到前台。读取结果先进入核对区，你可以修改识别错误，再点击 **确认并使用正文**；正文显示来源平台、原岗位链接和采集时间。多个岗位链接需要分开处理。

静态链接读取通过当前工作台的 `/api/jd/extract` 完成，浏览器读取使用 `/api/jd/browser-session` 的 start/read/close 接续流程；两者由 Vite 开发服务和本地预览服务提供。`pnpm dev` 可直接使用；要在生产构建后本地预览，可运行：

```bash
pnpm build
pnpm --filter @better-me/web preview
```

也可点击 **打开独立浏览器**，先在专用 Edge 窗口中查看原网站。看到岗位正文后回到工作台，点击 **完成后读取原岗位**。读取和检查只观察当前页面，不自动刷新或跳回原链接；停在登录、验证或中转页面时保留现场并说明，由用户在专用 Edge 中完成操作并回到原岗位。页面自然跳转期间会有界等待，不采用其他岗位。每次新建独立岗位 Tab；读取完成、**关闭本次岗位页**、关闭采集弹窗、修改链接、切换方式、取消或 10 分钟岗位页到期都只释放该 Tab。平台 Context 和空白基础 Tab 常驻，登录保存在 Git 忽略的 `data/recruitment-browser/<平台>/profile/` 中；原网站仍可能使登录失效或要求再次验证。点击 **关闭招聘浏览器** 才明确关闭全部专用窗口，磁盘登录保留；服务退出也会关闭专用窗口。网络配置改变后，先明确关闭招聘浏览器，再重新打开，避免打断活跃验证。工作台不自动完成验证码，不读取日常浏览器的登录资料。

登录或验证需要更多时间时，在当前岗位页到期前点击 **再保留 10 分钟**，将同一页面保留到从点击起 10 分钟后，并显示服务端确认的新到期时间。此操作不会刷新、重新打开或读取页面；已经结束的页面不能恢复。若未确认延长，界面仍按原期限处理，可在到期前再次尝试。普通读取、检查和显示窗口不会自动续期。

如果结束岗位页时未能确认关闭，下次点击 **浏览器读取** 会先重试结束同一工作台已经结束的旧岗位页，只有关闭确认后才打开新岗位。关闭失败时不会清除旧会话归属或自动关闭整个招聘浏览器；仍在登录、验证或正常使用的岗位页继续保留。此恢复也适用于关闭采集弹窗或刷新工作台后不再持有旧会话标识的情况。

BOSS或猎聘第一次打开专用 Edge 时，如果出现浏览器账号/同步的首次设置，工作台会提示 **请先完成 Edge 首次设置** 并保留该窗口。可以在窗口中完成或跳过设置，再点击 **浏览器读取**，沿用同一专用浏览器继续。首次设置与招聘网站的登录、访问验证分别处理；软件不会修改系统的 Edge 策略或已有浏览器资料。

BOSS 还会被动监听本岗位页自然返回的精确 `detail.json` 响应；不主动调用接口或复制 Cookie。仅在成功响应的岗位 ID 与原链接一致、标题和整段职责可在当前可见正文核对时，作为 DOM 解析的后备来源。登录/验证、错岗、推荐或隐藏内容继续拒绝；没有实际返回该响应时不会猜造正文。持久化本身不保证免验证，真实结果见最新验收报告。

若页面空白、持续加载或原网站的按钮没有反应，先用 **检查当前窗口**。这一步不会刷新或跳转独立 Edge，也不会采用岗位正文；检查成功后显示主页面加载阶段、有无可见文字、可见内嵌页面数量及当前可识别的登录/验证状态，页面仍在跳转、检查失败或页面过大时会单独说明本次无法判断。界面还会显示本次会话中未处理的脚本错误次数，以及被工具限制、加载失败或返回 HTTP 错误的资源域名和类型，并列出已阻止的新窗口与实时连接次数。计数上限为 1000，资源错误最多保留 30 项；这些诊断仅在临时会话和当前界面内存中存在，不读取内嵌页面正文，不保存异常消息、资源路径、查询参数、认证页面正文或 Cookie。没有可见文字也可能是图片或画布页面，加载失败也可能来自取消请求；没有错误记录不能证明验证成功，出现某个域名或脚本错误也不能直接认定为空白或按钮无响应的原因。

只把 `apps/web/dist` 上传到纯静态托管时，不会同时获得 `/api/jd/extract`、`/api/jd/browser-session`、`/api/opportunities/source` 或 `/api/network/*`，需要另行部署兼容后端。没有提取服务时，仍可手动保存原链接和正文，或在配置好图片模型后使用截图识别。独立浏览器窗口打开在本地服务所在的电脑；此流程用于本机工作台，不能代替远程服务器的浏览器会话界面。

在 **截图识别** 中选择、拖入或 `Ctrl + V` 粘贴 PNG/JPEG/WebP 图片，最多 6 张，每张不超过 10 MB、总计不超过 24 MB，按阅读顺序上传。点击 **识别截图文字** 才会将图片发送给你配置的模型，模型必须支持图片输入；这不是浏览器内置的离线 OCR。核对原文后再确认使用，模糊文字、薪资和岗位要求尤其需要检查。原始截图只保留在当前页面，刷新后不会恢复；确认后的 JD 文字与来源会自动保存在当前浏览器。

已实现这些平台的官方链接识别、公开网页提取与截图识别流程，真实招聘平台的提取成功率、真实截图 OCR 准确性仍需实际样本验收。提取、识别和匹配分析都不会自动增加个人事实或发起投递。

## 网络与代理

点击左下角 **网络** 打开 **网络与代理**；岗位链接区及链接提取错误处也有入口。配置仅作用于 Node 本地服务发起的 **岗位链接提取** 和 **公司公开招聘源** 请求，包括 Greenhouse、Lever、腾讯官网。AI、简历/岗位截图识别、模型列表和 **打开原岗位** 等浏览器请求仍跟随浏览器与系统网络；在这里填写代理不会改变浏览器或操作系统的代理设置。

- **自动检测**（默认）：优先使用本地服务进程的 `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY`（也接受对应小写变量），再使用已启用的 Windows 当前用户系统代理；未发现代理配置时直接连接。按目标协议选择代理，遵守 `NO_PROXY` 和绕过规则；只配置 SOCKS 或 PAC 时会提示不支持，已选代理失败时不会静默改为直连。
- **直接连接**：本应用不额外使用 HTTP/HTTPS 代理，可与自动模式对照排查；系统的 TUN 等网络接管仍可能影响实际连接。
- **手动代理**：填写代理软件的 **HTTP 或 Mixed 端口**，例如 `http://127.0.0.1:7890`；地址支持 `http://` / `https://`，不能含用户名、密码、路径、查询参数或片段。暂不支持 SOCKS 和执行 PAC 脚本；如软件只显示 SOCKS 端口，需先在代理软件中启用 HTTP/Mixed 入口。

面板打开时自动检测，也可点 **重新检测**。检测读取的是运行本地服务的电脑，并检查常见本机端口；**端口有响应只代表存在监听，候选不会自动应用**。点击 **使用此代理** 仅填入手动配置草稿。可在 **不走代理的地址** 填写主机、IP 或域名后缀，以逗号分隔，默认绕过 `localhost,127.0.0.1,::1`。

选择 51job、BOSS直聘、猎聘、LinkedIn、Greenhouse、Lever 或腾讯，点击 **测试当前配置**，查看本次连接路线、HTTP 状态和耗时；测试使用当前草稿，不保存配置。连接成功只说明收到网站响应，登录、验证码、403 和动态页面仍可能阻止岗位提取。确认后点 **保存设置**，后续岗位请求生效；取消放弃本次修改。进程环境变量以启动服务时继承的值为准，修改外部环境变量后需要重启服务。

**国内招聘平台独立代理** 是可选配置，填写后仅 `51job.com`、`zhipin.com`、`liepin.com` 及其子域名使用该地址，优先于上方常规模式与绕过规则；其他来源保留常规路线。留空恢复普通设置。独立代理失败明确报错，不静默切到原代理或直连。

Windows 全局 TUN 可能继续接管软件的“直连”。需要保持现有 GPT 代理时，可运行 `pnpm network:domestic:start` 启动独立的物理网卡/DNS通路，再在上述字段填写 `http://127.0.0.1:17891` 并保存。`pnpm network:domestic:status` 查询，`pnpm network:domestic:stop` 停止；首次下载可加 `-DownloadProxy http://127.0.0.1:7890`，接口可加 `-InterfaceName WLAN`。脚本只管理自己的独立进程，不改变 FlClash/系统代理/路由/TUN；没有注册开机任务，系统重启后需要再启动。PowerShell 执行策略选项仅限该子进程，不修改机器策略。完整操作与校验边界见 [辅助进程说明](scripts/README-domestic-route.md)。

三个指定原岗位均已有正式产品全文读取：51job `166761768` 为393字符（5条职责及5条要求），BOSS原移动分享岗位为3175字符，猎聘 `1984701079` 为2263字符、33个换行。2026-10-18最新正式回归中，两个新BOSS岗位页均从默认四行折叠自动展开，首次0/30/120秒和关闭重开0/30秒共五次全文一致；随后51job、猎聘各0/30秒全文也与旧记录逐字一致。9次读取前后主文档请求数保持，4次关闭确认。51job/猎聘此前另通过五分钟、关闭重开与平台回切。这些是三个具体岗位的有限区间验证，多岗位与长期持续读取仍待验收。

当前标准51job、原生猎聘和原生BOSS三个引擎共享一个活跃岗位名额。BOSS原移动分享页的职位描述默认折叠时，读取会尝试点击与该正文关联、完整可见的“查看全部”，展开后再检查全文。按钮被遮挡、无法确认或点击后仍折叠时，会提示在“职位描述”区域手动展开后再读取，不采用四行摘要或隐藏尾文。真实进程退出后允许在确认归属及退出后重开，调试连接中断本身不触发替换浏览器。此前的持续刷新、猎聘空白和快照失败记录保留在报告中，不能与最新成功样本混为一轮。

前批网络证据见 [国内岗位可靠性验收](docs/reports/domestic-job-reliability-2026-10-17.md)，完整架构、自动检查、真实读取及尚未通过的范围见 [浏览器读取验收](docs/reports/job-browser-reading-2026-10-17.md)。合成测试、窗口已创建及HTTP200分别记录，不能替代原岗位完整正文与实际观察区间。

Google/GitHub及对应Playwright 1.64.1资料研究见 [访问路径研究](docs/research/job-reading-access-paths-2026-10-17.md)。本机纯本地实验确认：浏览器后续HTTP重定向不会再次进入同一个route回调，fetch(maxRedirects:0)后fulfill 3xx也存在这一行为。当前请求检查只覆盖进入回调的请求，最终正文另核对来源；独立helper有更宽的三平台出口规则，尚未实现逐会话、逐跳的单平台出站隔离。

网络配置独立保存到仓库根的 `data/network-settings.json`，`data/` 已被 Git 忽略，不进入简历/机会备份，也不随浏览器站点数据清理；同一仓库本地服务共享此文件。配置不保存代理凭据。网络接口随 Vite **dev / preview** 服务提供，并仅允许本机同源页面访问；纯静态托管没有这些接口，远程服务器也无法检测访问者电脑上的系统代理或本机端口。请通过正在运行的本地服务地址使用此能力。

## 机会与手动投递

机会库可以独立于 AI 使用。手动录入公司、职位和 JD，保留 **发现渠道 → 详情来源 → 原始申请链接**；来源平台与企业/猎头/中介主体分别记录。相同来源链接会提示已有记录并保留原信息，同名公司/职位不会直接合并。国内、海外和地区待确认由实际工作地点核对后填写；远程允许地区单独记录，`Remote` 不等于可在任何国家入职。

原始发布时间、平台刷新时间、首次发现时间、本次采集时间、最近核验时间和确认提交时间独立显示；未提供的字段保持缺失。发布方刷新职位、HR 活跃、今天读取或本人今天收藏，都不替代原始发布日期。岗位开放/关闭状态和自己的投递阶段分开保存。

列表、阶段看板、当前岗位/公司/面试/Offer 数量和文字地点分布使用相同的当前筛选。公司数按已保存名称统计，尚无公司实体去重；地区切换是个人库筛选，尚无可缩放、可点击的真实地图，也不代表覆盖全国或海外市场的岗位总数。阶段看板按当前阶段分组，修改阶段在列表或详情中操作，不提供拖拽改阶段。

岗位信息点击 **保存岗位**，备注和下一步点击 **保存跟进** 后才持久化；它们不使用简历的条件自动保存或草稿历史。未保存时关闭详情、重新读取或离开页面有放弃提示/浏览器离开保护；仍应在刷新或切换设备前主动保存。阶段变更、收藏所选和材料记录会立即尝试保存，失败显示错误，不把失败显示成成功。

**已投递** 由本人确认已经在原网站完成提交；打开链接、准备简历、AI 分析和生成材料都不会自动登记为提交。下一步与跟进时间用于手动记录，目前不发送后台提醒、邮件或消息，不自动填表/申请。详情里的 **记录当前简历快照** 保存当前语言的 Markdown 内容以及简历名称/视图/时间；之后修改事实或删除简历不会改写它。每个机会最多 30 份快照，可查看、下载或删除；这不是 PDF/Word 附件库，也不证明该材料确实已发送。

申请截止原文和明确截止日期分别填写；“招满即止”等文字不会被猜成日期，也不会自动把岗位关闭。联系人、申请渠道和联系方式由本人填写，点击 **保存跟进** 保存。**补录一次沟通** 记录已经发出或收到的内容，需要勾选已实际发生，不能填写未来时间；每岗最多 200 条，不会发送消息或改变阶段。

跟进时间和沟通时间统一按北京时间（Asia/Shanghai）输入、展示。**下一步，有安排** 按“已逾期 / 今日稍后 / 明天起”分组，与当前筛选同步；Offer 仍可安排谈薪、补问条款，未通过/已撤回不列入队列。申请截止日与跟进时间各自保存，截止日不自动生成待办。应用内确认框支持取消和 Escape，取消后保留未保存输入；浏览器关闭保护仍使用浏览器自己的离开提示。

机会区 **备份** 下载 `better-me-opportunities-日期.json`，包含全部机会、来源/时间、阶段历史、跟进与材料 Markdown 正文。**导入** 合并有效机会备份，重复 ID 或相同来源保留已有记录；损坏库有原文下载和显式恢复流程，多窗口修订冲突会阻止覆盖。**导出当前 CSV** 只导出当前筛选结果，用于表格查看，包含材料摘要但不替代完整备份。当前最多保存 2,000 个机会，JSON 上限 4 MB；清理浏览器数据前应下载备份。

### 从公司公开招聘页发现机会

选择 Greenhouse 或 Lever，填写正确的公司 board slug，或该系统的官方招聘页链接，例如 `https://job-boards.greenhouse.io/公司标识` / `https://jobs.lever.co/公司标识`。**查看公开岗位** 只读取预览，不写入个人库；勾选后点击 **收藏所选** 才保存。同来源已存在时保留其投递进度和原数据。

选择 **腾讯招聘官网** 可输入岗位关键词，固定读取官网搜索结果第 1 页、最多 100 条，不自动翻页。国家与单城市按官网披露保留，国家精确为“中国”才归国内；其它市场与多地点待核对。职责是搜索摘录，可能缺任职要求；`LastUpdateTime` 日期原文单独保留在摘录中，既不冒充发布时间，也不补造时分秒。2026-10-17“后台”样本当次匹配 112 条，返回 100 条并提示更多结果。详见[国内官网源记录](docs/research/domestic-official-source-2026-10-17.md)。

后台只读取固定官方 HTTPS API，限制为 ATS 最多 300 条/腾讯最多 100 条、15 秒和 8 MB，截断会提示；不接受任意网页代理或跳转。缺少可靠地理字段时，原始地点放在 JD 正文，市场和资格留待核对，公司名也可能仍是 board slug。源明确提供的发布时间与更新时间分别保留；开放列表只表示本次观察，未开启后续自动核验/关闭同步。

2026-10-17 的真实只读试点中，Greenhouse `duolingo` 返回 63 条、Lever `spotify` 返回 82 条。该记录证明当时两个公开 API 样本可读取，不保证所有公司或后续页面始终兼容；这也不等于 BOSS/51job/猎聘/LinkedIn 真实链接采集已经验收。接口由 Vite dev/preview 提供，纯静态部署需兼容后端。

## 本地保存与 AI 隐私

当前事实库、简历视图、简历编辑草稿、JD 草稿、机会库和 AI 配置保存在本机浏览器的 `localStorage`，简历历史版本保存在同一来源的 IndexedDB。重新打开相同地址可以继续使用；换浏览器、端口、设备，或清理站点数据后，不会自动获得原数据。简历和机会库分别备份，不包含 API Key、AI 配置、JD 草稿、原始截图或简历历史链。浏览器存储可能不可用或空间不足，页面会显示保存/读取失败；先检查保存状态，出现错误时下载对应备份或草稿。

每次编辑简历立即尝试写入独立的本地草稿，尚未补齐的姓名、日期、量化字段和无效邮箱也可以保护下来，刷新后恢复继续编辑。这种草稿保护不生成历史版本。只有满足所选自动保存条件，或手动点 **立即保存** / `Ctrl/Cmd + S`，完整内容通过严格校验才更新正式文档与版本。自动保存关闭或选择回车/离开字段时，刷新、切换页面也不会绕过条件生成正式版本；未保存的草稿会恢复，仍等待触发。保存设置按当前浏览器来源记忆，不进入简历备份或版本；机会编辑另按显式保存流程处理。

不完整草稿继续保留上次完整文档，补齐后仍需满足所选条件或手动保存。浏览器拒绝写入时会明确提示，此时修改可能只在页面中，需要先下载留存。未完成内容导出为 `better-me-draft-日期.json`，供保存和修正，不能当成完整备份直接恢复。

**历史版本** 保留最近 50 个完整快照，包含自动保存、命名检查点、导入和恢复记录。相邻自动版本默认在 60 秒内合并，可在保存设置改为 15–600 秒；固定窗口内更新同一版，持续编辑超过窗口才另建版本，内容未变不新建。命名检查点单独保留；超过总量上限时最旧记录会被清理，命名也不代表永久保存。恢复旧版本会先保护切换前内容，再产生新的当前版本，不会把后面的修改历史截断。它是此浏览器内的版本回看功能，不是 Git 分支，也没有远端或跨设备同步；完整文档 JSON 备份不携带整条历史链，长期保存某一版应先切换到该版并下载备份。

另一窗口修改同一份简历时，当前窗口会提示冲突并暂停自动保存；继续编辑仍保持暂停，需要手动保存才表示采用当前窗口内容，并先保护另一窗口的完整版本。切换前未完成草稿会另存并提供下载入口。若原有文档或草稿损坏，会保留原始内容并提供下载/恢复入口，不自动用演示数据覆盖。历史版本写入失败与当前文档保存失败分别提示。

离线规则解析、手动机会记录和资料导航无需模型服务。使用云模型时，分析所需的简历文本、JD 或页面图片会**直接发送给用户选择的模型提供商**，API Key 也会用于向该服务鉴权；模型请求不经过本项目的自建中转。岗位分享链接和公司 ATS 读取由本地 Vite 服务访问对应公开来源，资料外链会打开原站。本地保存不等于云推理全程离线。使用本机 Ollama 时仍需自己确认所选地址与模型部署位置。

AI 配置通过工作台界面完成。当前代码**不读取 `.env` 中的 `BETTER_ME_LLM_*` 变量**；`.env.example` 仅解释这一边界。不要把真实 Key 写进示例、源码或 Vite 的前端构建变量。

真实履历、联系方式、证据、Key 和私有备份不进 Git。`.gitignore` 默认忽略个人 SSOT、数据库、私有命名文件和 `better-me-backup-*.json`，但重命名、强制添加和已跟踪文件仍需人工检查。请把真实备份放在仓库外的私人目录。
