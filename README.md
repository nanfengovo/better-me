# 迈向更好 · BetterMe

本地优先的职业成长与求职 Agent。通过真实经历了解自己、围绕目标岗位查漏补缺，再将核实成果用于简历、面试和职业决策。
仓库：[github.com/nanfengovo/better-me](https://github.com/nanfengovo/better-me)

当前版本先交付简历工作室：**导入/编辑 Fact 事实库 → 核对量化与表述 → 自定义排版与六套模板 → 自动保存与历史版本 → 打印 PDF / 导出 Markdown → 岗位链接、截图识别与 AI 分析 JD**。对话规划、契约学习、测评、机会地图和投递属于后续阶段，尚未实现。

## 当前能力与边界

| 模块 | 当前提供的能力 | 使用边界 |
|---|---|---|
| 事实库与预览 | 编辑个人信息、经历、技术栈和成果要点；实时生成简历视图 | Fact 与 ResumeView 分离；AI 提示和结构校验不能证明经历真实 |
| 简历导入 | PDF、DOCX、HTML、Markdown、TXT，以及结构化 JSON；旧 DOC 尽力提取 | 提取结果、规则解析警告和未解析内容需要核对；不承诺任意格式完整还原 |
| AI / 离线规则解析 | AI 结构化、扫描 PDF 的视觉识别、手动选择离线规则 | AI 失败显示错误，不静默换成离线结果；缺失经历信息不补造默认职位、日期或成绩 |
| 量化核实 | 从原文提取可识别数字，导入后默认未核实 | 带未核实结构化量化的要点不进入正式预览；核对数值、单位和背景后再勾选“已核实” |
| 中英字段 | 编辑已有双语字段，切换中文/英文输出 | 不是自动翻译；缺少目标语言字段时会回退已有语言，应在投递前检查 |
| 头像 | 上传、部分文档图片提取、页面裁剪及照片显示开关 | 自动识别结果需要人工检查；简洁 ATS 模板固定不显示照片 |
| 排版与模板 | 六套自研模板；分节排序/隐藏；个人信息开关；经历/要点选择；主题色、字体、字号、行距和边距 | 隐藏只改变这份简历的展示，事实库保留原内容；模板与输出语言独立 |
| 文字格式 | 在姓名、职业定位和事实要点中选择文字，再加粗、斜体、下划线、高亮或调整大小 | 格式保存在简历视图中；PDF 保留视觉样式，Markdown 保留结构与强调，不保留页面尺寸和字号 |
| 岗位采集 | 粘贴 JD、读取 LinkedIn/猎聘/51JOB/BOSS 直聘官方分享链接、上传/拖入/粘贴截图识别；保存文字、来源与采集时间 | 公开链接读取依赖本地开发/预览服务；登录、验证码、动态页面或仅 App 可见的正文可能无法读取；提取后须确认文字 |
| AI 配置与 JD 分析 | Gemini、OpenAI 兼容服务、DeepSeek、本地 Ollama；匹配诊断、差距与表述建议 | 模型列表可访问不等于生成请求已验证；建议供审阅/复制，不会自动写回 Fact；分数不是录用概率 |
| 自动保存与版本 | 自动保存开关；回车、停止输入或离开编辑项触发；自定义停顿和版本合并间隔；即时草稿保护；最近 50 个版本、命名检查点、逐项差异与恢复 | 关闭自动保存仍保留草稿和手动保存。当前文档/草稿使用 localStorage，历史版本使用 IndexedDB；历史包括命名检查点，总量上限仍为 50；没有账号、Git 仓库或云同步 |
| 导出 | 浏览器打印/另存 PDF、当前输出语言的 Markdown、完整文档 JSON | PDF 依赖浏览器打印设置；尚无 DOCX 导出 |

六套模板已分别排版，支持同一份事实切换展示：

- `zh-classic`：经典正式，居中抬头与清晰分节。
- `en-ats`：简洁单栏，无照片和装饰侧栏，链接以文字保留。名称表示设计用途，不代表通过所有招聘系统的解析认证。
- `clean-modern`：现代信息布局，使用分区抬头与重点标签突出项目和技术经历。
- `editorial`：编辑部，大字抬头、侧标分节和书刊风格的留白。
- `sidebar`：左岸，个人资料置于窄栏，正文聚焦经历与成果。
- `compact`：精练履历，横向信息带与紧凑分节，适合信息密集的简历。

模板 ID 不决定输出语言；语言通过工作台的中文/英文按钮切换。预览缩放与「适应宽度」只改变屏幕显示，排版中的字号、间距和边距则同时影响预览与 PDF。

桌面端可拖动编辑区与预览区之间的分隔线，实时调整两侧占比；比例会在当前浏览器来源记住。双击分隔线或聚焦后按 `Enter` 恢复默认，左右方向键微调（按住 `Shift` 加大步长），`Home` / `End` 到达可用边界。窄屏自动切为上下布局。

预览默认适应实际宽度，拖动分栏时纸张同步缩放；也可以用加减按钮手动调至 20–130%，再点「适应预览宽度」恢复自动。默认开启「跟随编辑」：点击或输入某个字段、滚动左侧经历时，右侧定位并轻标记对应内容。手动滚动或浏览右侧会暂时暂停跟随，继续操作左侧后恢复；关闭「跟随编辑」可独立浏览。定位只移动预览内部，不带动整页；被隐藏的字段不会因此重新出现。

## 快速开始

准备满足 [package.json](package.json) 中 `engines` 要求的 Node.js，并使用 `packageManager` 指定版本的 pnpm。

```bash
pnpm install
pnpm dev
```

浏览器打开 Vite 提示的地址（默认 `http://localhost:5173`）。

首次启动显示演示数据。可先用 [examples/](examples/README.md) 中的样例熟悉操作，再处理自己的简历。

## 使用流程

1. 点击 **导入简历**，上传 PDF、Word 或文本文件；检查提取文字，选择 AI 或离线规则解析。扫描 PDF 的视觉识别需要支持图片输入的模型。
2. 对照原文检查解析结果、警告和未解析项，再确认替换当前文档。导入前可通过 **更多简历操作 → 下载 JSON 备份** 留存现有数据。
3. 在 **内容编辑** 中补充信息，核对每条数字与单位，再确认量化。需要强调某个词时，先选中文字，再用上方工具栏调整格式；加粗/斜体/下划线也支持 `Ctrl/Cmd + B/I/U`。
4. 打开 **排版与模板** 选择模板、调整分节顺序和显示开关。例如把工作经历移到最前、把教育背景放到最后，关闭 **抬头中的学历**；国内投递可以保留照片，海外投递可以用无照片预设。再选择输出语言，检查英文缺失、长链接及跨页效果。
5. 使用 **导出 PDF / 打印**，在浏览器打印对话框选择另存为 PDF；建议检查 A4 纸张、缩放、页眉页脚和分页。也可下载/复制 Markdown。
6. 顶部可开关 **自动保存**，旁边的 **自动保存设置** 可选择按回车、停止输入或离开编辑项保存。默认按回车，停顿模式可自定义 1–300 秒；输入法选词回车和 `Shift + Enter` 不触发保存。随时可点 **立即保存** 或 `Ctrl/Cmd + S`。投递前打开 **历史版本**，为完整内容命名并保存检查点；选择旧版查看简历和逐项差异，再用 **恢复为新版本** 切换。`Ctrl/Cmd + Shift + S` 打开历史版本。
7. 需要 JD 分析时，打开侧栏 **岗位** 或编辑器下方的岗位入口。可以粘贴正文，也可以先提取分享链接、识别截图并点击 **确认并使用正文**。在 **AI 配置** 设置服务地址、Key 和模型后再分析；结果供人工判断，不会自动改写事实库。
8. 点击右上方 **更多简历操作** → **下载 JSON 备份**，下载 `better-me-backup-日期.json`；更换浏览器或设备后，用 **从备份恢复** 读取该文件。完整备份包含事实库及简历视图，不包含 API Key、AI 配置、JD 草稿、截图或本地版本历史。

**恢复** 用于完整 BetterMe 文档 JSON；**导入简历** 用于提取/解析简历。仅含 FactBase 的 JSON 与 PDF/Markdown 不能替代完整备份恢复。确认导入或恢复会替换当前文档，建议操作前备份。

## 岗位链接与截图

在 **分享链接** 中粘贴 LinkedIn、猎聘、51JOB、BOSS 直聘的官方岗位链接或完整分享消息，然后点击 **提取岗位正文**。读取结果先进入核对区，你可以修改识别错误，再点击 **确认并使用正文**；正文显示来源平台、原岗位链接和采集时间。多个岗位链接需要分开处理。

链接读取通过当前工作台的 `/api/jd/extract` 完成，该接口由 Vite 开发服务和本地预览服务提供。`pnpm dev` 可直接使用；要在生产构建后本地预览，可运行：

```bash
pnpm build
pnpm --filter @better-me/web preview
```

只把 `apps/web/dist` 上传到纯静态托管时，不会同时获得这个接口，需要另行部署兼容的提取服务。没有提取服务时，仍可粘贴文字，或在配置好图片模型后使用截图识别。公开读取不携带招聘账号登录状态，不处理验证码；访问失败时可点击 **打开原岗位**，自行查看后截图。

在 **截图识别** 中选择、拖入或 `Ctrl + V` 粘贴 PNG/JPEG/WebP 图片，最多 6 张，每张不超过 10 MB、总计不超过 24 MB，按阅读顺序上传。点击 **识别截图文字** 才会将图片发送给你配置的模型，模型必须支持图片输入；这不是浏览器内置的离线 OCR。核对原文后再确认使用，模糊文字、薪资和岗位要求尤其需要检查。原始截图只保留在当前页面，刷新后不会恢复；确认后的 JD 文字与来源会自动保存在当前浏览器。

已实现这些平台的官方链接识别、公开网页提取与截图识别流程，真实招聘平台的提取成功率、真实截图 OCR 准确性仍需实际样本验收。提取、识别和匹配分析都不会自动增加个人事实或发起投递。

## 本地保存与 AI 隐私

当前事实库、简历视图、编辑草稿、JD 草稿和 AI 配置保存在本机浏览器的 `localStorage`，历史版本保存在同一来源的 IndexedDB。重新打开相同地址可以继续使用；换浏览器、端口、设备，或清理站点数据后，不会自动获得原数据。浏览器存储可能不可用或空间不足，页面会显示保存/读取失败；先检查保存状态，出现错误时下载备份或草稿。

每次编辑立即尝试写入独立的本地草稿，尚未补齐的姓名、日期、量化字段和无效邮箱也可以保护下来，刷新后恢复继续编辑。这种草稿保护不生成历史版本。只有满足所选自动保存条件，或手动点 **立即保存** / `Ctrl/Cmd + S`，完整内容通过严格校验才更新正式文档与版本。自动保存关闭或选择回车/离开字段时，刷新、切换页面也不会绕过条件生成正式版本；未保存的草稿会恢复，仍等待触发。保存设置按当前浏览器来源记忆，不进入简历备份或版本。

不完整草稿继续保留上次完整文档，补齐后仍需满足所选条件或手动保存。浏览器拒绝写入时会明确提示，此时修改可能只在页面中，需要先下载留存。未完成内容导出为 `better-me-draft-日期.json`，供保存和修正，不能当成完整备份直接恢复。

**历史版本** 保留最近 50 个完整快照，包含自动保存、命名检查点、导入和恢复记录。相邻自动版本默认在 60 秒内合并，可在保存设置改为 15–600 秒；固定窗口内更新同一版，持续编辑超过窗口才另建版本，内容未变不新建。命名检查点单独保留；超过总量上限时最旧记录会被清理，命名也不代表永久保存。恢复旧版本会先保护切换前内容，再产生新的当前版本，不会把后面的修改历史截断。它是此浏览器内的版本回看功能，不是 Git 分支，也没有远端或跨设备同步；完整文档 JSON 备份不携带整条历史链，长期保存某一版应先切换到该版并下载备份。

另一窗口修改同一份简历时，当前窗口会提示冲突并暂停自动保存；继续编辑仍保持暂停，需要手动保存才表示采用当前窗口内容，并先保护另一窗口的完整版本。切换前未完成草稿会另存并提供下载入口。若原有文档或草稿损坏，会保留原始内容并提供下载/恢复入口，不自动用演示数据覆盖。历史版本写入失败与当前文档保存失败分别提示。

离线规则解析无需模型服务。使用云模型时，分析所需的简历文本、JD 或页面图片会**直接发送给用户选择的模型提供商**，API Key 也会用于向该服务鉴权；模型请求不经过本项目的自建中转。岗位分享链接则由本地 Vite 服务访问对应公开招聘网页。本地保存不等于云推理全程离线。使用本机 Ollama 时仍需自己确认所选地址与模型部署位置。

AI 配置通过工作台界面完成。当前代码**不读取 `.env` 中的 `BETTER_ME_LLM_*` 变量**；`.env.example` 仅解释这一边界。不要把真实 Key 写进示例、源码或 Vite 的前端构建变量。

真实履历、联系方式、证据、Key 和私有备份不进 Git。`.gitignore` 默认忽略个人 SSOT、数据库、私有命名文件和 `better-me-backup-*.json`，但重命名、强制添加和已跟踪文件仍需人工检查。请把真实备份放在仓库外的私人目录。

## 开发检查

```bash
pnpm test
pnpm lint
pnpm typecheck
pnpm build
pnpm memory:check
```

`pnpm lint` 运行 ESLint，`pnpm typecheck` 运行 TypeScript 类型检查。自动化检查覆盖核心解析/投影/存储等约定，不等于真实模型调用、任意简历 OCR、全部浏览器打印或招聘系统解析均已验收。`memory:check` 只检查约定记忆文件是否存在。

## 仓库结构

```text
apps/web              # React 19 + Vite + Tailwind 工作台
packages/core         # @better-me/core — Schema / 解析 / 投影 / 校验 / AI 薄客户端
packages/storage      # @better-me/storage — localStorage 草稿/文档、IndexedDB 版本、差异与 JSON 备份
examples/             # 虚构/泛化示例，不含用户真实简历或 Key
docs/planning/        # 产品规划，区分愿景与当前实现
docs/research/        # 开源来源研究与采用边界
.agent-memory/        # 开发侧跨会话记忆；私人求职 SSOT 默认忽略
templates/            # 模板来源与资产约定；实际布局目前在 apps/web
```
