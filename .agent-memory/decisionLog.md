- **决策**：对外英文名 **BetterMe**；npm scope `@better-me/*`；公开仓库 **https://github.com/nanfengovo/better-me**。
- **理由**：与成长定位一致，便于开源与包名；中文品牌仍为「迈向更好」。

- **决策**：自己用爽 → 再开源。
- **理由**：早期迭代快；开源后再处理多用户与贡献流程。

- **决策**：不做系统锁机；契约打卡属远期。

## 2026-10-16 | V1 核心 = 写好有亮点的简历

- **决策**：Fact 事实库 + STAR + 空洞检测 + 量化须用户确认；AI 禁止凭空加数字。
- **理由**：填表工具同质化；差异在证据化亮点与可答辩。
- **不选**：「一键生成整份简历」无追溯。

## 2026-10-16 | 模板库来源

- **决策**：自研 3–4 套为主；合法 MIT 等开源主题可适配并保留 NOTICE；禁止爬商业简历站。
- **内置意向**：`zh-classic` / `zh-sidebar` / `en-ats` / `md-plain`
- **不选**：镜像超级简历、五百丁等商业模板。

## 2026-10-16 | 开发侧记忆用 Memory Bank

- **决策**：采用 `.agent-memory/`（精简四件套），不用并行 better-handoff；MCP 记忆延后。

## 2026-10-16 | activeContext「必读附加」+ 无感续聊

- **决策**：`activeContext` 增加「必读附加」；用户说「聊到哪了 / 继续」时，Agent 必须连同附加文件一起读，无需用户点名。

## 2026-10-16 | 求职记忆拆分规则

- **决策**：求职 SSOT 拆为 `careerObjectives.md`（目标/红线/人设）、`factBase.md`（经历与开源事实）、`resumeGuidelines.md`（改简历硬规则）；原 `careerStrategy.md` 降为索引。拆分通则写入 `README.md`（体量 / 受众 / 更新节奏 / 开局误读）。
- **理由**：单文件易膨胀；目标少改、事实常改、禁令少改，受众与节奏不同；避免进度指针被厚正文淹没。
- **不选**：继续向单一 `careerStrategy.md` 追加聊天式内容；无规则提前建一堆空文件。

## 2026-10-16 | 终局架构：Headless Core + Multi-Shell

- **决策**：成长飞轮终局（认知 → 差距 → 学习打卡 → 成果变现）；V1 = Fact 底座 + 简历成果交付器。代码用 **pnpm workspace + Turborepo**，包名 scope **`@better-me/*`**；`packages/core`（纯 TS/Zod Schema、校验、STAR/防编造、AI 抽象）+ `packages/storage`（存储端口）+ `apps/web`（V1）；远期 `apps/mobile`（Expo）、`packages/plugins`（OB/VS Code）、可选 `apps/desktop`（Tauri）。
- **理由**：求职是收割，飞轮本体是认知与进阶；Core 无头才能被 Web/RN/插件复用，避免推倒重来。
- **不选**：各端独立仓库；V1 就上多端/插件/SaaS；用 Flutter/Go/Rust 写领域核心（无法直复用 VS Code/OB）。

## 2026-10-16 | V1 技术栈拍板

- **决策**：`apps/web` = **React 19 + Vite + Tailwind + Shadcn**；AI = **轻量 OpenAI 兼容 Client**（云 Key + Ollama/LM Studio）；语言 **TypeScript 100%**（指应用与核心包）。
- **理由**：本地单机、组件可进 Webview；与终局 Expo/插件同语言。
- **不选**：Next.js（本地分发/离线多余）；V1 绑定 LangChain/重型 AI 框架（图里若写 LangChain 仅表示「可编排」，实现以薄 Client 为准）；V1 上 Electron 全家桶。

## 2026-10-16 | 存储 SSOT 与 Markdown 关系

- **决策**：**运行时唯一真相源 = 结构化本地库**（Web：SQLite/OPFS 或同等；忌用 LocalStorage 存 Fact）。Markdown（含 Frontmatter）= **一等公民的导入/导出/与 Obsidian Vault 的同步适配器**，不是第二套可并行改写的主库。双向同步若做，必须有明确 leader（默认结构化库）与冲突策略。
- **理由**：双 SSOT 会导致 Fact 防编造与版本漂移；OB 友好靠适配器而非把 Vault 当唯一主库。
- **不选**：云库（Supabase/Firebase）做默认主存；LocalStorage 扛简历/事实数据；无规则的 MD↔JSON 双主写入。

## 2026-10-16 | 动态拉取可用模型与连通性测试 (高可用与用户体验优先)

- **决策**：
  1. 废除前端写死模型名称的生硬逻辑，在 `@better-me/core` 实现 `fetchAvailableModels` 与 `testLlmConnection`；
  2. 针对 Google Gemini：直接请求 Google AI Studio 官方模型列表接口 `GET https://generativelanguage.googleapis.com/v1beta/models?key=${apiKey}`，过滤 `supportedGenerationMethods.includes("generateContent")`，自动剥离前缀生成干净模型 ID；
  3. 针对 OpenAI / DeepSeek / Ollama：请求标准 `GET ${baseUrl}/models` 动态获取可用模型；

  5. JD 诊断失败时直接暴露「前往 AI 配置重新选择可用模型」按钮。
- **理由**：不同用户的 Google 账号与服务商开通的模型版本不同（如老模型下架、新模型灰度）；动态探测能保证 100% 连通性与高可用性，以用户体验为最优先。
- **不选**：在前端固定一两个静态模型名称让用户猜；无测试连接按钮盲目点击后才报错。

## 2026-10-16 | 多格式简历导入、智能排版与视觉 OCR 架构 (替换虚拟数据)

- **决策**：
  1. 支持全主流格式简历导入：PDF（数字文字版与图片扫描件）、Word（DOCX/DOC）、HTML、Markdown、TXT 以及 JSON 备份；
  2. 针对普通数字 PDF：采用 `pdfjs-dist`，基于 Y 轴坐标与段落垂直间距算法重构行首尾换行与段落布局，严密避免文字挤压在同一行的排版破坏；
  3. 针对扫描件 PDF / 图片简历与 OCR 需求：自动检测文字层长度（< 50 字符判定为扫描件），调用 Canvas 渲染高清页面缩略与图像 DataURL，通过多模态视觉模型（如已原生配置的 Google Gemini 1.5/2.0 Flash）执行 Visual OCR 与结构化一体提取，比客户端传统 WebAssembly Tesseract.js 识别率更高且零体积包袱；
  4. 双模解析策略：支持「AI 智能结构化（推荐，自动提取战绩、量化与中英对照）」与「离线启发式规则（单机零网络零 Key 快速解析）」；
  5. 导入即生效：解析成功后生成最新 `FactBase` 与默认简历投影，存入本地 LocalJsonStore，立刻替换 UI 上展示的虚拟 Demo 简历；
  6. 默认种子轻量化：将默认 Demo 调整为更精简合理的产品引导形态（展示已核实 vs 未核实过滤防编造机制），并在 `examples/` 提供完整范例文件。
- **理由**：求职者已有简历格式多样，手动逐字录入门槛极高；通过支持 PDF/DOCX/HTML/MD 多格式一键提取并引入多模态视觉 OCR，大幅降低使用门槛，并实现本地隐私数据无缝上屏。
- **不选**：仅支持 JSON 导入；引入庞大的 60MB+ Tesseract WASM 造成首屏加载缓慢；使用闭源第三方商业付费 OCR 服务破坏单机本地优先原则。

  2. **AI 解析纠偏（零丢失红线）**：重新设计 System Prompt，严禁合并或丢弃任何经历；强制细化分类（`work` 对应公司、`other` 对应项目经历、`education` 对应院校学位），设置 `temperature: 0.1` 杜绝幻觉与跳步，确保所有 Claim 成就完整保留；
  3. **规则解析重构为分段状态机**：彻底废弃此前单行正则暴力匹配，重构为基于教育背景、工作经历、项目经历、专业技能、自我评价的段落状态机，精准提取候选人姓名、职位头衔、最高学历与量化指标；
  4. **投影渲染全覆盖**：修改 `projectResume` 与 `ResumePreview`，解除此前仅渲染 `work` 与 `opensource` 的硬编码限制，使 `education`（教育经历）与 `other`（重点项目经历）、`traits`（核心优势）全部正常渲染呈现在 A4 纸张上。
- **理由**：真实简历普遍带有照片且格式复杂多变；此前投影层与解析层的粗糙逻辑导致项目与教育容易被过滤、头像缺失，严重影响导入体验与保真度。
- **不选**：将头像上传到第三方图床破坏单机隐私原则；仅在前端修补而不修复 Core 层投影过滤。

## 2026-10-16 | 简历头像全场景自动提取、画布智能扫描与一键可视裁剪工具

- **决策**：
  1. **PDF 物理对象级提取**：在 `file-parsers.ts` 解析 PDF 时，遍历 `page.getOperatorList()` 与 `page.objs`，获取嵌入的真实图像 XObject 并自动转换为高清 Data URL，杜绝此前 PDF 导入固定返回空头像列表的缺陷；
  2. **Page 1 画布智能测算与预选**：对基于 Canva、Figma、WPS 等矢量/裁剪蒙版导出的 PDF，在 Page 1 高清 Canvas 上针对标准证件照区域（右上角、左上角）执行非文本色彩方差（Variance）扫描，自动预裁切候选证件照；
  3. **Word DOCX 内嵌图像提取**：通过 `mammoth.images.imgElement` 将 DOCX 中的内嵌真实照片安全转码为 Base64，并做图标尺寸过滤；
  4. **交互式页面裁剪器 (`PageCropperModal`)**：在导入模态框增加「从简历第 1 页截取头像」可视化交互，支持拖拽框选、等比 (3:4) 缩放与快速定位预设（右上角/左上角/居中），实时预览证件照效果，无论 PDF 是矢量、图片还是扫描件均可 1 键秒级截取完美头像；
  5. **多模态 Vision AI 坐标自裁剪**：在多模态视觉 OCR Prompt 中注入 `avatarBbox` 归一化坐标指令，Gemini 视觉模型识别到人像坐标后前端立即无感完成亚像素精准裁剪；
  6. **头像展示与剪贴板增强**：`ResumePreview` 增加「显示/隐藏照片」切换开关（ATS 或外企场景可无痕隐去照片）；`FactEditor` 增加直接 `Ctrl+V` 粘贴剪贴板图片设置头像能力。
- **理由**：求职者简历中 90% 以上为 PDF 格式，此前因 PDF 图片对象抽取未实现导致用户反复反馈「依然存在头像问题」；通过「物理提取 + 画布智能探测 + 视觉 OCR 坐标 + 1键可视框选」四重保障，实现 100% 覆盖任何排版与格式的简历照片。
- **不选**：强制要求用户单独找修图软件裁切后再上传；依赖庞大第三方人脸识别模型拖慢首屏。

## 2026-10-16 | 职业成长 Agent 的首批用户、学习约束与下一阶段顺序

- **决策（用户本轮明确选择）**：先服务本人技术岗社招，国内为主并探索海外；“强制学习”采用契约模式（提醒、专注计时、测验验收、补学与复盘）；保留简历事实底座，下一阶段优先对话规划与学习闭环。本轮先调研与规划，不写业务代码。
- **理由**：长期愿景覆盖从自我认识到提升、求职和 Offer 决策；先以真实个人使用验证缺口→学习→证据→事实回流，比同步铺开所有平台和人群更可验收。
- **不选**：首期就服务海内外所有职业人群；系统级锁机/屏蔽退出；立即把全部愿景塞进当前 V1；先以地图或自动投递替代下一阶段学习闭环。
- **承接文件**：`docs/planning/betterme-product-roadmap-2026-10-16.md` 与 `docs/research/` 四份研究记录。未确认的架构选型、海外路径和学习主线保留为草案/待确认，不视作用户已拍板。

## 2026-10-16 | 国内外机会切换、原始平台主源与既有技术栈补强

- **决策（用户补充明确）**：国内/海外可切换且地图动态变化；地图、数量与列表共享筛选。职位优先使用公司招聘官网、LinkedIn、51job、BOSS、猎聘等原始平台数据，开源聚合作补充；详细展示来源平台、原文链接、发布时间等。学习围绕现有工作经验和主技术栈补目标 JD 的真实缺口。
- **理由**：用户需要能追溯、能判断时效的实际机会，也需要在既有积累上持续提升；地域作为可切换条件，不要求先确定迁居路线。
- **不选**：开源招聘清单作为默认主数据源；正式地图只覆盖个人收藏；平台刷新/采集时间冒充发布时间；默认切换为 AI/Agent 转型路线。
- **设计承接**：规划第 8/9 节与 `docs/research/map-reference-and-counting.md` 细化来源链、原始/相对时间、发布主体、冲突及地图统计。逐平台接入方式和真实可用性仍待实施验证。

## 2026-10-17 | 当前版本可靠性先行与本地提交

- **理由**：导入固定数字与默认事实、预览不同步及保存失败不透明会影响后续成长闭环的可信基础。
- **不选**：仍将旧“只讨论不编码/提交待明示”当作当前约束；当前同时铺学习、地图或自动投递；未经本轮要求直接 push。

## 2026-10-17 | 有效文档与页面草稿、恢复数据分离

- **决策**：维持正式 Schema 严格校验；输入中的不完整状态保留在页面并明确未保存，补齐自动保存，可导出待修草稿；原有损坏存储报错并允许下载/恢复，绝不自动写 Demo 覆盖。localStorage 仍是当前过渡实现，SQLite/OPFS 迁移未完成。
- **理由**：实时输入需要容纳中间状态，同时不能把不完整字段当作有效事实或让恢复操作丢掉原始内容。
- **不选**：放松正式 Schema 接受任意字段；保存失败静默吞掉；把损坏数据等同首次使用；把草稿宣称可直接恢复的完整备份。

## 2026-10-17 | 显式选择语义与导入核实权

- **决策**：ResumeView 增加 all/selected 可选选择模式，兼容旧空数组=全部；显式 selected 空列表表示不选，活动视图跟随新增经历/Claim并清理删除项。新解析量化强制未核实；不能结构化的内容有诊断或明确失败，不补造、截断或静默切换解析方法。
- **理由**：防止新增条目不显示及删除最后选中项后意外暴露隐藏条目；用户核实与模型提取分开。
- **不选**：永远以空数组同时表达全部和零项；直接信任模型的 confirmed=true；用固定数字/默认日期凑合法数据。历史“零丢失/100%连通/绝不上云”描述不作为当前能力保证，以 README 与本轮验收边界为准。

## 2026-10-17 | 简历工作室与视图排版

- **理由**：突出工作成果、弱化非优势字段是展示取舍，不能因此删除或复制改写事实库；模板语言与版式也应独立。
- **不选**：为每套模板维护另一份 Fact；强制把学历置顶；国内/海外仅靠固定模板决定照片；爬取商业简历站样式或用未经处理的 HTML 富文本。

## 2026-10-17 | 即时草稿与完整历史版本

- **决策**：替代上轮仅页面草稿方案：每次编辑同步写入独立 localStorage 草稿，650ms 防抖后严格校验正式文档；IndexedDB 保存最近 50 个完整快照，15 秒内自动快照合并，支持命名检查点、逐项差异、预览与恢复。恢复先保护切换前内容，再新增版本；多窗口冲突暂停自动覆盖。历史与文档/草稿写入失败分别提示，配置与 Key 不进入版本或 JSON 备份。
- **理由**：未完成字段也需抵御刷新，完整事实的校验不能放松；版本需要可检查的前后值与恢复路径，不能只留最后一份 JSON。
- **不选**：把不完整编辑当成正式有效文档；让输入过程只留内存；把整个 Git 引擎或无限增长快照塞进浏览器；宣称本地 50 版等同 Git 分支、永久备份或跨设备同步。JSON 备份暂不包含整条历史链。

## 2026-10-17 | 用户分享链接与截图回退

- **决策**：当前 V1 增加用户提供的 LinkedIn/猎聘/51JOB/BOSS 官方链接/分享消息读取，Vite dev/preview 提供受限 HTTPS 公开页提取接口；逐跳校验官方域名，保留来源与观察时间。截图支持选择/拖入/粘贴，点击识别才发送至用户配置的图片模型；提取文本核对确认后才用于匹配。

- **不选**：任意 URL 的通用代理；复用用户登录 Cookie、绕过验证码或反爬；未经点击就发送截图；识别结果自动写入个人 Fact；把单链接导入等同岗位地图、持续抓取或全平台实测成功。纯静态部署需另配提取服务，真实平台成功采集与云 OCR 仍待样本验收。

## 2026-10-17 | 分栏偏好与语义预览跟随

- **决策**：桌面分栏可拖动并独立保存浏览器偏好；默认自动适应预览宽度。左侧交互以稳定字段/经历/要点 ID 定位右侧，只滚动预览画布；拖动保持最近语义目标。跟随默认开启，可关闭，手动浏览右侧暂停、继续左侧交互恢复。分栏/跟随偏好不进入 Fact、ResumeView 或文档历史。
- **理由**：编辑表单与六种简历版式长度和顺序不同，语义对应才能定位实际修改内容；工作区偏好无需制造文档版本，用户也需要独立查看预览。
- **不选**：按左右总滚动比例硬同步；scrollIntoView 带动整页；resize 自动抢回手动浏览；让隐藏字段因为定位重新显示；将屏幕定位高亮打印到 PDF。

## 2026-10-17 | 按条件正式保存与历史合并

- **决策**：替代固定 650ms 自动正式保存。增加独立浏览器保存偏好：开关、回车（默认）/停顿 1–300 秒/离开字段三选一、自动版本合并 15–600 秒（默认 60 秒）。即时草稿保护始终启用且不造历史；手动保存/检查点仍可用，关闭或回车/失焦模式的刷新与离开页面不绕过条件。输入法选词与修饰键回车不触发，触发限制在简历编辑字段。
- **理由**：防丢编辑与保留正式历史的频率是两个需求。草稿可及时保护，完整版本由用户选择的条件控制；固定合并窗口减少碎片，同时避免持续编辑永远覆盖同一版。
- **不选**：关闭后把草稿一起停掉；刷新静默提交；修改保存偏好制造简历版本；用输入法确认键保存；自动条件冲突时覆盖另一窗口；设置切换让已启动手动保存的结果失真。冲突后继续编辑仍暂停，须手动保存采用当前内容。
