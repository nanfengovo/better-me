# Memory Bank 地图与拆分规则

跨会话 SSOT：本目录。禁止另建并行 `.handoff/`。

## 文件地图

| 文件 | 职责 | 更新频率 | 写法 |
|------|------|----------|------|
| `activeContext.md` | 停点指针（≤1 屏） | 每里程碑 / 收工 | **改写**；含「必读附加」 |
| `progress.md` | 完成项勾选 | 每里程碑 | 勾选；定期删噪音 |
| `decisionLog.md` | 已拍板决策 | 有取舍时 | **只追加** |
| `projectbrief.md` | 产品边界 | 很少 | 改写 |
| `careerObjectives.md` | 求职目标 / 红线 / 人设 | 少 | 改写，禁止贴聊天 |
| `factBase.md` | 工作经历与开源事实（STAR） | 常（加项目/量化） | 改写段落；按经历分节 |
| `resumeGuidelines.md` | 改简历硬规则 | 少 | 改写 |
| `careerStrategy.md` | **索引页**（兼容旧引用） | 结构变时 | 只链到上面三份，不堆正文 |

## 开局读什么（无感续聊）

1. **必读**：`activeContext.md` → `progress.md`
2. **若 `activeContext` 的「必读附加」非空**：按列表再读（用户说「聊到哪了 / 继续」时也要读，无需用户点名文件）
3. **按需**：产品边界 → `projectbrief.md` / `decisionLog.md`；改简历/面试/生成 Fact → 目标+事实+硬规则三份

## 拆文件规则（何时拆、怎么拆）

**默认不拆。** 满足任一条件再拆：

1. **体量**：单文件稳定超过 ~150 行，或扫一遍超过 ~2 分钟
2. **受众不同**：例如「产品进度」vs「个人求职事实」vs「改简历禁令」
3. **更新节奏不同**：常改的事实库 vs 很少动的红线/产品 brief
4. **开局误读**：厚内容淹没了「当前焦点」，导致第一遍续聊答偏

**拆的时候必须同时做：**

1. 新文件只保留**一个主责**（见上表）
2. 旧路径留**短索引**或改 `README` 地图（避免断链）
3. 更新 `activeContext` 的「必读附加」指向新真相源
4. 在 `decisionLog.md` 记一条「拆了什么 / 为何 / 不选的方案」

**禁止：**

- 把对话原文、过程流水账追加进任何 memory 文件
- 在 `activeContext` 里粘贴长 Fact / 长战略正文
- 同一事实在多处全文复制（一处 SSOT，别处只引用）
- 为「看起来整齐」提前建空文件

## 防膨胀

- `activeContext`：永远薄；焦点过期就改写，不追加历史
- `factBase`：按公司/项目分节改写；过时经历可折叠为「归档」一小节，勿无限追加聊天式备注
- `decisionLog`：只记结论与「不选的方案」，不记讨论过程
- 日后 Fact 进程序/JSON 后：md 可只留目标与红线，事实库迁出并在此地图改链
