# Project Brief — 迈向更好

## 一句话

本地优先的**职业成长与求职 Agent**（中文：**迈向更好**；英文：**BetterMe**；仓库：https://github.com/nanfengovo/better-me）。通过对话了解个人经历与目标，组织查漏补缺、契约学习和测评，将核实成果用于简历、面试和职业决策。**现有 V1 核心保留 Fact 真实性底座 + 简历成果交付器**（事实库 → 亮点 → 模板 → 导出 → 中英 → JD 匹配）。

## 终局飞轮（完全体视角）

1. **认知与基线**：性格/爱好/价值观（输入信号）→ Fact Base → 能力矩阵
2. **目标与差距**：JD / 目标岗 → AI 伴学教练 → Skill Gaps
3. **伴随成长**：学习规划 → 移动端契约打卡 → VS Code/OB 插件流 → 测验/项目
4. **成果变现**：经验回写 Fact → STAR 亮点 → 靶向简历 → 半自动/授权投递与面试复盘

V1 只交付第 4 步的地基（Fact + 简历武器库）；上层模块进路线图，不进 V1 范围。

## 2026-10-17 最新实施顺序

用户明确要求 **Agent 层先不急，先做好非 Agent 层**。当前优先简历/导出、多简历、岗位获取和溯源、手动投递记录与跟进、数据恢复及 UI；对话规划、契约学习、自主执行后置。以下旧阶段顺序是历史背景，不继续作为当前施工顺序。

聚合方向补充确认：**先自用，把各招聘平台和公司官网岗位集中起来，并关联简历与投递记录**。沿用本地优先个人工作台定位；公共招聘搜索站、账号和多用户共享岗位池不纳入本次范围。来源目录、关注公司、统一列表与安全刷新等首版细化仍为实施建议，见 `docs/planning/recruitment-aggregation-assessment-2026-10-17.md`；不据此宣称跨源归并/持续更新已实现，也不替代既有岗位读取修复目标。

2026-10-18 新增明确工程目标：国内 / 全球岗位搜索与高品质 3D 地球、国内 3D 地图，共享岗位工具、查询、证据和统计，并接续 JD 匹配、岗位简历与投递。已确认本机自用后台（预留服务器）、按关注岗位 / 地区 / 公司手动刷新（预留定时）、直线距离（后续通勤）、人民币税前年薪可切原币、按已核实最终控股方来源分类（未知与人工修订）。来源目录 / 适配器与颜色规则可配置，未来由 TS LangChain / LangGraph 包装共享工具；非 Agent 底座先行。三维是正式体验目标，覆盖历史“二维先行、三维后置”建议；当前完成研究与方案，产品尚未实现。完整口径和里程碑仅维护于 `docs/planning/job-atlas-architecture-2026-10-18.md`。

用户进一步明确：岗位需关联求职方向/技术栈、自动推荐与推送；简历导入确认或保存后对比 JD，给出匹配情况和优化规划，重点是**个人真实技能与依据**。需求已记录，匹配需区分能力、简历呈现及偏好，未知不能当不会；具体设计见 `docs/planning/job-skill-matching-loop-2026-10-17.md`。本轮仅需求/设计，尚未实现保存触发、证据匹配、持续采集或推送；不据此启动实际定时任务。完整对话 Agent 与学习执行仍后置，具体功能按新需求分阶段扩展。

已新增机会库/筛选/看板、多简历与独立 MD 材料、GH/Lever 及腾讯官网按需预览收藏、RenderCV YAML、DOCX、资料入口、截止日/联系人/真实沟通和到期队列。最新见 `docs/reports/non-agent-followups-and-export-2026-10-17.md`，前批报告为历史交付。真实地图、持续采集、跨源同岗与自动投递未交付；DOCX 正文/结构已回读，逐页视觉待渲染环境。

用户随后要求优先修复真实简历离线/AI导入，并明确关注不同原稿的布局/字号及手机截图的正确提取。当前导入仍是内容结构化后以自研模板重排；提取原文、模型OCR转录与待补录快照本地留存，不能等同保留原文件或原版式。原稿文档层与Fact语义层、逐字段来源定位及原稿局部编辑是后续设计，未实现。最新质量记录见 `docs/reports/resume-import-repair-2026-10-17.md`。

## 2026-10-16 原先确认的阶段方向

- 首先服务本人技术岗社招，国内为主并探索海外；之后再扩校招/实习、海内外更多职业场景。
- 当时计划保留简历底座、优先“对话规划 + 契约学习 + 验收/证据回流”；2026-10-17 已按用户要求改为非 Agent 优先。
- 契约学习采用提醒、专注、测验、补学和复盘，不采用系统锁机。
- 国内/海外为可切换的机会视图，地图/数量/列表同步变化；官网、LinkedIn、51job、BOSS、猎聘等原始平台为主源，开源聚合作补充，逐条保留来源链、原文链接、各类时间与状态。
- 第一学习方向围绕现有工作经验与主技术栈，补目标 JD 的真实缺口，不默认转型或先选定迁居路线。
- 长期模块补充：AI 模拟面试/口语/刷题、机会地图、授权申请辅助、Offer 对比、OB/VS Code 采集入口。
- 产品草案与来源采用策略见 `docs/planning/betterme-product-roadmap-2026-10-16.md`；成长模块仍处于规划。用户后续已授权先完善当前简历版并做本地 Git 提交，本轮只修现有能力。未经确认的规划细节是建议，不是实施承诺。

## V1 范围（做）

- 结构化填信息 + 实时预览（Fact vs Resume View 分离）
- 简历模板库（自研为主 + 合法开源适配）
- 展示开关、分节排序、选中文字格式；多份简历共享事实；未完成草稿自动保存与本地版本对比/恢复
- 岗位库、来源/时间、手动阶段/跟进、岗位简历及独立材料快照；官网ATS按需预览收藏和备份
- 外部求职资料导航、RenderCV YAML导出；不依赖Agent调用
- 导出：PDF / DOCX / Markdown
- 一键中英（同源事实，禁止两套胡写）
- AI 分析 JD 与岗位匹配度
- 用户提供的 LinkedIn/猎聘/51JOB/BOSS 官方分享链接静态/动态读取，或在各平台专用持久Edge中由用户自行登录/验证后接续原岗位；不接管日常浏览器profile。正文核对后采用，原来源及关闭失败可追溯。四个指定岗位最终各两次正文与一次关闭通过，有限样本不外推全站或长期稳定；当前验收与历史失败见 `docs/reports/job-browser-reading-2026-10-17.md`。
- 本地岗位读取服务支持自动/直连/手动HTTP代理及本机检测/连接测试，配置独立；AI与浏览器外链仍使用系统网络，连通不保证站点正文可提取
- AI：可配置 API Key，也支持本地模型（OpenAI 兼容薄 Client）
- 亮点引擎：STAR、量化确认、空洞检测、Fact 防编造（AI 只出 Proposal，确认后写库）

## V1 不做

- 契约打卡 / 学习计划 / 性格分析（愿景保留，不进 V1）
- 自动投递 / 无范围的招聘站全站抓取（单岗提取已交付；用户按范围手动聚合与地图进入新工程目标，持续定时更新仍后置）
- Obsidian / VS Code 插件
- 移动端 App（架构预留 Expo，V1 不实现）

## 技术架构（已拍板）

- **组织**：pnpm workspace + Turborepo；scope `@better-me/*`
- **核心**：`packages/core`（纯 TS + Zod Schema）+ `packages/storage`（Local-First 端口）
- **V1 UI**：`apps/web` = React 19 + Vite + Tailwind + Shadcn（非 Next.js）
- **存储**：结构化本地库为运行时 SSOT；Markdown/Frontmatter 为一等导入导出与 OB 适配（非双主库）
- **远期壳**：Expo 移动端；OB / VS Code 插件；可选 Tauri 桌面
- **约束**：私人数据与密钥本地保存且不进 Git；云模型推理仅将所需内容直发用户选择的模型提供商，本地保存不等于全程离线；配置与用户数据分离

详情与取舍见 `decisionLog.md`。
