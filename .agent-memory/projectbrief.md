# Project Brief — 迈向更好

## 一句话

本地优先的**职业成长与求职 Agent**（中文：**迈向更好**；英文：**BetterMe**；仓库：https://github.com/nanfengovo/better-me）。通过对话了解个人经历与目标，组织查漏补缺、契约学习和测评，将核实成果用于简历、面试和职业决策。**现有 V1 核心保留 Fact 真实性底座 + 简历成果交付器**（事实库 → 亮点 → 模板 → 导出 → 中英 → JD 匹配）。

## 终局飞轮（完全体视角）

1. **认知与基线**：性格/爱好/价值观（输入信号）→ Fact Base → 能力矩阵
2. **目标与差距**：JD / 目标岗 → AI 伴学教练 → Skill Gaps
3. **伴随成长**：学习规划 → 移动端契约打卡 → VS Code/OB 插件流 → 测验/项目
4. **成果变现**：经验回写 Fact → STAR 亮点 → 靶向简历 → 半自动/授权投递与面试复盘

V1 只交付第 4 步的地基（Fact + 简历武器库）；上层模块进路线图，不进 V1 范围。

## 2026-10-16 本轮明确的下一阶段

- 首先服务本人技术岗社招，国内为主并探索海外；之后再扩校招/实习、海内外更多职业场景。
- 保留简历底座，下一阶段优先“对话规划 + 契约学习 + 验收/证据回流”，不先铺全平台地图和自动投递。
- 契约学习采用提醒、专注、测验、补学和复盘，不采用系统锁机。
- 国内/海外为可切换的机会视图，地图/数量/列表同步变化；官网、LinkedIn、51job、BOSS、猎聘等原始平台为主源，开源聚合作补充，逐条保留来源链、原文链接、各类时间与状态。
- 第一学习方向围绕现有工作经验与主技术栈，补目标 JD 的真实缺口，不默认转型或先选定迁居路线。
- 长期模块补充：AI 模拟面试/口语/刷题、机会地图、授权申请辅助、Offer 对比、OB/VS Code 采集入口。
- 产品草案与来源采用策略见 `docs/planning/betterme-product-roadmap-2026-10-16.md`；成长模块仍处于规划。用户后续已授权先完善当前简历版并做本地 Git 提交，本轮只修现有能力。未经确认的规划细节是建议，不是实施承诺。

## V1 范围（做）

- 结构化填信息 + 实时预览（Fact vs Resume View 分离）
- 简历模板库（自研为主 + 合法开源适配）
- 展示开关、分节排序、选中文字格式；未完成草稿自动保存与本地版本对比/恢复
- 导出：PDF / DOCX / Markdown
- 一键中英（同源事实，禁止两套胡写）
- AI 分析 JD 与岗位匹配度
- 用户提供的 LinkedIn/猎聘/51JOB/BOSS 官方分享链接尽力提取，以及岗位截图视觉识别；核对正文后分析
- AI：可配置 API Key，也支持本地模型（OpenAI 兼容薄 Client）
- 亮点引擎：STAR、量化确认、空洞检测、Fact 防编造（AI 只出 Proposal，确认后写库）

## V1 不做

- 契约打卡 / 学习计划 / 性格分析（愿景保留，不进 V1）
- 自动投递 / 招聘站全站抓取与持续岗位同步（用户提供的单条分享链接提取已纳入本轮）
- Obsidian / VS Code 插件
- 移动端 App（架构预留 Expo，V1 不实现）

## 技术架构（已拍板）

- **组织**：pnpm workspace + Turborepo；scope `@better-me/*`
- **核心**：`packages/core`（纯 TS + Zod Schema）+ `packages/storage`（Local-First 端口）
- **V1 UI**：`apps/web` = React 19 + Vite + Tailwind + Shadcn（非 Next.js）
- **存储**：结构化本地库为运行时 SSOT；Markdown/Frontmatter 为一等导入导出与 OB 适配（非双主库）
- **远期壳**：Expo 移动端；OB / VS Code 插件；可选 Tauri 桌面
- **约束**：私人数据与密钥本地保存且不进 Git；云模型推理仅将所需内容直发用户选择的模型提供商，本地保存不等于全程离线；配置与用户数据分离

详情与取舍见 `decisionLog.md`。
