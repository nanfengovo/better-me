# BetterMe 开发路线图

状态基线：2026-10-18。本文区分已实现、本轮建设与后续提案，作为 GitHub 首页的实施导航；不承诺日期。更早的完整愿景见 [产品规划草案](planning/betterme-product-roadmap-2026-10-16.md)，若其中旧顺序与本文不同，以当前“非 Agent 工作台优先”为准。

## 实施原则

1. **先服务真实求职任务**：完善简历、导出、来源核对、投递与恢复，再发展长期职业成长 Agent。
2. **事实、表达与推断分开**：改好文案、模型判断和课程完成都不能自动变成新的履历事实。
3. **以可恢复为前提迭代**：保留旧数据兼容、未完成草稿、历史和备份；来源刷新不得清掉私人投递记录。
4. **按实际环境验收**：自动测试、浏览器操作、PDF/DOCX 视觉、模型调用与招聘站兼容分别记录。
5. **来源与许可可追溯**：公开可见不等于可再分发；模板逐源维护 LICENSE / NOTICE，不爬商业简历站。

## 已交付的基础

以下为现有实现，不代表所有输入、浏览器、招聘平台和模型均已覆盖。

| 领域 | 已交付 | 仍需验证 / 改善 |
| --- | --- | --- |
| 简历数据 | Fact 与 ResumeView 分离、多简历、双语字段、展示选择、校验与量化确认 | 更丰富真实材料、逐字段来源与证据关系 |
| 内容导入 | PDF/DOCX/图片/文本/JSON、离线与可选 AI、裁剪、原文/OCR/待补录核对 | 复杂原稿与 OCR 错误；原稿保真编辑未实现 |
| 视觉系统 | 119 套模板、10 套简历主题、4 套工作台配色 × 明暗、响应式工作台 | 大包按需加载、其他系统字体、极端长文与组合分页 |
| 输出 | PDF、可编辑单栏 DOCX、Markdown、RenderCV YAML、JSON | DOCX 逐页视觉、RenderCV 实际引擎；各格式不承诺同版 |
| 保存恢复 | 草稿、保存条件、最近 50 版、命名检查点、单项/整版恢复、多窗口保护 | 历史链独立备份、长期留存、容量与迁移 |
| 岗位工作台 | 列表/看板、筛选、来源时间、手动投递、联系人、截止与跟进、材料快照 | 观察历史、同岗候选、持续更新、附件管理 |
| 岗位入口 | 单条分享链接与本地浏览器读取；Greenhouse/Lever/腾讯按需预览收藏 | 更多真实岗位与长期覆盖、后端独立运行 |
| 可选 AI | 用户配置模型、结构化导入/OCR、JD 分析、样例阻断与原句引用约束 | 真实生成链、建议确认应用、证据化与持久报告 |

## 阶段 1：发布、性能与质量基础

目标：让每次发布可追溯、可验证，用户可放心更新工作台。

- [ ] 持续集成：固定 Node/pnpm，干净安装，运行测试、Lint、类型检查和生产构建。
- [ ] GitHub Pages 自动发布：主分支验证通过后部署；PR 验证与生产发布分离。
- [ ] 验证线上子路径、静态资源、刷新、导入导出与保存，不把构建成功当部署完成。
- [ ] 写清静态版与本地完整版的边界；本地招聘浏览器不迁移成不可见的远程窗口。
- [ ] 对导入工具、模板 CSS 与大块依赖的按需加载做性能实测，记录首屏、切换与导出成本。
- [ ] 扩展浏览器/系统字体/窄屏与键盘检查，尊重减少动态偏好。

**验收事项**：失败的检查不更新线上；发布可定位到提交与运行记录；旧浏览器数据更新后可用；子路径资源不丢失；无真实 Key 或私人样例入包。免费平台与实际启用状态以 [部署文档](deployment.md) 和工作流为准。自动部署只更新应用代码，不将 localhost 的简历同步到线上。

## 阶段 2：真实文件与输出可靠性

目标：把“导入准确、内容可核对、导出不丢字”做扎实。

- [ ] 建立脱敏真实文件案例集：多栏、表格、手机长图、扫描 PDF、跨页经历和中英混排。
- [ ] 对提取原文、OCR、未解析项与 Fact 结果做可定位核对，保留错误，不补造字段。
- [ ] 在真实 Word / 兼容编辑器中逐页检查 DOCX，覆盖中文字体、长链接与跨页标题。
- [ ] 扩充模板 × 主题的代表性长文 PDF 组合，针对问题定点修复。
- [ ] 将字体回退、分页和兼容差异整理为可理解的选择说明。
- [ ] 评估原稿文档层与逐字段来源定位，区分按模板重排与原稿保真编辑。

**验收事项**：预期正文与必要署名完整，错误量化继续待核实；没有已知裁切、孤立标题或 UI 泄漏；记录具体格式、环境与样本，不宣称 DOCX 同版或 ATS 认证。

## 阶段 3：有依据的 JD 匹配与建议应用

目标：匹配结果说明依据、承认未知，并支持真实改进。

- [ ] 将 JD 拆成带原句的职责、必要要求、优先条件与约束，绑定原文快照。
- [ ] 建立技能/事实证据关系，区分自报、项目材料、测评观察和模型推断。
- [ ] 分别输出**能力匹配、简历呈现、机会适配**，不只比较关键词或给模型总分。
- [ ] 报告保留 JD / Fact / ResumeView / 规则版本；来源变化标记旧报告过期。
- [ ] 建议逐条展示原句、修改差异和依据，确认后安全应用；不自动写 Fact。
- [ ] 增量分析处理取消、晚结果、重复保存、云模型并发和预算。
- [ ] 再接导入确认 / 保存后的可选触发与应用内推荐，改颜色不触发能力分析。

**验收事项**：已有能力未展示时不判不会；未知不记为确定缺口；只改措辞不提高能力判断；新增证据能解释结果变化；陈旧结果不覆盖最新内容；无资料时不制造精确分数。

详见 [真实技能匹配与优化规划](planning/job-skill-matching-loop-2026-10-17.md)。这是设计方向，现有 JD 诊断不等于完整的证据匹配系统。

## 阶段 4：可追溯的岗位来源与增量更新

目标：从个人收藏库，逐步建立自用的跨来源岗位工作区。

- [ ] 来源目录与关注公司显示接入方式、最近成功时间、覆盖范围和错误。
- [ ] 用户选择的少量公司/来源支持手动刷新，区分新增、变化、确认关闭与暂时失败。
- [ ] 保存观察历史与原文版本，来源时间、采集时间与核验时间独立。
- [ ] 疑似同岗先保留候选、岗位编号/地点/职责与冲突，再确认关联。
- [ ] 来源数据与私人备注、简历、材料、申请及沟通记录分开更新。
- [ ] 地点与统计口径可靠后，再实现国内/海外交互地图，与列表/数量使用同一筛选。
- [ ] 评估可选持续刷新与通知运行方式，明确休眠、离线、重复结果和预算限制。

**验收事项**：每岗可回到原来源，不伪造时间；一次失败不判下架；刷新不丢私人记录；筛选下地图/列表/数量一致；通知有实质变化且不重复刷屏。

详见 [自用招聘聚合方案](planning/recruitment-aggregation-assessment-2026-10-17.md)。公开搜索站、账号与多用户共享岗位池不在当前自用范围。

## 贯穿各阶段：数据与维护

- [ ] 历史链独立导出与长期留存，说明版本、草稿和备份各自能恢复什么。
- [ ] 扩展容量不足、损坏备份、多窗口、升级与回滚案例，保持资料可取回。
- [ ] 按实际容量与运行需求评估 IndexedDB 扩展、SQLite / OPFS 等方案。
- [ ] 若抽取岗位后端，先完成身份校验、来源范围、资源限制、会话归属与部署设计。
- [ ] 确定根项目许可证，复核目标分发方式下的第三方义务，受限模板保持独立标记。
- [ ] 维护说明、真实演示截图、变更记录与验收范围，不将计划包装成已交付。

跨设备同步和云账号尚未实现。即使前端部署到公网，资料仍按浏览器来源存储；部署不是数据同步方案。

## 后续探索：职业成长闭环

在简历与机会工作台稳定后，再考虑以下模块。它们不是当前 V1 的已交付功能，也不因写入路线图而开始执行。

| 方向 | 可评估的最小形式 | 前提 |
| --- | --- | --- |
| 持续职业对话 | 一个目标与少量 JD，给出可接受/修改/拒绝的计划 | 可信事实、可定位要求与用户目标 |
| 学习与练习 | 小任务、时间预算、作品与验收标准 | 区分证据、表达与真实知识缺口 |
| 测评与证据回流 | 题目版本、rubric、提交材料、反馈与确认的新 Fact | 课程完成、AI 表扬不直接转成能力事实 |
| 模拟面试 / 口语 | 先文字追问真实故事，再评估语音 | 真实项目依据与可审查反馈 |
| Offer 对比 | 真实条款、未知项与个人权重的场景比较 | 实际 Offer 与明确决策需求 |
| 更多宿主 | 可选桌面壳、Obsidian / VS Code 入口、移动端 | 核心闭环稳定，另立范围与许可审查 |

长期方向是“真实经历 → 目标岗位 → 有依据的差距 → 可验收改善 → 经确认的新证据 → 更好的材料与决策”。自动投递、系统锁机、全站无限采集不进当前 V1；学习打卡、插件与自主编排后置。

## 如何参与与跟踪

优先欢迎可复现问题与有限范围的改进：注明浏览器、模板/主题 ID、输入类型、预期/实际结果，使用合成或已脱敏内容。真实 Key、联系方式与私人履历不要放进 Issue、截图或 PR。

完成时更新实现、适当检查、README/报告与本路线图；只有设计文档不能勾选已实现。历史证据由 [README 文档导航](../README.md#文档与验收记录) 进入，避免用过期数字代替最新工作流状态。
