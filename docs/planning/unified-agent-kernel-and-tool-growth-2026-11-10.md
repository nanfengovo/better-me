# 一个 BetterMe Agent：统一任务内核、工具调度与沙箱造工具

日期：2026-11-10。状态：**用户已批准实施；首条岗位任务纵切片及受限工具构建已完成隔离验收，M2 全入口迁移尚未完成。** 具体代码范围、工具接入清单与回执见[实施验收](../reports/unified-agent-kernel-2026-11-10.md)。

观察对象：本地 `agent-os`，HEAD `cafe1d0`，包含大量未提交工作区源码。下文“当前路径”和行号保留设计前的静态快照，不代表现行代码位置、远端或真实模型效果。后续实施使用离线 reasoner、合成账号和实际 QuickJS 验证，没有调用真实模型、读取真实简历库或重启用户服务。

## 1. 结论与这次要收敛的东西

下一步采用“**一个宿主任务内核 + 多种交互视图 + 统一受控工具目录 + 分级沙箱能力补齐**”。先把“针对选定 JD 准备岗位专用简历”做成端到端雏形，再扩到职业规划、学习和面试。

对应此前三版比较：现在以 **B 的最小统一宿主**为主线，把 **A 的证据工作集**做成内核内部能力；**C 先限于可验证的纯转换工具**，不先建设插件市场或通用软件开发平台。不是把三套平台一起重写。

- AI 顾问是面向目标与交付物的主入口；右侧伴写是同一 Agent 在当前经历上的上下文视图，不拥有另一套运行器。
- 所有获准的业务工具逐步登记到同一目录；本轮模型只看到当前任务适用且已授权的工具，执行时再核验。
- 缺少执行能力时，允许在明确范围内构建临时工具、独立测试并回到原任务；不能把缺事实、没权限或服务故障包装成“需要造工具”。
- 职业资产仍由 Career Workspace 管理。工具输出、候选文案、个人事实、已保存岗位版是不同对象。
- 统一的是任务身份、授权、预算、证据、执行记录、暂停恢复及审批，不要求所有算法改写成同一种循环或替换现有 LangGraph。

## 3. 用户看到一个 Agent，代码只有一个任务权威

```text
AI 顾问主工作区      简历旁的伴写      后续其他任务入口
        \                |                /
             同一个 Task Client / 事件投影
                          |
             Agent Host：统一任务内核
       任务状态 · 授权 · 根预算 · 证据工作集 · 回执
                          |
                受控工具目录与执行网关
           /               |                 \
   现有领域工具       受审外部 Adapter       沙箱能力构建/调用
           \               |                 /
               候选产物 + 独立检查记录
                          |
                用户批准指定版本/差异
                          |
        Career Workspace 命令 → 正式版本与业务回执
```

模型提议下一步；宿主决定能否执行、扣账、运行并记录真实观察。执行结束不等于任务完成，草稿待审不等于已经保存。界面显示可审查的动作、来源和检查结果，不展示或保存模型私有思维链。

### 内核的外部 Interface（拟议）

仅提供四类操作：`createTask(request)`、`dispatch(taskId, command, expectedRevision)`、`readTask(taskId)`、`watch(taskId, afterSequence)`。创建请求先得到任务草案/待授权状态，不凭请求里的 `ownerId`、资料列表或 `consent: true` 授予权限；宿主使用可信身份与当前交互确认签发授权。

`dispatch` 的人工命令包括启动、回答、暂停、恢复、追加额度、撤权及审阅。模型只能给内核提交受约束的下一步决策，不能调用人工批准命令。事件流支持游标重连；初期可由同一事件投影支持轮询，不强制先引入新消息基础设施。

内部采用少量有真实职责的 Module：

| Module | 隐藏的 Implementation | 不拥有的东西 |
| --- | --- | --- |
| 任务运行与记录 | 生命周期、修订、执行代次、检查点、事件、故障接手 | 简历与个人事实的另一份主库 |
| 授权与预算 | 固定底座、材料/字段/目的地许可、有效期、撤权、统一扣账 | 模型可修改的权限规则 |
| 上下文编译 | 来源索引、精确取片、否定/纠正、按窗口选择、可回读摘要 | 把摘要变成事实 |
| 工具目录与执行 | 发现、参数/结果校验、版本选择、超时、幂等与真实回执 | 任意安装、外部发送或业务提交资格 |
| 产物与审阅 | 带来源的差异、检查记录、未知项和批准绑定 | 模型自行批准自己的内容 |

不为了目录整齐新建独立“记忆中心”、画像库、第二套账号或新的同级 Agent。MVP 单运行器推进；将来的评审角色或子任务也必须用父任务身份、授权交集和同一本预算。

## 4. 一项任务需要固定什么

沿用 `CONTEXT.md` 的 Task Contract、Run、Artifact、Verification Receipt 和 Business Receipt，不新增含混的“超级 Agent 记忆”。

任务约定至少固定：目标/验收条件；账号和工作区；目标 JD 快照；原简历版本与字段锚；允许的材料/目录；所选模型、处理位置与具体通道；可用行动；累计上限；后台生存策略。角色、提示词与工具返回内容不能修改这些项。

**启动交互建议：**确认目标 JD 和简历后，只集中确认一次模型/本机或云端/材料范围/预算。增加可选项“允许本任务在沙箱内构建临时纯转换工具”，默认关闭，明确列出次数与执行限制；启用后不为每次读取、测试或修复反复弹窗。未启用时，真正遇到工具缺口才询问一次。此项不是安装、联网、访问新目录或换模型许可。

任务类型可有不同验收：解释性聊天返回回答即可；岗位定制必须交付逐句差异与依据；正式保存必须另有 Workspace 回执。轻量聊天不必先填满岗位任务表单，但一旦需要新资料或执行权限，先补任务约定再执行，不能靠关键词路由代替授权。

生命周期建议：待确认 → 已授权 → 运行中 → 等回答 / 等授权 / 等审阅；也可暂停、预算耗尽、执行中断或失败。批准后先进入“正在提交”，只有验证指定业务版本实际存在才进入“已完成”。没有回执或结果不明必须保留待核对状态，不能重新调用模型来“补一个成功”。

## 5. 全部工具接入，但不是全部权限常开

分三层：**已登记**表示宿主认识；**本任务可用**表示权限、运行环境、版本与目标适配；**本轮展示**表示当前上下文确实需要。界面可列出未启用能力及原因，但发现接口不能泄露未授权材料的名称或内容。

| 工具族（拟议名称） | 复用方向 | 结果与约束 |
| --- | --- | --- |
| `job.*` | JD 导入、快照读取、原句拆解、现有匹配能力 | 绑定原始快照；门禁要求人工接续，不伪造完整 JD |
| `evidence.*` | 七个读取工具与 EvidenceBroker、项目理解的检索 | 按明确范围/字段读取，返回来源与 span；不以已有项目会话代替新任务授权 |
| `resume.*` | 当前简历读取、字段定位、候选 patch 与版本差异 | 模型工具只形成候选，不直接改正式简历或 FactBase |
| `verify.*` | 来源引用、原文锚、字段与版本、格式/长度等确定性检查 | 语义支持和本人贡献无法完全自动证明，报告疑点而非宣称全面认证 |
| `artifact.*` | 任务内草稿、差异表、预览与检查报告 | 在允许的任务私有范围保存，不等于职业资产正式采用 |
| `capability.*` | 查合格版本、提构建方案、测试、调用沙箱工具 | 自建与调用分开；没有匹配能力不默认安装第三方包 |
| 外部 Adapter | 经审的岗位读取、MCP、原生 CLI/模型路由 | 数据与出网目的地重新检查；CLI 内部工具不自动继承 BetterMe 权限 |
| Workspace 提交命令 | 现有保存岗位版、另行接受长期事实提案等命令 | 由人工审批处理器调用，不作为模型可自由选择的普通写工具 |

第一版仍直接展示少量常用工具；工具多起来后再做可控的检索加载。工具目录完整，不代表每轮把所有 Schema 塞给模型。[Anthropic 的工具发现设计](https://www.anthropic.com/research/advanced-tool-use)与[代码执行/MCP 文章](https://www.anthropic.com/research/code-execution-with-mcp)支持按需发现、在执行侧过滤大量结果；这是借鉴原则，不是要求改用 Claude，也不把其效果数字当本地模型收益。

### 工具契约与唯一执行网关

每个登记版本至少声明：`id/version`、输入/输出 Schema、适用条件、效果类型、所需资料与目的地、执行档位、输入输出限制、超时、重试/幂等语义、来源及验证状态。MCP 描述、生成 manifest 与工具输出均不自动可信；登记/更新须经宿主检查，变化不能继承旧批准。

统一顺序：核对当前 owner/任务代次 → 解析固定工具版本 → 检查 Schema、授权与数据流 → 预留预算并记录调用 → Adapter 执行 → 再核对撤权/超时/来源变化 → 校验输出 → 写观察和回执。权限拒绝、空结果、部分覆盖、运行失败、结果不明是不同状态。

结果默认给受限摘要、`resultRef`、证据引用、分页游标、检查与限制，完整结果在获准私有存储中按需重读。任何子调用都必须经过同一网关。不能把有内部模型调用的旧图包装成一个“工具”，就绕开模型计费与停止条件。

## 6. 首个岗位任务怎么真正做精准

1. 核对目标岗位、JD 完整正文/快照与当前简历版本；没有选定岗位就先选择或提供，不从侧栏、机会库前几条猜目标。
2. 按原句拆职责、门槛、优先项和约束。关键词相同不是完成证据。
3. 在授权材料中找对应证据，区分项目背景、本人陈述、可归属的个人行动与模型推断。团队做过不能自动写成本人主导。
4. 对每条要求区分：已有依据且表达清楚、已有依据但表达弱、信息未知、经现有依据可识别的真实差距。未知不能直接写成“不会”。
5. 问会改变判断的关键问题；本人回答立即带来源用于当前任务，不自动变长期 Fact。保留否定、纠正、范围与不确定性。
6. 生成精确锚定旧字段的逐句 patch：旧句、新句、对应 JD 原句、理由、证据和待确认项。修改排序/表达不被当成能力提升；不为迎合 JD 凭空增加指标、职级、职责或上线规模。
7. 先做机器可验证检查，再提示仍需人工判断的语义支持和事实疑点；可选模型评审也计入同一本额度，不能用第二个模型的赞同冒充事实证明。
8. 用户逐项采用后，Workspace 另存岗位专用版本。绑定原文版本、所批草稿摘要和批准项，写后回读并生成业务回执。来源已变或并发冲突则停止重比，不覆写其他简历。

“精准”的衡量应是要求覆盖、正确引用、保留未知、可解释改动、可恢复保存和实际审阅结果，不是一个黑盒匹配总分，更不能保证面试/录用。

## 7. 沙箱为什么造工具，以及怎么造

### 7.1 先判断是不是工具缺口

- 缺本人负责范围：问本人，不能写代码猜。
- 未授予目录/模型权限：申请授权，不能换入口偷读。
- 招聘站登录/验证码或供应商故障：暂停/人工接续，不能把规避门禁当工具创新。
- 已有工具可组合：优先组合，避免重复造轮子。
- 确实缺少受限变换能力：例如把新格式的已授权项目清单规范化，才进入构建。

### 7.2 第一版的闭环

原任务发现执行能力缺口 → 搜索已有合格版本 → 提出限定输入输出/效果的构建方案 → 核对本任务是否获准构建 → 宿主冻结验收清单 → 本次固定底座生成函数 → QuickJS 独立运行全部样例 → 针对失败修复且全量回归 → 合格候选获得本任务临时调用资格 → 处理本任务新输入 → 检验实际输出 → 回到原岗位任务。

能自行完成的是已授权范围内的构建/测试/调用，不是自行扩大权限。持久安装复用与正式保存简历有两个不同审批点，均不能由工具自批。

当前实验台仍是独立入口、独立额度和本机模型通道；**只有改为从父任务预留并扣账、使用相同底座或明确追加授权，才允许自动接回职业任务**。父任务使用云模型时，不能暗中另启本地 CLI；当前实验台不支持该底座就明确提示，不能伪装已经接通。

### 7.3 分级执行，按需要升级

| 档位 | 适合能力 | 隔离和限制 | 建议顺序 |
| --- | --- | --- | --- |
| 可信领域函数 | JD 拆解、字段投影、版本差异等已有确定性逻辑 | 宿主维护，输入输出和账户校验 | 先复用，不必让模型重写 |
| 纯 JSON 工具 | 规范化、筛选、可复核计算、结构转换 | 沿用 QuickJS/WASM；全新 realm、堆/栈/墙钟/输入输出限制；不桥接文件、网络、进程、凭据 | 首个自建闭环 |
| 受控组合计划 | 多次受审读取后在执行侧汇总，减少模型来回复制 | 初期用有节点上限的声明式计划，宿主逐节点调同一网关；不允许任意循环、隐藏调用或绕开审批 | 有真实重复工作后加入 |
| 工具视图/微应用 | 展示结构化证据、差异或检查结果 | 独立 iframe/CSP 与白名单消息；只给明确记录/字段投影 | 有交互需要时加入，不把展示当计算工具 |
| 完整编码环境 | 真正需要文件、多文件构建、依赖、测试的工具工程 | 单独受控进程/容器或 VM；无默认网络、固定依赖、任务临时目录、非 root、资源上限；无宿主个人目录/凭据/Docker socket | 单独设计与验证，不纳入首版默认权限 |

原 QuickJS 档位不能通过直接开放 Node host function 来变成全能编程环境；若未来确需程序化调工具，另设计带 task lease 的窄 RPC 或受控计划执行器。[Node 官方文档](https://nodejs.org/api/vm.html#vm-executing-javascript)明确 `node:vm` 不是运行不可信代码的安全机制；iframe 也不保护构建阶段的 Node 主进程。

### 7.4 能力包与采用生命周期

候选包绑定：代码和整个 manifest 的摘要、输入输出契约、执行环境、依赖锁、权限/数据流、资源上限、生成来源、测试集版本、验证器版本、适用范围与已知限制。不打包真实简历、项目私密摘录或凭据；提示词/修复日志若含私料也不进入可复用包。

状态区分：未验证候选 → 已验证候选 → 当前任务临时启用 → 提案申请私有安装 → 用户批准固定摘要版本 → 已安装私有版本 → 在新任务授权内可调用。验证通过不等于已安装；已安装不等于永久获准读取资料；“本地发布”只指该账户的私有目录，不是公网发布。

源码、Schema、权限、依赖或执行环境改变，都要重新核验；扩大权限须新批准。撤销阻断新调用并取消/丢弃可阻断的迟到结果；已经暴露给外部供应商的数据无法假装撤回。切换能力版本不回滚已批准的简历业务版本，业务撤销另走 Workspace 命令。

### 7.5 验证不能由生成器自说自话

验收意图由业务需求确定；测试清单由可信宿主和审阅流程冻结，生成器不能修改裁判。检查 Schema、预期值、来源 ID/原文保真、缺失/重复/恶意输入、资源上限与回归。另保留不参与修复的留出样例。纯格式转换可以做精确断言；语义提取应保留人工疑点而不是伪造一个绝对正确的标志。

分开记录“这版工具通过哪些资格测试”和“这次输入得到的结果通过哪些检查”。只保留当前最好候选也要保留所有真实尝试。函数样例通过不代替浏览器 UI、依赖供应链或 OS 隔离验收。

## 8. 上下文与恢复：保留任务状态，不把全历史塞回模型

每轮编译四层：不可裁掉的任务/授权/预算约束；当前 JD 要求与精确原句；当前需要的证据片段和近期动作—观察；更早历史的可重读索引与结构化摘要。重要否定/纠正、来源冲突与尚未解决的问题不能在压缩时消失。

来源片段保留 `sourceId/versionHash/span/evidenceId/kind`，支持长行内偏移与分页，不能只靠 `slice(-N)`。重读应能把早期原文重新放回工作集。摘要附来源，只用于导航；重新取片、模型发送前及恢复时都要核对当前许可与版本，撤权派生摘要同样失效。

窗口按具体模型预留输出和协议空间；未知 tokenizer 时说明估计口径并保守处理，不把字符数宣称为真实 token。放不下必要约束/证据就分步或暂停，不无声裁掉来源。额外模型摘要、格式修复、评审全部扣父预算。

借鉴[长运行 harness 原文](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)的初始化、逐项目标、可交接记录和可重复测试；它不是 OS 沙箱规范。后续[应用开发 harness 文章](https://www.anthropic.com/research/harness-design-long-running-apps)还讨论了验收约定和评估职责，及按模型能力减少无效脚手架。本项目先借职责与产物，不默认复制多个常驻 Agent。

## 9. 预算、授权与宿主生存规则

- 保留可配置起步上限：根任务累计 12 次模型请求、30 次工具读取、600,000ms 活跃执行；任一项到上限停止。新增纯计算执行也必须有调用数、逐次资源和累计上限，不能因为不是“读取”就无限跑。
- 内部模型请求、失败重试、协议修复、摘要、评审和构建全部计入根账本。子构建只从父任务剩余额度中划拨，额外子上限取更小值，不复制额度。初期串行推进，根任务活跃时钟不因子调用重复扣两遍；另记实际模型/工具耗时便于诊断。
- 等回答/授权/审阅不计活跃时间，关窗后台执行要计；恢复不重置。追加额度须明确确认，新上限不能低于已使用量。
- 调用前持久预留，完成后结算；崩溃/发送结果不明不返还请求次数，也不盲重放。只报告可观察额度，CLI 内部隐式重试/token 不可见时不承诺账单硬封顶；严格核算模式拒绝不满足的 Adapter。
- 同一 Host 还活着且权限有效：关闭窗口可继续到待审。缺事实、缺授权、预算耗尽或来源失效就停。退出 Host 或重启后，只恢复记录为中断，等待手动恢复并重新校验，不能因打开页面自动续跑。
- 更换供应商、处理位置、CLI 或扩大材料/效果范围，需要新的授权版本；现有底座失败不暗中换付费 API。当前实现尚不支持原任务扩范围时，应明确建立关联后续任务并保留额度约束，不能偷偷清账。
- 本人回答当前任务可用；长期事实更新另行提案。采用一句文案不顺带写 FactBase。无自动投递、外部发送或系统自修改权限。

## 10. 截图对应的交互改造

不再新增一个工作区。左侧保留岗位/JD、简历编辑预览和产物的工作面积，右侧保持唯一 Agent 对话入口。

- 左侧“岗位研判”里的导入/核对是任务准备；“开始拆解”产生同一任务的 JD 分析产物，“为这个岗位定制简历”推进同一任务，不再启动另一份无关联流程。
- 右侧“伴写对话”按当前任务/字段聚焦；同一任务在 AI 顾问与简历页显示相同 ID、状态、用量、问题和草稿。八条批注是发现的待完善项，不自动变成八个后台任务或八次模型请求。
- “共识与进度”呈现真实动作、来源、待确认、逐句改动与检查；项目理解共识、本人陈述和长期事实提案分开。
- “模型与工具”呈现本任务已固定的底座、可用/缺授权/不适用的工具与剩余额度；不是永久“全部允许”开关。设置只维护一处，侧栏不再复制配置表单。
- 生成临时工具时，在原对话内显示构建用途、范围、实际测试、修复与临时启用记录；持久安装给单独版本审批卡，简历采用继续用逐句审阅。
- 页面切换/隐藏不启动或结束任务；账号切换、撤权和任务本身失效才改变执行资格。切到另一简历不把正在运行任务的固定目标偷偷换掉。

## 11. 渐进收敛，而不是换个框架重写

| 批次 | 改什么 | 完成条件 |
| --- | --- | --- |
| M0：契约与工具盘点 | 列现有入口/工具、实际副作用、模型调用点、授权来源与预算；固定统一事件/修订/错误语义 | 能指出所有绕过统一核算或真实执行的路径；不把登记当接入完成 |
| M1：内核首条纵切片 | 从 `tasks/service.ts` 提炼通用运行、账本、上下文和工具网关；保留岗位 profile 的领域规则 | 同一任务完成取证→必要追问→逐句草稿→批准→独立岗位版；原版与 FactBase 不变 |
| M2：两个入口同一任务 | 浏览器 `betterme-agent/kernel.ts` 变为客户端 facade；AI 顾问与旁写订阅同一任务；旧 JD/理解流程经 Adapter 接入 | 切页不丢任务；关窗后 Host 继续；重启不续跑；每个内部模型/读取都计同一根账 |
| M3：一个真正可用的自建工具 | 接编码实验台与能力版本目录，先做一种纯转换；同底座、父预算、冻结裁判、临时启用、单独私有安装 | 首任务真实生成并检查；第二任务用新合成输入复用固定版本且零重新构建；撤销后拒绝调用 |
| 后续：广度与更强沙箱 | 再纳入更多职业工具、受控组合、MCP/微应用视图和完整编码环境 | 各自具备契约/权限/真实验收；不以工具数量替代任务成功率 |

拟议代码落点：宿主 `src/kernel/` 承接执行与记录；`src/tasks/` 保留岗位领域规则和兼容入口；`src/understanding/` 复用证据 Broker 与理解能力；`src/sandbox/` 承接构建/运行 Adapter；`src/capabilities/` 复用版本/资格/实际输出验证。`packages/agent-contracts` 放任务/工具/事件契约，`packages/core` 和 `packages/storage` 保持业务事实、投影、版本及接纳权。不要为一批设计预建一堆空目录。

旧流程逐条接管，新任务先用新路径；旧会话只读兼容，不自动搬迁真实数据/授权，不双写两套任务主记录。旧 LangGraph 内部可以保留，但接入前必须支持逐次预算和停止，不能用“最终结果回来了”证明受控执行。宿主断线时可编辑/看已有草稿，工具任务停止；不能回退浏览器直连模型绕开内核。

## 12. 雏形验收：缺一项都不能只叫“已统一”

1. 一个合成 JD/简历任务，从顾问创建，在旁写看到同一 ID/修订/事件；只有一个活动执行者。
2. 实际观察驱动下一动作，拒绝不存在的工具、错参数、未授权读取和伪造证据。
3. 早期的否定回答、长行尾部证据在压缩后仍能精确重读；引用变更或撤权后停止发送/使用派生内容。
4. 缺事实就问，不生成工具猜本人职责；“参与”不会因 JD 要求变成“主导”。
5. 在真实工具缺口时，用同底座和父额度生成一种 JSON 工具；冻结测试，修复不回归，留出输入独立评估；未验证工具不可调用。
6. 工具测试失败、Host 离线、包篡改、运行环境变化时均拒绝；不由客户端补成功回执。
7. 重试/摘要/子构建都不另开额度；等人不计时，后台计时，手动恢复不清账，耗尽保留半成品和下一步。
8. 关窗仍能到待审；退出/重启/账号切换/撤权按规则停止，不自动续跑或切付费通道。
9. 审阅绑定指定来源与草稿；双击、断线与回执丢失最多产生一个岗位版，结果不明先核对，不重做推理。
10. 保存岗位版不改变原简历、其他简历和共享 FactBase；长期事实另行批准。
11. 同版本新合成输入可复用；私有安装/移除/撤权有真实记录，工具版本回退不改已保存业务历史。
12. Web 与桌面同构建、同接口、同一行为；静态版不能伪装拥有本机执行能力。

首批使用合成资料、独立账户与离线替身验证机制；真实选定模型的成功率/耗时需另经授权记录。报告首轮/修复后/留出成绩、正确引用、未知保留、重复写入、模型请求、读取次数和用时，实报 token 与估算分列，不给未经实测的提升百分比。

## 13. 参考的用途与限制

- [Anthropic：Effective harnesses for long-running agents](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)：初始化、增量目标、进度交接与测试，不是安全隔离规范。
- [Anthropic：Harness design for long-running apps](https://www.anthropic.com/research/harness-design-long-running-apps)：验收约定、生成与评估职责，以及按需要减少额外脚手架，不要求 MVP 默认多 Agent。
- [Anthropic：Advanced tool use](https://www.anthropic.com/research/advanced-tool-use)：按需发现工具与使用示例；本地模型仍需自己验证协议可靠性。
- [Anthropic：Code execution with MCP](https://www.anthropic.com/research/code-execution-with-mcp)：在执行侧处理/过滤中间数据与组合调用；隔离、授权和资源治理仍是宿主的责任。
- [MCP Apps 官方说明](https://modelcontextprotocol.io/extensions/apps/overview)：工具关联交互视图、宿主 iframe 与受控消息，适合未来微应用展示层；不承担构建、测试、安装或业务批准。
- [Node `vm` 官方安全说明](https://nodejs.org/api/vm.html#vm-executing-javascript)：不把 V8 context 当不可信代码安全机制。

本文是上述原则在 BetterMe 当前源码与既定授权约束下的工程设计，不是这些资料对 BetterMe 的安全、成本或模型质量背书。
