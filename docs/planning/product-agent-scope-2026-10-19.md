# 产品内 Agent：首批场景与边界建议

日期：2026-10-19，Asia/Shanghai。状态：**产品建议，尚未确认架构、启动接入或交付功能**。

用户已澄清：问题是 BetterMe 产品内接入 Agent 应做什么，不是开发协作 Agent 如何分工。[此前两执行 Agent 文档](two-agent-integration-plan-2026-10-19.md) 仅为开发协作历史提案。

## 优先建议

先做“有依据的岗位匹配与简历优化”，再做限定范围的岗位研究与推荐。依靠现有 Fact、ResumeView、JD、岗位来源及机会工作台组织真实求职任务，首批一条 JD、一份目标简历即可使用，不等待四平台全覆盖。

已有的单次 JD 分析是基础；Agent 的增量价值是：按任务获取所需上下文，调用受控工具，遇到证据缺口追问，组织可检查的修改提案，并跟踪确认后的结果。来源解析、数据校验、排名聚合和最终写入继续由业务服务执行。

## 一个总控与两个专业角色

| 角色 | 负责的用户任务 | 主要结果 |
| --- | --- | --- |
| 求职总控 | 理解目标、确定本次任务和允许使用的材料，路由任务，管理进度、预算与确认 | 可追溯的任务状态、下一步和两个专业角色的汇总结果 |
| 岗位研究 Agent | 在指定公司、地区、职位及支持来源中寻找候选，读取原始 JD，检查来源、完整性与条件 | 有链接、观察时间、覆盖范围、未知项和限制的候选清单；交给匹配流程 |
| 匹配与材料 Agent | 将 JD 要求与允许参与匹配的个人事实逐项对照，解释差距，提出岗位简历与材料修改 | 证据匹配报告、待确认问题、引用原句的修改差异及岗位材料草稿 |

总控第一版可以是对话入口、任务状态和确定路由；角色不要求独立模型、常驻进程或每次互相讨论。通过窄接口分工，避免多角色重复分析和重复计费。

## 最先落地的闭环

用户从已有岗位或粘贴 JD 发起：“这个岗位适不适合我？按真实经历给我改简历。”

1. 确认目标 JD、目标简历及可用于匹配的事实范围，绑定输入版本。
2. 将 JD 拆为有原句依据的职责、必要条件、优先项和偏好条件。
3. 查询被允许的 Fact/Claim，分开给出能力证据、简历呈现和机会适配。当前简历未展示的经历不能自动发往模型或进入对外材料。
4. 对关键不明项提出少量具体追问。没有记录表示资料未知，不能直接认定不会；回答先形成待核对证据。
5. 给出有依据的修改，每项包含原文、建议、引用、理由、目标条目和输入版本。
6. 用户逐条确认后，由宿主校验并修改目标简历视图，保留历史；新增经历、技能、数字或核实状态另走 Fact 确认。
7. 预览并保存岗位材料快照；调用现有导出能力。JD/Fact/简历变化后旧结果标过期。

首批验收：无依据不编造；隐藏但有依据的能力不被判成不会；未知不计作确定缺口；改文案不提高能力判断；修改可拒绝、可追踪、可恢复；取消与陈旧结果不覆盖新内容；完整走通一条修改到材料快照的流程。

具体领域设计继续以 [真实技能匹配与优化规划](job-skill-matching-loop-2026-10-17.md) 为依据，不另建第二套事实主库。

## 岗位研究的下一批

示例：“在我关注的公司和来源中找符合已确认地区、薪资与岗位方向的职位，列出值得看的候选及原因。”

- 自然语言转为可检查的结构化条件；硬约束不被模型语义相似度覆盖，关键歧义先明确。
- 先查询现有索引和收藏；需要更新时按本次任务授权范围调用已审核来源，限制页数、数量、时间与成本。
- 候选逐条保留来源、原文和缺失字段；薪资、位置、发布时间及在招状态不凭模型补全。
- 匹配由同一证据流程处理，地图/列表复用同一查询结果；候选采用和来源启用是明确业务动作。
- 当前四平台卡片尚未完成真实验收，不能因增加 Agent 就宣称任意招聘站已可搜索；未知公司无搜索 provider 时仍需明确官网。

## 后续场景

| 顺序 | 场景 | 最小形式 |
| --- | --- | --- |
| 后续 1 | 面试准备 | 依据所选 JD 和真实项目追问、整理 STAR 草稿，指出证据与表达问题 |
| 后续 2 | 求职复盘 | 使用实际阶段与沟通记录分析流程问题，生成待确认的跟进草稿 |
| 更后 | 能力提升与证据回流 | 从确认的缺口形成可验收练习，核实产物后再更新依据 |

持续刷新、外部通知、自动发消息、自动投递、长期自主学习与多端插件不纳入首批。

## 接入原则与实际前提

- 沿用现有 TS 核心、存储和工具服务；编排层作为薄适配，不搬入上游 Markdown 主库或整套 Web。
- 模型返回结构化提案，宿主验证、确认并提交；外部 JD 是数据，不能改变工具权限或要求读取全部个人资料。
- API Key、私有库路径、家庭精确位置及内部授权不放入模型工具参数；事实材料按用户许可与当前任务最小范围提供。
- 使用真实调用证据说明工具成功、失败、部分结果和等待人工状态；模型不得宣布尚未返回回执的操作完成。
- 报告及任务需保存版本、来源和可恢复状态；本地数据保存不等于云模型推理离线。
