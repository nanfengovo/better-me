## 业务和资料边界

1. **Workspace 是业务权威。** Fact、简历、岗位、投递和版本接纳继续使用现有命令和回执；新模块返回分析产物或待审核提案，不创建第二个职业事实库、投递状态库或业务写入入口。
2. **项目存在不等于个人贡献。** 源码、Git 作者、测试通过和 Understanding 共识分别只能支持其检查范围。本人实现、仅设计、不是本人完成、不确定沿用既有核对语义；旧记录不批量晋级为 Verified Fact。
3. **支持程度和来源性质分开。** 表述支持程度为 supported / partial / contradicted / unknown；来源另分自述、源码、文档、设计、测评观察和模型推断。引用格式通过不等于语义或业绩真实性通过。
4. **授权不能传递或升级。** 读取、模型推理、云端发送、保存提案、采用、公开发布分别授权；绑定服务端派生的 owner、会话代次、任务、操作、输入版本、资料范围、用途和有效期。账号切换、撤权、输入变化后复核，迟到结果不能写入。
5. **真实资料保持不动。** 开发与验收使用合成仓库、独立账号库、独立 Origin 和临时目录。不自动安装真实仓库 Hook、监听任意目录、发布个人页面、访问现有云账号、迁移真实简历或覆盖私人规则。
6. **外部内容是数据。** JD、源码注释、MCP 工具描述、网页、录音转写均不能授予权限、安装工具或发出业务命令。
7. **未知维持未知。** 未读到不等于不存在；读取失败不等于岗位关闭；未收到回音不等于被拒；匹配分不是录用概率；信号不是对企业动机的裁定。
8. **原历史保留。** 修改用版本和 CAS；采用、撤销和分叉不覆盖原记录。哈希证明版本一致性，不证明作者身份或事实真实性。

## 共享接口与现有模块接缝

输入统一是本次明确选择的、不可变的授权快照：Workspace 和简历版本、Claim 原文及哈希、JD 快照、允许的证据与行号、规则版本、目标和预算。owner 与有效会话由 Host 注入，不接受模型自行填写。

纯计算模块不读取文件、不联网、不保存职业资产；依赖通过 Interface 注入。Host Adapter 负责授权、取消、额度、持久产物和现有 Workspace 命令。UI 只提交明确操作并呈现报告、未知、差异和回执。

- `EvidenceBroker` 继续管理有界源码读取。Git 历史使用独立的显式仓库采集 Adapter，不开放隐藏目录或 `.git` 的通用读取权限。
- `workspace/evidence-proposals.ts` 与现有简历业务命令继续拥有本人核对、提案和采用规则。
- 正在开发的 `tasks/*` 不被当作已经稳定的执行器；待其文件、契约和测试稳定后通过 Adapter 对接，不复制其任务生命周期。
- `routing/service.ts` 的固定运行时、撤权和不自动重放约束保留。隐私流水线不是两个提供方的并发投机发送。
- `checkpointer.ts`、run 日志、业务回执分别代表图状态、执行观察和业务结果，不能混作一种恢复凭据。
- Vork 是渲染 Adapter；徽章的事实描述由受信任的证据投影产生，渲染器或聊天文案不负责认证。

## 实施顺序

1. 完成边界规划和需求索引；建立不改变业务状态的证据、权限与测试接口。
2. 可信审查/Golden Evals、隐私出口和证据采集分别实现；现有虚构默认值由 root 单独修复并回归。
3. 接入委员会、排版闭环、架构白板和证据徽章；共享 UI 入口串行合入。
4. 接入情景模拟、岗位情报、数字胶囊、MCP 与反馈；假设、公开和私人数据分别存储。
5. 接入安全分叉恢复，完成跨能力流程、故障注入和全部验收。评测贯穿每一批，不等待最后补测试。

所有十二项保留在总目标中。阶段顺序不改变完成定义；纯函数、模型夹具、UI Lab、真实模型、真实导出、桌面和外部协议各自提供证据，不能相互代替。

## 质量与发布门禁

- 单测覆盖支持/冲突/未知、个人归属、输入版本、幂等、CAS、重复请求、取消和预算。
- 集成覆盖两个账号、切号、撤权、晚结果、磁盘满、进程崩溃、重启、格式错误和恶意外部内容。
- Golden Evals 至少二十组，包括夸大诱导、模糊缩写 RCS、冲突薪资与错误引用；每例有独立预期，不能由生成模型修改裁判。
- 浏览器 QA 清单覆盖每个新增控件的初始、执行中、成功、空、失败/取消和恢复状态；至少两项探索性逆向流程。
- Web 和 Electron 都验证正常流程与最小窗口；单独检查首屏、密集结果、键盘可达性、浅/深色、减少动画和无溢出。DOM 测试不替代截图检查。
- PDF 与 DOCX 以最终文件分别核对正文、数字、引用链接、分页和视觉；网页正确不等于 Word 正确。
- 所有前端改动完成后执行 `pnpm desktop:build`，准确刷新 `BetterMe.app` 并核对产物哈希；构建产物与源快照一致才验收。不得仅因应用接到了旧 5173 服务而判定新版通过。
- 隔离服务使用新端口/临时用户目录，不停止现有 5173/5178/5179、Casdoor、Ollama 或日常浏览器。只清理本任务创建且核对过的进程。
- 最终运行 `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build` 和 `pnpm desktop:build`；不把并行未完成改动导致的失败伪装成本模块通过。
- 不自动提交、推送、上线、开启常驻监听或发布真实个人胶囊。只有逐项完成证据充分，才将总目标标记完成。
