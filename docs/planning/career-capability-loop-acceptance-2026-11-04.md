# 八步能力闭环：工程契约与验收附录

日期：2026-11-04。状态：**待实施的设计与验收要求**，不是已经通过的测试报告。业务八步、场景与里程碑见[主规划](career-capability-loop-2026-11-04.md)；领域术语见[CONTEXT](../../CONTEXT.md)。本附录负责对象、权限/并发语义、恢复与可观察验收，避免验收标准散落在各个业务页面。

## 1. 最小记录模型（建议）

| 记录 | 必要信息 | 关键不变量 |
| --- | --- | --- |
| TaskContract / CareerTask | 服务端owner、goalRef可选、意图、交付物/完成条件、输入引用及版本/hash、预算、授权引用、步骤/依赖、结果与业务回执引用 | 任务验收标准和资料范围不能由生成器为过关而改写；重试是新attempt，不冒充原尝试继续 |
| AcquisitionPlan | taskRef、缺口类型、候选已有能力、未采用原因、补齐方式、适用规格、权限/费用变化、验证方法和退出条件 | 缺授权/资料或暂时故障与真实实现缺口分开，计划批准不等于所有副作用获准 |
| CapabilityVersion | owner、capabilityId/version、不可变实现/配方hash、输入输出契约、适用条件、依赖/环境指纹、来源/许可、所需权限、验证引用、发布/停用状态 | 代码/依赖/契约变化生成新版本；用途描述用于检索，不用相似度单独授权或判适用 |
| BuildAttempt | owner/taskRef、生成提供方/模型与规格版本、候选源码/依赖hash、构建环境、时间/成本、失败原因 | 原始与修复尝试均留审计；不存模型隐藏思考或秘密；构建资料与可共享能力包分开 |
| VerificationReceipt | kind=qualification/task、目标hash、输入/测试集/验证器/规则版本、实际结果、证据/限制、passed/failed/inconclusive | 可信验证器签发或关联不可变存储，模型字符串不能伪造；历史回执不改写，但适用性可失效 |
| ExecutionGrant | 服务端owner、授权人、task/capability范围、允许资料/目的地/动作/凭据引用、有效期、次数/费用上限、撤销代次、交互lease或后台授权类型 | 能力经过验证≠此刻获准；授权始终可撤销，任务冻结的是引用和范围而不是永远有效的权限 |
| RunAttempt / Artifact / BusinessReceipt | 输入与能力版本、状态/事件、实际调用、输出hash/来源/局限；领域命令、预期revision、幂等key、影响的资产版本和真实回执 | 运行结束、结果有效、业务保存分别记录；既有Artifact/Run契约可扩充，不用平行聊天摘要替代 |

首版只新增能力/任务/报告命名空间，不搬迁既有简历或Agent历史，不自动将历史聊天生成能力包。owner由已认证会话决定；客户端owner仅用于竞争检测。共享岗位索引继续是安装级范围，不存私人报告、简历匹配或能力运行结果。

## 2. 状态与门禁

任务的建议主路径：`proposed → ready → assessing → acquiring(可跳过) → executing → verifying → awaiting-acceptance(按业务需要) → completed`。等待资料、等待授权、部分完成、失败、取消、进程中断均有独立原因与可继续条件，不伪装成已完成。

能力版本：`candidate → qualified → reusable`；任一阶段可失败/隔离，后续可停用/退役。qualified仅通过指定资格测试，首次限定任务运行并通过其结果验收后才可reusable；资格通过、发布状态和某账号当前授权是三个维度，不合并为一个enabled。

业务采纳独立于能力晋级：只读任务不要求写入；合格报告被用户拒绝采用不等于转换实现错误。若任务约定包括保存，保存失败则任务不能完整完成，但合格产物与能力验证证据保留，可在新授权下只重试保存而非重生成。

复用选择顺序：账号可见目录 → 当前契约/环境/验证有效性 → 输入适用性 → 权限与预算 → 稳定版本选择。模型可建议候选，但禁止把模糊名称匹配当可执行证明。组合依赖固定具体版本；依赖改变使有关组合验证失效。

建议的开发验收预算档位：每任务最多1次初始构建＋2次修复；每owner同时1个构建，超过排队；纯转换输入/输出各≤2MiB、执行≤2秒。内存硬上限由M0选定运行器实测确定后写入强制策略，未实现限制不得开启此档位。生成调用另有明确的次数、费用与总时限，不因修复新建子任务绕过父预算。这些是提议默认值，不是已有实现或性能保证。

## 3. 信任与权限

- 生成代码只接收所需序列化输入，无业务库、宿主环境、账户秘密、验证器/发布权限。工具通过可信包装器调用隔离执行器，不能动态import到Host或页面主上下文；语法过滤不代替执行隔离。
- 资格验证在受限环境先于业务数据执行；生成器只可提交实现和补充测试建议。固定判分规则、保留样本、参考输出与晋级逻辑由可信层维护，代码无权修改。错误反馈可用于有限修复，不能通过删除失败用例晋级。
- Skill/网页/工具输出都是不可信输入，不能要求扩大授权。安装/出网/凭据使用/数据发送/业务写入/外部动作分别判定，既有资料只读授权不自动授权云模型发送。
- 构建阶段使用规格和合成示例；若实际任务确需私人数据参与生成，另外最小化范围并取得明确授权，不默认为“已给Agent看过就可发给任意生成器”。
- 每次调用、资格晋级、发布、结果接纳和业务提交都核对owner、有效grant/revision、任务状态与目标资产版本；交互任务复核原identity lease，包括A→B→A。不能在迟到回调里读取当前账号给旧结果重新归属。
- 交互任务与未来后台任务分开：前者会话失效后停止新的执行/晋级/采用；后者仅在本人另授的有限后台授权内继续，页面退出不默认生成后台授权。显式撤销后台授权后同样禁止新副作用。
- 可共享的只是经审查通用实现/方法/合成测试，默认能力私有。能力包不能夹带用户输入、结果、邮件、源码片段、路径秘密或令牌；审计记录按原owner保存。

## 4. 并发、恢复与失效

- 首版单Host权威写入。每owner能力族发布和资产提交使用原子预期revision校验；同版本代码不可覆盖。跨进程/多实例一致性不由内存Map或浏览器读后写保证，未验前不开放多写入者。
- 撤权与资格晋级/发布/业务命令接受共用明确原子排序点：在同一事务或串行关键区核对grant撤销代次、任务状态和目标revision后提交。检查后发生撤权的未接受操作必须拒绝，不能先查权限再异步无条件写入。外部动作发起前另核对并登记受控发起点；已接受/在途动作如实查询回执，撤权不能被描述为撤回已经发生的动作。
- 幂等作用域绑定owner、领域命令、逻辑操作key；同key同输入返回同一持久回执，同key异输入拒绝。任务attempt可变，已发生副作用的逻辑key保持，不能重试时换key绕过重复检查。
- 同账号相同规格可复用在途构建，需重新检查输入和授权；不同账号即使hash相同也不共享私有构建上下文/日志或借用授权。并发晋级只有合法revision成功，冲突者保留候选不覆盖。
- 取消后区分尚未提交、已提交、结果未知：停止新副作用，查询持久回执。无法确认外部动作是否发生时显示未知/待核对，不自动再次提交。停止执行不会自动撤销已经接受的简历版本或外部消息。
- Host或页面重启后先核对真实运行和回执。纯转换可在有效授权和明确重试策略内新建attempt；付费构建和外部写入不得盲重放。原始输入、产物、失败原因可恢复，不伪造仍在运行。
- 实现、依赖、契约、关键规则/策略变化及发现缺陷会失效相应验证或隔离版本；重新验证后才能复用。新版本失败保留旧版，回滚只是改变将来选择，不重写历史产物；发现受影响报告时标记待核对，不静默修用户资产。

## 5. 资格、任务与业务验收的差别

| 检查层 | JD首版检查 | 其他业务如何延伸 |
| --- | --- | --- |
| 能力资格 | 固定/留出样本、空值/重复/错格式、换顺序、新字段值、资源/越权、来源保留、不可比较输入明确拒绝 | 解析器看实际来源映射；实践运行器看真实运行与资源；服务Adapter看协议、数据/费用范围与错误，不止health 200 |
| 本次任务结果 | 每行处理覆盖、同岗依据、引用确属本次输入、变化可复算、缺失/冲突单列；本批未见不代表关闭 | 简历检查事实依据；面试引用本次原答；匹配区分能力/呈现/偏好；无确定性判据则标参考与人工核对 |
| 业务效果 | 私有报告保存回执绑定输入、能力、验证及资产版本 | 简历新版本/历史保留；成长计划采纳；实际投递/沟通的回执或本人确认，草稿不能冒充外部动作 |

同一个模型生成、评价并说“通过”不构成独立证据。纯数据工具用可信期望值、属性/变形测试与实际输出；开放职业判断保留来源、限定适用范围及必要人工判断，不追求虚假的全自动正确认证。

| A06 三种结果 | 工具exit0但输出错；schema合法但来源假；结果正确但保存失败；任务部分可比较 | 分别记录资格/任务/业务状态；不显示已完成/已保存，未决项可见；保存失败保留产物供独立恢复 |

| A09 并发幂等 | 并发构建/发布、同资产旧revision提交、同key同/异输入；检查后暂停→撤权→恢复提交，以及命令先接受再撤权两种顺序；提交后断连接 | 撤权先发生则未接受操作拒绝；命令先接受则保留真实回执并停止新动作；只允许合法原子晋级/效果，冲突不覆盖；未知状态不重做真实动作 |

| A11 失效回滚 | 修改代码/依赖/契约/关键策略，停用一个已用版本，新版本失败 | 旧验证不能冒用，停用阻止新调用；保留历史与可用旧版；受影响产物标待核对，回滚不改业务历史 |
| A12 可观察与恢复 | 多次失败修复、预算耗尽、用户拒绝、取消、页面重载/Host重启 | 真实阶段/原因/费用/下一步可查，无虚构百分比；有限重试，停止不删除输入/历史；恢复查回执，不自动重发未知副作用 |

## 7. 证据包与判定

每次验收使用独立临时owner和库，保存脱敏的任务约定、规格/代码hash、模型生成来源元数据、验证器版本及逐项结果、输入hash、运行/业务回执、第二次复用记录。真实履历、已有Agent记录、模型密钥和招聘账号不进入测试或Git。

MVP通过要求：主规划M0/M1所有适用项通过、第一/第二次结果可人工复核、代码真生成且真执行、账号/并发/迟到边界保持。A10属于后续执行档位，不因其未开放否定纯转换MVP；但安装/外部服务不能标为已支持。真实模型未验、只有回归替身时，只能报告“协议与回归通过，动态生成待验”。

主要风险对应验收：目录/Skill冒充自扩展看A03/A07；模型自我证明看A04/A06；先开放任意执行再补安全看A05/A08/A10。任何一步无法提供证据，都不能用动画、自然语言承诺或总测试数替代。
