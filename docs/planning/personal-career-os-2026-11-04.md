## 1. 用户明确的方向

BetterMe 是围绕用户职业发展目标的个人职业操作系统，而不是仅增加聊天记忆的求职 Agent。

- **Career Workspace** 管理真实、结构化、可追溯的职业资产与业务状态：资料、项目经历、技能证据、简历及版本、岗位与 JD 快照、匹配、投递/面试/结果、目标与发展计划。
- **Personal Career Agent** 是统一智能入口与执行者：理解目标，判断能力，识别真实缺口，利用代码、工具、Skill 或外部服务补齐，执行、验证、沉淀并复用能力。
- Agent 可以生成简历候选，但版本、修改记录、事实校验和投递关联仍由 Workspace 管理；不能让 Agent 直接接管全部业务数据。

这不是增加一组平级聊天机器人，也不要求推翻现有业务底座。用户职业技能、个人记忆与 Agent 执行能力分开；更了解用户与能完成更多类别的任务是两个维度。

## 3. 建议架构：两个产品职责，三条受控接口

保持统一 Agent 与现有模块，通过少量应用层接口连接，不先拆一组微服务。

1. **Workspace 应用接口**：查询返回有归属、版本和来源的快照；提交只接受明确业务命令，如提出/采用简历变更、创建版本、记录已确认投递。内部复用现有领域校验和持久化，不提供 `writeWorkspace(path, json)` 这样的万能入口。图框架的 `Command` 不等于业务命令。
2. **能力接口**：查找、评估、构建候选、验证、启用/停用与执行某个能力版本。复用 `ToolDefinition` 的契约及 `ToolRegistry` 门禁，补足能力清单和验证记录，不重复造一套互相绕过的工具系统。
3. **可信执行接口**：由系统注入身份、权限、资源快照、预算、取消与幂等上下文；执行器只返回产物、执行证据和真实回执。安装/网络/凭据/业务写入不是 prompt 中的自律约定。

执行、策略检查与测试可以是内部模块或 Worker，不成为用户必须逐个配置的多个 Agent。具体语言、沙箱产品和外部框架留到实施时按当前代码及官方资料验证后选择。

## 4. 能力闭环不是“失败就装工具”

用户八步、各步业务连接、完成条件和分流规则见[主规划第2节](career-capability-loop-2026-11-04.md#2-八步如何接入业务)。复用优先，真正缺实现时才补齐；缺输入、缺授权或依赖暂时故障分别处理。补齐可采用代码、工具、Skill或服务，不局限于Prompt优化。

有三种不能互相代替的证据：**能力版本验证通过 → 本次任务结果验证通过 → 业务系统确认实际变更**。只读任务不需要业务变更，但仍需要任务结果验证；复杂职业判断无法确定性验证时，明确给出证据、未知项与待本人判断，不伪造自动验收。

## 5. 能力如何保存、复用和失效

建议能力清单至少包含：稳定 ID/版本、用途与触发条件、输入输出契约、实现或组合配方的 hash、依赖锁定、来源与许可、所需资源/网络/凭据能力、预算、验证回执、适用限制、维护/停用原因。

能力的**验证成熟度**（候选、已验证、失效/停用）与**当前可执行性**（当前账号获准、依赖可用、输入符合、预算足够）分开。一个布尔 `enabled` 不能同时表示这两件事。依赖、实现、契约或安全策略变化时使有关验证失效，重新验收；保留旧版本和可回滚的选择记录，不覆盖历史回执。

能力默认私有；若以后支持共享，只发布经过审查的通用代码/方法/合成测试，不发布用户事实、对话、任务结果或授权。凭据保存在现有受保护系统，能力声明需要哪类凭据，不内嵌秘密。生成 Skill 文本不等于构建了执行能力，也不等于该能力已经获准运行。

## 6. 不能被“自扩展”绕过的边界

- **冻结执行归属**：任务开始时由可信系统确定 owner、run、会话代次或明确的后台任务授权、能力版本、目标资源版本、资料授权与预算。迟到回调不读取“当前登录账号”重新分配归属。
- **A → B → A 仍是新会话**：只检查 owner 相同不够。交互任务要复核原租约/epoch、撤销状态和资源版本；旧产物可保留在原账号审计中，不能自动采用到当前简历或复用新会话授权。
- **并发与幂等**：同一资产的并发提交需在权威写入口原子检查 revision；同 key 同请求只产生一次效果，同 key 异输入拒绝。取消后先查已有回执，不以“不知道是否成功”为由重新投递/安装/写入。
- **权限分层**：可对明确范围、有效期、预算内的低风险读/分析授予自动执行；安装、联网、付费、敏感资料发送、真实事实采用或外部投递分别按风险授权。不是每步都弹窗，也不是一次授权无限扩展。
- **生成代码不可信**：需要按 owner/run 限定的文件挂载、禁用环境秘密继承、受控网络/凭据代理、进程与资源限制，以及不可被生成器修改的验证器和权限内核。禁止直接操作业务 DB、localStorage、私有 JSON 或核心鉴权代码。
- **现有 CLI 门禁保留**：[sandbox](../../apps/agent-host/src/runs/sandbox.ts) 的 auto 默认只是进程隔离；Linux 路径将整个 `/` 只读挂载，macOS 配置允许出网；[RunManager](../../apps/agent-host/src/runs/run-manager.ts) 仍继承环境。独立运行目录或工具白名单不能证明跨账号读取/秘密隔离，不能用于宣称可安全执行任意新代码。
- **持续跟踪有明确契约**：后台/周期任务以后需单独持久化目标、owner、输入来源、周期、预算、授权有效期、停止条件与通知策略，撤销后禁止新副作用。关闭页面后的持续执行不能冒充已实现；本轮不创建定时任务。
