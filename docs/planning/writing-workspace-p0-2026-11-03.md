## 已核实的依据

### 布局：根因是抽屉策略，而非纸张溢出

`apps/web/src/components/agent-sidebar.css:51` 的 `@media(max-width:1599px)` 将侧栏变成 `position:fixed`；工作区不再为它预留宽度。使用同一高度、只改宽度的 1599/1600 检查，分别得到 366px/0px 纸张水平重叠。测量中未见文档水平溢出。

此前 `docs/reports/agent-sidebar-layout-2026-11-02.md` 接受窄屏抽屉，验收重点是预览高度不变。这次用户明确要求“看着简历与 Agent 一起修改”，需要补上**正文不被 Agent 覆盖**的验收条件；过去通过不代表这个新条件已满足。

### 对话：可以滚动到输入，但第一屏没有主操作

`ProjectUnderstandingPanel.tsx:242` 的四阶段导航、说明与字段摘要先于 `:294` 的输入区；本轮授权与发送也在内容流中。1512×600 时输入框顶边约 716.7px，发送按钮顶边约 986.9px；需先滚过说明。这里不是“无法发送”或滚动失效，而是主要动作在首屏不可见。

四步是理解项目、核对共识、认领贡献、旁批候选的**协作阶段**，不是四轮固定问答。紧凑进度应写“阶段 1/4”等明确名称，保留动态追问、自由纠正和本人确认。

### 授权：相同文案不等于相同权限

`ResumeWritingCopilot.tsx:40/:245/:302` 与 `AgentCompanion.tsx:287/:632/:757` 各自持有 `shareAgentMemory`，用于不同任务；`BetterMeAgentCenter.tsx:23` 的共享控件却显示相同文案。合成设置页实际同时显示了两项“本轮使用已共享共识与成长上下文”。

实现时分别处理：伴写共享记忆、自由对话共享记忆、项目文件只读范围、本轮项目理解发送、已确认项目共识、简历非联系方式摘要。这些不是可直接合并的同一授权。继续保持默认不共享、撤回与停止语义、发送前核对目的地、证据可追溯和人工确认。

### 保存：现有状态机已有区分，展示需一致

`App.tsx:377/:413` 按 `saved/draft/pending/error/loading` 显示真实状态；`:465` 的底栏固定文案容易被当作保存成功。`useDocumentPersistence.ts` 与 `packages/storage/src/document-history.ts` 已区分草稿保护、完整简历提交和历史记录失败；自动保存关闭不会被页面离开强制打开。

建议在相应真实状态下显示“本地草稿已保护 · 完整简历尚未保存”“简历已保存 · 时间”；历史失败另行显示。完整简历保存不等于每次都新增历史快照，不能用文案扩大保证。本轮未发现或证明数据丢失，也未更改持久化行为。

## 实施顺序与完成条件

1. **先改布局和输入区**：Agent 关闭保留编辑+纸张；可用宽度足够时三栏；不足时编辑/预览切换+Agent；手机单视图导航。最小栏宽先通过实际内容验证，不能照搬 1600px 作为唯一阈值。视图切换保留现有挂载节点、草稿、焦点、任务与 owner 租约，不新增第二个 Agent。
2. **再统一保存与授权展示**：使用已有状态，不重写保存器；授权按用途就近呈现，不联动独立权限。新布局里错误、撤权、来源与确认/撤销仍可访问。
3. **以写作闭环验收**：合成资料打开 → 编辑经历 → 看见具体观察/追问 → 补充事实 → 比较候选 → 人工采用或撤销。每一步可定位当前经历，输入与主操作可达，保存状态准确。
4. **补响应式与生命周期回归**：覆盖 1920、1600、1599、1512×600、1366×768、1024 和 390px；长中文、长输入、缩放、键盘导航/焦点与减少动态效果。真实设备软键盘需单独验收；隐藏视图不卸载任务。继续验证换号、并发同 key、迟到 fetch/SSE、撤权后的结果、候选版本冲突与恢复草稿，不弱化身份边界来让界面通过。

本轮没有实施此顺序，新增的“无覆盖/首屏主操作”条件仍未通过。下一批首先补红测试，再进行最小实现和完整验收；不将旧单元测试通过当作改版完成。
