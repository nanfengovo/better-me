# 首条成长闭环：从一个目标到一份可复核的实践成果

**设计稿 · 2026-11-12。** 配套[个人成长 OS 总体设计](personal-growth-os-system-design-2026-11-12.md)。输入来自两份参考对话，尤其是第二份「建立自己的 AI Agent 工程能力」场景。源码锚点对应本机 `agent-os` 工作树（核对时 HEAD 为 `cafe1d0`，含尚未提交的代码），不是已发布能力清单。下文的首片、数据关系和验收用例均为提案；没有运行练习、安装 Worker 或改动业务记录。

## 1. 用什么判断这条链真的通了

**三个月的示例目标：** 能解释 Agent Loop、工具调用、上下文和恢复，并独立演示一个能运行的小 Agent。**第一周只交付一个动作：** 学习者实现或修改一个小循环，调用一次只读工具，遇到中断后从已完成步骤继续，附上可重放的练习包、测试回执和自己的解释。一次通过只证明这个版本在这组测试里的表现，不代表三个月目标已达成，更不证明生产经验。此为合成产品验收场景，不是替用户建立真实目标。

| 时间窗 | 本人可见的交付物 | 一票否决条件 |
| --- | --- | --- |
| 第 1 周：最薄闭环 | 一个已采纳目标；一段可回到原处的资料；一次作答；一个固定只读工具的最小 Agent；一份测试回执；一次周复盘草案。可以一直不写简历。 | 找不到原始材料或作答；展示成“已掌握”却无测试；恢复时重跑了已经完成的工具；实际只生成计划未产出项目。 |
| 第 2–4 周：间隔复测 | 换一份资料、相同能力点，另开一次尝试；对照两份独立回执，按本人决定调整学习计划。 | 覆盖首周作答或把“看过资料”等同于通过复测。 |
| 第 2–3 月：可演示项目 | 小 Agent 带版本、说明、可重放样例和限制；对照目标岗位要求生成可选择的实践描述及下一阶段目标。只有另行选择真实材料与授权时，才可能形成与工作场景有关的描述。 | 用模型输出或教学样例冒充本人贡献、客户项目、线上部署或工作资历。 |

### 六个领域交接的是引用，不是六份档案

| 领域 | 在同一个示例中做什么 | 权威产物；不做什么 |
| --- | --- | --- |
| Goals | 本人选三个月目标，采纳首周里程碑：“能演示中断恢复并解释为什么没有二次执行”。 | `Growth Goal`、里程碑与确认过的完成标准；不据聊天时长或生成文本判达标。 |
| Knowledge | 固定一段获准的公开技术材料，记录来源、版本/抓取时间、片段定位与内容哈希。最简版用随样例交付的原创合成文字；也可由人选取[LangGraph 持久化官方说明](https://docs.langchain.com/oss/javascript/langgraph/persistence)讨论“线程检查点与长期数据不同”。 | 资料版本与可打开的引用。引用不代表理解、授权联网或允许把整本文档送给模型。 |
| Learning | 基于该段出一道题：“工具已完成、界面随后关闭，哪些事情可以安全地再做？”保存原答和反馈原句；本人采纳练习。 | 路径、原答、带依据反馈、待复测项。自述、反馈与确定性结果区分保存。 |
| Projects | 基于明确的材料与练习说明建立独立合成项目，保存源码快照、题目和测试版本、实际运行报告。标明哪些由本人编写、哪些由 Agent 生成、哪些尚待说明。 | 版本化 Artifact、Verification Receipt。练习转项目只附引用与授权，不复制全套职业记录。 |
| Career | 本人选择某次成果后，可以预览一句**实践范围内**的描述，并核对依据与个人归属。默认不采纳。 | Change Proposal；只有目标简历、原版本、差异和本人确认均匹配才有 Business Receipt。不自动写 FactBase、不投递。 |
| Insights | 展示“本周测试通过／解释未证实／下周待复测”，提出在新样例上复测的建议。本人点采纳才改计划。 | 可重建的只读投影及版本化建议；不能替 Goals 调整目标或替 Career 确认事实。 |

## 3. “是我的目标”不等于“可为我执行”

术语沿用[领域词汇](../../CONTEXT.md)。下表是设计中的最小归属与标识，不要求另起六个数据库，也不表示这些都是现有字段。

| 记录 | 谁负责写 | 最小约束 |
| --- | --- | --- |
| Growth Goal / Milestone / GoalTaskLink | Goals | 目标有稳定 ID、owner、版本、阶段标准和用户采纳历史；关联存目标/里程碑和原任务 ID。目标不是身份、工作区、授权令牌，也不是整个季度共用的无限预算。 |
| Task / Run / Step | Agent Host 的 Kernel | Task 是约定，Run 是一次尝试，Step 是一步有序事实。保留原任务 ID、工作区、rootScopeKey、rootTaskId 与消耗；显式启动前不执行。关联历史根不重开账本、不退费、不发放资料权限。当前旧根关联只允许目标工作区尚无根，不能合并多根。[范围与根唯一性](../../apps/web/src/services/agent-task-scope.ts#L7) · [历史关联约束](../reports/task-scope-association-2026-11-12.md#L3) |
| Artifact / Evidence Link / Competency Observation | Projects 或 Knowledge 持有原产物；证据记录持有来源关系；Learning 管理学习观察 | 不可变版本引用源、定位、内容哈希、作者/生成方式与许可；观察另记评估人/验证器、任务范围、限制、时间及复测到期。观察的是人的表现，不是 Agent Capability。相反的观察可以并存。 |
| Change Proposal / Business Receipt | Career | 候选引用原证据和本人归属说明，无权限写职业档案。业务回执由 Career 校验目标资产版本、预览哈希、当前权限、去重键后签发；职业文案不能先被 Insights 或模型落库。 |

**目标进展的所有者是 Goals；Insights 只读。** 例如首周展示“练习通过、本人解释待核、尚未复测”，不显示“Agent 工程能力 100%”。满足所有约定条件时里程碑变为“可验收”；用户采纳或明确采用预先约定的客观验收规则后才成为“已达成”。职业描述是否采用，不是学习里程碑的必选条件。源丢失、已撤权或哈希不符时保留可用历史元数据，展示“依据不可用／需复核”，不把它继续算作可靠观察。

### 一条命令和一条事件（示意，不是现有 HTTP 接口）

```text
LinkTaskToGoal(goalId, milestoneId, taskId, expectedGoalRevision, requestId)
  → Host 以当前身份检查双方所有者、可见范围、业务理由及目标版本
  → 按 requestId + 内容指纹去重；只写链接及新目标版本，不启动任务

PracticeVerified(eventId, goalId, taskId, runId, artifactRef@sha256,
                 receiptRef, evaluatorVersion, passed/failed/skipped, sequence)
  → Goals 与 Insights 按 eventId 幂等更新各自读模型；
    Career 只提供“查看并起草”，不因事件写履历
```

身份由 Host 从有效会话推导，不信任调用者在事件里自报的 owner；读取索引、打开文件、提交命令时分别校验。每个订阅者按发布者及对象序列保存游标；遇到缺口先回读权威记录，不从乱序事件推断“已完成”。新增同库业务更新和待发布事件应同事务提交；不能跨库同事务时保留待对账记录并通过幂等重放投影。重放**不会**重新调用模型、重跑工具或签发 Business Receipt。

## 4. 一周薄切片：最小 Agent 要真的做什么

1. **冻结输入。** 给一份完全合成的资料集，含两段带 ID 的术语说明；确定题目、固定测试集版本和允许的工具。工具 `lookup(noteId)` 只能读取清单内的片段，不接收任意路径、不联网、不写文件。学习者的作品与 BetterMe 自己掌握的 Agent Capability 是两件事。
2. **留下工作过程。** 学习者提交代码版本以及“哪些由我完成／哪些由工具生成”的说明。验证时采用固定决策序列，保证断网也可重现；它验证循环、工具协议和恢复，而不声称验证某个真实模型的推理质量。本机语音朗读、OXR、PDF 翻译和 DeepTutor 在线服务均可关闭。
3. **设一个真的中断点。** 在工具结果和步骤状态持久化成功后、呈现最终答案前停止这次执行。关掉并重新打开界面，先只读任务、游标、既有产物和已花预算。学习者明确继续后，从同一已保存步骤构造结果。外层 BetterMe Task 与练习内的检查点分别命名，不能用截图代替真实的持久化、重开与比较。
4. **由独立验证器判定。** 对相同输入至少检验：引用到正确片段；未知 ID 返回显式“找不到”而不猜；无权限工具被拒；上述中断恢复后总的 `lookup` 计数仍为 1，结果与不中断基准一致。报告保存源/用例哈希、验证器版本、每项预期/实测、通过/失败/跳过计数及限制。超时、缺件、无法验证一律不是通过。
5. **交回给人。** 展示源码差异、报告、学习者作答和未解决的问题。可选择“仅留作练习”“在 Projects 保留成果”或预览职业用途的实践描述；需要关联材料或采纳到目标简历时分别确认。Insights 可推荐下周换一题，但不能替本人改目标、设闹钟或发送提醒。

**关键反例：** 若在“外部动作可能已经发生、尚未取得持久回执”时断线，不能承诺全局 exactly-once。把该次派送结果标记为“待对账”（这是提案的业务结果，不是已有 Task 状态枚举）；先凭原任务、稳定请求 ID 和来源凭证只读核查。查到唯一回执才继续；不能判定则保持未知、保留已占预算，不自动重试、不另建根任务。简单练习只证明上述**已持久化的断点**不会重执行，不能推广为所有外部动作的保证。

## 5. 放行、退回及撤销

以下是未来实现要跑的验收，不是本次已测的结果。同一夹具在 Web 和 Electron 上复用，所有用户、资料、岗位和简历均为合成。

| 场景 | 预期观测 |
| --- | --- |
| 正常路径与重开 | 一个目标可沿引用追到来源片段、原答、项目版本、逐项验证和复盘；关闭重开仅 GET，模型/工具派送计数不增加；“继续”才有新的授权命令。 |
| 并发、重放、断线 | 双窗口对同一请求只生成一份链接/业务回执；同键不同内容、过期版本或素材哈希改变被拒。事件重复、乱序、缺失能从原记录补齐且不重复计数；未知结果按对账规则处理。 |
| 主体隔离与撤权 | A 的目标、任务或产物 ID 用 B 访问不返回正文；A→B→A 后旧回调也不能写；撤权后不再获取材料或启动处理。已开始的外部动作只核对真实结果，不能宣称已撤回。 |
| 成就边界 | 自述完成、答案引用不符、测试失败/跳过、模型代写但未说明归属时不得显示能力达标；主动拒绝职业采用后，练习历史保留、简历版本不变；没有投递动作。 |
| 文件与版本 | 错哈希、缺页或证据被撤权时不展示“已核实”。真实中文简历、默认模板、已有英语稿不动；对合成简历示范采用产生唯一版本回执，撤销只撤本次改动，不还原整份旧档。[现有补偿撤销语义](../../apps/agent-host/src/workspace/resume-adoption.ts#L79) |
| 完全本地 / 后端不可用 | 固定资料和确定性练习不要求云 Key、GPU 或外部教学账号。缺少本地验证器时显示“未运行”，可以保留草稿，不能以模型估分、系统终端或自动切云顶替。 |

**上线与回退。** 首先以新开关、独立命名空间和两名合成用户开放只读投影；再只对新创建且已明确归属的目标开启链接与练习。旧资料、旧根账和无主记录不扫描认领、不迁移、不覆盖；后续历史接入先列范围、差异和授权预览，选择后才建立元数据关系。关闭开关应停止**新的**写入/派送，使在途工作暂停或待对账；保留原任务、预算、证据、回执、原版简历和可读历史，仍能通过原入口读取。任何删除另走主体授权与保留策略，回滚不删除业务记录。
