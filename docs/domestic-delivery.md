# 国内平台投递行动卡

本功能把 BOSS 直聘、前程无忧（51job）、猎聘的投递准备、本人操作和回执拆开。它是现有「机会与投递」工作台的一部分，不是全自动投递机器人。

## 从哪里开始

1. 在「机会」收藏岗位，填写三家平台的 HTTPS 官方岗位链接。申请链接优先于来源链接；短链、其他平台和仿冒域名不支持。
2. 打开岗位详情，展开「国内平台 · 投递行动卡」。选择发起沟通、共享简历或提交岗位申请。
3. 填写便于本人识别的平台账号标记、明确收件对象和待发文案。不要填密码、验证码、Cookie 或完整敏感号码。
4. 共享简历或申请前，先在详情下方保存「投递材料快照」，再选择该快照，填写官方平台在线简历版本、附件版本与实际分享范围。Markdown 快照只用于核对，不表示已经上传 PDF/Word。
5. 保存草稿并核对行动卡。只有本次明确核对后才出现「本人去官方平台操作」；点击前先保存本地交接记录，保存失败就不打开链接。
6. 在官方平台由本人完成实际动作，回到行动卡记录结果、依据、时间和最小说明。没有回复、按钮消失或网络超时都不能直接证明失败。

现有「分析 JD」「创建岗位简历」继续复用原 Agent 和业务模块；本功能不增加第二个聊天 Agent、不擅自调用模型，也不自动写简历事实。

## 状态与提醒

| 状态 | 含义 | 允许的下一步 |
| --- | --- | --- |
| 待核对 | 只保存准备草稿 | 明确核对或取消 |
| 已核对 · 待本人操作 | 绑定本次岗位、账号标记、对象、文案、材料与分享范围 | 打开官方平台、记录本人结果或取消准备 |
| 已打开平台 · 待核实 | 只证明本地已记录打开意图，不证明页面加载或已经发送 | 本人核实实际结果 |
| 结果待核实 | 可能已发，也可能未发 | 不自动重试；先查平台记录，再补充本人回执 |
| 本人确认已完成 | 本人确认本卡所述动作实际完成 | 保留历史，不重复排队 |
| 本人确认未发送 | 本人核实没有发送 | 可重新准备 |
| 已取消准备 | 尚未交接平台的准备被取消 | 可重新准备 |

岗位信息或所选材料变更/删除后，旧准备不能继续打开平台；取消旧卡并重新准备。已交接或结果不明的卡不能简单取消来掩盖可能已发送的结果，原材料快照和全部回执保留。

站内「投递待核实」由完整机会库派生，包含未知结果、已交接和过期准备，不因当前筛选隐藏。当前不发送系统通知、微信、短信、邮件或 Web Push；页面关闭后没有后台调度。这里的提醒不是 Git 推送。

发招呼、共享简历、提交岗位申请分开记录。行动回执不会自动改动原投递看板或伪造沟通日志；如需更新看板，请在原「投递阶段」中另行确认真实提交。本人标记“查看平台记录”仍是自述，不代表 BetterMe 已读取平台或独立验证。

## 国内平台差异与授权

- BOSS：沟通、简历共享与岗位申请不能合并。2026-11-04 经浏览器核对的[官方用户协议](https://about.zhipin.com/agreement?id=registerprotocol)四.11、七.5/7 对未经许可第三方工具获取服务、数据及非正常浏览等有限制。页面标明 2023 年 3 月版；具体用户 App 当前适用版本应再次核对。
- 51job：[官方帮助](https://m.51job.com/about/help.php?qid=9)说明快速申请设置影响默认简历；[协议/隐私汇编](https://login.51job.com/xyservice.php?display=h5&page=1)说明在线简历与附件可能同时向招聘方展示。不能只核对本地 PDF。汇编中的广泛自动化限制部分属于视频面试协议，不扩大解释为所有业务。实际 App 的最新规则仍须核对。
- 猎聘：查到的[官方协议 PDF](https://image0.lietou-static.com/img/66a85a9cb1f15833544b120d07u.pdf)更新于 2024-07-25，第二条 4.3/4.4 包含规避限制、程序化或非正常获取平台数据的限制；尚未核实其为具体 App 最新适用版本。

截至本次研究，没有核实到三家普遍向第三方开放、允许代表普通求职者自动投递的 API。这不等于接口不存在；企业 ATS、BossHi 或前端内部接口不能代替个人侧授权。用户允许、系统权限和平台许可分别确认，最后一步人工操作也不自动解决其他自动化行为的许可。

真机 + OpenCV 不等于获得平台许可，也没有官方证据证明能降低封号概率。产品不承诺安全发送配额、不模拟真人规避检测、不轮换账号或绕过验证码。

## 手机与模型路线（尚未接入）

移动首版的两条入口与同一条草稿流程见[Android Mika／iOS 分享设计](planning/desktop-job-agent-workflow-2026-11-05.md#mobile-job-workflow)和[验收矩阵](planning/desktop-job-agent-workflow-2026-11-05.md#mobile-acceptance)。以下设备执行方向不改变上面已交付的手动行动卡，也不是给真实平台开通自动操作。

后续可在获得相应许可后，以 Android USB 真机优先做受控验证：桌面本地 Ollama 做分析，设备桥接层提供可见接管，控件语义优先、OCR/OpenCV 辅助感知，确定性的平台状态机执行已支持动作。截图不直接交给模型自由点击。未知页面、验证、账号警告、低置信度或结果不明时停止交还本人。

设备桥接、配对、手机采集、自动点击、后台发简历、截图上传和跨设备同步均未交付。能力工厂即使学会解析页面，也不能自行获得外部发送权限。先用脱敏界面和合成样本验证，再针对明确许可的动作决定真实执行范围。

## 存储、备份与 Docker

行动卡与回执作为机会记录的可选字段保存在当前浏览器，沿用原机会库的版本冲突、损坏保护和 4 MB JSON 备份上限。旧 v1 备份无需迁移；首次保存行动卡时升级为 v2，旧客户端会明确拒绝读取/覆盖，而不是静默丢弃新字段。新字段完整 JSON 往返；删除全部岗位也不会降级版本。降级程序前应先备份并保留兼容版本，不能清空存储来绕过提示。重复岗位导入仍遵循“现有记录优先”，不会覆盖旧行动与投递历史。每个岗位 20 张卡只是资源上限，不是平台允许的发送配额。

本机开发、Docker runtime 和 static 构建都包含该前端功能。Docker 命名卷不包含浏览器行动卡；不同 origin、端口、浏览器仍是不同资料空间，升级前分别备份。Docker 默认不挂载手机 USB、ADB、个人浏览器 profile、源码、凭据目录或 Docker socket，不开启 privileged，也不为手机联动开放公网。

构建与独立验收命令、镜像标签覆盖见 [Docker 指南](docker.md)。验收仅用合成岗位/材料，不登录招聘平台、不采集或投递真实资料、不调用模型。
