# 非 Agent 跟进与导出增强验收记录

日期：2026-10-17，Asia/Shanghai。本文接续[上一批非 Agent 工作区交付](non-agent-workspace-upgrade-2026-10-17.md)，记录本轮增加的手动求职跟进、国内官网来源、Word 导出和交互修复。职业对话、学习计划、自主投递及插件继续后置。本轮没有创建 Git 提交或推送。

**本轮的结果是：机会库可以保存截止日、联系人和实际沟通，并组织到期跟进；当前可见简历可以下载为真实 DOCX；腾讯招聘官网可以按关键词预览后收藏。** DOCX 已通过实际文件结构与正文回读检查，逐页渲染检查仍受本机缺少 LibreOffice 限制。完整浏览器验收与最终检查结果由主任务在文末补齐。

## 手动投递与跟进

岗位信息新增“申请截止原文”和“明确截止日期”。原文可保留“招满即止”等表达，日期字段仅接受有效的 `YYYY-MM-DD`，不会把相对描述猜成日期。截止日不会自动关闭岗位，也不会冒充已安排的跟进时间。

申请记录新增手工填写的渠道、联系人、联系方式／备注。它们与下一步、跟进时间和私人备注一起保存；填联系人不等于已经联系，保存备注不等于已经发送消息。

实际沟通另行记录：

- 收到／发出方向，以及邮件、电话、招聘平台／即时消息、视频、当面或其他方式。
- 实际发生时间、沟通对象、内容摘要，以及由系统记录的补录时间。
- 保存前必须确认沟通已经发生；拒绝未来发生时间。待发内容应写入“下一步”。
- 记录沟通不会发送外部消息，也不会改变投递阶段；删除单条记录需要明确确认。

每个岗位最多保留 200 条沟通记录。超过上限明确报错，不截断已有记录。新字段进入 JSON 备份、CSV 和检索，恢复时继续采用字段白名单；旧库缺失这些字段时补为空值，已有历史与时间保持原样。机会库原有的 4 MB、2,000 个岗位、修订冲突及配额失败保护继续生效。

页面新增“已逾期／今日待办／未来安排”队列，与当前市场、搜索和阶段等筛选使用同一组岗位。时间已过即归逾期；北京时间当日尚未到期归今日，其余归未来。Offer 阶段仍可安排谈薪或补问条款，仅“未通过／已撤回”排除。队列可打开岗位修改下一步，每 30 秒及窗口重新获得焦点时更新当前时间；没有后台通知或消息提醒。

显示、输入和队列分组统一使用 `Asia/Shanghai`，不依赖电脑当前时区。旧的无时区时间按北京时间解释。只修改联系人等其他字段时，保留原始时间的秒、毫秒和时区表示；只有实际修改时间输入才转换存储，清空则明确移除。合法旧备份中“已投递但未记录提交时间”的岗位允许补充备注与联系人，不补造提交时间；从其他阶段进入“已投递”仍要求确认已经完成外部申请。

岗位信息、跟进和沟通需点击相应保存按钮；它们没有套用简历的条件自动保存／最近 50 个完整版本。未保存的岗位编辑、跟进与沟通补录纳入关闭、切换和刷新前的保护。`Ctrl/Cmd+S` 在岗位弹层中按当前聚焦表单保存，避免误提交另一张表单。

## 应用内确认与图片粘贴

简历视图／经历／历史快照删除、恢复演示、机会删除、材料快照、沟通删除、未保存内容放弃及真实投递确认改用统一的异步应用内确认框。原有确认语义保留，默认焦点在取消；Escape 取消；确认期间拦截保存快捷键。一个问题尚未回答时，后续请求不会替换当前问题。确认框使用原生 `<dialog>`，可以显示在岗位详情弹层之上。

简历视图删除在确认后读取最新文档，经历删除读取最新 Fact 引用；机会保存仍需通过持久化修订校验。跨窗口更新不会因确认框异步化而直接覆盖已有记录。

审查发现个人信息页的全局图片粘贴监听在编辑器隐藏或其他弹层获得焦点时仍可能运行，进而把 JD 截图意外当作头像。本轮把头像粘贴限定在**当前可见的 FactEditor 滚动容器内**，继续排除输入框、文本域、选择框和可编辑内容。向确认框、JD、机会及其他工作区粘贴图片不会据此修改简历头像。

## DOCX 导出

预览工具栏新增“下载 DOCX”。导出以当前 `ProjectedResume` 为输入，使用 MIT 的 `docx` 依赖生成真实的 Word ZIP／OOXML 文件；依赖在点击导出时动态加载。导出过程不调用模型，不上传简历，不下载头像或其他远程资源。

Word 输出采用可编辑的 A4 单栏正文，保留：

- 当前输出语言、可见个人字段、要点、技能和经历，以及分节顺序和显示开关。
- 姓名、职业定位和事实要点的加粗、斜体、下划线、高亮和字号变化；保留正文换行。
- 合法 HTTP／HTTPS 链接、语义标题、项目要点、页边距、基本字号、字体类别和行距。

隐藏经历／字段／分节、未核实量化、面试私有要点与坑点不会进入文件。导出器再次排除私有／未核实要点，并拒绝带账户密码或危险协议的超链接。下载名保留中英文姓名，过滤 Windows 路径和控制字符；作者、修改者等文档元数据不写入用户身份。

DOCX 使用独立的便携排版，不逐像素复刻网页六模板的分栏和装饰，也不包含照片。界面在下载前后说明这项边界；需要保留网页照片和装饰的场景继续使用浏览器打印 PDF。中文实际字形和分页仍受打开文件的编辑器及本机字体影响。

`apps/web/tests/docx-export.test.tsx` 的 6 项测试生成真实 DOCX，再读取 ZIP 中央目录／OOXML，并用 Mammoth 回读正文或 HTML，覆盖中英、分节顺序、链接、A4 结构、隐藏信息、未核实与私有内容、重叠文字样式、换行、长简历末尾完整性和安全下载名。正文回读不能代替分页视觉检查，也不代表招聘网站 ATS 已验收。

浏览器已触发实际下载，文件位于 `%USERPROFILE%/Downloads/resume-zh-林知行.docx`，该名称来自独立演示来源，未读取私人求职 SSOT。另生成了中英文匿名长简历及回读结果，保存在仓库外的 `<local-artifacts>/betterme-2026-10-17/docx-export/`。这些导出文件不进入 Git。

### DOCX 视觉检查停点

本轮按本机安装的 `documents` 技能执行文档渲染检查。该检查流程明确要求：

> Run `render_docx.py` to produce `page-<N>.png` images (optionally also a PDF with `--emit_pdf`).
>
> Open the PNGs (100% zoom) and confirm every page is clean.

已经尝试通过配套渲染器检查匿名长简历，但当前运行环境没有 LibreOffice／`soffice`，未生成可供检查的逐页 PNG。因此本报告只确认 DOCX 文件生成、结构、选定内容和正文回读；**不能把中文缺字、裁切、实际页数、跨页位置和版面视觉标为通过**。源文件及回读产物均保留，后续具备渲染运行时后直接接续检查。该技能没有因此要求暂停已经授权的应用开发，也没有要求用户先批准代码修改。

## 腾讯招聘官网试点

机会库的公开招聘来源新增“腾讯招聘官网”，与已有 Greenhouse／Lever 并列。具体请求、真实样本、字段语义与上游做法取舍见[国内官网主源研究](../research/domestic-official-source-2026-10-17.md)。

本轮仅支持用户触发一次公开搜索：固定腾讯 Query 接口，第 1 页、最多 100 条；关键词可留空。结果先预览，勾选并点击收藏才进入机会库；结果不完整时明确提示。真实适配器样本中“后台”匹配 112 条，本次返回 100 条、`truncated=true`，只是当次接口观察值，不代表长期固定数量。

固定主机、公司标识、关键词校验、同源 POST／JSON、32 KB 请求体、8 MB 响应体、15 秒总超时和拒绝重定向继续生效。不接受任意上游 URL，不使用账号、Cookie、登录或验证码绕过；不抓取详情，也不自动翻页或发起申请。

`PostId` 作为来源独立岗位编号；`RecruitPostId` 仅保留为可能覆盖多条发布的招聘编号。官网返回的详情链接经核对后保留，对同一腾讯主站岗位页升级为 HTTPS；额外只允许真实样本中观察到的精确腾讯 Workday 租户和岗位路径，未向该站发请求。

职责正文明确标为“官网搜索结果摘录”，可能缺任职要求，使用前需回原岗位核对。`LastUpdateTime` 只有日期原文，保留在摘录中作为更新日期，不改写为发布时间，也不补造时分秒和时区。国家／单城市来自官网明确字段；国家精确为“中国”才归国内，其他市场待核对，多城市不强塞进一个城市字段。未披露的薪资、远程资格、工作方式和招聘类型保持未知。

来源测试 13 项包含原有 8 项及腾讯 5 项，覆盖固定请求、编码与拒绝输入、数量上限、空结果／错误区别、链接、地点、独立编号和时间语义。当前不是全平台搜索或持续同步服务，纯静态 `dist` 部署仍需要兼容后端。

## 首次加载体积

`ResumeImportModal` 改为首次打开才加载，包含 PDF／Word 解析工具；下载失败有重试和关闭入口。组件加载后保持原有打开／关闭与取消过期操作的逻辑。DOCX ZIP 写入器也使用独立动态 chunk。

本轮一次实际生产构建对比为：

| 构建项 | 大小 |
| --- | --- |
| 上一批入口 JavaScript | 约 1.415 MB |
| 本轮入口 JavaScript | 592.87 kB；gzip 176.71 kB |
| DOCX 按需 chunk | 约 394.50 kB |
| 导入工具按需 chunk | 约 846.37 kB |

这项改动减少了首次编辑页面需要下载的代码；解析工具本身仍然较大，构建仍可能提示大 chunk。本轮没有把体积提示写成已全部消除，也没有把所有导出或页面改成按需加载。最终构建若产生小幅变动，以主任务补录输出为准。

## 后续非 Agent 差距

- **真实地图与地点底座**：国家／城市实体、地理坐标、远程允许范围和工作授权仍需核对；地图、数量和具体岗位列表尚未形成真实交互。当前队列与文字分布只统计个人已收藏库。
- **跨源同岗与持续更新**：仍以相同来源链接防重，没有跨平台同岗归并、公司实体归并、持续同步、关闭复核或旧新 JD 观察历史。
- **导出质量**：DOCX 实际分页／中文字体逐页检查、六模板真实多页 PDF、阅读顺序和招聘 ATS 回读尚未完成；RenderCV YAML 仍未运行实际 PDF 渲染器。
- **备份与材料**：机会仍保存 Markdown 内容快照，PDF／Word 附件库、完整版本历史独立导出／导入、单文件恢复和跨设备同步未实现。
- **国内外原始平台**：BOSS／51job／猎聘／LinkedIn 的真实岗位成功提取与多图 OCR 样本仍需逐站验收；腾讯搜索摘录不等于补齐这四个平台，也不等于获得完整 JD。
- **简历闭环**：JD 建议逐条确认应用、真实个人文件导入与头像识别保真仍有验收和实现工作；现有双语字段切换不构成自动翻译。

后台提醒、自动填表／投递、职业 Agent、学习打卡与训练、Offer 自动决策及插件没有因本轮交付而实现。
