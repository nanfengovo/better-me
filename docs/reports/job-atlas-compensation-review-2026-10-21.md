# 来源薪资核对与搜索联动

本批补上“来源披露了薪资，但网页无法核对为可比较金额”的操作链路。岗位详情新增“核对来源薪资”，通过同一套 TypeScript 契约完成读取依据、逐字段预览、明确确认、追加历史和撤销。原始薪资与岗位正文保留；本人核对仍标为待核实。

这一步只解释已保存的原文，不额外采集招聘网站，不从平台惯例推断税前、固定工资或保证发薪月数。外币继续保留原币；带出处的汇率快照管理和企业控股证据核对仍待后续实现。

## 网页操作

1. 本机岗位后端就绪后，单击已入库岗位，在详情薪资下方选择“核对来源薪资”。合成演示和未连接后端的视图不提供保存入口。
2. 点击“读取薪资依据与历史”，检查具体来源、岗位链接、来源字段、当前有效值、适用地点及既有记录。面板不自动把现有解析值认定为本人核对。
3. 按原币基本单位填写金额，选择明确披露的币种、周期、税前／税后、工资组成及计薪数量。每个填写的字段分别选择同一原岗位已保存的观察或正文，并逐字引用支持该值的原句。未披露字段留空或保持未披露。此次是对整份结构化披露的核对，未填字段按未知保存，不是只修改单个字段。
4. 填写核对说明并预览。检查拟保存值及年化结果后，另行勾选“确认本人已逐项核对薪资依据”，再提交。
5. 保存后重新读取索引，列表、筛选、排序、地图与覆盖统计使用同一有效投影。来源薪资底账、JD、观察时间、正文快照及地点范围不因核对而改写。
6. 再次读取依据与历史，可以明确撤销当前核对。撤销保留历史，恢复上一条仍适用的核对或来源披露；失效记录不会自动复活。

例如原文分别明确写有“税前固定月薪人民币20,000–30,000元”和“每年保证发放13个月固定工资”，受审结果为税前固定年薪 **260,000–390,000 CNY**。仅写“最高13薪”、奖金、股票、总包、税后或税制未知时，不能通过勾选变成该结果。未明确保证的月数不存入核对；网页的覆盖统计、筛选和排序默认不采用未披露计薪数量的估算。底层显式估算能力继续独立保留，不能称为保证13薪。

保存或撤销后的面板顶部采用当前索引有效值；已读取的依据、字段表和历史明确标记原读取版本，新的索引不会静默重置草稿，继续核对需重新读取。

同一岗位的多地点薪资和跨来源披露继续分别保存。有效薪资只作用于原披露的地点范围；不同可比较区间有歧义时，不任取第一条进行排序。

## 共享工具与后端

| 工具 | HTTP | 效果 |
| --- | --- | --- |
| `compensations.read-review` | `POST /api/v1/compensations/review` | 只读来源值、有效值及本条薪资历史 |
| `compensations.preview-review` | `POST /api/v1/compensations/preview` | 同版本、同原岗位的逐字段证据验证与预览 |
| `compensations.confirm-review` | `POST /api/v1/compensations/confirm` | 明确审核后追加核对决议及耐久回执 |
| `compensations.revoke-review` | `POST /api/v1/compensations/revoke` | 明确撤销本人的核对并追加历史 |

四项能力都由已有工具 Registry 和认证 HTTP 暴露，同源网关仅增加这四个固定 POST 路径。后续 Agent 可调用同一 Schema 和工具，不需要复制另一套薪资逻辑。调用工具不免除来源依据、版本、权限、明确审核与幂等键要求。

SQLite 从 V4 升为 **V5**：`base_compensations` 保留来源底账，`compensation_decisions` 仅追加确认、撤销及来源失效记录。有效投影在跨源归并前应用，再写入统一索引，相关岗位版本随有效薪资改变。V1–V4 完整备份继续可恢复；V5 完整备份增加底账、决议及相应回执，恢复前重放验证其关联和投影。

确认归档当时的 listing 来源／编号／链接身份、原始薪资以及实际支持字段所用的观察或正文。历史重放使用归档材料，当前有效性另与最新来源比较。来源薪资、所属原岗位、招聘链接或支持材料变化时，追加永久失效记录；来源 A→B→A 不重新启用旧确认。稀疏刷新没有披露新薪资时，不等于撤回原薪资。

确认与撤销都先按原 actor、工具、幂等键和原请求查耐久回执。数据库已提交而响应丢失时，网页保留原 body 和 key，允许核对回执。取得可信回执后若索引刷新失败，只重试读取索引。更改连接、岗位或薪资对象会取消原会话，迟到结果不能用于新的岗位。

公共岗位 JSON 保存有效薪资字段，不能替代完整备份中的核对历史。向同库回灌已覆盖的有效薪资不会覆盖来源底账；向空库导入公共 JSON 也不会凭空获得本人核对决议。需要保留核对语义时使用岗位服务完整备份。
