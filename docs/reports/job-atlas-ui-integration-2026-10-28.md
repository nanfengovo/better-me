# 岗位地图 UI 安全接入与运行验证

日期：2026-10-28。已将上一阶段的展示层接入主项目当前工作区，并启动独立体验入口。

## 入口与安全边界

- 新版入口：`http://127.0.0.1:5173/?workspace=atlas`。它直接运行主项目源码，不是合成演示或独立副本。
- 原有 `http://localhost:5173/` 页面保留，没有导航、刷新、关闭或重启。原 Vite 仅监听 IPv6 loopback；新版 Vite 显式监听 IPv4 loopback，使用 strictPort，不占用或替换旧监听器。
- 两个地址是不同 origin，简历 localStorage / IndexedDB 不共享；没有复制、恢复、导入或保存原页面的简历。体验页可能显示自己的示例简历或独立偏好，不代表原简历丢失。
- 岗位服务 5178 和 Agent Host 5179 复用现有健康实例，未重启、未迁移岗位库、未更换令牌。新版前端退出不负责停止它们。
- 修改主项目源码之前，先在独立 Vite fixture 验证旧 HMR 连接保护：旧连接不收到 update / full-reload，新连接仍能收到更新，普通消息和 HTTP 继续可用。随后仅对身份核对后的原 Vite 进程安装临时保护，避免旧页面受到源码更新影响；临时 Node 调试入口用完关闭。
- 接入完成后只保留已有旧连接的保护，新连接可正常热更新；旧连接关闭后自动清理。用户不需要为了体验新版而刷新旧页面。此保护不停止文件监听器或业务 API。

## 接入范围

UI 补丁已重新适配主项目当前基线，未直接套用包含首次基线分页阶段的工作副本。此次没有激活分页协议，也没有修改查询索引、同步协议、入库、补全调度、依赖或简历存储。

产品源码范围为 AtlasWorkspace、MapLibre 视角、地图视觉类型、采集 / 补全状态标记，以及三个独立展示模块：AtlasActivityRail、AtlasViewControls、atlas-experience.css。

| 接入前 | 接入后 | 原因 |
| --- | --- | --- |
| 采集、入库、补全和地图状态不易分辨 | 四条独立状态，各自保留未知值和真实计数 | 不将并行工作画成虚假的统一完成率 |
| 地图只有装饰性的空间标签 | 同一渲染器内切换 2D / 3D | 不重新查询岗位或上传不变的几何 |
| 工具与列表争抢空间 | 多维筛选默认折叠，搜索主操作与卡片层级清晰 | 优先展示岗位与地图 |
| 动效可能干扰高频阅读 | 克制的按钮反馈、减少动态效果支持；列表不播放入场 | 采集更新时保持阅读目标稳定 |

浏览器接入验证另发现：现有工作区在仅切换市场范围时会准备一个空 intent，任务卡将它误标为“已结束”。此次只在展示组件隐藏无运行、无回执的空准备状态，保留实际运行、失败、取消和已有卡片的状态；未修改采集或查询状态机。新增回归先失败、修正后通过。

## 运维说明

- 需要复现独立入口时，可在仓库根目录运行 `pnpm --filter @better-me/web exec vite --host 127.0.0.1 --port 5173 --strictPort`；端口不空闲会直接失败，不替换现有服务。
- 正常后续 `pnpm dev` 也会使用已经接入的新 UI 源码；不要为了切换 UI 强制重启带未保存状态的现有页面。
- 查询索引优化继续作为独立阶段处理。本次没有提交或推送 Git。
