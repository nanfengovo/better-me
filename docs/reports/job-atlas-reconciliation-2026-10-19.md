# 跨来源岗位归并核对工具与工作台入口

日期：2026-10-19。功能已分工具与界面两批正常推送，独立冻结树完成完整验证；远端运行见文末。

本批把已有可撤销归并底座接到共享工具、认证 HTTP 和岗位地图工作台。用户可以查看同岗候选、比较双方来源和字段差异、明确选择保留摘要的方向，再决定合并或暂不合并；已有决定也能先预览影响，再明确撤销。任何候选或强关联线索都不会自动合并真实岗位。

这次交付改善已收录岗位的证据组织与人工核对，**没有扩大招聘来源或市场召回范围**。私人本机索引沿用此前的 **85 岗／revision 59**，未为展示本功能而合并真实岗位。合成回归不代表已经在原私人页面完成目视验收，也不代表 51JOB、BOSS、完整 JD、办公地址、可比薪资和全市场覆盖已经解决。

## 共用契约、工具与 HTTP

严格输入和输出定义位于 `packages/opportunities/src/reconciliation-tools.ts`，服务组合位于 `apps/job-service/src/reconciliation.ts`，HTTP 只负责将已认证请求分派给同一工具。未来 LangChain／LangGraph 执行器可以复用这些工具及其 effect、预算、执行身份和幂等约束，不需要另建一条绕过预览的写入路径。

| 工具 | HTTP | 行为 |
| --- | --- | --- |
| `jobs.list-merge-candidates` | `POST /api/v1/jobs/reconciliation/candidates` | 有界读取已收录岗位的同岗候选，显示关联信号、字段差异、快照版本和扫描限制；可按岗位筛选 |
| `jobs.preview-merge` | `POST /api/v1/jobs/reconciliation/preview` | 在同一版本解析目标／来源岗位及历史 ID，返回双方原始来源、结构化字段、冲突和绑定完整输入的预览指纹；不写入 |
| `jobs.merge` | `POST /api/v1/jobs/reconciliation/merge` | 本人核对后追加合并决定，保留目标摘要方向以及双方全部来源贡献 |
| `jobs.reject-merge` | `POST /api/v1/jobs/reconciliation/reject` | 核对同一份预览后记录暂不合并，排除当前这对候选，不删除岗位或来源 |
| `jobs.list-merge-decisions` | `POST /api/v1/jobs/reconciliation/history` | 有界读取合并、暂不合并和撤销历史，区分生效中、已撤销和撤销记录 |
| `jobs.preview-revoke-merge` | `POST /api/v1/jobs/reconciliation/preview-revoke` | 在同一版本模拟撤销本人有效决定，展示相关岗位组的撤销前后组合、来源及摘要 |
| `jobs.revoke-merge` | `POST /api/v1/jobs/reconciliation/revoke` | 核对撤销预览后追加撤销决定，保留原决定、原文和更新历史 |

只读工具使用 `read-index` effect，三项写工具使用 `local-write` effect。HTTP 沿用 loopback 本机服务、Bearer 认证、允许的 Origin 和公开字段契约。工具不接受客户端指定执行身份、任意来源证据或私人字段。

归并预览输入为：

```json
{
  "targetJobId": "synthetic-target-job",
  "sourceJobId": "synthetic-source-job",
  "expectedRevision": 11,
  "reason": "逐一核对原文、雇主和招聘需求的说明",
  "companyIdentityConfirmed": true
}
```

确认合并或暂不合并时，重交同一份规范化输入、`previewFingerprint` 和 `reviewed: true`，同时提供 `Idempotency-Key`。目标方向、说明、企业确认或版本变化都会使原预览失效。企业实体不同且没有充分的已核实法律实体依据时，合并还要求独立确认实际雇主；同名企业不能自动当作同一主体。

撤销预览输入为 `{ decisionId, expectedRevision, reason }`，确认撤销再携带该预览的指纹与 `reviewed: true`。只能撤销同一执行身份的有效合并或暂不合并决定；已撤销的决定以及撤销记录本身不能再次撤销。

## 保留来源、摘要方向与可逆分组

归并保留稳定的原岗位身份、来源条目、观察、JD 快照、地点与薪资分项。界面中的“保留摘要的目标岗位”决定标题、正文、雇主和招聘状态等标量摘要的方向；另一条岗位的不同值继续保留在来源和冲突记录中，不被默认为事实一致。

地点、薪资及远程资格等多项贡献保留原来的独立项，不把不同金额平均或混成一个数字，也不把一方的地点证据移给另一方。来源后来刷新时仍更新原来源贡献，撤销后可以保留各自最新内容，避免把拆组简单恢复成合并时的旧拷贝。

合并采用追加决定和 alias 投影，已有岗位 ID 仍能解析到当前 canonical 岗位。归并历史和原始证据不会因当前列表只显示一组而消失。公共投影导出用于读取当前状态；需要完整恢复决定、原始贡献和耐久回执时，仍使用完整仓库备份。

撤销预览展示受该决定影响的**当前全部相关岗位组**，而非仅显示最早参与的两张卡片。多层合并可能因其他有效边继续保持一组，也可能拆成多组；预览展示实际重放结果。撤销暂不合并只恢复候选资格，不改变岗位正文；最终是否再次出现在候选中，仍取决于当前证据和有限扫描范围。

字段冲突显示的是供核对的截取摘要，单字段最多 1000 字。完整内容应打开各来源岗位原文核对，不能用截断摘要代替完整 JD 一致性判断。

## 有界候选的实际含义

候选页默认返回 50 项，单次可请求 1–100 项；历史页使用相同显示范围。候选生成按已收录记录中的名称、标题、申请链接等关联组织，不发起新的市场搜索。

底层本次至多枚举 10000 对候选关系，至多返回 1000 个解释后的候选供应用层排除有效拒绝、按岗位筛选并截取。`scannedCandidateLimit: 1000` 表示该有界处理范围，不表示库内只存在这些岗位对。`truncated` 反映已生成候选的返回截断，**即使为 false，也不能推断全库已扫描完整**。没有候选不代表没有重复；面板支持手动选择两条已收录岗位继续核对。

跨来源相同岗位级申请地址或有证据的官方岗位编号可以作为强线索；普通招聘首页、搜索页或通用申请表不能自动成为单岗身份。相同雇主名称、相同标题仍为弱线索。强线索同样需要本人确认，不能据此提升招聘状态、雇主控股性质、办公位置或岗位事实的核实等级。

## 工作台中的实际操作

“重复岗位核对”入口只出现在已经连接真实本机索引的岗位地图工作台，当前机会库和合成演示模式不提供这条写入口。面板按需加载，打开面板本身不联网、不扫描、不写入。

1. 点击“读取候选与记录”。页面共同读取快照、候选和历史，只接受三者 revision 一致的结果；读取期间索引变化时要求重读。
2. 选择候选，或手动选择两条已收录岗位。明确指定“保留摘要的目标岗位”和“并入的来源岗位”，可以交换摘要方向。
3. 填写核对依据，必要时独立确认实际雇主身份，再点击“预览来源与差异”。双方显示岗位、雇主、来源标签、原文链接、地点、薪资项数量、关联依据和字段差异。
4. 阅读预览并独立勾选后，选择“确认合并岗位”或“记录暂不合并”。修改说明、方向或企业确认会清除原预览和勾选；外部索引版本前进会使旧预览不可提交。
5. 在处理历史中查看生效状态、说明、时间和版本。撤销时重新填写说明，先查看相关岗位组的撤销前后影响，再独立勾选确认撤销。

成功回执后重新读取共享索引，由现有共享查询重新计算岗位列表与地图。归并并不会创造办公坐标，也不会把城市参考点变成核实地址。

连接身份变化会卸载原核对会话。关闭、卸载、切换工作台或断开连接会停止等待并丢弃迟到结果，避免旧连接更新新页面；浏览器停止等待不等于服务端数据库回滚。

## 同一请求的耐久重试与等待反馈

服务端先检查同身份、工具和幂等键对应的完整命令指纹及耐久回执，再决定是否需要验证当前版本、重新预览或写入。已提交但响应丢失后，可以用原 body、原 `expectedRevision`、原指纹和原 key 取回原回执，即使索引已因其他操作前进，或者服务已经重启。同键不同 body 产生冲突，不能将新的核对内容伪装成旧请求重试。

决定、投影、alias 和回执由仓库事务一起保存，回执保存失败会回滚对应写入；取消信号和逻辑 deadline 还需通过最终提交门检查。工具注册层现提供可信、只读的持久回执恢复回调，仅三个归并写工具启用。原请求任何已缓存失败都可查回执；没有回执仍返回原错误，不重新执行写入。恢复保留原身份、完整输入签名、权限、取消、截止时间、输出 Schema 与字节上限，成功后缓存确定的回执。已实际复现并修复“提交后超时、同进程原键永远只得旧超时”的问题。提交后的 Schema／预算失败也能读取原回执，mutation 次数保持 1。

UI 等待有处理中动画，25 秒后停止等待。写入结果不确定时保留原 body 和 key，锁定草稿并提供“重试本次处理 · 核对回执”；重试不生成新 key，不把外部新版本替换进原命令。明确版本冲突、权限或无效请求等拒绝会清除旧预览，要求重新核对。

已经获得成功回执、但快照读取失败时，页面保留已保存版本，只提供重新读取索引，不再次提交写入。未确定请求暂存在当前面板内存，界面提示保留面板以核对回执；本批不宣称关闭页面或刷新后可以恢复该未确定请求的 body 和 key。

Web 客户端严格校验输出结构及预览上下文、版本、双方身份、来源字段引用和写回执的 action／方向／版本。对合法历史 alias 保留兼容，不依赖当前客户端实例的预览缓存来判断耐久重放。
