# 岗位地图：地区参数修复与四平台单页搜索工具

记录日期：2026-10-18；启动恢复协议更新：2026-10-19。状态：**国内省市区、空关键词浏览和直辖市真实名称参数已修；本机搜索会话支持可恢复启动与精确取消，四个真实平台的搜索列表尚未逐站验证**。本文记录阶段证据，最终浏览器结果和覆盖全部新增代码的全仓检查另行补充。总体边界见[岗位地图架构](../planning/job-atlas-architecture-2026-10-18.md)，工具设计见[公司招聘发现与岗位搜索工具](../planning/company-career-search-tools-2026-10-18.md)。

## 截图所反映的入口问题

原页面在已选地区时仍可能显示四个平台均不可搜索，源码中有两个独立原因：

| 触发条件 | 原因 | 当前处理 |
| --- | --- | --- |
| 未输入岗位关键词，只选择地区 | 关键词必须非空的入口校验把地区浏览一起禁用 | 空字符串或纯空白允许按所选地区浏览；界面说明未填写关键词。长度、换行和控制字符仍校验。 |
| 选择北京、天津、上海或重庆的城市 / 区县 | 目录保留上游城市分组 `name: "市辖区"`，而可读 `label` 是直辖市名称；调用方误把分组名提交给平台地区解析 | 仅对四个直辖市的统计分组显式传递所属直辖市名称，避免用“市辖区”作城市。其他省的省直辖分组不随意回退。 |

另修复国内模式下香港的国家 / 地区参数：原调用固定传 `CN`，而香港映射保留 `HK`，产生冲突并阻断本可使用的 LinkedIn 入口；现在使用实际选择生成的国家 / 地区代码。国内模式是一种产品视图分组，不重写原始地点证据。香港目前只有明确的 LinkedIn 地区映射，其他平台仍说明未配置，不能静默改成全国或平台默认地区。

平台地区配置独立于行政目录。一个省市区可以用于已收录岗位筛选，并不代表四个平台都有相同的搜索代码。未知地区和国家 / 城市冲突继续阻断；未指定地区时明确说明原站可能采用默认或上次地点，不宣称全国 / 全球搜索。BOSS 地区仍标为仅核对参数，LinkedIn 文本地点仍需打开原站核对实际解析范围。

## 2023 省市区目录的范围

国内下拉采用固定版本的 [modood/Administrative-divisions-of-China](https://github.com/modood/Administrative-divisions-of-China) 统计区划数据；版本、字节数、SHA-256、覆盖和许可证记录在 [source-manifest.json](../../config/geography/china-administrative/source-manifest.json)，授权副本与说明随数据保存。

- 数据时点为 **2023-06-30**，上游公布日期为 2023-09-11；仓库版本日期更晚不代表行政数据更新到该日期。上游已停止维护，不能称为当前权威行政目录。
- 覆盖大陆 31 个省级节点、342 个含统计分组的地级节点、3,056 个末级条目；其中 2,974 个为六位统计地区，82 个为九位镇街 / 功能区，界面不将它们全部改称法定区县。
- 港澳台仅补充地区级选择，不伪造下级目录。修改上级清除失效下级；直辖市分组原名和用户可读标签分别保存。
- 目录提供选择与文本别名，不给岗位补国家、地址、坐标或行政事实。国家及各层地区条件必须匹配同一个工作地点；不能用一个办公室的国家和另一个办公室的城市拼成命中。

因此，这批地区工作解决入口参数与本地过滤组合，不能单独证明来源已经按该地区返回真实岗位。

## 新增本机 search session

外部链接仍由 [`buildPlatformSearchRequest()`](../../packages/source-adapters/src/platform-search.ts) 按固定官方入口和独立地区映射生成。新增执行工具通过 [`jd-session-router.ts`](../../apps/web/server/jd-session-router.ts) 的 `startSearch()` / `readSearch()` 路由到标准或原生浏览器后端，搜索和单岗详情共享同一个页面租约；启动中、关闭中或已有会话时不会让另一路线争用浏览器。搜索用途和详情用途分别检查，计划路由 / 关键词 / 地区变化后拒绝沿用旧结果。

开发宿主的 [`POST /api/jd/search-session`](../../apps/web/server/jd-search-api.ts) 已接入可恢复启动协议，使用原有本机同源请求约束和 owner；客户端核对响应的平台、URL 条件、卡片数与状态。

| HTTP action | 输入与实际调用 | 当前边界 |
| --- | --- | --- |
| `start` | 规范 `input` 与合法 `requestId`，调用 `startSearchRequest(owner, input, requestId)` | 同一请求绑定原 owner、用途和计划搜索条件；重试恢复原逻辑启动，不另开一个不同搜索。 |
| `cancel-start` | 原始 `input` 与同一个 `requestId`，调用 `cancelSearchStart(owner, input, requestId)` | 只取消该次启动及可能迟到取得的页面；不能用当前筛选替代原输入或关闭其他会话。 |
| `read` | 已确认的 `sessionId`，调用 `readSearch()` | 只读取该会话当前单页，响应仍核对原计划搜索范围。 |

面板在发起请求前保存原始输入和 `requestId`。启动响应丢失、读取等待被中止或网络结果未知时保留该绑定；“重试恢复本次搜索”复用原标识和原条件，即使上方筛选已变化也不换成新查询。“取消本次等待”只中止等待，不能表示页面已经关闭；“结束本次搜索请求 / 会话”才发出精确取消，并在服务确认 `cancelled: true` 与 `closed: true` 后清除本次状态。

取消请求设 **8 秒等待上限**。超时或关闭未确认时保留原绑定，允许继续重试结束；8 秒是客户端等待限制，不是保证浏览器已关闭的期限。组件卸载时中止进行中的读取，并对原始绑定发出 `keepalive` 精确取消；卸载后的请求属于尽力清理，不能作为已取得关闭回执的证据。这些行为由受控面板测试覆盖，仍需真实平台与生命周期端到端验证。

该接口属于本机 Web 开发宿主，独立岗位服务 `/api/v1` 尚未注入 browser companion。GitHub Pages 和现有静态 Docker 不运行招聘浏览器，也不会因发布这些前端文件而获得采集能力。

列表模块 [`jd-search-capture.ts`](../../apps/web/server/jd-search-capture.ts) 使用各平台独立、有限的选择器配置；共享纯结果类型位于 [`job-search-types.ts`](../../apps/web/src/lib/job-search-types.ts)。读取边界如下：

| 项目 | 当前行为 |
| --- | --- |
| 采集范围 | 当前已渲染单页最多 50 张卡片；候选扫描、HTML 和摘录均有预算。成功结果保留 `partial: true`，不声称总覆盖。 |
| 岗位身份 | 必须有可见锚点、官方 HTTPS 白名单和支持的单岗路由身份；拒绝搜索页、公司页、跨平台链接及一张卡内多个不同单岗身份。同 ID 去重并保留首次观察到的原链接。 |
| 字段与证据 | 标题、可用企业、明确地点、薪资和发布时间原文分别来自配置字段；保存原搜索页、卡片选择器、字段选择器和原文。经验 / 学历混合标签不猜地点，整卡文本不猜薪资。 |
| 可见内容 | 原生搜索投影仅额外保留可见 `A.href` 和 `TIME.datetime`；标准快照直接从可见 DOM 构建惰性文档，不先复制隐藏内容，不读 Cookie、storage、表单值或隐藏 JSON。 |
| 时间 | 明确发布时间字段才写 `publicationText`；更新、活跃、刷新和推广时间不充当发布时间。`TIME.datetime` 不自行变成发布日期；HTTP 的 `capturedAt` 由可信宿主在本次读取完成后提供。 |
| 门禁和失败 | 登录、人工验证、未知布局、快照超限、不支持页面分别保留；只有原站明确的可见空结果才返回 `empty`。阻断、加载中或选择器失效不显示为“0 匹配”。 |
| 原文与索引 | 当前是手动触发的单页读取；卡片是摘要，非完整 JD、在招核验或个人事实。结果留在本面板，可接续显式核对 / 收藏入口，不自动写入本机规范岗位索引或地图。 |
