# 参考汇率快照与同版岗位查询

本批补齐跨币种薪资比较的实际操作链路：读取或粘贴参考汇率原文，预览换算方向，明确保存和启用，再以同一份索引版本重算覆盖统计、列表、筛选、排序、地图与分页。原币、来源薪资、正文及本人薪资核对记录继续保留。

参考汇率只用于比较人民币税前固定年薪。它不能补足来源缺少的税前口径、固定工资组成、保证计薪数量或地点适用范围，也不是实时成交价、银行结算价或薪资认证。

## 网页操作

1. 本机岗位后端就绪后，在岗位地图打开参考汇率管理。
2. 明确点击读取公开参考汇率，或填写实际来源名称、原文出处、读取时间和原始 JSON。只读取不会保存或启用。
3. 预览原文日期、出处、内容哈希及每单位原币到人民币的换算。核对后另行确认保存，可选择同时启用。
4. 已保存快照可以重新选择或停用；选择变动追加历史，并提高共同索引版本。旧游标不能继续使用。
5. 写入结果不明时保留原请求和幂等键，核对原回执；保存已确认而索引读取失败时，只重读索引。等待期间隐藏旧汇率结果。

手工导入及本人启用均明确标注为本人导入，不据此宣称发布机构已经认证。切换连接、数据视图、索引或日期时，迟到的旧上下文不能覆盖新查询。演示和旧机会库不使用私人后端的汇率。

## 原文与换算

共享 Schema 支持两种显式格式：

- `eur-reference-json-v1`：`{ "date": "YYYY-MM-DD", "base": "EUR", "rates": { "CNY": 8, "USD": 1.25 } }`，可带 `amount: 1`。
- `frankfurter-v2-eur-json-v1`：`[{ "date": "YYYY-MM-DD", "base": "EUR", "quote": "CNY", "rate": 8 }, ...]`。

两种格式均要求明确 CNY、正且有限的汇率及真实日期。数组所有记录须为同一日期且币种唯一；重复 JSON 键及其转义别名、未来日期、无效 EUR 基准和溢出结果均拒绝。原始响应最多 256 KiB，原文、格式、出处及实际读取时间共同绑定快照身份；SHA-256 另绑定原始 UTF-8 字节。恢复和客户端读取会从原文重算，不能只信看起来合法的哈希或派生值。

若原文明示 `1 EUR = 8 CNY`、`1 EUR = 1.25 USD`，则 `1 USD = 8 / 1.25 = 6.4 CNY`。这是合成计算示例。CNY 始终为 1，EUR 采用明确的 CNY 报价，不套用硬编码市场汇率。薪资换算沿用 UTC 日历窗口：第 30 天仍可用，超过 30 天、缺币种或未来快照不可比较；历史原文继续可查。

## 来源工具与持久化

| 共享工具 | 认证 POST 路由 | 效果 |
| --- | --- | --- |
| `fx.fetch-reference` | `/api/v1/fx/reference` | 受控外部读取，返回待核对草稿 |
| `fx.read-state` | `/api/v1/fx/state` | 按岗位索引版本读取保存记录及当前查询上下文 |
| `fx.preview-import` | `/api/v1/fx/preview` | 从原文重建快照并预览 |
| `fx.confirm-import` | `/api/v1/fx/import` | 明确确认后保存不可变快照，可同时启用 |
| `fx.activate` | `/api/v1/fx/activate` | 选择已存快照或停用，追加历史 |

默认参考源通过 [宿主配置](../../packages/source-adapters/src/default-fx-reference.json) 指定 Frankfurter V2 的 ECB 记录：`https://api.frankfurter.dev/v2/rates?providers=ECB`。通用 Provider 工厂支持宿主安装其他符合上述格式的公开 HTTPS 来源；工具请求、导入内容或模型不能更改网络端点。沿用受控传输的精确主机／路径、公网 DNS 固定、禁止重定向、请求／字节／超时预算及取消机制。

选用 V2 前已核对 [Frankfurter V1 源码](https://github.com/lineofflight/frankfurter/blob/main/lib/versions/v1.rb) 的弃用标记及 [V2 OpenAPI](https://github.com/lineofflight/frankfurter/blob/main/lib/public/v2/openapi.json)。实际默认混合源返回 165 条、跨两天，被同日约束拒绝；随后明确限定 ECB 的请求成功返回 **30 个币种、参考日 2026-10-21**，约 2.2 秒。完整原文及哈希仅保存在本地验收目录，未写私人岗位库。有限一次成功不能证明长期可用。

SQLite 升为 V6，增加不可变 `fx_snapshots` 和追加 `fx_activations`。确认与选择都有耐久幂等回执。V1–V5 完整备份继续兼容；V6 完整备份携带汇率原文、选择历史和回执，恢复前重建验证。公共岗位 JSON 继续只描述岗位，不能替代包含汇率管理历史的服务完整备份。 目标时钟看来尚未发生的FX证据或选择事件在写入前拒绝；若恢复会丢弃目标库已有快照或选择历史，则返回`conflict`。完整恢复宜使用空库，不以旧备份任意回滚既有FX历史。

后端 `jobs.search` 在同一 SQLite 事务取得岗位数据和有效汇率，宿主注入不能另换一份汇率或查询日期。网页按 `expectedRevision` 读取上下文，覆盖统计和查询共用该汇率及日期；版本改变或读取失败时遮蔽旧结果。UTC 跨日重新读取上下文，保留同一日内稳定分页。
