# 岗位地图：大库计算隔离与增量写入验收

日期：2026-10-28。环境：macOS arm64、Node v26.7.0。所有压测使用合成岗位与独占临时 SQLite，不使用用户库、不采集真实招聘网站。

## 结论与范围

本阶段拆为服务端计算隔离、浏览器计算隔离、地图投影优化三个独立边界，没有增加 UI 动画，也没有改变来源坐标、人工核对、幂等回执和部分采集状态的含义。

5000 / 15000 岗并发读写测试通过。5000 岗旧路径红测出现约 5240ms 的调用方事件循环间隔；最终隔离路径复测为 42ms，15000 岗为 36ms。浏览器真实地图回放中，5000 岗没有超过 50ms 的长任务；15000 岗仍出现一次 52ms 长任务，因此不能声称零卡顿或所有硬件均能保持固定帧率。

主要成果是隔离计算对 HTTP 与界面主线程的抢占，并减少无效重写；不是把整个数据层改造成 O(delta)，也不是让大库查询瞬时完成。

## 三个解耦边界

| 边界 | 本次实现 | 保持的约束 |
| --- | --- | --- |
| Job Service | 单一写线程处理采集、投影与自动补全；独立只读线程通过 WAL 读取已提交版本；输出校验与 JSON 编码在线程内完成，HTTP 直接发送转移后的字节 | 单写、CAS、耐久回执、认证与 Origin/Host 校验不变；只读线程不消费补全队列 |
| 浏览器计算 | 快照下载、解析、校验、查询、覆盖统计、AI 岗位扫描和地图几何交给独立 Worker；快照按对象身份复用，最多缓存 3 份，每份最多缓存 4 个查询 | 仍使用原始查询与证据规则；过期查询取消，列表与地图按同一结果版本提交；不跨连接沿用统计 |
| 地图提交 | Worker 预计算 GeoJSON、签名、办公地址顺序与同坐标分组；签名未变不重新提交地图源；同坐标累积由反复复制数组改为线性追加 | 城市参考点和无精度坐标仍不能冒充办公点；不抖动真实坐标；原有地址选择与地图视角行为不变 |

### 服务端细节

- 启动仍先取得数据目录独占锁、迁移并恢复中断任务，然后关闭初始化连接，进入单写线程与只读线程模式。正常 `pnpm dev` 入口不增加人工启动步骤。
- 只读连接要求数据库版本匹配，使用只读事务获取一致快照，不以 `BEGIN IMMEDIATE` 抢占写锁。读取可以看到提交前或提交后的完整版本，不读取半次事务。
- `base_jobs` / `base_locations` 只处理当前导入涉及的来源 ID；相同文档不重复写入，预处理语句在批内复用。人工覆盖、合并投影不写回来源基表。
- 线程启动失败或退出会关闭计算入口，不回退到 HTTP 线程同步执行，不自动重放可能已提交的写入。关闭时先等待应用和 SQLite 排空，再回收线程。
- 权限、请求预算和原有工具注册校验仍存在。线程是计算隔离，不是额外的操作系统安全沙箱。

### 浏览器细节

- 本地 / 演示数据按每块 128 条安装；服务端快照在 Worker 下载和解析后，按同样大小回传。
- 回传需要主线程逐块确认，避免大快照一次结构化复制或一串消息淹没输入事件。地图数组也使用该协议。
- 相同数据的搜索、统计共享已安装快照；不同版本不会仅凭 revision 值混用。缓存淘汰后可重装一次。
- 首次安装尚未结束时，旧搜索也能立即停止等待；共享安装不会随旧观察者取消，新搜索可继续复用。
- Worker 故障会拒绝等待中的请求、清理缓存并显示可操作错误。实际浏览器无法启动 Worker 时不执行阻塞式回退；Node / happy-dom 的纯参考实现仅用于测试与非浏览器调用。

## 性能结果

### 1. 实际服务生命周期、SQLite 和 HTTP 并发

场景：导入一个增量岗位，同时搜索 C# 的 30 条第一页；随后导出，包含自动唤醒的补全链路。测试父线程每 10ms 采样一次。

| 岗位规模 | 搜索返回 | 并发写入、搜索与导出合计 | 最大定时器间隔 |
| --- | ---: | ---: | ---: |
| 5000 | 1185ms | 3636ms | 42ms |
| 15000 | 2774ms | 10263ms | 36ms |

优化前同一 5000 岗红测：搜索约 3315ms，并发流程约 8616ms，最大定时器间隔约 5240ms，按 `<150ms` 断言失败。最终数据是另一轮运行，不是稳定的吞吐或百分位基准。

测试：`apps/job-service/tests/compute-isolation-scale.test.ts`。最终日志：`output/atlas-streaming-preview/compute-scale-service.log`。

### 2. 实际 Worker 调度器与主线程响应

使用真实 node Worker 运行与浏览器相同的计算调度器，不是 mock。初次耗时包括安装快照、查询、统计和地图几何；第二次查询换成 TypeScript，不是重复命中相同关键词。

| 岗位规模 | 安装与首次计算 | 换词查询 | 调用方最大定时器间隔 |
| --- | ---: | ---: | ---: |
| 5000 | 1711ms | 517ms | 12ms |
| 15000 | 5048ms | 1482ms | 13ms |

这些定时器数据不代表浏览器帧率。测试：`apps/web/tests/atlas-compute.test.ts`；最终压测运行 8 项全部通过，无跳过。日志：`output/atlas-streaming-preview/compute-scale-worker.log`。

同坐标分组单独测量：15000 个完全重叠来源地址从约 224ms 降至约 10ms，保留全部地址和岗位计数；这不是整个地图渲染耗时。

### 3. 真实浏览器、真实地图与连续入库回放

独占预览使用本次源代码、实际 MapLibre WebGL 地图与两份实际临时 SQLite 服务。初次地图加载后再开始采样；每种规模连续导入三批、每批 16 岗，期间手工切换 TypeScript / C# 并操作地图缩放。没有访问真实招聘平台，没有启动动画。列表保留上一份结果，新的列表和地图随快照更新。

| 浏览器指标 | 5000 岗 | 15000 岗 |
| --- | ---: | ---: |
| 三批流程总耗时 | 16112ms | 55204ms |
| 新增岗位 / 最终库规模 | 48 / 5048 | 48 / 15048 |
| 最终 C# 匹配 / 当前页 | 2524 / 30 | 7524 / 30 |
| 最终可点办公地点 | 1262 | 3762 |
| 10ms 定时器最大间隔 | 30ms | 77ms |
| 定时器间隔 p95 | 11ms | 11ms |
| rAF 间隔 p95 / 最大值 | 9ms / 17ms | 9ms / 59ms |
| 超过 50ms 的长任务数 / 最长 | 0 / 0ms | 1 / 52ms |

总耗时包含三轮实际入库、完整快照读取、分块传输、查询、统计与地图更新，不是输入被冻结的时间。15k 三批仍需 55.2 秒，反映完整快照路径仍重；不能只展示低主线程阻塞数字而省略这个事实。

15000 岗的一次 52ms 长任务没有精确归因。已检查当前 MapLibre 6.15 的源码，不能将其直接归因于旧版本式的主线程整份 `JSON.stringify`；也没有为消除一个未定位样本而修改其内部机制。仍需针对更大规模的地图提交、GC 与真实底图做单独 trace。

截图：`output/atlas-streaming-preview/compute-15000-browser.jpg`。隔离预览服务及代理均已关闭，自己的临时库已清理，用户原有浏览器和服务未重启。

## 正确性与回归

- 只读 WAL 事务在外部写事务未提交时仍能搜索旧版本；提交后读取新版本。
- 增量基表写入测试用触发器禁止改写无关来源行，验证导入成功且证据保留。
- 实际服务线程保持 CAS、幂等重放、取消、关闭与启动失败的既有契约。
- 实际浏览器计算调度器与参考查询逐项等价，覆盖分页、选中岗位、游标版本、地图几何、统计、取消、缓存淘汰、严格响应校验与 loopback 限制。
- Worker 不可用、崩溃、等待首次上传时取消都有回归用例；地图仍以来源精度门槛筛选坐标。
- 最终相关链路完整回归：623 项、620 通过、0 失败、3 个显式压测跳过，耗时约 128 秒。覆盖 Job Service 全部测试，以及岗位工作区、来源采集、分批入库、自动补全、断点与刷新恢复、地图和 Worker；不是全仓库测试。日志：`output/atlas-streaming-preview/compute-regression-final.log`。
- 两个新增大库压测入口已另行开启执行：服务端 1 / 1 通过，计算 Worker 8 / 8 通过，均无跳过。最终针对计算和地图的聚焦回归为 27 项、26 通过、0 失败、1 个显式压测跳过。
- `apps/job-service`、`apps/web`、`apps/web/tsconfig.node.json` 的 TypeScript `--noEmit --incremental false` 检查全部通过。没有执行全仓库测试、发布或生产构建，也没有重写被既有开发服务监听的 workspace `dist`。

## 复现

在仓库根目录执行；大库测试独立开启，避免普通测试默认消耗大量内存和时间：

```sh
BETTER_ME_SCALE_BENCH=1 pnpm exec tsx --test apps/job-service/tests/compute-isolation-scale.test.ts
BETTER_ME_SCALE_BENCH=1 pnpm exec tsx --test apps/web/tests/atlas-compute.test.ts
pnpm exec tsc -p apps/job-service/tsconfig.json --noEmit --pretty false --incremental false
pnpm exec tsc -p apps/web/tsconfig.json --noEmit --pretty false --incremental false
pnpm exec tsc -p apps/web/tsconfig.node.json --noEmit --pretty false --incremental false
```

浏览器隔离验收夹具：`output/atlas-streaming-preview/compute-server.ts`、`compute-smoke.tsx`、`compute.html`。入口：

```sh
node --import ./node_modules/tsx/dist/loader.mjs output/atlas-streaming-preview/compute-server.ts
```

仅此夹具使用端口 5296，内部服务使用随机端口和新建临时目录；不要用真实数据库目录替换。结束时向该自建进程发送 SIGINT，让其关闭自己创建的服务并清理目录。

## 下一阶段边界

1. 单独做 revision/change-feed 增量快照同步，减少每轮完整下载、校验、传输与双份驻留；保留完整快照校验作为恢复入口及 64MiB 上限，不截断数据冒充完整。
2. 单独做可复用查询索引 / SQL 分页和版本化聚合，进一步缩短 15k 搜索与写线程整库投影耗时。当前这些 CPU 工作已隔离，但没有全部消失。
3. 单独 profile 地图提交、绘制与 GC，验证更多办公点、真实底图和较弱硬件；不能用本次合成、无远程底图的结果保证所有地图场景。
4. UI 动画、3D 美化与生图仍在独立阶段，不与本次计算协议和事务正确性绑定。

实现取舍参考 Node 官方的 [worker_threads](https://nodejs.org/api/worker_threads.html) 与 [node:sqlite](https://nodejs.org/api/sqlite.html) API；MapLibre 行为以本仓库安装的 6.15.0 源码为准。
