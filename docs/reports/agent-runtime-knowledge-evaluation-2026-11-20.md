# Agent 执行、项目记忆与同题评测

三个模块共用一份合成仓储材料和一个问题。两段可引用的原文分别记录了联调中的重复入库去重、测试中的 Redis 回放。第三段只谈货架位置。“可能减少重复处理”属于推断，上线收益缺少证据。简历定制和项目理解都通过产品正常的账号与任务入口处理这些材料，版本矩阵单独比较检索与回答，标准答案留在评分端。[共享题目与标准答案](../../evals/resume-quality/gold/warehouse-replay-v1.json)

## A　服务重启后能继续哪一步

任务沿用 BetterMe 自研的 AgentTaskKernel。它根据任务类型、权限和已挂载材料生成可发现的工具列表，将下一步决策交给绑定的模型适配器，在 Host 校验后执行。此前的简历任务只保存工具名，恢复时可能重复尝试同一份材料。现在调用参数与预算登记一同持久化，返回结果和证据关联到同一调用序号。进程丢失时能区分“已发起”和“已读到”，用户在原任务上显式恢复；写入仍使用版本校验和人工确认。[执行循环](../../apps/agent-host/src/kernel/service.ts) · [工具目录](../../apps/agent-host/src/kernel/tools.ts) · [模型适配](../../apps/agent-host/src/tasks/runtime.ts)

真实进程验收中，同一任务跨过四个 Host 进程。读取第一条证据后手动暂停，重启后恢复，在已经读取岗位时强制终止；再次启动读到“已中断”，继续取得 Redis 原句，生成草稿，第四个进程重发确认后仍只有一条回执。共登记六次工具调用，五次成功，一次按预期拒绝未授权材料。三项迟到返回测试覆盖暂停、撤销和会话过期。流程使用本机可控的模型替身，以便在相同位置终止进程。[重启用例](../../apps/agent-host/tests/agent-runtime-restart.test.ts) · [调用轨迹与确认回执](../../output/module-a-20261120/verification.json)

## B　结论从哪份材料得来

学习材料库按用户保存本机导入的文本和 PDF，保留文件指纹、页码及文本块。项目任务通过显式授权的文件和对话获取证据，在已授权文本片段中结合 BM25 与字符级 TF-IDF 向量的余弦相似度排序，将选中的原文送入模型。默认检索完全在本机计算。它能找出有部分字形重合的词形和标识符；本轮测量没有覆盖跨语言语义召回。长期保存的项目理解包含版本和确认记录，供后续经历改写引用。[文档导入与出处校验](../../apps/agent-host/src/growth/learning-materials.ts) · [检索与精确范围](../../apps/agent-host/src/kernel/evidence-retrieval.ts) · [项目上下文](../../apps/agent-host/src/kernel/project-understanding.ts)

需要使用本机嵌入模型时，工作室另有显式授权的向量排序入口。它绑定选定片段及模型修订，核对来源和权限后才计算稠密向量。项目任务的上述默认检索和八格实验使用稀疏向量。[本机嵌入模型与来源绑定](../../apps/agent-host/src/career-studio/privacy-local-http.ts)

用户明确替换项目原文时，系统现在记录新旧来源关系。在下一轮提示、可引用材料和经历改写交接中排除旧原文，同时保留历史和其他独立补充。在项目理解面板中展开某一项结论，可以核对文件行号与原文指纹，或查看用户当时的说明。仓储回归的两条事实分别定位到两份文件的第 2 行；推断引用了去重记录，上线收益保留为未知。测试还覆盖替换后拒绝旧引用、重启后的确认以及另一个账号的读取限制。[仓储证据和更正回执](../../output/module-b-20261120/warehouse.json) · [浏览器展开引用](../../output/module-ui-20261120/project-citations.png)

同题也通过产品任务入口交给真实模型自行读取目录。初版曾将六次模型额度全部花完，未交出答案。修复后，只有生成了材料读取句柄才开放按句柄翻页；如果重复读取没有得到新证据，或只剩最后一次模型调用，系统要求根据已收集的原文作答。综合阶段的引用选择限于有效材料和当前用户消息。[初次真实执行](../../output/module-b-20261120/live-warehouse-before.json) · [项目决策协议](../../apps/agent-host/src/kernel/model-protocol.ts)

自由撰写项目理解的实测保留了两次失败。普通 Gemma 预设在四次模型调用、十一次工具操作后，最后一次返回 2,051 个输入和 2,045 个输出 token，达到 4,096 上下文上限。Host 在“模型输出不完整”处暂停，逐字保留了模型返回的 2,620 字符部分正文。同权重的 65,536 上下文预设读到了三份文件，却把两份 Markdown 中的记录标为代码事实，只给出两个标题；Host 拒绝将它们送审。两次均没有形成合格答案。[普通预设与部分回包](../../output/module-b-20261120/live-warehouse.json) · [长上下文预设与原始决策](../../output/module-b-20261120/live-warehouse-ctx65536.json)

因此，正常项目理解任务在收到明确的逐字核对请求时，会把已读取的原文位置列给模型。模型选择相关行，给出推断所依据的行，并列出仍不清楚的结果。Host 在采纳前重新读取选中的精确范围，比对授权、文件指纹及内容，再用实际原文生成证据卡。文档陈述和代码观察按来源分别标注，最后交给用户审核。在交付源码的同题实测中，同一套 Gemma 权重以 4,096 和 65,536 两种上下文分别运行。每次都用两次模型调用、八次工具操作取得两条完整原句，来源都是对应文件的第 2 行。两次均排除了货架图，正确区分推断和缺少证据的上线收益，并进入待审核状态。[4,096 上下文的完整答卷](../../output/warehouse-project-shipped-4k-confirmed-20261120/result.json) · [65,536 上下文的完整答卷](../../output/warehouse-project-shipped-65k-20261120/result.json) · [原文位置与采纳校验](../../apps/agent-host/src/kernel/project-quote-review.ts)

## C　同一题改变一个因素

使用一份冻结输入，两套真实本机模型权重，两份不同的系统提示和两版生产检索代码。八组均使用相同的三个候选片段、Top-K、温度、种子、上下文及输出预算。每格保存实际输入、选中的证据、模型原始响应、版本指纹、耗时与 token。可以离线核对 12 对只变化一个因素的组合。此处的 Agent 版本指检索策略，模型直接回答材料核对题；完整的任务调度、恢复与确认另由 A、B 验证。[冻结的执行计划](../../output/agent-version-matrix-final-20261120/plan.json) · [评测命令](../../evals/resume-quality/README.md)

| 本机模型 | Prompt | BM25 v1 | 混合检索 v2 | 逐项检查 |
|---|---|---|---|---|
| Gemma 4 E2B | 原句引用 v1 | 通过 | 通过 | 两句齐全、推断正确、收益未知 |
| Gemma 4 E2B | 来源复核 v2 | 未通过 | 未通过 | 多选货架图，并将推断判为事实 |
| SmolLM2 135M | 原句引用 v1 | 未通过 | 未通过 | 只有一句完整命中，回放引文漏了开头的“我”，还列入了货架图 |

## 下一批回归

1. 为两个名字相近的不同项目、文件被替换以及缺少上线数据分别保留独立的测试项目。对每条事实预标必须保留的原句和禁止转移的归属，分别统计错误放行与漏选。
2. 用同一份两轮简历修改任务继续验证，第一轮只允许调整 Redis 句，第二轮只允许调整另一句，同时核对原版、已确认字段及正式保存的版本。
3. 在这些独立项目上复跑同题矩阵，再决定是否更换默认 Prompt 或模型。裁判模型的判断与原文引用、程序校验和用户最终采纳分别记录。
