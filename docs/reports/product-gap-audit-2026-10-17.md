# 迈向更好：原始规划与当前实现差距审计

日期：2026-10-17。审计基线：本地 `main` 的 `ff67cdd`，业务功能提交为 `94c5a5e`。本报告是检查结果和后续验收清单，不表示新增功能已实施。

实施后更新：本报告保留 `ff67cdd` 的审计基线。用户随后要求非 Agent 优先，本批机会库、多简历、材料快照与官网ATS等已新增，当前状态请读[非 Agent 工作区交付报告](non-agent-workspace-upgrade-2026-10-17.md)。

## 1. 结论与审计口径

**目前的实际产品是简历工作室，加上 AI 导入、单份 JD 采集与诊断；长期职业成长 Agent 的主闭环尚未实现。** 简历编辑、模板、条件自动保存和浏览器版本回看已有可用实现；对话规划、学习执行、测评证据、机会库/地图、投递和 Offer 尚未串起来。

不能用一个主观百分比概括进度：简历底座与后续成长模块的体量、完成标准不同。以下按三种状态记录：

- **已实现**：存在实际业务代码，已有检查或交互验收记录；仍明确列出实际使用边界。
- **部分实现 / 待真实验收**：有入口、字段或请求代码，但缺少完整行为，或者没有真实服务/文件样本通过记录。
- **未实现**：当前没有相应业务对象、持久化和完整界面/执行流程；规划和调研不算实现。

对照材料包括用户最初愿景与补充确认、[产品路线图](../planning/betterme-product-roadmap-2026-10-16.md)、四份 `docs/research/` 研究记录、项目 brief/决策/进度、源码/Schema/依赖及[简历工作室验收记录](resume-studio-upgrade-2026-10-17.md)。本轮检查不修改业务代码，不连接招聘账号、不投递、不运行真实云模型，也没有重新浏览外部项目。

本报告沿用已确认的阶段边界：V1 是可信简历底座；下一阶段优先服务本人技术岗社招，围绕现有工作经验/主技术栈做“对话规划 + 契约学习闭环”。原 V1 对打卡、插件等的排除不代表它们从长期路线图删除。具体依据见 [projectbrief](../../.agent-memory/projectbrief.md) 与 [decisionLog](../../.agent-memory/decisionLog.md) 的 2026-10-16 下一阶段决策。

| 页面关闭后的学习提醒 | 未实现；学习任务本身尚未建立，不能承诺浏览器关闭/休眠后提醒必达 |
| 结构化主库 | 正式简历/草稿等仍为 localStorage，版本为 IndexedDB；SQLite/OPFS 迁移未做 |
| 跨设备/跨宿主与备份 | 无自动同步；当前 JSON 只备份简历文档，不含整条历史、Key、JD 草稿/截图，更不包含尚未建立的学习状态 |
| Agent 运行控制 | 有模型超时/错误处理和输出校验基础；无完整工具编排、任务状态、提案执行/撤销、成本记录与执行追溯 |
| 加载性能 | 上一轮构建主 JS 约 1.35MB，存在体积提示，按需加载仍待做 |

这些缺口不意味着要先重写技术栈。TS Core、Schema、存储端口、现有 UI/模型调用可继续复用；最小学习闭环不必等待 SQLite、桌面壳、语音或复杂云同步。新增业务对象的持久化/迁移/备份则必须与首期功能一起交付。

## 7. 建议的实施顺序与完成标准

以下沿用既有路线图，不是本轮新开工或时间承诺。

### 第一组：完成必要的底座真实验收

- 用真实 PDF/DOCX/扫描件验收导入、数字/经历、头像、模型与多页打印；分别记录成功与未通过样本。
- 用真实平台链接和多图 JD 验收提取/OCR、失败提示与核对；需要发布时明确 JD 服务运行端。
- 将 JD 建议逐条核对/应用与多简历视图作为简历闭环补项，DOCX/历史链导出按真实使用优先级补；不要求先穷尽模板数量才进入成长阶段。

### 第二组：下一大阶段的主验收——完成一条真实成长闭环

最小范围是：一个目标、一份 JD、一个优先缺口、7 天、3–5 个任务。初期不需要全平台岗位库或海量题库。

1. 用户填写目标、每周时间和约束；读取完整 Fact 与固定版本的 JD。
2. 对话指出一个优先缺口，列出 JD 原句、已有证据与未知项，区分未展示与真实不足。
3. 提出 7 天计划，每项有时长、产物和验收；用户修改/接受后保存正式版本。
4. 提交一份文字讲解或小实验结果，按事先约定规则检查，给出可定位反馈。
5. 分别走通未达标补练、漏学改期和一次复测，保持时间预算。
6. 形成真实证据后提出 Fact 变更；用户确认后才入库并用于目标简历。
7. 刷新/重开后恢复目标、正式计划、下一任务、最近反馈；备份恢复也能重现这些状态。

最小领域对象建议为 Goal/Preference、JdSnapshot/Requirement/Gap、Conversation、LearningPlan/Task、Submission/Assessment/Evidence、Proposal。事实、正式计划和聊天摘要各有主对象，不能全塞进一段聊天摘要或把当前 JD 草稿当成岗位库。

### 第三组：机会库与地图，先有可信数据链

1. 用 3–5 份真实 JD 建立稳定岗位库与收藏，保留来源、分开的时间、缺失字段、原文版本和材料关系。
2. 用同一查询驱动国内/海外二维地图、列表、岗位数和公司数；实际复算多源重复、多地点、受限远程、未知地点、来源失败样本。
3. 再验证一个国内来源和一个官网/海外来源的真实持续更新、关闭/冲突处理，逐步扩大原始来源覆盖。个人收藏是早期原型工作区，正式地图不能永远只统计收藏。
4. 加入投递跟踪与材料版本，之后再按限定平台实施辅助填表/授权提交。

### 第四组：面试、口语、Offer 与插件按使用瓶颈扩展

先文字多轮模拟与测评，再做语音试点；Offer 有真实比较需求时可插入轻量版；OB/VS Code 先择一做用户主动提交证据的入口。与原路线图一致，不一次扩成多个完整客户端。
