# 通用 JSON 地点映射与地区筛选 · 2026-10-22

原 `mapped-json` 只保留字符串地点，对象中的国家、城市、街道和邮编被丢弃。即使上游明确提供国家，来源范围及地图地区查询也可能因此排除岗位。本批增加显式地点子字段配置，并沿用现有来源预览、同步、索引、查询与地址核对工具。

## 实现与边界

- `locationsPath` 支持单对象、对象数组或空路径选择岗位行；子路径相对单个地点，不跨地点组合。未配置子字段保留旧字符串行为。
- 国家仅接受实际 ISO2 目录成员，或由显式 `name` 模式精确解析名称／别名；不从城市、域名、币种或搜索条件推国家。未知国家原文保留。
- `raw` 优先采用配置的原地点文本；缺失时只拼该地点已披露字段。邮编只接受字符串，保留前导零及字符串 `"0"`，数值 `0` 不转换。
- 每字段保留原 selector、原始引用和响应 URL；按实际输出地点序号分组，去重和跳过空值后仍正确绑定。投影优先采用对应序号证据，既有适配器的未分组证据保留兼容行为。
- 严格映射 Schema 与剥离宿主额外选项的 Schema 共享相同校验，来源面板和目录继续正常使用；路径不执行脚本、getter 或原型访问。
- 所有新增字段可选且不插入默认属性，旧解析形状保持；改映射会使旧分页游标失效。原预算、访问策略和明确启用／刷新语义不变。

结构化地址只是来源披露，不产生坐标或办公确认。`jobs.plan-address-enrichment` 可从保存的来源地址继续核对，但不会赋予通用来源“官网”身份或新详情读取能力。远程资格／总部地址不得映射成办公室；通用工作方式映射及其刷新迁移语义留待独立实现，现有远程预设未修改。GitHub JSON 仍为线索，线索接续原岗位的完整工作流继续建设。

输出受既有500条证据及各字段长度限制，很多地点或重复条目可能导致整条记录无效并报告部分覆盖；本批不承诺1000地点无损处理。

## 有限真实接口探测

2026-10-22 对 Bosch SmartRecruiters 公开列表进行单页只读能力探测：

```text
https://api.smartrecruiters.com/v1/companies/BoschGroup/postings?limit=10
```

系统 DNS 路径被现有端点安全检查拒绝（`unsafe-endpoint`，0次请求），未放松检查。另一次明确采用已有 Google DoH resolver 的探测成功：共2次请求（含解析）、28,954字节；返回10条，10条保留国家＋城市，6条有来源 `address` 字段，6条有字符串邮编。`address` 中有仅为城市名的内容，不能将这6条称为道路或精确办公地址。清单未返回任何岗位原链接，未由ID拼造链接；完整度仍为部分覆盖。

本次只证明通用映射能保留真实协议已有字段，不是新增来源配置、完整 JD、岗位入库或市场覆盖验收。私人数据库和运行来源配置未读取／改写，新增岗位和已确认办公点均为0。实际生产接入 SmartRecruiters 应继续使用现有专用适配器取得同ID详情与原始链接。

## 验证

新增适配器测试覆盖旧文本、单／多地点、空路径、跳空与去重后的证据、ISO2与名称、非法国家／路径、getter与继承属性、邮编前导零和零值、配置变化拒旧游标、严格／宿主选项解析。新增应用测试使用真实安装的适配器与内存SQLite，通过来源注册／预览／同步、详情、共享工具及认证HTTP查询，确认国家和城市不能跨地点匹配；来源街址可规划核对，尚无坐标、已确认办公点或可比距离。

8个产品文件的精确树 `8aa569ee515828f1efab776c932e6e02264ba73e` 已独立导出并离线冻结安装：全量 **2846/2846**，失败／取消／跳过／todo均0；类型检查 **10/10**、Lint及构建 **6/6** 通过。快照文件未变，当前产品文件按仓库换行规范后的Git blob均与受测树一致；Windows CRLF转换造成的原始字节差异未被误当源码变更。独立审查曾发现的Zod包装兼容和多地点证据串位均已修正并受新测试覆盖。

运行时原5173／5178保持，不把代码发布当成本机后端已升级。自动化覆盖不替代实际招聘平台全站或地图GPU验收。
