## 地区确认工具与接口

严格共享契约位于 `packages/opportunities/src/location-confirmation.ts`，工具定义位于 `apps/job-service/src/location-confirmation.ts`；Web 与 HTTP 复用相同工具，不为未来 Agent 再实现一套写入路径。

| 工具 | HTTP | 行为 |
| --- | --- | --- |
| `locations.preview-confirmation` | `POST /api/v1/locations/confirmations/preview` | 校验岗位、来源地点归属、当前版本及地区选择，返回原始／当前／拟保存地点和预览指纹；不联网、不写索引 |
| `locations.confirm` | `POST /api/v1/locations/confirmations` | 重交完整预览输入、`previewFingerprint` 与 `reviewed: true`，追加地区确认决议，原子保存投影和耐久回执 |
| `locations.revoke-confirmation` | `POST /api/v1/locations/confirmations/revoke` | 提供岗位、地点、目标 `decisionId`、当前版本、说明与 `reviewed: true`，追加撤销决议，恢复上一条有效选择或来源地点 |

预览输入为 `{ jobId, locationId, expectedRevision, proposal, reason }`。`proposal` 仅接受地点性质、国家代码与行政范围；地点性质为 `office | remote-region | unknown`。输入不接受任意坐标、来源证据、核实状态或客户端指定的决议身份。

国内行政选择使用 `china-catalog` 的省、市、区县代码，服务端从固定目录解析名称、上级关系、目录版本和省域标识，并校验目录 SHA-256；客户端不能提交自称可信的目录名称或来源。目录沿用 2023 年统计区划快照，部分末级为镇街／功能区，不声明为现行行政权威。只确认国家或使用海外地点时可提交 `manual-area` 的明确文字范围；国家代码仍须在项目目录内。

确认绑定完整输入、原始来源地点、解析后的行政范围及当前 revision。版本或预览指纹不一致会拒绝写入。地点须能明确归属于该岗位的单一来源贡献，并有对应来源观察证据；模糊或缺失归属不直接覆盖。

写操作需要本机认证、允许的 `local-write` effect、执行身份与 `Idempotency-Key`。SQLite 先检查同身份／工具／幂等键的原请求指纹及回执，再检查新写入的当前版本。因此丢失响应后可以用完全相同的 body、旧 revision 和 key 取回原回执；同键不同内容冲突。撤销须由原确认执行身份发起，保留目标决议和撤销说明，不删除确认历史。

## 来源、位置精度与备份边界

地区确认存为独立的追加决议。`base_locations` 保留来源地点，`location_decisions` 保留确认／撤销历史；当前查询、筛选和详情使用投影结果。来源地点原文及证据不被改写，也不会把“本人确认”提升为“来源已核实”。投影带 `userResolution`，可追溯决议、时间、原地点身份和选择依据。

本批只保存行政范围，**不生成、不继承办公坐标**。确认后的精度仅为 `country | region | city`，即使选择了区县，也不声称已经核实街道或办公室。来源若原有坐标，本次地区确认的投影会移除坐标及其解析元数据；撤销全部相关确认后恢复来源地点，包括来源原有的坐标。`remote-region` 始终表示远程资格范围。

因此，确认“中国／上海市／浦东新区”可以用于国内和省市区过滤，但本身不会增加“已定位岗位”，不能生成离家距离，也不会在地图上画一个自称精确办公地址的点。既有 `locations.geocode-candidates` 仍是独立的城市参考点查询：用户另行明确选择后只用于本次地图浏览，不写回岗位地址或本批决议。

SQLite 仓库与完整备份格式升级为 V3。V2 数据库升级时以原地点初始化 `base_locations`，保留已有行和索引 revision。V3 完整仓库备份新增 `baseLocations` 与 `locationDecisions`，并保留原有来源、岗位、归并历史、任务和耐久回执；旧版备份仍按各自版本规则校验。

恢复先校验来源引用、决议次序与执行身份、撤销目标、可信目录解析结果，再从原始地点重放地区确认和岗位归并；重放结果必须与备份投影及相应历史回执一致。伪造地区名称、来源原文、投影或回执会被拒绝，现有仓库由事务保护。公共数据集导出用于读取当前投影，不能替代包含决议和回执的完整仓库备份；普通来源导入也不能伪造 `userResolution`。确认归属于来源地点贡献，岗位归并／拆分不把该选择转移给其他来源地点。

## 本人核对界面

真实本机连接下，岗位详情新增地区核对入口。面板展示来源地点原文与当前行政范围，再选择地点性质、国家和地区。国内按省→市→区县级联，上级变化清除下级；切换国家清除旧的国内选择或海外文字。旧来源没有提供地点性质时，默认保持“尚未确认性质”。仅披露上级范围时可以停在该级，不要求补造下级地点。

“核对依据或说明”必填。用户点击“预览地区变更”后，面板显示实际拟保存范围、索引版本和精度警告；独立勾选确认后才能点击“确认保存地区”。修改草稿会使旧预览和勾选失效。撤销当前确认使用自己的勾选与说明，不能沿用保存时的确认。

请求等待带处理中状态，25 秒后停止等待。响应丢失时保留原写入并提供“重试本次地点写入 · 核对回执”；外部 revision 前进不会更换这个未确认请求的 body 或 key。明确陈旧／无效拒绝会清除旧写入和预览。已经取得成功回执但快照读取失败时保留已保存版本，只重试“重新读取索引”。关闭、卸载以及地点／岗位／端点／令牌变化会中止等待并隔离迟到结果；停止等待不等于数据库回滚。

客户端同时校验预览的 revision、岗位和地点，以及写入回执的岗位、地点和版本，避免将其他请求的有效结构当成本次成功。入口和面板的真实运行验收状态见下文，不能仅凭合成测试宣称用户数据闭环已通过。

## 猎聘薪资读取与有限真实证据

本轮检查当前可见 DOM 后，猎聘增加精确字段选择器：

```css
.jobDetailBox > a > div > .jobTitleBox ~ span._40108qjbMk
```

当前结构中薪资位于标题后，有时中间插入“急聘”标签，因此使用带准确薪资类的后续同级元素；不使用任意相邻 `span`，也不从整张卡片正则猜薪资。既有专用薪资选择器继续保留。此类名随上游构建可能变化，未读到时仍保留未知，不把招聘者活跃时间、学历、经验或标签误写为薪资。

主 UI 在真实本机猎聘 `C# / 上海` 当前页读取返回 **22 张卡片**，目标岗位“高级 C# / .NET 软件工程师”现在独立显示 `15-30k`；原文的“2天前在线”保留为招聘者状态，不作为岗位发布时间。目标原岗位为 [猎聘 1985706689](https://www.liepin.com/job/1985706689.shtml)，雇主与地点沿用此前核对的来源记录。

对同一岗位再次预览、明确审核后更新到统一索引，**revision 23 → 24，岗位总数仍为 50**。这次是已有岗位补充来源薪资摘录，没有增加重复岗位。薪资仅保留原文与逐字段证据，不从 `15-30k` 擅自推断币种、税制、发薪周期或月数；统一税前年薪仍须满足独立的可比较薪资契约。

22 张是本次当前页读取数量，并不证明全部卡片的薪资字段都逐一核验，也不代表猎聘全市场、其他地区或其他平台已全量接通。51JOB、BOSS、更多 LinkedIn 地区和完整 JD 覆盖仍按原有未完成项继续。

## 真实地区确认的有限闭环

使用同一张猎聘来源岗位，而非新增合成位置：

1. 先将目标 `15-30k` 原文重新审核入库；索引保持50岗，revision由23前进到24。
2. 在原数据库完整备份之外建立独立克隆，实际升级到V3并检查所有来源数据、岗位数量和revision不变，`quick_check`通过。
3. 更新自有本机岗位服务后，在目标地点点击“核对并保存地区”，对照原文选择中国、上海市与浦东新区，保留明确核对说明；经预览和勾选保存，回执revision25。
4. 切换国内并使用上海／浦东条件，目标岗位可检索；有效字段带本人确认标记，原始“上海-浦东新区”与来源证据保留。未产生坐标，位置仍不计为已定位，也没有离家距离。
5. 安全重启该本机服务后重新读取，revision25的地区确认保留；证明它已持久入库，不只是当前页面状态。
6. 再明确撤销该条确认，回执revision26，恢复原来源的未知国家／行政字段。明确国内／地区条件不再匹配该岗，验证筛选确实依赖有效证据；全球视图原文检索仍可访问它。岗位总数50不变。

这是一次实际来源地点的可逆写入验收。后续重新确认会继续增加revision，以上数字是各操作时点，不能被描述为永远固定的当前版本。撤销使已选岗位退出当前筛选时，详情面板原先可能保留缓存地区；`d450d5d` 已清除选中岗位、旧详情和定位，并在面板外保留更新回执提示。两个新增回归分别覆盖主索引刷新，以及实际地区组件的撤销→新快照→退出国内筛选→全球重新打开新详情。最终独立1916项检查通过，不能将此前1914项当成这两项收尾的结果。收尾后原页面实际恢复50岗／revision26、C#14个文本命中／9家企业，目标薪资原文15-30k可见，未新增坐标；自有原站浏览器会话均已结束。

独立产品树的冻结离线依赖安装、类型检查、lint、测试和构建均实际完成。原站读取、数据库克隆升级、真实确认／撤销与服务重启是额外有限实证；这些证据不代替更多平台、所有地理范围、精确办公地址或大规模性能验收。
