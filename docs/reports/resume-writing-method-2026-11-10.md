# 简历写作：从岗位定位到一条有依据的贡献

2026-11-10 · BetterMe `agent-os` 工作区。本文只保留可复用的判断和合成样例，不保存来稿、联系方式、雇主材料或作者样例的原文。来源与各自的适用范围见[四份内置写法参考与两位工业工程师的公开简历](../research/resume-writing-exemplars-2026-11-10.md)。

## 实际怎么用

在**简历工作台 → 简历伴写 → 检查当前简历**看两级反馈：全篇建议读当前版本的可见投影，不需要模型；单条批注则针对某个可编辑字段。打开批注中的**一起完善这条经历 → 看参考写法**，可以读一条虚构的完整示范和四份外部参考。只有自己主动打开链接才会访问第三方；示例不进入模型输入、事实库或候选草稿。

| 想改善什么 | 已接入的行为 | 边界 |
| --- | --- | --- |
| 第一页先讲什么 | 全篇检查提示经验型简历中冗长且重复技术词的开场；顾问会区别社招、在校与转行，围绕目标岗位挑证据。 | 不固定一页，不给所有人套同一顺序。仅看到单句或摘要，不会据此断言实际 PDF 的页数和分页。 |
| 标题和项目是否对得上 | 检查「全栈」职称所在经历有没有前后端交付线索，简介里的 AI 声明是否在可见项目中有对应动作；可定位到相关段落。教育未识别只给条件性提醒。 | 文字启发式不是能力认定。正式职称不擅改，隐藏材料不代表没有该经历，原型不推成生产使用。 |
| 把职责写成贡献 | 顾问、岗位定制与单字段伴写共用按范围裁剪的写作方法；笼统结果先问机制，有真实记录才写改善幅度。离线 JD 比对不再用预置 JD 或轮流挂接事实编号来制造“已验证”的匹配。 | 单条伴写无本人补充只追问。候选仍需本人核对、再明确采用；建议不是写入或独立事实核验。 |
| 不把好看的话写成假事实 | 单条候选校验原文引用、常见数字及单位、显式团队与本人归属、部分否定/未知/上线表述；无依据则不出示可采用的候选或直接提示拦截。 | 窄规则不能理解所有自然语言；即使规则放行，也需逐句核对。模版、JD、团队材料不能充当本人的证据。 |
| 导出时经历不被拆坏 | 主预览的打印规则把公司标题、引导标签和第一条正文尽量留在同一页，后续条目仍可跨页；按钮与帮助说明给出关闭浏览器页眉页脚的位置。 | 主预览走系统打印框，网页不能代为关闭浏览器日期和网址。最终以所选模板、浏览器、纸张和预览为准。 |

## 一条原文有两种正确的处理

假设原文是「维护导入工具，提升数据质量」。

- **只提供了原句：**问「工具校验什么？遇到不合格的数据，用户会看到什么？」不先猜功能，不给出候选。
- **本人确认**「我为导入表校验必填列，缺列时返回列名」：可整理为「为导入表校验必填列，缺列时返回列名。」这条已经写清交付物和可观察行为；没有必要再加“质量显著提升”。

这里的“学习”是把编辑判断放到运行时代码、离线检查和回归用例中。没有微调模型，没有抓取或导入商业模板，没有把个人简历加入任何训练集。候选人的项目、指标和学历仍由本人提供。
