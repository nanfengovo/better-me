## 交付行为与使用流程

- **提取岗位正文**保留静态入口，核对受支持来源、重定向和岗位身份。静态 HTML 中没有 JD 时明确说明，而不把 HTTP 200 当成正文成功。
- **浏览器读取 / 打开独立浏览器**使用本机工具专用可见 Edge，通过 `POST /api/jd/browser-session` 执行 start → read → close。明确登录或验证门槛时保留原岗位页，由用户在网站自行操作，再点击“完成后读取原岗位”。
- 各平台有独立持久 profile 和空白基础页，每个岗位租约使用独立子页。普通取消、读完、换链接、关闭面板和到期释放对应岗位页；显式关闭招聘浏览器及服务退出关闭工具浏览器，保留磁盘登录状态。
- 单个岗位默认最多 10 分钟，提供显式延期入口；start 最长 30 秒、read 最长 45 秒。读取超时保留可接续页面，不把超时直接当作浏览器已经关闭。启动回执支持启动响应丢失后恢复原租约，重复请求不额外创建岗位页。
- 关闭失败继续跟踪原 owner 并允许重试；未确认退出不报告成功或争用同一 profile。自有空闲浏览器仍在而调试连接断开时可恢复连接，旧调用的迟到网络结果不能影响新岗位。
- 读取正文进入待核对预览，用户确认后才使用；不会自动覆盖 JD 或个人事实。兼容自动入口 `POST /api/jd/extract` 的 `mode:browser` 仍保留，服务端最长 60 秒、客户端 65 秒。

工具登录资料位于 Git 忽略的 `data/recruitment-browser/<平台>/profile/`。不复用日常浏览器 profile，不导出私人 Cookie，不自动完成验证码、同步账号或发起投递。窗口运行在本地服务所在电脑，仅本机同源工作台可操作；远程部署不等于能控制访问者的本机浏览器。网络配置改变后需显式关闭再重开，避免打断活跃验证。

## 引擎选择与正文采用条件

最终路由在 start 前按精确来源选择：移动 `msearch.51job.com` 继续使用已通过实站的 standard 路径；精确 HTTPS `jobs.51job.com/<单层非 jobs 目录>/<数字 ID>.html` 详情使用 native；BOSS、猎聘使用各自的原生路径。read 失败不自动切换引擎，已有会话与启动回执保留其原后端。

native 使用普通 Edge 及有限 CDP/DOMSnapshot，不启用 Runtime 求值。HTTP 响应地址与同一 loader 的逻辑 URL 分开保存，支持同一 Document 的 history 地址变更，同时保留来源、loader 和正文可见性检查。移动 51job 的未验收 scope/geometry 扩写未被采用，没有放宽全局 visibility 来取得正文。

正文必须来自当前原岗位及已提交文档，可见内容、岗位身份、主文档响应和稳定性均通过才采用。排除隐藏祖先、推荐区、表单值和脚本；JSON-LD 需要可见正文印证。BOSS 自然页面响应仅作为受限被动后备，要求原岗位 ID、当前文档及完整可见正文一致，不主动调用私有接口，不用隐藏数据补齐不可见 JD。折叠正文的自动展开只针对已确认结构，仍重新核验全文。

## 网络适配的实际范围

国内三站的独立 helper 绑定物理接口及独立 DNS，监听本机 loopback，招聘域族及已观察到的精确资源主机允许 DIRECT，其余 REJECT。验证组件按平台和精确 HTTPS 443 主机适配，没有开放云服务父域或任意租户；网站是否接受登录或验证仍由网站决定。脚本与配置边界见 [domestic-route 使用说明](../../scripts/README-domestic-route.md)。

`jd-managed-browser-proxy.ts` 对已审查的本地 helper 做只读身份核验，包括固定 EXE/完整配置散列、候选 manifest、进程创建及命令、loopback listener 归属和检查前后文件身份。当前实现固定本机接口条件和 manifest 身份，只服务本次受管环境；新机器、接口、端口、配置或 manifest 不会被自动信任。公开代码和脚本不构成即装即用的通用代理支持，不能通过放宽核验来获得通过。

helper 核验只证明该时点启动归属和未变的磁盘启动配置，不查询进程内存规则，也不证明岗位已读取。原生浏览器里的 iframe、worker、SW、WS 依赖 helper 既有允许规则与最终 REJECT；该范围包含三站域族，不等同于单平台网络沙箱，更不等同于所有协议/UDP 隔离。Playwright route 对后续重定向并非逐跳全部覆盖，最终来源拒绝不能被描述为每次联网前均已阻断。

## 保留的失败历史与结论

| 阶段 | 真实观察 | 保留的边界 |
| --- | --- | --- |
| 静态提取 | 51job 返回带 WAF 标记的 HTTP 200；BOSS 返回空应用壳；猎聘返回脚本中转 | 收到响应不等于取得 JD，静态解析不执行网站动态页面 |
| 早期持久会话 | 猎聘首次 2263 字符成功，15/30 秒后 blank；BOSS 两次仍需验证 | 持久 profile 本身没有解决空白或平台验证，不能用缓存旧成功覆盖当次失败 |
| 原生 strict 实验 | worker 策略被 Edge 拒绝，同进程 iframe WebSocket 仍出站 | strict 方案未启用；合成通过不足以证明真实出站约束 |
| 新桌面 51job 早期测试 | 工具曾阻止精确验证资源；补齐后出现 HTTP 200、空资源错误列表，但仍需验证，人工操作后仍“验证失败，请刷新” | 资源允许、请求传输完成和网站验证通过是不同状态，未取得站方 WAF 日志，具体拒绝原因未知 |
| 有限验证传输诊断 | 同页三个初始化/上传/设备 XHR 均 request → response 200 → finished，门槛仍存在 | 只记录固定 host/type/本地序号/状态/相对时间，最多 32 请求/128 事件；不保存 body、query、Cookie 或验证码参数，不能判断响应体业务结果 |
| native 51job 首次启动 | 岗位导航前出现 Edge 首次设置，返回 `browser_setup_required` | 浏览器初始化待用户处理，与岗位验证码失败分开；后续用户完成后复用原窗口 |
| native 移动原岗 | 先为 `frame_url_mismatch`；修复地址关联后又为 `snapshot_visibility_unsupported / overflow_clip_or_scroll`，read 仍 422 | 当时没有正文成功；最终恢复已验 standard 移动路径，native 仅选择精确桌面详情 |
| 工程检查中途失败 | 编辑期间曾有散列 pin 未冻结导致测试失败、隔离构建首次缺入口、实验初始化及超时失败 | 原始失败与修复后的最终检查分别归档，未把首次失败改写成通过 |

阿里云公开 WAF 文档描述 WebDriver 相关检测字段，并不能证明本次拒绝就是该原因；多个条件同时变化后的单次 native 成功，也不构成唯一因果证据。最终四岗通过覆盖上述对应样本的当前读取结果，保留各历史失败发生的事实。

## 自动检查与本地实验

实现分批通过真实本地 HTTP/HTTPS/CONNECT、Edge 生命周期和 source/loader/可见正文等回归。本地 managed-proxy 实验覆盖指定允许/拒绝的 HTTPS/WSS、worker/iframe 及明文 HTTP；指定禁止源命中为零，清理确认。它没有验收真实网站验证或招聘全文。

native 51job 集成阶段全量 **1038/1038**、lint、types **5/5**、build **3/3** 通过。最终地址关联修复候选 **306** 项、独立额外 **6** 项及主仓库 **299** 项通过；移动/桌面路由候选与独审各 **46** 项、主仓库 **61** 项、server 类型及全 scope lint 通过。以上均为相应阶段记录，不能当作所有后续改动的同一轮全量结果；既有大 chunk 提示保留。

真实验收时先精确关闭旧岗位页、确认工具浏览器释放，再按进程身份停止旧服务，只加载已审差异并核对运行源码、首页/组件及 helper，随后执行四岗实测。公开摘要省略机器进程、会话及启动流水；完整 manifest、冻结清单、检查日志、采用记录和读取收据均在本地忽略归档。工程检查、部署核对和实站读取分别作为独立证据。

## 通用复现概要与后续边界

1. 使用 Windows、本机 Edge 和本地服务；先阅读 helper 的本机适配限制。准备已审查的网络配置后，在工作台打开受支持的具体岗位链接。
2. 点击浏览器读取；出现首次浏览器设置、登录或访问验证时，在保留的同一窗口自行处理，再显式读取原岗位。不要把端口可达、HTTP 200 或空错误列表当作正文成功。
3. 核对原链接、标题、职责/要求、截断或折叠状态。读取成功后间隔至少 15 秒再次读取，比较全文并确认关闭；每个新岗位分别建立基线，不套用旧字数或散列。
4. 只在待核对预览确认后采用 JD。遇到来源不符、页面不可见、验证未完成或不支持的布局，保留失败说明，使用粘贴/截图入口也不能算作该链接已读通。

当前交付完成指定四岗的实际读取与关闭；多岗位覆盖、全部布局、长期稳定、真实多窗口并发及跨服务自动接管仍需单独实现或验收。未进行私人简历匹配、AI 生成、自动投递，也未证明任何平台的登录和验证可以永久免除。
