## 本阶段实际改动：R3

`apps/agent-host/src/kernel/evidence-retrieval.ts` 为内核内部的纯本地 Module，不读文件、不联网、不生成摘要，也不增加外部依赖。

1. 在**已收集且获准的原文**上做无损段落分块，偏好空行/换行边界。长单行明确分成可寻址片段，CRLF 与 UTF-16 代理对边界保留；存储原文不变。不会为粗排自动扫描整个授权目录。
2. 使用 JD 标题、正文及当前目标做 BM25 粗排（k1=1.2，b=0.75），支持拉丁技术词及中文双字片段；按查询覆盖度再排序，确定性去除相同来源/版本/偏移的重复片段，默认装入 Top-6，每片最多 2400 UTF-16 单元。
3. 完整本人陈述/纠正与最近一次明确 `read_evidence` 请求页额外挂载，不因排序排掉。完整原始证据、观察及回答不会由工作集替换；manifest 元数据完整列出未挂载来源，`indexTruncated:false` 只表示索引完整，不宣称全文都在当前 Prompt。
4. 每个实际挂载片段在模型调用前持久化其精确 ID/文本/坐标。私有任务记录保存已暴露 ID；模型引用仅允许实际挂载过的片段，不能将 manifest 句柄或只见于索引的整份来源当成已读证据。
5. `read_evidence` 接受任务中现有证据 ID 或 `ref_` 句柄，支持绝对 UTF-16 offset/length，并返回下一页坐标。没有明确行范围时默认页长 2400；指定行范围继续按原行读取。范围并非完整来源的替身。
6. EvidenceBroker 为目录/精确文件读取和搜索结果增加原始文本的 `startOffset/endOffset/sourceLength`；保留全文件 hash，使用原始 CRLF 原文而非重组换行。句柄回读重新检查授权与来源 hash，不允许借句柄跳到另一目录/任务的未授权材料。
7. 每次模型发送前重新核验 Broker 来源版本，校验读取仍扣原任务 toolCalls。来源变更先暂停，不把旧摘录交给下一轮模型。事件 detail 也完整保留，不再裁到 1000 字符。
8. 历史记录若只有行号而没有绝对字符坐标，完整保留在 manifest，并标记 `coordinateRereadRequired`；不会以 offset=0 伪造可排名片段。重新读取校验相同 hash/原文后才补齐坐标，同一证据 ID 不重复或替换原文，随后才可挂载/引用。

这替换的是**内核 Prompt 的隐式全量装载策略**，不是裁短 Agent 输入输出、历史或原文存档。模型收到显式的检索策略、完整句柄目录及当前可引用 ID。模型输出及原生传输限制保持明确失败而非静默缩短。BM25/覆盖度排序不等于语义事实核验、Embedding 模型或真实写作质量提升。
