## 产品边界

- 记录 JSON 不包含未发送草稿、模型凭据和服务端完整会话。浏览器 origin 与 Agent Host / Docker 数据卷分别备份，不提供云同步保证。
- 项目背景、实际实现证据、设计意图和个人贡献分开确认。代码出现某项能力不证明该用户实施或上线，也不推断客户真名。
- 选择模型或工具不启动调用。运行期间禁止更换项目阅读工具；未兼容或未安装的工具显示不可用，默认容器不会继承宿主机 CLI。
- 不自动修改自动保存偏好，不自动切换付费 API，不因收起/切页取消任务。关闭浏览器后前端任务的持续运行不在承诺范围。

本地定向回归覆盖侧栏连续性、备份去重与冲突、共识版本、贡献私有字段隔离、读取预算与清单复用、存储断连恢复。全工作区测试初轮 3,581 通过、0 失败、10 平台/环境条件跳过；发布快照与 Docker/CI 结果另在发布说明记录，不能用混合工作区结果代替发布快照。

只含本次暂存文件的独立发布快照：全量 3,575 通过、0 失败、10 既有平台/环境条件跳过；生产构建 8/8、类型检查 13/13、运行时检查 6/6、零警告 lint 与 memory 检查通过。备份、侧栏和存储恢复最终定向回归 19/19。上述浏览器回归与这些自动测试分别报告，不冒充真实模型调用或本机镜像更新。

本机 Docker 初轮因宿主机 `ENOSPC`、BuildKit 提交层 I/O 错误而失败，未把该次尝试当作成功。用户随后授权清理旧构建与未使用内容：移除已核对的旧 Vite/Turbo 缓存、pnpm 未引用包和元数据、超过 24 小时未使用的 Docker 构建缓存（20.42 GB），以及两个没有容器引用的旧 BetterMe 验收镜像。原源码、归档备份、业务镜像、23 个原容器和 14 个原数据卷全部保留；未执行全局容器/镜像/卷清理或恢复出厂。

恢复引擎后，从同一独立发布快照完成 Linux ARM64 静态与完整运行镜像构建。静态镜像实际通过 409 次 HTTP/资源/许可证检查；完整镜像在随机命名的隔离 Compose 项目中通过启动、认证/来源、项目理解授权与撤销、会话/SQLite/令牌持久化、进程崩溃恢复与容器重建。脚本仅清理自身创建的容器与测试卷，没有调用模型、读取宿主机源码或连接现有岗位卷。这是本机验收；对应新 HEAD 的远端 CI 仍须独立核对。

发布快照使用独立源码与同锁文件依赖进行检查，岗位采集脏文件不进入该快照。宿主机空间故障不是代码测试失败，不以删测试、放宽门禁或混入其他改动修复。
