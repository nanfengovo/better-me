# 官网原岗精确读取与地点核对

已有岗位补地址时，原流程重新列举来源的有限前若干条，再按原编号与链接寻找目标。原岗不在本次列表范围内时，即使原链接仍有效也可能遗漏。本批增加精确原岗读取，不扩大默认采集范围。

## 共享工具与已支持协议

三个共享工具分别负责外部读取、只读预览和明确审核后的本地保存：

| 工具 | HTTP 路径 | 效果 |
| --- | --- | --- |
| `jobs.read-owned-detail-locations` | `POST /api/v1/jobs/owned-detail-locations/read` | 按索引已有身份读取原岗 |
| `jobs.preview-owned-detail-locations` | `POST /api/v1/jobs/owned-detail-locations/preview` | 比较来源地点，返回绑定版本的预览 |
| `jobs.import-owned-detail-locations` | `POST /api/v1/jobs/owned-detail-locations/import` | 经勾选确认，只保存该 listing 的地点贡献 |

输入使用规范岗位 ID、原 listing ID 与索引版本；实际 URL、来源配置和原岗位编号由后台读取。调用方不能以任意 URL 替代目标。

当前实际实现精确读取的协议为 **JobPosting JSON-LD** 与 **SmartRecruiters**。前者读取原持有网页并核对同源、路径及结构化岗位身份；后者读取既定租户的原 posting API 并核对编号、引用与原公开链接。均沿用来源权限、请求预算、时间预算与访问策略，不从旧记录拼接缺失字段。其他适配器继续原有限线索能力；缺原岗位编号的 listing 不标记为支持精确读取。

## 审核、保存与恢复

读取后的 capture 由宿主瞬态 HMAC 绑定岗位、listing、来源指纹、记录、观察时间、session 与读取序号。它证明本宿主读取结果的完整性，不证明雇主已核实办公关系。网络返回后再次检查版本和目标，防止迟到结果覆盖变化后的岗位。

网页展示来源、原链接与地点证据，预览后独立勾选才能保存。保存只替换该 listing 的地点贡献并追加摘录观察，保留 JD、快照、薪资、企业、工作方式、其他来源贡献及 `recordLastSeenAt`。没有有效地点不能删除旧地址；远程资格范围不成为办公室。按地点关联的薪资不能被静默孤立，来源搬迁后旧办公确认失效，A→B→A 不自动复活旧确认。

同宿主已保存的较新读取阻止旧 capture 回盖，包括同一毫秒内的两次读取。重启使未提交 capture 失效；已经提交的相同请求可用原幂等键恢复耐久回执。提交后响应丢失时，网页保留原请求与键重试；取得回执后只重读索引，不再外读或重写。

## 验证与限制

适配器全套 330/330、后端新工具 18/18、后端连地址计划 29/29、独立后端与地址 UI 44/44，以及客户端／地址 UI 34/34 均在各自时点通过；范围重叠，不累加为总测试数。独立暂存树 `9195a57f50e1d760159d6c9bf205f2e85fe52ae4` 完成 **2566/2566 全仓测试、10项类型任务、Lint、6项构建和隐私检查**；随后同源宿主配置补修的最终树完成2567/2567。不同树与定向数字不相加。产品 `e873168` 已按功能推送，GitHub Actions `39605053370` 的质量、Linux 构建、Docker HTTP 与 Pages 部署全部成功。

关键 Web 回归使用真实 React → 严格客户端 → 隔离认证 HTTP → 真实应用工具 → 内存 SQLite，外部公开页面以固定响应替代。原岗位于来源单条列表预算之外，仍仅 GET 原链接一次；读取不改库，明确保存仅改地点。模拟数据库提交后丢失 HTTP 回执，原 body/key 恢复无第二次外读或写入；原 JD、快照、薪资、企业及抓取时间保持，地图已定位数仍 0。

这不是所有官网的通用完整抓取器，也不自动产生坐标。真实索引当前仍为 **89 岗、revision 85、18 份来源街址、0 已确认办公点**；本批未据此声称新增真实地址或接通高德。完整备份并确认无运行任务后，原岗位服务已更新。实际同源 HTTP 地址计划识别到3个精确原岗目标；分别对已有 JSON-LD 原岗和 SmartRecruiters 原岗提交一次只读请求，均返回 HTTP504／`timeout`，没有成功 capture，未预览导入或新增来源地址。两次前后快照 SHA-256、令牌保持，SQLite V4、quick_check与外键检查通过，办公确认仍0。该运行证据证明工具已接通和故障正确暴露，不能声称官网实时读取或坐标补齐成功。
