# 岗位地图：轻量浏览、后台完整查询与单岗证据懒加载

日期：2026-11-17。分支：`agent-os`。本文先记录功能实现与验收阶段；当时尚未提交或推送，并保留工作区已有的采集、回执和视觉兜底改动。后续发布前复核见文末。

## 结论与范围

针对截图中分页读取停在 `3,958 / 8,047`、整库反复处理带来的卡顿，新增与完整备份分离的浏览路径。真实公开岗位库只读验收已完整获得 8,047 岗，C# 全文查询、当前页顺序和地图桶与原完整查询一致。

这一轮解决的是完整性、重复传输和前台重计算，不宣称所有冷启动或 3D 渲染性能问题均已解决。真实首次读取和首次查询仍有可见等待；未测得可对比的真实用户 INP、地图拖动 FPS 或同场景前后内存峰值。

没有重新采集平台、调用模型、改变登录状态、写入真实岗位或简历、重启用户现有窗口/服务。真实验证使用 `readOnly: true` 的独立 SQLite WAL Worker，关闭后台补全且只允许公开读取工具；验证结束后只关闭本轮创建的服务与窗口。

## 实现

1. 后台新增已鉴权的 `/api/v1/atlas/browse`、`query`、`penetration`、`detail` 四个接口，复用既有 Origin、令牌、只读工具与独立计算通道。
2. 浏览投影保留岗位事实、来源链接、证据引用、发布时间及其冲突信息。整库 JD、历史快照正文、诊断告警、证据摘录/选择器不传给列表和地图；这些内容仍完整保存在原库中。
3. 浏览投影带 `view: "browse"` 标记，严格完整数据导入契约会拒绝它。原完整快照、备份、采集和入库接口保持原有语义和字节预算；没有通过提高 96 MiB 上限掩盖问题。
4. 查询和关键词规则在后台捕获的完整索引上运行，返回全量统计/地图和真实当前页。因此未下载到页面的 JD 正文仍能被搜索命中，翻页和选中地址不会把全图缩小为当前页。共用同一份分页和关键词规则实现。
5. 小批更新仅传变化实体；无变化仅返回版本标识。保留现有 Worker 分块确认、观察者取消、共享计算及背压机制，浏览投影解析、索引和几何准备不回退到浏览器主线程。
6. 打开单个岗位才读取该捕获版本的完整证据。切换岗位/版本/连接或关闭时取消读取，迟到结果不能启用另一岗位的操作。读取中或失败时收藏、分析保持禁用。
7. 浏览句柄按仓库 epoch 与 revision 捕获并限制缓存数量，同一修订的并发读取复用身份。浏览系列固定到同一个只读 Worker，并计入该通道负载，让其他状态读取能选择另一通道；版本过期显示重新读取提示，不悄悄用空 JD 本地搜索。
8. 增量协议拒绝重复 upsert、重复 delete、重叠删除、非法版本及悬空引用；旧服务只有明确 404/405 才协商回原路径，错误成功信封不会被当作旧服务吞掉。
