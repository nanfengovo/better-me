## 结论与审查范围

当前已有薪资年化、外币换算、最终控股分类、配置化配色及网页筛选的计算基础。主要缺口是让真实用户带着来源依据核对字段，并通过预览、明确确认、持久保存、撤销与重新计算完成闭环。继续增加筛选控件或合成样本，不能补足真实数据缺少的证据。

本次只读核对领域契约、来源投影、服务工具注册、HTTP 路由、Web 查询与详情操作。没有读取私人岗位库，没有新增真实岗位、调用外部 Provider、调整服务或执行产品验收。本报告不提供当前真实数据覆盖数；既有合成回归不能证明真实岗位普遍具备薪资或控股依据。

| --- | --- | --- |

## 薪资：计算有效，真实字段核对链路缺失

[薪资契约](../../packages/opportunities/src/schema.ts)（审查时第 214 行）区分原文、币种、金额范围、周期、税前／税后、固定工资／奖金／股权、年化参数、地点范围、证据及验证状态。

[normalizeCompensation](../../packages/opportunities/src/compensation.ts)（第 115 行）保留来源披露，不混合奖金、股票或税制猜测。第 140 行起依次检查冲突或未知验证状态、绑定原文段落或结构化字段的证据、固定工资、税前口径、金额及币种。月薪需要明确发薪月数，或以单独的估算标记采用 12 个月；小时、日和周薪需要各自的年化参数。来源状态为 `unverified` 本身不等于完全不可计算，缺少明确工资组成或税前依据才是常见阻断条件。

真实输入目前主要保留披露边界：

- [四平台受审卡片导入](../../apps/job-service/src/reviewed-cards.ts)第 59 行只保留薪资原文，`period`、`tax`、`kind` 均为 `unknown`。
- [旧机会库投影](../../packages/opportunities/src/legacy.ts)第 244 行采用相同策略，不猜币种、发薪月数或税前口径。
- [Lever](../../packages/source-adapters/src/adapters/lever.ts)第 41 行可保留币种、金额及周期，但 `tax`、`kind` 仍未知。
- [Ashby 薪资分项](../../packages/source-adapters/src/adapters/ashby-fields.ts)第 81 行可保留金额、币种、部分年周期及固定工资／奖金／股票分类，`tax` 仍未知。
- [JobPosting JSON-LD](../../packages/source-adapters/src/jobposting-jsonld-reader.ts)第 170 行主要保留 `baseSalary` 原文，未全面解析其中金额、币种及周期。

[岗位详情](../../apps/web/src/components/atlas/AtlasJobDetail.tsx)第 108 行能显示“来源薪资已披露 · 年薪口径待核实”，并显示原文与可用的汇率日期；当前没有“核对薪资”入口，也没有逐项解释缺税前依据、缺发薪月数或薪资范围冲突的操作面板。

[服务注册](../../apps/job-service/src/application.ts)与 [HTTP 路由](../../apps/job-service/src/http.ts)没有专用薪资核对、确认或撤销能力。已有通用 `jobs.import-public`，所以底层并非完全不能导入薪资；但修改完整公共 JSON 再导入不是受审字段修正流程。[仓库合并](../../apps/job-service/src/repository.ts)的 `compensations` 分支还会拒绝同一薪资 ID 的原地改值，应采用独立决议与有效投影保留来源数据。

## FX：宿主注入和网页查询之间存在断层

[FxSnapshotSchema](../../packages/opportunities/src/compensation.ts)第 11 行包含快照 ID、Provider、日期和原币到 CNY 的汇率。换算函数会拒绝缺失、未来、过期或缺币种的快照。当前快照契约没有原始数据 URL、读取时间、内容哈希或独立 evidence；它能够重现数值，但完整出处追溯仍需设计。

[QueryOptions](../../packages/opportunities/src/query.ts)允许传入 FX，并将快照纳入查询指纹。[应用工厂](../../apps/job-service/src/application.ts)第 65 行和第 122 行提供宿主 `resolveQueryOptions` 钩子，但 [正式服务启动](../../apps/job-service/src/lifecycle.ts)第 210 行没有接入 FX 配置。当前也没有 FX 列表、导入、激活或读取工具及 HTTP 端口。

Web 使用 [queryAtlasPage](../../apps/web/src/components/atlas/client.ts)第 93 行在浏览器中执行领域查询。真实模式读取公共数据集后，仍通过这条路径搜索，而不是直接复用带宿主 FX 的 HTTP `jobs.search` 结果。

[AtlasWorkspace](../../apps/web/src/components/AtlasWorkspace.tsx)第 157 行的覆盖统计与第 181 行的查询选项都没有传入 FX；[公共数据集](../../packages/opportunities/src/schema.ts)第 388 行也没有 FX 字段。因此，仅给后端注入汇率可能形成“后端可换算，网页仍提示缺有效汇率并禁用筛选”的不一致。

后续必须让覆盖统计、筛选、排序、分页及详情使用同一份可识别的有效快照。可通过独立的同版本查询上下文接口读取，或统一服务查询；后者还需保留地图颜色、私人距离参照点及本地视图的既有边界。此处尚未选定具体接口和存储方案。

## 控股：有证据分类器，没有证据核对操作

[企业契约](../../packages/opportunities/src/schema.ts)第 80 行定义带证据的最终控股集合，第 90 行定义带理由、时间及基线 revision 的手工覆盖记录。

[effectiveCompanyControllers](../../packages/opportunities/src/colors.ts)第 137 行可解析有效手工覆盖。[classifyCompany](../../packages/opportunities/src/colors.ts)第 156 行只采用有证据、已核实且不是模型提案的控股信息。办公地点和品牌印象不会自动变成企业来源；多控制方和缺失国家保留独立处理。

[新企业来源投影](../../apps/job-service/src/projection.ts)第 68 行将控股状态初始化为 `unknown`，这是合理边界。当前 [企业服务工具](../../apps/job-service/src/application.ts)主要提供招聘官网发现，没有控股证据预览、确认、历史或撤销入口。通用公共导入及已有手工覆盖 Schema 不能替代这些用户流程。

[默认配色](../../packages/opportunities/src/default-colors.json)已包含北欧、德国／法国、其他欧洲、美国、新加坡／香港、国内国有和民营等规则。[Web 配色面板](../../apps/web/src/components/AtlasWorkspace.tsx)第 438 行可改现有规则颜色并保存至当前浏览器；第 462 行依据实际分类覆盖启用企业性质筛选。配色编辑不会提高企业证据等级，也不是控股国家、分组或规则条件的编辑器。

详情当前显示分类摘要，尚未提供实际雇主、母公司、最终控股主体、依据原文、出处及核对历史的完整审阅界面。

## 建议实施顺序

### 切片一：来源薪资核对后进入真实筛选与排序

优先完成 CNY 闭环，避免将首个可交付结果依赖于在线汇率采集。以下均为规划，工具名称和端口尚未确定：

1. 有界读取单条薪资披露、所属岗位／listing、适用地点及来源依据，并显示每个不可比较原因。
2. 提供结构化字段核对预览，区分固定工资、奖金和股票，区分明确发薪月数与估算，逐项保留金额、币种、周期和税前依据。
3. 独立保存本人核对决议，绑定完整来源指纹和索引版本，不覆盖薪资原文、观察及不可变 JD。
4. 工具、HTTP 和 UI 共用契约，明确复核后保存，支持历史、撤销、幂等回执及丢失回复恢复。
5. 来源变化使旧确认失效，保留历史；重新出现相同来源值不能静默复活旧确认。
6. 保存或撤销后，详情、覆盖数、筛选、排序、地图桶和分页采用同一有效投影。

字段依据必须绑定具体披露段落或结构化 selector。仅有链接、勾选或模型解释不能证明税前或保证发薪月数。原文没有披露时保持未知；额外证据应另建可追溯观察，不能伪装成原岗位原文。

### 切片二：受审 FX 快照及前后端同口径

先支持带日期、出处、读取时间及哈希的快照导入与明确激活，再考虑受控在线 Provider。保持原币及原始范围，记录计算实际采用的快照身份、汇率日期和方向。没有可用快照时解释原因，不自动套用固定汇率。

读取当前有效快照的接口必须同时接到浏览器覆盖统计与查询，不能只接后端工厂钩子。更换有效快照后应使旧查询游标失效，避免一页结果混用不同汇率。

### 切片三：企业控股证据核对与分类联动

复用证据、预览、确认、撤销和回执机制，但保持企业域独立。明确实际雇主、母公司、最终控制方及来源国家的区别；展示支持控制关系的原文与观察时间。用户修正的身份和依据需要明确标注，不能仅因点击确认就宣称雇主或官方机构已认证。

同一企业决议可影响相关岗位，但跨来源同名、品牌相似或招聘网站显示名称不能自动证明是同一雇主。共同控制、无实际控制人、国家缺失及证据冲突均需要明确的契约和显示规则。

## 后续验收标准

以下是未来实现的验收标准，不代表本次已通过验收：

- 明确披露 CNY 税前固定月薪 20,000–30,000、保证 13 薪的合成记录，经预览和明确复核后应为税前年固定工资 260,000–390,000；来源原文及证据不变。
- 仅写“最高 13 薪”、不确定奖金或未说明税前的记录继续分项或不可比较；本人勾选不能制造未披露事实。
- 多地点、跨来源薪资冲突不能任取首条；不适用于当前地点的薪资不能进入比较。
- React → 认证 HTTP → Registry → SQLite 的预览、确认、撤销、重启及备份恢复一致；相同幂等键重试或丢失回执恢复不会重复写入。
- 陈旧预览、来源指纹变化、跨 listing 证据及无权限写入被拒绝。来源 A→B→A 不会重新激活已经失效的旧核对。
- 无 FX 时保留原币并解释原因；有效快照激活后，前后端的金额、覆盖数、排序和出处一致。未来、过期、缺币种快照不产生可比较 CNY 金额。
- 控股补证前保持 unknown；受审证据满足分类标准后，相关岗位的分类、颜色、筛选和地图桶一致；撤销恢复原有效状态。工作地点不能反推最终控股来源。
- 分别记录合成闭环、公开来源实证和真实用户核对的验收范围，不将合成通过外推为全市场覆盖、官方认证或自动事实核验。

本次交付仅为上述源码缺口审查与后续规划，没有新增薪资、FX 或控股能力。
