# 岗位地图：多来源进度、文本召回与岗位定位交互

日期：2026-10-19，Asia/Shanghai。状态：**新机制已落盘，完整自动检查与新版有限真实浏览器交互已通过；四平台来源覆盖继续独立验收，尚不宣称全网接通。**

此次修改回应三项实际反馈：来源读取等待长却缺少过程、少量官网摘录不能代表相关岗位覆盖、岗位卡片缺少清晰详情和定位动作。修改复用现有来源配置、共享机会域和本机索引，不创建公开多人岗位池，不自动启用新来源，不修改私人简历或投递事实。

## 已识别的问题

旧主入口只选择一个来源，额外限制最多 50 条 / 2 页，并等待整次同步和快照后才展示结果。腾讯官网本身对 `C#` 可返回宽泛候选，旧有限详情只读取列表前几个岗位；前几个地点不符，或摘录已经明确命中时，也会占用默认每页两个详情名额。随后应用层直接过滤摘录，没有读到的要求可能导致漏收。

此外，旧采集范围对一段多词输入按连续短语检查，而索引查询按多个词 AND 匹配。例如“后端工程师”的要求中出现“熟悉 C#”，本应符合 `C# 后端`，却可能在采集阶段被提前排除。页面上的宽泛上游总数、已读取数、完整要求覆盖和本地命中必须分别理解，不能用一种数字代替另一种。

并行来源还暴露了实际服务写入竞争：两个来源各回一岗、同时基于旧快照投影时，后写者会触发版本保护，结果为一项完成、一项 `stale-version` 部分结束，只有一岗入库。这一问题使用纯内存 SQLite 与合成来源复现，没有访问网络或用户数据库；服务端修复采用网络读取并行、页投影与提交短队列、仅对实际索引修订竞争作有限重算，不移除版本、代次和取消校验。

## 多来源读取与真实进度

主入口默认选择全部已登记、启用且具备本机岗位列举能力的来源，也可以指定一个来源。`runAtlasSourceSearch()` 接收来源、各来源请求构造、独立幂等键、取消信号和回调，不绑定腾讯或固定公司，后续 UI / Agent 调用可复用同一执行规则。

- 默认并发两项来源调用；单源失败隔离，其他来源继续。
- 每条实际回执先更新逐源状态，再串行刷新公开快照，避免较慢的旧快照覆盖新结果。
- 充分读取每源最多 500 条 / 20 页，快速读取最多 50 条 / 2 页，两者都受已配置的更小额度和原请求预算限制。
- 每源客户端等待上限 60 秒，快照展示刷新另有 20 秒等待上限。它们是等待上限，不是预计完成时间。
- 收到明确终态回执后，新一轮刷新使用新幂等键；回执未知或服务端仍运行时保留原键。取消不回滚已经提交的岗位。

`AtlasSearchProgress` 分开显示实际收到的来源回执数与结束客户端等待的来源数。进度条的分母是本轮选择的配置来源，分子包含成功、失败和取消，不能作为成功率、岗位百分比或全市场覆盖率。每源显示真实提供的条数、页数、新增、更新、人工核对计数，并可展开上游警告、错误码和限流建议；缺失计数不填成零。

面板使用骨架、低强度雷达、shimmer 和真实进度宽度过渡，列表读取中保留状态提示。已用秒数由实际计时得到，没有虚构剩余时间；系统开启减少动态效果时停用装饰动画。未知回执明确提示重新读取索引核对，来源采集失败和索引展示刷新失败分别提示。

## 共享关键词匹配与有限详情分配

新增来源本地匹配工具 `assessSourceScopeMatch()`、`locallyMatchesSourceScope()` 和 `countSourceScopeMatches()`。岗位文本使用索引 UI 相同的单词匹配质量函数；一项兴趣内多个词按 AND，可分别出现在标题、正文、公司或已披露地点，独立兴趣之间保持 OR。普通文字使用既有有限模糊规则，`C#` / `C++` / `.NET` 保留精确技术含义，不能相互替代。独立公司、国家和地区条件继续使用原文匹配，国家与地区必须来自同一办公室。

评估分为三种结果：

| 结果 | 含义 | 是否作为本地关键词命中 |
| --- | --- | --- |
| `matched` | 已读取字段满足条件 | 是，但仍保留摘录 / 完整正文标识 |
| `unknown` | 其他范围符合，但摘录未出现关键词且要求尚未完整读取 | 否，计入待核对与警告 |
| `excluded` | 已披露公司 / 地点不符合，或已读取完整正文仍未匹配 | 否，只说明本轮已读内容范围内不匹配 |

腾讯详情在原额度内重排工作队列：跳过已披露公司 / 地点不符合范围的记录，优先读取未能在摘录中核对关键词的候选，再补已知摘录命中。排序只作用于详情请求队列，返回记录保持原站顺序。请求仍限于已允许的官方 ByPostId 路径、同一岗位 ID、已有请求 / 字节 / 速率 / 取消预算；未添加平台权限或提高配置限额。

要求未读的候选保持 `excerpt`，不注入关键词、不补正文，也不算正式命中。页警告明确给出仍无法确认的摘录数；本机任务回执保留相应待人工核对数量。该补丁减少有限名额浪费和分词口径造成的漏检，不能证明未读取的后续页面没有相关岗位。

实现位置：[local-match.ts](../../packages/source-adapters/src/local-match.ts)、[query.ts](../../packages/opportunities/src/query.ts)、[tencent.ts](../../packages/source-adapters/src/adapters/tencent.ts)。腾讯原始实际探测及 `.NET` 要求漏筛证据见[历史报告](job-atlas-tencent-search-2026-10-18.md)。

## 岗位详情与定位

单击岗位卡片打开独立的非模态阅读侧栏，显示显著的“打开岗位原文”、当前岗位各 listing 的来源 / 发布时间、薪资原文、地点、正文完整度及既有收藏 / JD 分析入口。原文链接必须通过 URL 契约并绑定当前岗位 listing，来源未提供安全链接时显示缺失状态；来源正文按纯文本展示，不能执行其中的 HTML。

双击卡片打开详情并尝试定位。已有有效 WGS84 坐标时，相机移动到对应办公室并显示岗位高亮；缩放受实际位置精度限制，不能把城市坐标当楼宇位置。逐办公室定位、重复定位、切换岗位清除旧高亮及减少动态效果均有独立处理。

只有地点原文、没有坐标时，通过本机 `locations.geocode-candidates` 取得离线地名候选，显示候选国家、行政信息与数据来源，由本人选择城市参考点。候选始终标为城市估算，选择只改变本次浏览视角，不写回岗位地址、坐标、核实状态或距离事实。异步候选请求绑定岗位 / 地点，切换或取消后不采用旧结果；远程资格区域不能当办公室。

Google 地图仍为官方外链，可带已有坐标或地点原文；未接入 Google 内嵌地图、地理编码 API 或通勤时间。新定位动画采用可中断的相机过渡和位置提示，不增加事实精度。

实现位置：[AtlasJobDetail.tsx](../../apps/web/src/components/atlas/AtlasJobDetail.tsx)、[map-focus.ts](../../apps/web/src/components/atlas/map-focus.ts)、[MapLibrePrototype.tsx](../../apps/web/src/components/atlas/prototypes/MapLibrePrototype.tsx)。
