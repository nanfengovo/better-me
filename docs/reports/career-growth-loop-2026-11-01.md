# BetterMe 职业成长闭环：实现与隔离验收

日期：2026-11-01。分支：现有 `agent-os`，基线 `296401c7c759e98a84e25c401bb519198bad485e`。功能实现与隔离验收记录；用户随后授权仅发布本次成长相关改动，已有岗位采集改动不属于本次功能。下方未提交及测试数字是实现阶段的记录，发布检查另列。

## 已接通的路径

1. **目标确认**：继续使用现有规划分析，根据自定义方向、背景、时间预算及明确授权的简历/JD生成理解和追问。用户可选项或自由补充，确认绑定分析记录、目标/预算指纹和资料范围；目标或资料变化需重新确认。未知不视为不会，项目背景不视为个人能力。
2. **学习规划**：确认后生成包含阶段、任务、交付物、验收条件和资源检索词的候选方案。仍使用既有预算和结构校验；生成不等于采纳。旧资料不再共享时可以重新分析生成新计划，不删除旧计划，也不把旧计划偷偷发给模型。
3. **实际练习**：新增原创“状态迁移与重复操作”练习 v1，允许导出/导入匹配版本的 JSON。用户确认后在 opaque-origin iframe 的 Worker 中实际执行 11 项测试；父页面确定性比对结果，产生逐项期望/实际值、执行时间、代码 SHA-256、完整提交代码。回执关联当前计划/任务，不自动标为完成。
4. **有依据的评价**：提交和请求模型反馈分开。练习回执、用户解释与模型意见明确区分；代码过长时只发送标注的摘录，完整代码仍保留在结构化回执。不能访问链接的模型不宣称核验链接，也不把一次通过当生产能力认证。
5. **计划调整**：实践、刷题或面试反馈可以手动带入计划输入，发送前重新核对衍生资料授权。显示实际任务与时间预算差异，用户确认后采纳新版本；旧方案、原任务进度、提交代码和反馈保留并可查看。
6. **针对性刷题**：正式提供方依据目标、授权上下文和主题生成题目/评价标准。保存原回答后再评价；要求反馈引用真实原答，失败可重试且不重复作答。可质疑评价、跳过保留草稿，或基于上次原答/参考反馈生成下一题。历史有复习入口，当前采用本人选择的 1/3/7 天间隔，不声称已接入 FSRS。
7. **自适应文字面试**：保留既有固定轮次模式，新场次可选择自适应追问。至少收到一次实际回答后才可提前总结，最多不超过本人设定的本场预算；结束不是能力认证。逐轮保留原答/评价，回答草稿可恢复，新场次归档旧场次；反馈可请求计划修订。

## 复用与保护边界

- 没有建立第二套模型选择、共识系统或任务管理器。成长请求和本地实践复用 `BetterMeAgent.run`；本地执行显示真实“运行练习”状态，不显示等待模型。
- 原来的共享共识、当前简历/JD均保持明确授权；衍生问题/计划/反馈也受来源记录核验。账号未授权、额度或模型异常均不自动切付费 API。
- 折叠/切换页面使用现有保留挂载机制；任务仍由统一 Agent 持有。明确停止、授权/目标变化和真实卸载会取消请求；迟到结果不得采用。整页重载不自动恢复网络请求或计费调用，已保存记录可恢复并手动继续。
- 默认关闭的持续跟踪规则不变；用户开启后才收录目标确认、采纳计划、实际回执等事件，不追溯扫描私人文件。
- 扩展独立职业成长 IndexedDB 的可选字段，不迁移、清除或重写简历/岗位库。取消原 80 条模型记录、240 条提交的计数限制；仍保留 3 MB 保存上限、CAS 冲突保护、失败备份提示，不自动裁剪历史。
- 执行器没有宿主文件系统接口、业务项目入口或模型访问；iframe 不设置 `allow-same-origin`，CSP 禁止网络连接，Worker 禁用网络/存储/二级 Worker 入口，执行超时 2 秒，父页面等待上限 5 秒；不支持时失败关闭，不降级到主页面或终端 eval。
- 这不是 OS 级内存/CPU 配额沙箱，也不是任意项目运行器。只面向用户确认的小型 JavaScript 函数练习，不能把它称为 C#/.NET、Docker 或任意业务代码执行能力。
