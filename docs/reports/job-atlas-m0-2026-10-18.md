## 已实现

`@better-me/opportunities` 独立于 React、Vite、地图、SQLite 和 Agent SDK。严格 Zod 契约覆盖公司 / 控股证据 / 人工修订、规范岗位、来源能力与范围、Listing、不可变观察与 JD 快照、薪资及位置；Dataset 校验重复 ID、引用及归属。确定性 SHA-256 ID 与保守 URL 规范化保留岗位身份参数。

薪资保留原币、原文和证据，仅固定税前现金进入 CNY 年化比较，换汇带日期 / 来源与有效期。缺薪数的月薪十二个月估算需显式允许；小时薪不猜工时，奖金和股票不抬高固定薪资，多来源不同范围保留候选并标歧义。工资可以绑定办公地点，地区与半径筛选不会串用另一办公室工资。

距离严格使用 WGS84，国家 / 省中心、远程资格地区与未知位置不当成办公室；城市估算需明确允许，多个可选办公室取最近可用点。企业来源与工作地独立，只有有依据的已核实控股关系参与地域配色，未知 / 冲突 / 共同控制及人工修订保留。用户要求的地域颜色与优先级由版本化 JSON 管理。

内存 QueryService 统一模糊 / 技术关键词、薪资、工作地区、企业 / 来源、距离与稳定正倒序，返回完整结果的地图桶 / 统计及分页列表。一岗多地计一岗多点，半径只保留命中位置，未知数值双向排序均末尾。游标绑定条件、数据与派生日期 / 配置；`asOf` 为 UTC 日起点，来源状态取每条 Listing 的最新观察，分别保留部分、失败和需人工。

`jobs.search` 使用真实 QueryService 和严格嵌套输出 Schema，由可信 host 注入家庭参照点、换汇及颜色配置；家庭坐标不在工具参数 / 结果。通用工具执行器具备运行时输入输出验证、JSON 限制、effect 权限、预算、取消、绝对 deadline 与进程内幂等回执。它不代替服务身份认证、网络端点限制或跨重启事务回执。

旧 v1 迁移先生成公共白名单 Dataset 与独立私人 sidecar。旧 ID、时间、JD、材料、申请 / 联系人 / 沟通原对象不被更改；空 JD 不造快照，企业控制方、坐标、薪资数字和新的在招状态均不猜。服务成功回执、revision / fingerprint 及返回前并发核对均满足才生成引用；没有读取、迁移或清空真实用户库。
