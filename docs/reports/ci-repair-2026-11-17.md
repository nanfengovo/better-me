## 根因与红绿验证

1. **Windows PDF 路径是真实缺陷。** PDF.js 的 `getFactoryUrlProp` 要求资源目录以 `/` 结尾；原实现使用 `path.sep`，Windows 的 `\\` 会直接使解析失败。抽出实际 Worker 调用的资源目录构造，新增 POSIX/Windows 原生路径回归，先观察 Windows 分支失败，再统一末尾为 `/`。仍传绝对文件系统路径，保留 Worker 空环境、内存/时间/页数限制及失败关闭行为。
2. **界面测试滞后于当前产品。** 在本机复现 Agent、Dock、成长页面与面试入口的旧文案/默认值失败。改为当前控件的可访问名称、专用输入组件和现有文案；保留外发默认拒绝、草稿恢复、实际 HTTP/内核、本人接受、未知回执不重发和来源原文不变等行为断言。补 Dock 85% 旧默认迁移至 28%、其他预设不变的独立回归；成长验收仍显式核对 `pending_retest`，不把 4/4 声称为长期掌握。
3. **语音上游字节被 Git 换行转换破坏。** 原工作区的已验证文件 SHA-256 是 `29504515526e974f4cb053cf08811c4de5fb2a74007c0a5a957db50eaa8d5d0c`；Git 原 blob 被 input 归一化为 `11530c83...`，Windows CRLF 转换后为 CI 的 `6665cecd...`。确认原工作区与 blob 只差换行后，仅对 `vosk.js` 设置 `-text -whitespace` 并重新纳入原始字节，固定哈希和资源版本不改。新增真实 `git -c core.autocrlf=true checkout-index` 隔离检出回归，先失败后通过，不用修改预期哈希掩盖损坏。
4. **隐私正向测试混入五秒磁盘竞态。** 用受控时钟在第一条持久预留写入后推进 5.5 秒，先复现准备阶段 `privacy_deadline_exceeded`，而非预期的后续磁盘拒绝门。仅将正向 HTTP 测试夹具准备预算设为 30 秒；保留生产代码与单次本机调用预算，并新增同一慢预留在显式五秒预算下仍拒绝、零模型/云端派送的负例。先检查 prepare/approve 回执，避免未准备成功被报成 `undefined.hash`。
5. **回执只读测试混入后台补全写入。** 修复后第一次全量重跑捕获地址补全恰好更新测试库，导致回执前后全快照比较失败。该 HTTP 夹具显式禁用独立后台补全，保留完整快照相等、幂等重放、原始证据与冲突不覆盖断言；后台补全自己的测试仍执行，生产后台功能不改。
