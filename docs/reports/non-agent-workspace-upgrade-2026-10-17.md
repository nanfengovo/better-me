# 非 Agent 求职工作区增强与验收 · 2026-10-17

日期：2026-10-17（Asia/Shanghai）。本轮根据用户“Agent 层先不急，先做好非 Agent 层”的明确调整，把当前简历工作室向可独立使用的求职工作区推进：**岗位发现与收藏 → 核对原文及来源 → 关联具体简历 → 保存当时材料 → 本人在原网站提交 → 手动记录阶段与跟进**。

后续已继续交付 DOCX、截止日/联系人/沟通/到期队列、腾讯官网试点与确认框修复，并完成本报告中资料分类和独立来源备份恢复的验收余项。最新状态见[续批交付报告](non-agent-followups-and-export-2026-10-17.md)。下文保留本批当时的162项检查与待办，作为历史记录。

本报告记录本轮新增实现、开源做法的具体采用、已有验收和剩余边界。此前六模板、编辑与预览、条件自动保存和简历历史继续沿用，详见[简历工作室升级记录](resume-studio-upgrade-2026-10-17.md)。原始规划的缺口审计是实施前基线，不能继续用其中“机会库、多简历、RenderCV 未实现”等旧状态代表本轮之后的代码。

## 1. 本轮新增行为

| 范围 | 当前实现 | 使用边界 |
| --- | --- | --- |
| 主导航 | 简历内容／设计、机会与投递、求职资料库；已有版本与 AI 设置入口保留 | 不是完整成长 Agent；职业持续对话、学习规划与自主编排后置 |

岗位信息和跟进通过各自的保存按钮持久化；阶段、公开岗位收藏、材料记录等操作立即尝试保存。它们不使用简历的条件自动保存和最近 50 个版本机制。跟进日期当前仅作记录，没有后台提醒、邮件或消息。

## 2. 公开招聘源的实际接入

新增 Vite dev／preview 接口 `POST /api/opportunities/source`，接受指定 provider 和公司 board slug。服务仅向 Greenhouse、Lever 固定官方 HTTPS API 请求，设置同源检查、slug 校验、拒绝重定向、15 秒超时、8 MB 响应体和最多 300 条岗位上限。是否截断明确返回给界面。

读取只生成预览；选择后点击“收藏所选”才写入个人库。来源页面、申请页面和发现 API 分开保存，原始发布时间／更新时间独立处理。地点原文保留在 JD 中，不据此猜测国家、城市或工作授权；仅源明确披露的工作方式映射为 remote／hybrid／on-site。列表来自公开接口这一事实记录为 `lastVerificationMethod: source-read`。

本轮真实读取样本见[非 Agent 开源做法研究](../research/non-agent-patterns-2026-10-17.md)：Greenhouse `duolingo` 当次返回 **63 条**，Lever `spotify` 当次返回 **82 条**；两个不匹配的 Greenhouse slug 返回 HTTP 404 并明确报错。浏览器另外验证了 Greenhouse 预览、选择一条收藏及重复收藏不新增。

这些证据说明当时两个公开 API 样本可读取，不能推导为所有公司可用，或 BOSS／51job／猎聘／LinkedIn 四平台的真实提取已经验收。纯静态发布 `apps/web/dist` 不包含此服务，也不包含已有 `/api/jd/extract`；生产部署仍需兼容后端。

## 4. RenderCV 数据与真实性边界

适配器为 `projectedResumeToRenderCvYaml(ProjectedResume)`，公开返回 `yaml`、`document`、`diagnostics` 和 `targetVersion`。目标为 RenderCV **2.8**，实际核对提交 `1d4b87bc427e4cf61c0ef49623c971b0e2224708` 的官方 example、JSON Schema、字体说明与 Markdown／Typst 处理逻辑。

导出按当前语言、经历／要点选择、隐藏开关和分节顺序处理；未核实结构化指标、面试笔记与 pitfall 不输出。指标仅保留可展示原文，不从 `metric.value` 组装新的量化结果。教育使用通用条目保留原文，不推测拆分学位和专业。链接按无凭据 HTTP(S) 地址规范化后作为文本保留，电话不推断国际区号。

YAML 字符串使用带引号的转义值；正文转义 Markdown，并阻断上游原始 Typst 命令／数学识别。照片不打包或远程获取；网页主题、颜色、字号、间距和选中文字格式不直接映射，导出说明明确列出。中文选用 Schema 支持的 Noto Sans 字体族；本地字形覆盖和分页仍需实测。

中英示例结构化输出通过本轮实时取得的上游 JSON Schema 校验；这证明字段结构可接受，不代替 YAML 渲染、中文字体或 ATS 检查。

## 5. 数据保护与交互修复

- 机会库读写与 JSON 导入严格校验；损坏／未知版本保留原文，空字符串损坏也按恢复状态处理。显式恢复先保护原文，普通保存不覆盖损坏库。
- 保存采用修订号检查；检测到其他窗口修改时进入冲突状态，阻止继续覆盖并提供重新读取。当前机制不等同账号云同步或跨设备协作。
- 新建时遇相同来源保留现有记录和当前表单，避免刚录入的大段 JD 被直接丢弃；备份合并保留已有 ID／来源对应的进度和备注。
- 岗位表单与跟进输入关闭、重新读取、进入其他编辑动作前检查未保存内容，并设置浏览器离开保护。机会 `Ctrl/Cmd+S` 与简历保存入口分开处理，避免只保存简历却误以为跟进已保存。
- 机会分析使用独立临时 JD 副本；通用采集草稿、分享链接与来源不被岗位分析覆盖。
- 材料快照持有当时 Markdown 和名称，不只引用可能被裁剪的简历历史 ID；之后改名、修改事实或删除视图不改变旧快照。
- 岗位与简历关联索引使用无原型对象，特殊可导入 ID 不命中对象原型；岗位弹窗通过 `aria-labelledby` 关联标题。
- CSV 采用完整引号并处理电子表格公式前缀。机会备份白名单不包含模型 Key、任意附带字段或截图；简历与机会分别下载和恢复。

机会库当前最多 2,000 个岗位、JSON 上限 4 MB、每岗最多 30 份材料。机会尚无自动草稿、完整历史链或跨设备同步；未保存输入在浏览器异常退出时仍可能丢失。简历自动草稿与历史机制的既有边界继续适用。
