## 日期与证据

来源原文时间和本次拉取时间分开保存。例如 Linear 返回的某条 `publishedAt` 为 `2021-04-27T20:13:45.158+00:00`，不会用 2026-10-18 的抓取时间覆盖它，也不会仅因 board 列出就宣称该岗位近期发布或仍在招。Greenhouse 的来源发布时间、更新时间及原文均随观察保留。

28 个岗位均能追溯到各自 listing、观察和 JD 快照。当前没有企业最终控股方证据，不生成企业归属；没有结构化薪资、坐标或税制就保留未知。地图可以显示真实岗位列表及缺失精度提示，不能用此批数据证明距离排序或地图点位已经完成。

## GitHub 通用发现与结构检查

通过本机 `sources.discover` 执行通用查询 `jobs engineering hiring in:name,description`，GitHub 返回总计 74 个仓库候选，本轮仅读取前 3 个元数据。返回结果包含用户未列举的仓库，验证发现工具不依赖固定仓库清单；搜索匹配仍可能是求职工具或招聘产品，不能直接当作岗位源。

三条候选均为 `needs-review`，不注册、不启用、不计入 28 个真实来源岗位。两条候选没有明确仓库许可证，第三条带 MIT 元数据；仓库代码许可证也不代表其链接的招聘正文可再分发。仓库 `pushedAt` 仅作为仓库元数据保留，不冒充岗位发布时间。

另对用户提供的 [xixicc2027 JSON](https://raw.githubusercontent.com/xixicc186/xixicc2027/main/jobs.json) 执行种子发现与有限结构检查。上游 402 条；第一次检查 5 行，后续核对提案调用时只检查 1 行。此处是候选结构抽样，不导入岗位或线索。最后单行样本未推断出稳定 ID、标题或 URL 映射，提案因此保持 `review-required-json`、`enabled:false`、`status:needs-review`，且未注册。

本地验证脚本第一次把提案参数多包了一层，服务正确返回 `400 invalid-input`；修正为工具公开 Schema 后生成提案成功。未修改服务实现来绕过验证。

当前服务启用注册时要求配置有已安装的 `list-jobs` 适配器。为运行通用发现，本机发现配置使用已安装的 `mapped-json` 元数据，同时声明 `discover-sources`；刻意不配置 list `entryUrl` 或字段映射。这项配置只用于发现/检查，不能作为可以同步的岗位来源。后续可将发现能力注册与列表能力验证分离；本轮保持既有服务边界。
