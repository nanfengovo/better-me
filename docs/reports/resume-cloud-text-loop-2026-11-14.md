## 文本闭环实现

沿用 `resume_tailor` 与唯一 `AgentTaskKernel`，新增 `workflow: text_v1`，没有第二个执行器或简历库。

1. **授权选材**：用户先选要发送的字段、补充和模型。完整授权文字进入任务，不读取目录、不做 Top-K 截断；已知凭据样式在发送前拒绝。首次显式运行只产出完整字段清单，每项都有采用/暂不采用理由与本字段原文引用，最多五个事实追问，不直接成稿。
2. **追问与确认**：勾选最终采用字段、填写实际贡献或“未知”、核对后本人确认。提交绑定原计划 hash；缺问题、重复问题、旧 hash、非本人确认均拒绝。补充是本任务的自述，不自动采纳为长期事实。
3. **显式成稿**：再次授权才调用同一模型，单阶段一次发送，没有隐式格式修复。只允许改写本人最终选择的字段；引用需来自本字段/本字段确认回答，仍受原句、目标、数字、技术实体、个人归属和逐句审核规则限制。这些是确定性拒绝检查，不是通用事实证明。
4. **人工批准与独立版本**：逐条批准后，沿用真实 `createCareerTaskResume` 与工作区保存/回读/回执流程。未批准字段保持原文，原始版本与共享事实不变；独立版本沿用源视图的其他内容，不声称已实现整份简历的自动筛删重排。
5. **确定性文本导出**：只从完成任务的匹配审批回执生成 Markdown。只导出本轮最终选材，未批准改写保留其原文，未知项独列；重复或不一致回执拒绝。不会调模型。另提供打开真实独立版本进入已有预览/PDF 导出的入口；新增 PDF 流程没有完成本片真实点击验收。

新协议通过已有多供应商 transport。仅对**明确选中的官方 DeepSeek 端点的新文本阶段**增加 JSON-object mode；旧 v7 比较参数不改，自定义端点与其他供应商不自动套该参数。OpenAI/Gemini/Ollama 的全部真实供应商兼容性、本片云端两阶段闭环的实际写作质量均未因此得到证明。

## 恢复与防重

- Host 耐久保存计划、确认、草稿、原根累计用量与业务回执。GET、刷新、重开、Host 重启不运行模型；继续始终需要新的显式授权。
- 未发送的选材/回答仅存当前账号的私有本机存储。重开恢复文字，不恢复“本人确认”或模型发送同意；写存储失败会明确警告。整体补充超出提交上限时留在本机，不能点确认发送。
- 创建前先保存不含凭据的原创建编号及精确范围。丢创建响应、稍后才得到原稿指纹时，仍以原 idempotency key 核对；恢复创建成功也不自动启动模型。原稿/账号/模型变化仍需重新核对。
- 迟到结果只归档在原 owner 私有 journal，带原 run generation 与 late 标记；暂停或失权后不采用为计划/草稿、不恢复调用。
- 保存丢回执只检查原版本并补写回执，不再创建版本；已有持久回执与源版本核对测试继续保留。

本片负例先红后绿发现并修正：冒号字段编号的回答归属碰撞（改为字段/问题 tuple 的固定 hash 与精确匹配）；“未负责上线”被误当个人上线依据；超长确认 payload；异步原稿指纹导致丢创建编号恢复失败；已返回迟到 wire 未归档。评测桥另验证严格 Origin、接收方、并发独占 claim、失败后重启只观察及凭据不落盘。
