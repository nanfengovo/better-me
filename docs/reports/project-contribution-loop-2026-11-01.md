# 项目理解到个人贡献与简历候选验收

日期：2026-11-01。范围：现有 `agent-os` 工作区，本轮未暂存、提交或推送。

## 行为与边界

- 项目理解新增可选 `contributionLeads`：Agent 根据已取得的证据动态生成线索、问题与回答方向。服务端检查引用和唯一标识，不把没有证据的职责、客户名称或上线推断自动当作事实。
- 明确区分代码所示、文档描述、设计方案、本人说明、Agent 推断和未知。代码存在也不证明部署、客户使用或个人作者身份；Markdown/README 不再能直接充当实现结论。
- 保持三个独立门槛：确认项目共同语言 → 本人认领实际实现或设计贡献 → 核对候选后采用到一个字段。用户可选择不是我做的、不确定，或自由纠正；不限制访谈轮数。
- 客户/现场/职责为可选上下文。私有客户备注只保存在本机独立草稿键；白名单构造的伴写补充不包含该字段或 Agent 假设。可公开描述需另行勾选。自由输入中主动填写的其他内容不具备自动脱敏保证。
- 贡献草稿按会话与线索保存；恢复时不恢复个人确认勾选，新理解版本要求重新核对。向 Agent 继续提问只预填主输入框，仍需本轮授权与发送；交给伴写仅追加补充，不自动生成或写简历。
- 伴写沿用原字段 CAS、逐字确认与撤销。显示真实原文/本人补充引用，手动改候选会撤销旧引用映射。设计口径出现实现/上线措辞时保守拦截。引用包含性和措辞检查并非外部事实认证或完整语义验证。
- 伴写发送前、返回后核对项目确认版本、摘要和原文。返回后的检查在统一 Agent 记录成功之前完成，变更或撤权导致迟到结果失败，不进入成功历史。

## 读取预算与目录复用

- 先用测试复现批量 read 越过剩余预算时直接退出、理解卡片未更新的问题，再改为消费预算内请求，预留一次只总结调用。
- 最后调用明确 `SYNTHESIS_ONLY`，要求用已有证据更新完整理解、线索与未知；若模型仍要求读取，保留取证检查点，并标明“上次理解 · 本轮尚未更新”，不制造新总结。
- 检查点包括本轮使用量、阶段、取得的证据和目录复用次数。错误、取消或重启显示 partial，用户显式继续；不自动重发、不切换计费。
- 目录清单以授权范围、相对路径、stat 指纹及五分钟有效期复用，最多32份/每份200条；保存前后验证指纹，变化或撤权失效。跨 Host 重启可以恢复清单。缓存命中仍占调用预算以终止无效循环。
- 目录观察只是历史路径线索，不是实现证据；真正文件读取、权限和符号链接校验仍走 Broker。不是无限缓存，也不承诺跨所有目录变动永不重读。
- 新协议字段可选，未给旧确认对象补默认空数组，避免无意改变历史摘要；旧 source 声明若没有代码引用，在 UI 中标为未核对历史材料。

## UI复核

| Before | After | Why |
| --- | --- | --- |
| 理解停留在背景描述 | 有依据的线索、针对性问题和可编辑认领草稿 | 把阅读结果转为可以行动的写作材料 |
