# BetterMe 职业成长 Agent MVP

日期：2026-10-29（Asia/Shanghai）。现有 Agent 工作台已接入职业成长 MVP，覆盖规划分析、修改建议、长期学习方案、学习监督与模拟面试，复用原简历、目标 JD、模型配置和批准写回接口。新增状态独立保存，不建立第二份简历事实库。

后续已使用现有 Ollama 配置进行真实模型验收并修复兼容性问题，最新测试命令、隔离体验入口和隐私边界见[真实模型验收记录](career-coach-real-model-2026-10-29.md)。下文原始合成 UI 验收不应当作真实模型调用证据。

## 入口和接入方式

从现有 **AI 顾问工作台 → 职业成长** 进入；可返回原对话与 JD 工作区或简历编辑器。复用当前选中的简历视图、目标岗位和已有模型配置。

- 五种任务共用目标、背景说明、周数、每周时间预算、面试轮数。
- 简历字段和目标 JD 分开授权，默认都关闭；未授权时只分析用户本次主动填写的信息。
- 普通对话、原 JD 匹配和 CLI 快速运行仍保留。这版新增工作流不调用 CLI，也不依赖旧 Career 图尚未修复的审批恢复路径。
- 新 MVP 使用现有 core 的模型请求模块，由浏览器直连用户配置的模型服务；支持既有 OpenAI-compatible/Gemini/Ollama 配置，不新增账号或云端平台。浏览器跨域或网络失败会显示可行动错误，不伪装成功。

## 功能明细

| 工作区 | 用户输入 | 模型输出 | 实际产品动作 |
| --- | --- | --- | --- |
| 规划分析 | 目标、自述、可选授权简历/JD、当前采纳方案、补充回答 | 可选方向、材料依据、取舍、优势、未知/需练习项、少量关键追问与下一步 | 用户选答或填写后显式提交下一轮；不自动扮演用户、不自动写画像 |
| 修改建议 | 当前授权简历字段及改写目标 | 原文、候选表达、理由、准确目标字段 | 先验证本次授权目标和逐字原文；用户逐条批准后复用原简历写回接口，宿主再次校验当前原文与跨窗口冲突 |
| 学习方案 | 1–52 周、每周 1–40 小时、目标/背景、可选旧方案 | 连续阶段、每周任务、预估分钟、交付物、验收条件、资源检索词、风险和复盘节奏 | 校验时间预算及每周覆盖；生成先作为候选，明确采纳才开始跟踪；替换旧方案需确认 |
| 学习监督 | 已采纳方案中的任务、学习证据文字、实际投入分钟 | 证据不足/需修改/可自查、优势、改进、下一步、核对问题 | 提交与模型反馈分开保存；失败不抹掉提交；任务状态为未开始/进行中/已提交/本人自评完成，显示逾期与投入时间 |
| 模拟面试 | 目标、可选 JD/简历、2–8 题、用户逐题真实回答 | 首轮一道题及评价标准，后续上一回答反馈与下一题，最后总结 | 首轮不能评分，未作答不能继续，达到轮数不再追问；支持停止和明确重开，模型失败保留回答并可重试 |

计划分析会使用界面明确披露的已采纳方案；在时间或目标改变后生成替代候选，而不是默默改动当前计划。规划分析提供“用本轮结论制定方案”，面试总结提供“用面试反馈调整方案”：点击后只把选定内容放入学习重点，用户核对并点击生成后才发送。资源提供的是检索关键词，不冒充已经打开或验证的课程链接。规划分析、修改建议和学习方案可以选择本类历史结果查看。

## 建议使用流程

1. 打开已有 AI 顾问工作台，点击顶部“职业成长”；原对话、JD 和返回简历入口仍可使用。
2. 先确认原来的模型配置。填写本阶段目标、背景与限制、计划周数、每周小时和面试轮数。示例目标：8 周内补齐接口设计与测试，准备全栈岗位面试；每周 5 小时。
3. 在“本次资料授权”分别决定是否共享当前简历字段、目标岗位。不勾选也能用自己主动输入的内容做规划。
4. 在规划分析中提交问题；查看方向、证据、取舍与未知项。选择追问选项只会填入输入框，确认后再次提交。需要转入学习时，点击“用本轮结论制定方案”。
5. 在修改建议中先授权简历，生成原文对照，逐条核对并应用或拒绝。本批已批准的修改允许继续批准其余条目；不相关的外部原文变化会阻止旧提案写回。
6. 在学习方案中生成候选，展开任务核对交付物和验收条件，再点击“采纳此学习方案”。新候选不会自动替换当前方案。
7. 在学习监督中选择任务，填写可阅读的证据和实际分钟，先“保存学习提交”，再“请求模型反馈”。自评完成由本人单独选择，模型评分不能自动完成任务。
8. 在模拟面试中开始一轮，逐题真实回答。失败后可重试同一轮，回答不会重复追加；轮数用完显示总结，可将反馈带回学习方案形成下一轮调整。
9. 正常保存的内容可在刷新后恢复。用“下载备份”导出当前工作区 JSON；本版没有 JSON 导入、跨设备同步或后台提醒。清除前先确认备份。

## 数据、权限与失败语义

1. 按当前简历视图 ID 隔离成长工作区，计划、提交、模型结果和面试状态保存在独立 IndexedDB 数据库，不混进 Fact、岗位索引或 API Key 配置。
2. 不持久化整个共享简历/JD上下文；本轮授权只影响实际请求。用户填写内容与模型生成成果可能包含个人信息，仍属于私人本地记录，不能当公共数据分发。
3. 本地保存失败明确显示未保存，并保留本页内容供下载；同一页面运行期间离开再返回该工作区，也能恢复失败草稿。此临时副本不是持久化，刷新或关闭整个页面仍可能丢失未保存内容，应先下载。损坏或不兼容数据不会自动覆盖。跨窗口 CAS 拒绝陈旧写入，需用户下载备份后明确重读。
4. 提供 JSON 下载备份和只针对当前成长工作区的明确清除；不会清除原简历、简历历史或岗位库。清除后只保留空工作区的递增版本信息，阻止旧标签页重新写回已清除内容。
5. 取消传递到实际模型请求，切换任务、授权、工作区或离开界面时隔离迟到结果；取消后不能发布成成功成果。
6. 模型输出经过严格 Zod 校验；空输出、截断、结构不合法、模式不符、任务越界、预算超额、无效简历目标都不是可采纳成果。没有以模板结果假装真实模型成功。
7. 计划最多 64 项任务；本地最多 80 条模型记录和 240 条学习提交，达到上限提示下载和处理，不静默删历史。面试重开会重置当前会话，需明确确认；成功模型记录继续保留。

## 明确未包含

- 不做后台屏幕/进程监控、强制锁机、自动学习或替用户打卡。
- 逾期提示在打开工作区时计算；没有创建系统定时器、后台通知或跨设备提醒服务。
- 模型不会实际运行学习代码、访问用户提交链接或认证能力；所有反馈、评分和自评状态均不是资格证明。
- 不自动投递、不发消息、不自动把学习成果或面试评分写回 Fact。
- 不把这版持久本地工作区宣称为跨设备记忆、完整职业画像或普通聊天/CLI 的统一线程。
- 不在本轮顺带修复或宣称修复旧 CLI 结果真实性、工具权限和 Career 图审批恢复等既存审计缺口。

## 实现结构

- `apps/web/src/lib/career-coach/types.ts`：五种模型产物和本地工作区的契约。
- `model.ts`：模型请求、显式上下文、结构解析、预算/原文/面试轮次校验。
- `state.ts`：采纳、任务状态、提交和进度的纯业务操作。
- `storage.ts` / `use-career-coach.ts`：独立 IndexedDB、串行保存、版本冲突和失败保护。
- `apps/web/src/components/CareerCoachWorkspace.tsx`：五个工作区及实际交互。
- `AgentWorkspace.tsx` / `App.tsx`：复用原工作台、当前简历视图、JD 与写回接口。
- `packages/core/src/ai/client.ts`：向现有聊天请求补充可选 AbortSignal，原有调用保持兼容。
