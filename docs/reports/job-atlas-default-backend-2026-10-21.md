# 岗位地图默认后端连接

用户反馈：本机使用时不应反复填写“连接本机服务”，岗位索引应像普通应用后端一样自动连接。本批将正常入口改为固定同源后端，高级配置保留手动直连。

## 使用行为

- 首次进入岗位地图并激活工作区时，自动读取 `/api/atlas/api/v1/dataset/export`，展示真实索引的岗位数与版本。读取索引不触发外部岗位采集。
- 顶端显示后端连接状态及设置；手动地址、令牌收进折叠的高级连接。默认路径无需网页填写令牌。
- 后端不可用时保留真实索引视图，首次未取得数据时显示数量未知；已经取得快照时保留快照并标明连接故障。失败不切换演示、不将故障当零岗位。
- 本标签页此前显式选择的机会库／演示视图继续保留；已成功保存的手动直连仍可恢复。使用默认后端会清除旧手动凭据，即使本次默认连接失败。
- 默认会话只保存固定路径及空令牌。切换身份、停用工作区、取消和迟到响应沿用原隔离规则。

## 宿主与部署边界

Vite 的开发及预览服务器安装同源网关。网关把白名单 API 转发到本机岗位服务，默认目标为 `http://127.0.0.1:5178`，并从宿主私有数据目录读取 `BetterMe/job-atlas/service.token`。Windows 默认使用 `%LOCALAPPDATA%`；其他平台使用 `XDG_DATA_HOME` 或 `~/.local/share`。

浏览器不接收该凭据，也不提交任意上游 URL。网关检查本机连接、Host 和同源请求，限制方法、路径、请求与响应大小，禁止重定向，转发取消，并拦截凭据回显。上游使用固定的 `http://localhost:5173` Origin，岗位服务应允许这个 Origin。

自定义服务位置在**启动 Vite 的终端**设置：

```powershell
$env:BETTERME_JOB_SERVICE_URL = "http://127.0.0.1:5178"
$env:BETTERME_JOB_SERVICE_TOKEN_FILE = "D:\Private\BetterMe\job-atlas\service.token"
pnpm --filter @better-me/web dev
```

也可在 Git 忽略的 `apps/web/.env.local` 保存这两项宿主设置。Vite 只加载 `BETTERME_JOB_SERVICE_` 前缀用于服务端网关，终端 `process.env` 优先；修改后重启 Vite。默认数据目录无需配置。不能使用 `VITE_*`，令牌正文不进入配置、网址或 Git。

本机实际遇到 Windows 应用隔离数据重定向：原服务持有的数据目录与普通终端解析的默认目录不同，导致普通终端 Vite 返回 `unconfigured`。已依据岗位服务实际日志和文件 realpath，在私有项目配置中保存真实令牌文件路径，未复制正文。重新以无临时终端覆盖的方式启动后验证 `ready`；此路径是本机配置，不写死到产品或公开文档。

GitHub Pages 与现有 Nginx Docker 镜像仍是静态网页，没有此 Vite 网关或岗位数据库。静态版可以在高级设置显式直连本机服务；远程常驻后端、账号认证和生产反向代理属于后续部署工作。`vite preview` 的网关也不等于它支持四平台专用浏览器 API。
