# Agent 底座功能拆分发布验证

日期：2026-11-05。发布基线为既有 `agent-os` 的 `5d5438f`。本报告记录推送前的精确发布副本验证；远端提交和 CI 结果应以 Git / GitHub Actions 为准，不把本地测试称为云端授权成功。

## 三组功能

1. **账号隔离基座**：服务端验证的稳定 owner、请求归属与并发 CAS；浏览器身份代际和账号/恢复空间存储边界；现有账号显式关联 Casdoor/OIDC；旧资料只读档案入口。无自动认领、搬迁、覆盖或恢复真实资料。
2. **原生工具授权与适配**：每个 BetterMe 账号独立凭据/运行目录，强制隔离后启动；Codex / Claude 官方原生登录适配与显式 API Key 入口；OpenCode / Gemini 等已适配工具；按未安装、未接入、待授权、待验证、隔离、协议与管理策略分别报告状态。未关闭限制来制造“可用”。
3. **统一选择与批准链备援**：自由对话、简历伴写、职业成长、项目理解共用账号路由；手动选择已登记底座，自动仅沿本人批准链，优先原生授权；API 备援默认关闭；启动前的跳过原因和实际底座可见；已发送/未知结果不重放到其他工具。默认保留旧选择，不自动替换模型或付费来源。

## 发布边界

- 从上述基线导出独立副本，只装载明确的功能文件与混合文件中的相关片段。账号基座先于原生适配，统一路由在最后一组接线；每组均使用独立快照检查。
- 不纳入岗位采集与公司冲突、能力闭环/简历自动采用、旁批连线与工作台布局、手机/桌面工作流方案等其他在途工作。
- 不暂存真实简历、岗位记录、账号库、Cookie、模型 Key、本机登录材料、私有归属档案、测试输出或截图。
- 不新开产品分支，不重写历史，不重启正常 Web/Host，不刷新原浏览器页面，不创建或切换真实模型账号。

## 尚需本人授权的部分

真实云账号仍须本人在对应 BetterMe owner 下单独登录，或明确配置 API Key。Codex 的本机管理策略同步阻塞未通过绕过方式解决；它不再阻塞其他已批准工具。Linux/Windows 若没有对应强制隔离适配，应明确显示系统隔离不可用，不降级继承宿主共享凭据。正常运行页面尚未重启加载本批代码，不能仅以 Git 推送宣称当前页面已接通。
