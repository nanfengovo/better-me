# 同岗位详情地点与桌面地址核对 · 2026-10-19

本批补齐四平台已入库岗位的详情地址链路：读取原岗位明确披露的结构化地点，核对证据，预览并保存到原岗位，再按需核对具体办公坐标；另增加当前结果的有界逐岗补全流程，并减少地图缩放时重复的数据上传和命中查询。电脑上在固定第三栏完成阅读和地址核对，地图与结果列表保持原有位置；空索引使用两栏及接入入口。这些能力不等于已有岗位都具备门牌地址，也不代表招聘平台或地图提供方已实现全量准确覆盖。

前置能力见[桌面稳定阅读与地址查询约束](job-atlas-desktop-precision-2026-10-19.md)、[办公地址与 SQLite V4](job-atlas-desktop-office-address-2026-10-19.md)和[真实地址提供方实证](job-atlas-office-provider-real-2026-10-19.md)。

## 从原岗位详情取得地点

51JOB、BOSS直聘、猎聘、LinkedIn 共用版本化 `PlatformDetailLocations` 契约。现有公开页读取及专用浏览器读取可以附带 `detailLocations`，保留当前已接受 `JobPosting` 的 `jobLocation`，包括国家代码、地区、城市、街道、邮编、原始文字、结构化对象原文、选择路径和观察时间。邮编作为字符串保留前导零。

只接受明确的 `PostalAddress` 字段，不从公司名、总部、币种、搜索城市、页面其他岗位或正文关键词补办公地址。只有明确的两位国家代码才写入 `countryCode`；国家名称可保留在原文，但不能凭名称外观填造代码。地址中的 `geo` 不自动成为办公坐标。

地点必须与当前官方单岗位链接身份一致。有结构化岗位 URL 时逐一验证同平台同岗位；没有岗位 URL 时，必须同时具有匹配的 canonical 和主标题证据。同一岗位多份结构化地点披露发生冲突、地点格式无效或无法确认身份时，不选取任意一份地址。仍可保留已经通过原规则验证的 JD 正文，页面会说明没有可核对的结构化工作地址，原地点保持不变。

专用浏览器的同岗位有效跳转会重新绑定原请求 URL 与本次观察时间；跳到其他岗位不能带入地点。浏览器安全投影只保留已通过现有读取规则的当前岗位内容，不放宽登录、验证、可见正文和多岗位歧义检查。需要本人登录或验证时，继续使用现有专用岗位窗口，由本人完成，不自动越过挑战。

实际 Web production build 还暴露了服务端宽导出图中的运行时导入问题：原生 Node 读取公共 `browser-contracts` 子路径时，会间接触及需要另一种装载方式的 `contracts.js`。本批将官方单岗身份定义提取为共享 `platform-job-identity`，保留原搜索及卡片模块重导出，并提供独立 `./platform-job-identity`、`./platform-detail-locations` 包子路径。三个服务端运行入口改用所需窄导出，不再依靠测试环境的 TSX 装载掩盖原生运行差异。平台枚举与身份规则仍只有一份定义；原生 Node 无 TSX 导入回归、独立冻结构建和 37 项相关回归通过。

`jobLocationType` 的明确 `TELECOMMUTE` 证据可表示远程资格范围。没有此证据时不推断远程；详情地址补充也不会修改岗位既有 `workMode`。只有远程且没有地址的空披露不作为删除已有地点的指令。

## 严格契约与受审保存

共享 Schema 对字段长度、控制字符、对象深度、节点数量、最多 20 个地点、官方单岗位 URL 和版本号作限制。每个地点字段与 `jobLocation[n]` 必须能够从对应 JSON 原文严格重新解析，不能向原文未披露的地址加字段。工作模式同样要求能够重放 `jobLocationType` 证据。

这项检查保证数据与提交的证据一致，不能认证证据确由招聘平台生成，也不认证雇主办公关系或仍在招聘。公开页读取结果、受管浏览器结果和用户明确核对的保存过程分别保留其边界；客户端不能凭自行提交的 JSON 取得“平台已验证”标识。

| 共享工具 | 认证 HTTP |
| --- | --- |
| `jobs.preview-detail-locations` | `POST /api/v1/jobs/detail-locations/preview` |
| `jobs.import-detail-locations` | `POST /api/v1/jobs/detail-locations/import` |

输入绑定当前规范岗位 ID、原 listing ID、同平台同岗位 capture 和 `expectedRevision`。预览只读索引、不联网、不创建来源或岗位。保存还必须提交同一输入、`previewFingerprint`、`reviewed: true` 和 `Idempotency-Key`；身份、权限、索引版本、来源定义、岗位归属和捕获时间在服务端再次验证。过期别名 ID、其他岗位链接、未来异常时间、早于该 listing 最新观察的详情和旧预览均被拒绝。

工具当前只补充已有 `reviewed-platform-*` 来源下、身份符合原人工核对卡片协议的 listing。不会把任意官网或其他来源伪装成四平台受审来源。归并后的当前规范岗位可补充其实际持有的原 listing，但不能借此修改其他岗位或新建另一份岗位。

## 仅替换该来源的地点贡献

保存复用原仓库的原子 `importSnapshot`，读取来源基线投影后，仅替换选中 listing 对该岗位的地点贡献，并记录本次地址观察。其他 listing 的地点、原 canonical URL、岗位标题、公司、薪资、岗位状态、既有工作模式、所选 JD 快照和 JD 正文保持原值；不创建新岗位、新 listing 或新 JD 快照，也不把读取时间写成发布时间。

新地点仍标为来源待核实。即使含街道、邮编，也保留可被来源字段证明的国家／地区／城市精度，没有坐标，不含本人确认覆盖。明确远程披露成为 `remote-region`，不会进入办公定位。若地点替换会使已有薪资的地点适用范围失去引用，则拒绝该次变更，不静默改变薪资适用关系。

地点 ID 绑定 listing、完整来源地址和地点性质；预览指纹绑定完整输入与协议版本。相同 capture 重放不新增观察、岗位或索引版本；若该历史 capture 的地点贡献已被后续更新替换，则拒绝历史重放，不以无操作回执掩盖已过期的地址。

写入沿用原输入、执行身份和幂等键的耐久回执。数据库已提交但 HTTP 超时、输出验证或后续快照读取失败时，可核对原回执，不能换键重复写入。SQLite V4 的来源失效语义继续生效：来源地点或证据一度改变，旧办公确认永久失效；即使以后 A→B→A 返回，也必须重新审核，不自动复活旧坐标。

## 按当前结果逐岗补全

新增共享只读工具 `jobs.plan-address-enrichment`，对应认证 HTTP `POST /api/v1/jobs/address-enrichment/plan`。输入为最多 50 个不重复的当前规范岗位 ID 和 `expectedRevision`；空数组明确表示零岗，不扩大成全索引。计划本身不联网、不调用地址提供方、不保存，也不要求幂等写入 key。服务端读取同版来源基线与有效投影，逐岗区分已有有效办公点、来源街址、原平台单岗详情、已持有的可读官网来源，以及仅有企业名称的弱线索。

每个条目分别返回当前有效办公点和 `pendingLocationIds`。已有一个可用办公室不能掩盖同岗其他尚待补全的非远程地点；只有当前已存在的地点都具备可用办公点才跳过。远程岗位仅作为资格范围处理，不生成办公查询目标。来源街址必须来自原 listing 自己的观察证据，且当前地点仍为办公室；本人本地覆盖、公司总部、同名企业地址、已改为远程或未知性质的地点都不能充作来源街址。官网协议还必须由宿主当前安装的 adapter 注册表明确确认可读，不凭来源声明的版本猜测代码已经安装。

“补全当前结果办公地点”只处理当前已加载岗位的前 50 岗，界面显示实际范围、逐岗进度、加载动画、部分错误和取消结果，并发最多 2 岗。本人点击读取后，每岗最多读取 2 个来源街址、2 个原平台详情和必要时 2 个已持有官网来源。街址查询将来源明确披露的街道、城市和邮编交给已配置的地址服务；原平台读取仍执行同岗身份、有效结构化证据、未编辑和非远程检查。读取到的证据、候选与官网线索均不自动写入。

官网读取复用原来源预览协议，以岗位标题和企业名称限制范围，单次最多 50 条。只有来源、原岗位编号和 canonical URL 唯一全同的已持有 listing，才将其明确街址显示为当前岗位的待审线索；同名、同城市或同企业不能证明同一岗位。该线索不伪装成平台 capture，也不通过四平台地址工具自动保存。仍缺街址时，按规范化企业名称合并重复的招聘入口发现请求；入口、企业关联和办公关系继续标为待核实。配置未提供可用发现能力、原协议有限返回或页面要求本人验证时，会保留相应失败与范围说明，不将其显示成市场无岗位或已有准确地址。

本人可勾选已读到的同岗位平台地址证据，再明确保存。多个保存依次执行各自的预览、写入和快照重读，不承诺整批原子成功；部分成功保留，未知写入仍用原输入及原幂等键核对耐久回执，已知回执后仅重读快照。办公坐标核对内嵌于本批阅读栏，使用已保存快照和该岗位实际引用的地点，不依赖它仍出现在当前筛选或首屏。保存新的有效办公确认后，另以准确的岗位／地点身份请求地址级地图焦点；只读快照或旧办公记录不会触发此动作。`Esc` 先从内部办公核对返回批量结果，再次关闭批量栏；输入法组合和已被其他控件处理的按键不被抢占。索引变化会清除旧选择并要求重新读取，不继续套用旧版计划。

## 电脑上的读取与核对

有岗位时，宽屏固定预留地图、结果列表、阅读三栏。单击岗位立即在阅读栏显示详情；从详情的“读取原岗位办公地点”进入同一第三栏的地址 reader，批量补全也使用该栏，三者互斥。开关 reader 不重挂地图，不移动结果列表轨道，列表滚动位置保留。地址原文、出处、预览和后续办公核对在阅读栏内正常滚动；不将这条桌面流程放到覆盖整页的大弹层。

空索引时不再占用整块空白详情栏，使用地图和结果两栏。结果区域区分读取中、未连接、索引零岗和筛选无匹配，并提供连接真实来源、配置／获取来源岗位和读取收藏单岗入口。选择真实模式而尚未连接时打开连接设置，不因此自动联网或用演示岗位填充。接入真实岗位后恢复稳定三栏，避免点击与双击期间卡片轨道移动。

reader 提供“读取公开岗位页”和“打开专用岗位页”，并有明确的加载、停止等待、错误与清理状态。读取和预览均不保存；本人核对来源及变化后单独勾选，再点击“确认保存来源地点”。仅打开或关闭 reader 不触发读取或保存。

按 `Esc` 关闭地址 reader、返回普通岗位阅读；关闭按钮具有独立可访问名称。点击另一岗位回到其普通详情，取消旧读取并隔离迟到结果。专用窗口由创建它的读取范围负责结束；清理未确认时保留可重试状态，不把其他岗位的新窗口当作旧窗口关闭。

保存回执后必须重新读取不低于回执版本及当前父版本的完整快照，才展示本次保存且仍被当前岗位引用的地点，并提供“核对这个办公位置”。快照读取失败仅重读快照，不重新保存。保存结果未知时，在当前页面内关闭再打开同一连接、同一岗位可继续核对原请求；该临时恢复状态不写入磁盘，页面刷新前需完成核对。

地址 reader 独立于岗位是否仍满足当前结果筛选。保存使岗位退出原地区筛选时，仍能完成本次地点及办公地址核对，不依赖它再次出现在首屏。连接身份、岗位、索引版本或活动页面改变时，迟到回调不能覆盖新的选择或较新数据。

## 从来源街址到地址级地图

来源地点保存后，可直接接续已有办公地址预览／确认流程。本人明确核对完整地址、WGS84 坐标及楼宇／入口／园区含义、依据链接和关联说明，独立勾选后保存。来源地址与本人核对记录继续分开，地址候选本身不能证明雇主确在该点办公。

已有有效办公地址的岗位，原生双击进入地址级视野并高亮，详情保留本人核对和待核实提示；城市分布参考继续标为城市估算，不成为具体办公室或精确离家距离。有来源街址但没有有效地址点时，优先进入核对，不被城市参考入口截获。多地点先选择本次要定位的办公室，远程资格不当办公室。

当前未内嵌 Google Maps SDK。正常地图底图可连续缩放至街道，但门牌与建筑展示取决于底图覆盖；底图能放大、来源含街址、地理编码候选匹配和雇主办公关联分别验收，不互相代替。

## 地图缩放期间的重复工作

源码核对确认，原 `onViewChange` 在相机移动结束后回调，并非逐帧触发 React 父组件。实际重复工作来自另一条路径：依赖整个 props 的地图更新 effect 会在无关父更新后重建全部点 GeoJSON，并无条件调用 `setData`，让地图 worker 再解析；鼠标每次移动又同步查询岗位点和大范围国界要素，即使相机正在缩放也照常查询。低缩放自动旋转还会在手势结束后立即恢复，与下一次滚轮或惯性动作交错。

本批将点几何、选中桶、选中地区和焦点分别比较，只有对应值发生变化才上传数据或写入样式。Hover 查询每帧最多一次，相机运动时停止查询；手势结束 700ms 后才允许恢复自转。父组件仍把相机保存到 ref，但只在跨越 zoom 10 的街道层级时更新用于界面的 zoom 状态。街道底图、最大缩放 22、现有 DPR 限制、投影和定位动画保留，没有通过降低画质或禁用地址级缩放处理延迟。

冻结性能回归为 89/89，失败／取消／跳过／todo 均为 0，并完成 types 10 项、lint 及 build 6 项。操作数量验证显示：2,000 点下连续 120 次无关更新的 `setData` 为 0；100 次鼠标移动合并为 1 次命中查询，相机运动期间查询为 0。实际 React 地图 renderer 回归还检查 30 次相机／视觉／回调更新不重建地图、不上传点、不写无关样式，真实点变化上传一次，以及地址焦点、减少动态效果、标记清理和卸载。这些结果验证减少了重复工作，尚未测得真实 GPU 帧率、滚轮端到端延迟或远程瓦片延迟，不能据此给出倍数或毫秒改善承诺。
