# 岗位地图：真实搜索与筛选接线验收

## 问题与修复

用户报告“查询、筛选目前都是假的”。原页面处于国内视图、输入 `C#`，默认真实机会库为 0 条，且没有连接本机来源索引。原主输入仅筛选当前快照，提交没有来源获取动作，页面也未说明缺数据的筛选能力。

现在输入会实时筛选已收录内容，主按钮独立执行认证来源 `sync`，完成后重新读取真实公共快照。来源按实际能力区分腾讯远程关键词与公司 ATS 列举；每次限制为配置上限与 50 条、2 页的较小值。取消、部分覆盖、失败和未知回执都保留，不回填合成数据。

新增全量快照数据覆盖统计：可比较薪资、有效汇率、可算距离、位置、已核实企业性质、工作国家和地区。没有数据时对应筛选/排序禁用并说明原因。国家筛选发送结构代码；国内默认排除国家未知项，明确勾选后才纳入。来源提供的地区/城市字段可筛选，原始位置文本不自动得到坐标。

公司名纳入共享关键词匹配。与来源配置公司名相同的搜索按公司列举，避免把雇主名当岗位关键词传给上游。`C#`、`C++`、`.NET` 保留完整技术语义，不用会改变语言含义的模糊纠错；普通中英文模糊查询继续可用。切换数据视图、来源或连接信息会中止旧请求，晚到响应不能切回旧视图。

## 真实请求与边界

本轮在原本机网页通过主按钮实际调用腾讯来源：`C#` 读取 20 条、2 页，本地完整关键词未命中，返回部分完成及页数限制；没有把官网返回的 C 端产品岗位当作 C# 岗位，也不据此推断全站没有岗位。

`.NET` 初次读取官网列表 1 条，但职责摘录未含该关键词，本地未命中。随后受控读取同一 PostId 官方详情，确认任职要求中包含 `.NET`。该真实假阴性促成有上限的详情补全；详情接线后的结果另见下面最终验证记录。

真实岗位内容只保存在仓库外私人 SQLite 中；报告不发布完整岗位正文、访问令牌或个人机会记录。既有 51JOB/BOSS/猎聘/LinkedIn 仍为单个分享链接读取与收藏，尚未实现四平台统一全站搜索。GitHub 发现结果仍是待审来源候选，不能直接计为岗位。
