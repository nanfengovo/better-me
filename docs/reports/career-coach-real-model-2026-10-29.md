## 实测发现与修复

1. **手工填写的 JD 未进入职业成长资料授权**：原先只从已启动旧匹配流程的 currentJob 取值。现在从已填完整 JD 构建待授权投影，不提前触发旧流程，不默认共享。补充工作台回归测试。
2. **小模型学习计划结构不合约且超过时间预算**：保留原有 Zod / 周预算 / 阶段覆盖检查，增加本地 Ollama 的分操作 JSON Schema 解码约束，提示词明确真实预算及逐周总和。没有以宽松解析吞掉错误。
3. **面试把评分示例的占位文字当成评语**：移除带固定示例分数的面试输出样例，改为阶段专用 JSON Schema 与评分依据说明；传给模型的历史只含题目和用户回答，不含旧模型评分；拒绝已观测到的占位文字。
4. **有效但低质量的面试反馈缺少安全重试入口**：增加「重新生成上一题反馈与本题」。保留原回答和轮数，不重复提交；有未提交回答草稿时禁用，避免覆盖。

结构化输出是本地模型的可选能力提示，最终仍以应用校验为准；不假定任意兼容网关或 Ollama cloud 支持相同参数。[Ollama 官方结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs)、[OpenAI 兼容接口文档](https://docs.ollama.com/api/openai-compatibility)。

## 五条真实模型流程结果

| 流程 | 实际结果 |
| --- | --- |
| 规划分析 | 基于合成目标及每周 3 小时限制给出方向、已知依据、待确认问题；未共享简历/岗位。 |
| 修改建议 | 首次提案把「专注于」增强为「擅长」，未采纳；重新限定纯标点后生成仅改分隔符的提案。生成后简历原文不变；人工点选「核对并应用此条」后，只有隔离示例简历的中文简介从 `全栈研发工程师 · 专注于高可用系统架构与工程化落地` 变为 `全栈研发工程师｜专注于高可用系统架构与工程化落地`。刷新仍在，原经历条目不变。 |
| 学习方案 | 2 周、每周 3 小时，每周 1 项 120 分钟的任务；在用户点击采纳前只显示预览。已采纳，刷新后仍在；两项任务均未自动标为本人完成。 |
| 学习监督 | 选第二周任务，保存 45 分钟投入与可读代码、测试结果、局限；模型返回「可以进入本人自查」，但任务状态仍是「已提交」，本人自评完成 0/2。刷新后提交与反馈均恢复。合成状态机练习的 9 个组合由终端真实执行通过，模型本身没有运行它。 |
| 模拟面试 | 2 轮逐题出题；空回答被拦截。第一轮回答先于反馈保留，首次评分占位被发现并修复、重新生成后保留原回答。第二轮实际回答后生成最终反馈与复盘，不再追问；刷新后显示已作答 2/2、已完成。 |

实际页面保存 9 条模型成功记录（各条模型均为 `gemma4:e2b-it-qat`）、1 条学习提交，面试两条回答都带反馈。备份文件位于本机 Downloads 中的 `better-me-career-2026-10-29.json`，仅供验收核对，使用时请按私人记录保管。首次无效模型结果没有计入成功记录。

### 后续修正：隔离入口的本机服务自动连接

`5193` 是完整应用却未注册 Vite 的 Agent Host / 岗位索引开发插件：Ollama 自己可用，Agent 伴侣的 CLI 运行时与岗位索引仍离线。现在从仓库根目录运行一条 `pnpm dev:isolated`，就会启动隔离页，并先探测及复用、必要时启动 `5179` Agent Host 和 `5178` 岗位服务；精确允许 `5173` 的两种本机来源及 `127.0.0.1:5193`。岗位连接仍由开发页本机专用路由提供令牌，免手填，不写入网址或长期浏览器存储。Agent Host 健康检查也验证浏览器所需跨域许可；如果端口已被未知服务、令牌不符或来源未放行，明确报错并拒绝替换它。前端关闭时只回收它自己启动的子进程。

这是**下次启动开发服务器时**生效的配置修改。若当前 `5193` 标签可能有未保存的真实简历草稿，不能为即时应用而擅自重启或刷新它；先保存或备份，再重启这个入口即可。普通项目开发仍可从仓库根目录单独执行 `pnpm dev`，无需另外输入服务令牌。前端对 Host 网络不可达与旧开发页没有索引路由的情况也改成具体启动建议，不再直接显示 `Failed to fetch` 或只让用户填写令牌。此次后续修正的定向回归与类型检查另计，不改变上面五流程真实模型验收的历史结果。

模型评分和职业判断仍可能不准确，不等于能力认证。模型没有执行学习证据中的代码；本轮由终端实际执行了合成练习的 9 个状态转换测试，并明确区分这两种证据。
