# 首次岗位基线分页加载验收

日期：2026-10-28。macOS arm64，Node v26.7.0。实现与验证位于独立工作树 `atlas-paged-baseline-lMJVL7`，基于原仓库当前未提交的各阶段改动制作；不是只基于旧 HEAD 的替代实现。

## 结论与运行边界

首次进入改为按页读取固定版本的公共岗位基线，闭合引用的首批数据先用于搜索、列表与地图，后续数据自动追加；完整读取后继续使用原有 revision 增量同步。没有实现查询索引，没有新增 UI 动画、3D 或视觉改版，也没有修改采集 / 补全调度。

**尚未合入或启用到原运行实例。** 原 Vite 会监听前端源文件并触发热更新。为遵守“不刷新当前页面、不影响未保存简历”，本轮没有修改原前端源文件、构建原 workspace dist、重启原服务、操作原浏览器标签，或使用真实数据库压测。独立补丁可在用户准备好切换时合入。

结束前只读检查原库：5490 岗、revision 3777、schema 7，26 张事实 / 工作流 / 同步表的内容散列与此前重启备份一致，epoch 一致，SQLite integrity 为 ok、外键异常为 0。原 5173 / 5178 / 5179 监听 PID 仍为 29285 / 10262 / 34879。

| 边界 | 本轮实现 | 明确不包含 |
| --- | --- | --- |

| 存储读取 | `dataset-baseline.ts` 在独立只读连接上按主键 / keyset 遍历岗位及依赖，固定 epoch / revision | 整库导出、整库投影、数据迁移、写入队列 |

| 浏览器读取 | `baseline-reader.ts` 验证每页、累计预算和版本，按几何间隔发布闭合前缀 | 每网络页重算整库、持久化半份游标 |

### 分页与一致性

- 新增认证只读入口 `POST /api/v1/dataset/sync-page`、`POST /api/v1/dataset/baseline`、`POST /api/v1/dataset/baseline/close`，沿用现有 loopback、Host、Origin、Bearer、预算及独立只读计算线程。
- `sync-page` 在需要初始 / 重置基线时仅返回 `baseline-required`，不会先构造完整快照。旧 `/dataset/sync` 与 `/dataset/export` 保持兼容。
- 初始种子 64 岗，之后每组最多 256 岗。正常每页最多 256 个公共实体、512 KiB 预算；不截断不可分割的长 JD，单个大行有 16 MiB 特例上限。一页不等于固定岗位数，因为还需企业、来源、地点、listing、观察和正文证据。
- 按引用图排队并去重，跨岗位证据、企业父级、循环引用闭合后才发布查询前缀。脱离岗位的企业、停用来源和历史记录在尾部按 keyset 补齐，不遗漏、不使用 OFFSET。尾部每次最多扫描 2048 个 ID，避免每个已传范围都发空响应。
- 每个会话使用同一个 WAL 只读事务，分页期间并发入库不会混入另一版本。完成后以其固定游标接入原 delta 流，补齐期间的新提交。
- 会话绑定执行身份，最多 4 个活动会话、30 秒空闲 TTL、120 秒绝对寿命；完成和主动取消会释放连接。只缓存上一页用于相同序号重试。取消、错误或会话过期不会推进完整游标；已展示的只读前缀可保留并明确提示未完成。
- 只在首批、几何增长的闭合检查点和最终完成时通知界面，不按每个 HTTP 页触发查询。15000 岗本次发布前缀为 64、320、832、1856、3904、8000、15000。后续页不再回传已展示岗位，最终也不重传完整基线。
- 旧服务只有明确 404 / 405 才降级旧同步；认证、预算、格式和网络错误均不绕过分页限制去下载整库。

固定读取版本采用 SQLite 既有隔离机制，见 [SQLite isolation](https://www.sqlite.org/isolation.html)。读者不阻塞 WAL 写入，但长读事务可能延迟 checkpoint，因此设置主动释放及绝对寿命，见 [SQLite WAL](https://www.sqlite.org/wal.html)。这不等于承诺任何读取都没有磁盘或 CPU 竞争。

## 性能验证：5000 岗与 15000 岗

独占临时 SQLite、正常 Job Service 生命周期、实际独立读 / 写线程、真实 HTTP、真实 Node Worker。数据由 `syntheticAtlas` 生成，只有 `.test` 合成链接，不访问真实招聘平台、不导入用户库。每个发布前缀实际查询 C# 和 TypeScript，验证 30 条列表及地图几何；首次可用耗时从已有服务发起初次同步开始，到首个 C# 列表 / 地图结果返回，不包含造库、服务启动、Vite 编译、地图瓦片下载或首个浏览器绘制。

| 首批可用前下载 | 169517 B，165.5 KiB | 171090 B，167.1 KiB |
| 旧完整同步 + 首次查询参考 | 3964ms | 14244ms |

| 首批可用前字节减少 | 98.71% | 99.57% |
| 新分页完整读取，含每检查点两次查询 | 6908ms | 20185ms |
| 新分页完整累计响应 | 13165453 B | 39675254 B |
| 网络分页数 | 133 | 397 |

| 分页读计算线程累计处理 | 1197ms | 4854ms |

这些是本机单次回放，不是跨设备 SLA。首次可用前的字节下降不等于完整下载减少 99%；完整加载的总字节略多，分页增加少量封装开销。新流程在每个前缀做两次交互查询，旧参考只做完整加载后的一次查询，因此不能用两种“完整耗时”直接声称总加载更快。收益是用户不必等完整库才开始浏览；既有查询算法仍会在大前缀上花时间，未将查询索引优化混入本轮。定时器间隔不是浏览器 FPS 或 Long Tasks 测量，不能据此声称零卡顿。

原始结果：`output/atlas-paged-baseline/scale.log`，显式开启压测后 1 项通过、0 失败、0 跳过，同时覆盖两种规模。整条测试约 117.5 秒，包含造库、服务启动、两个流程以及完整导出比对。

### 过程中发现并解决的分页开销

最初 5000 岗需要 279 个 HTTP 页，含多次交互查询的完整读取约 108.6 秒，15000 岗超时。500 岗最小回归确认出现 30 页；调整种子批量并合并有界尾扫后降至 15 页。随后独立测得，服务端处理只占很少时间，分页之间额外的 `setTimeout(0)` 在本机后台 Worker 中出现接近半秒的空档。移除这处多余定时器后，500 岗 HTTP + 单次前缀查询对照从约 4.16 秒降至约 0.73 秒；真实 HTTP 本身仍异步，Worker 分块 ACK 和界面表级让出仍保留。没有通过增加 120 秒超时来掩盖失败。

本地视觉夹具为 `apps/web/tests/fixtures/atlas-baseline-preview.ts` 和 `output/atlas-paged-baseline/preview.*`，仅用于本独立工作树，不随生产补丁启用。结束时关闭自建浏览器标签和 5296 预览进程，通过自身正常关闭流程清理可再生的临时合成数据库。原服务、数据与用户页面继续保持原状态。

保留边界：超大单个引用连通图仍可能推迟第一个安全前缀；不是任何库都保证恰好先显示 64 岗。分页完成仍需传完整公共库，当前默认累计预算 64 MiB、最大活动寿命 120 秒；长文本较多或低性能设备可能达到预算，需要明确重试 / 预算策略，不能静默截断。查询索引、完整浏览器大库帧率分析和视觉动效仍是后续独立阶段。
