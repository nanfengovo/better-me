# 岗位地图与来源工具：本机使用说明

岗位地图与原有“机会与投递”共用岗位数据契约和来源证据。本机网页首次打开“岗位地图”会自动通过同源后端读取**本机采集索引**，无需网页填写令牌；顶部“本机后端 · 自动”只是状态入口，不是必须执行的连接步骤。此前显式选择的机会库／演示及成功手动会话继续保留。合成演示需要手动选择，不计入真实岗位，也不能收藏或进入 JD 分析。

截至 2026-10-19，国内省市区筛选、企业招聘入口发现、已启用来源的聚合读取、逐源进度与岗位详情 / 地图定位已接线。四平台返回的卡片与已入库岗位分别显示；有企业字段的卡片可以经过预览和明确确认，作为待核实摘要加入统一索引。已入库地点还能经过本人核对保存可撤销的国家 / 省市区选择，用于国内地区筛选，不自动生成办公坐标。官网来源已有有限真实索引验证；四平台真实列表、审核入库和地图位置证据仍需分别验收，不能把前端面板或合成测试当成四站实际搜索成功。当前地区与薪资修复见[地区确认报告](reports/job-atlas-location-confirmation-2026-10-19.md)，卡片语义见[审核入库报告](reports/job-atlas-reviewed-cards-2026-10-19.md)，前批交互见[聚合与交互阶段报告](reports/job-atlas-aggregation-interaction-2026-10-19.md)。

通用 JSON 来源现在可按配置保留每个地点的国家、城市、地区、地址和字符串邮编；索引、来源范围与网页地区查询采用同一地点字段，地址披露可接续现有办公地点核对。旧文本映射保持兼容，来源字段不等于精确办公室，远程资格不能当办公地址；配置见[来源适配器](../packages/source-adapters/README.md#json-结构化地点)，验证范围见[本批报告](reports/job-atlas-json-locations-2026-10-22.md)。当前运行中的本机后端需要由原管理者加载新版，旧来源也须明确核对映射，本批没有自动刷新或升级原服务。

## 选择数据入口

| 数据视图 | 如何使用 | 保存与边界 |
| --- | --- | --- |
| 当前机会库 · 真实来源 | 显式选择此视图；收藏岗位后点“重新读取机会库” | 只在页面内存中投影公司、岗位、来源、原文地点与时间；不写回原库，不复制联系人、投递进度或个人材料 |
| 本机采集索引 · 真实来源 | 本机网页首次自动读取；顶端“本机后端 · 自动”可查看状态或重试；高级直连只用于静态网页／特殊回环地址 | 读取服务的公共快照，在浏览器执行共享筛选；采集数据持久保存在仓库外 SQLite 中 |
| 合成演示 · 仅体验地图 | 在“数据视图”手动选择 | 岗位、公司、薪资都是合成样本，用于体验视图与筛选 |

若搜索仍只显示自己收藏过的少量岗位，先核对“数据视图”。本机网页默认连接索引，显示岗位数与版本；后端未就绪时显示数量未知及“重试自动后端”入口，不能解释成市场零岗位。岗位服务仍需启动，自动读取不会自动采集。默认网关的凭据由宿主管理，手动地址与令牌在“高级直连”折叠区；配置见 [job-service](../apps/job-service/README.md#网页默认后端) 和 [本批报告](reports/job-atlas-default-backend-2026-10-21.md)。

空机会库会显示空状态，不自动补入示例。库损坏或版本不兼容时会提示读取失败，原始存储不被覆盖；到“机会与投递”先下载损坏原文或有效备份，再按恢复流程处理。

### 搜索与筛选的区别

| 操作 | 读取什么 | 会否更新本机岗位索引 |
| --- | --- | --- |
| 输入关键词 / 调整地图筛选 | 当前数据视图已收录岗位 | 否 |
| “从来源获取岗位” | 全部或指定的已登记、启用的官网 ATS / 受控来源 | 会，各来源独立执行有限同步，逐源返回后更新快照 |
| 来源工具的“继续上次扫描” | 原扫描范围内保存的下一页或待重读页 | 会，明确执行一批；不采用新填写的关键词／地区／企业条件 |
| “读取原站搜索结果” | 本机专用浏览器当前页的四平台可见卡片 | 否，保留在面板，另行显式核对 / 收藏 |
| “核对并加入统一索引” | 本人选择并核对的卡片字段及原文证据 | 预览不写入；勾选确认并提交后写入本机索引 |
| “查找企业招聘来源” | 已有公司来源或明确官网的有限招聘入口 | 否，返回已有来源、待审证据或禁用提案 |

输入框会实时筛选当前视图已收录的岗位；**“从来源获取岗位”会发起真实来源请求**，将已确认匹配的有限结果写入本机索引，再读取新快照。本机网页自动读取后端，未就绪时先启动岗位服务并重试；静态网页需高级直连。来源选择器默认“已配置岗位来源”，也可只选一个；不会自动启用配置、搜索任意域名或将 GitHub 仓库候选当作单岗。腾讯官方适配器把关键词发送给官网；Greenhouse、Lever、Ashby 按已配置公司的 board 列举，关键词在读取记录中匹配，不能代替全市场搜索。

“来源读取范围”提供“按来源配置读取”和“快速”两档。前者在来源配置内最多 500 条 / 20 页，后者最多 50 条 / 2 页；两档都取已保存的更小额度，也受共享请求、字节、速率和时间预算限制。“本次实际读取范围”可展开查看逐来源条数、页数及配置中的详情上限。因此，配置只允许 2 页时，前者仍然只能读取 2 页。

结束后进度面板默认收起逐源明细，保留部分覆盖、超时及待核对摘要。**原始返回条数不等于关键词命中数**。有待核对项时，可点“查看…未核对候选”，再明确选择“重新预览一页”。这会重新读取当前一页，并显示绑定的关键词 / 地区 / 公司与新读取时间，不是重放上次回执。候选按待核对、已读字段命中和条件排除区分；提供纯文本和安全原文链接，不写规范索引或地图。“核对后预填机会”只打开人工草稿，仍需按机会表单保存。新一轮搜索会关闭旧候选面板。

聚合任务最多同时等待两个来源。每个来源分别显示排队、读取、部分完成、失败、取消或最终状态，以及真实读取条数、页数、新增和变化；先返回的结果先更新索引与列表，一个来源失败不直接中止其他来源。“已返回”只计算实际收到的来源回执；进度条按结束等待的来源数计算，包含失败和取消，不能当成功率或市场覆盖率。已用秒数是实际计时，不是剩余时间估计。来源警告、错误与限流建议可展开查看，缺失计数不补成零。加载期间提供骨架、雷达和过渡动画，系统选择减少动态效果时停用。

本地岗位文本和索引查询共享分词规则：同一个输入的多个词按 AND 匹配，可以分别出现在标题、要求、企业或已披露地点中；多个独立关注条件之间保留 OR。普通文字支持有限模糊匹配，`C#`、`C++`、`.NET` 保留精确技术含义。例如标题是“后端工程师”、要求写“熟悉 C#”，可以命中 `C# 后端`；仅有 C++ 或“C端产品”不能命中 C#。地区与企业的独立筛选仍使用明确原文，不随岗位关键词做模糊改写。上游查询自身可能宽匹配，上限内零匹配只说明本次有限读取无命中，不表示全站没有岗位。

“当前索引筛选覆盖”按当前数据视图全量统计，与分页无关。缺可比较年薪、有效汇率、可用坐标或控股证据时，对应筛选/排序显示具体原因，不生成替代值。岗位信息源下拉只列出已有岗位的来源；来源搜索下拉列出可以实际调用的已启用来源，两者用途不同。国内视图默认排除国家 / 地区未知项；未指定明确国家或省市区时可显式纳入，指定范围后未知项不能满足该条件。仅有“上海”原文或浏览器的国内分组不自动成为国家证据。

切换关键词不清空旧索引；列表按当前全部已收录岗位重新筛选。一次来源搜索失败会显示错误并保留已读快照，取消可能已提交部分结果。网络回执不明或回执仍为运行中时，相同请求重试沿用幂等键；明确结束后再次点击产生新的刷新请求。取消只结束本次等待，未收到回执的来源会提示重新读取索引核对，不把取消当数据库回滚。索引展示刷新失败与来源采集失败分开提示。

### 国内省、市、区县与平台地区

国内视图可在没有已收录岗位时预先选择省 → 市 → 区县。更改上级会清除失效下级；选择区县时，只有城市原文、没有相应区县依据的岗位会被排除。国家与各层地区条件必须落在同一个工作地点，不能拼接多个办公室形成匹配。全球视图可选国家 / 地区并输入城市关键词，选项不依赖当前索引是否已有该地区岗位。

大陆目录使用固定的 2023 统计区划快照，部分末级为镇街 / 功能区，不能全部称为现行法定区县；港澳台保留地区级选择，下级目录待补。来源、时点、许可和哈希见 [source-manifest.json](../config/geography/china-administrative/source-manifest.json)。筛选时目录仅用于选择和文本匹配；另行核对并保存地区后，结构化字段明确标为本人确认，仍不生成坐标或声明来源已核实。

平台搜索另有独立的地区映射：空关键词可按已选地区浏览；北京、天津、上海、重庆使用实际直辖市名称发起请求，不将上游分组名“市辖区”发送给平台；香港保留实际 `HK` 条件。一个地区可在地图筛选，不代表四个平台都有对应代码。未知或冲突地区继续阻断，不静默回退；未指定地区时需到原站核对默认地点。

### 51JOB、BOSS、猎聘与 LinkedIn 手动分页搜索

1. 展开“51JOB · BOSS · 猎聘 · LinkedIn 原站搜索”，确认当前关键词与地区。外部“打开原站搜索”只打开原站链接，不导入岗位。
2. 使用“读取原站搜索结果”选择支持的平台，点击“搜索并读取当前页”。该功能需要成功运行更新后的本机 Vite 浏览器宿主；独立岗位索引服务本身不提供此浏览器接口。
3. 需要登录 / 人工验证时在专用窗口完成，再点击“再次读取当前页”。在原站手动翻页后，先再次读取以检查当前页面；确认后点击“追加当前页”将它纳入本次部分批次。工具不会自动翻页。
4. 核对原站单岗链接、标题、企业、地点 / 薪资原文和卡片证据；每次最多读取 50 张可见卡片，成功仍为部分覆盖。登录、验证、未知布局和明确空结果分开显示。
5. 使用“核对并收藏此岗位”把所选卡片预填到既有机会流程，继续核对后显式保存。若已披露企业，还可使用“核对并加入统一索引”，按下方步骤审核后写入本机岗位服务。卡片是摘要，非完整 JD；读取搜索结果本身不会自动入库或生成地图标记。

在原站手动翻到下一页后，点击“追加当前页”才会把该页加入同一搜索批次。批次按搜索条件、平台、官方搜索 URL 和读取顺序绑定，保留每页自己的读取时间、页面 URL、卡片证据和状态；显示的“第 N 次读取”是本工具的记录顺序，不声称对应原站页码。“再次读取当前页”只替换当前查看结果，不会隐式增加页数。面板可以切回之前已读取的页面，使用该页原始回执逐页预览、确认和导入；同一页面重复追加会被拒绝，关键词、地区或路径变化也会拒绝。批次只表示用户明确读取过的部分页面，不自动翻页，也不表示平台全量覆盖。

初次加载原站时，面板会显示等待动画并核对当前可见结构；遇到 `unknown_layout` 最多被动采样至固定的 8 秒宽限期结束，结构变化不会无限续期。可读卡片或明确空结果仍需稳定 800 毫秒。工具不会为此自动点击、翻页或另开原站页面；登录、验证和链接 / 可见性限制保持原规则。取消等待后保留原会话，可在原站加载完成后明确再次读取。

响应未知时，面板保留本次原条件和请求标识，“重试恢复本次搜索”恢复同一次启动；修改上方筛选不会改写原会话。“取消本次等待”只中止等待；“结束本次搜索请求 / 会话”按原绑定取消并等待关闭确认。取消最多等待 8 秒，超时仍保留绑定可重试；组件卸载会尽力发出精确取消，不代表已收到关闭回执。详情与搜索共享浏览器占用，需结束当前会话再发起其他用途。

**四站完整验收仍需逐站完成。** LinkedIn 默认美国单页 50 卡、猎聘 C# 上海单页 22 卡已有有限证据；本轮加载宽限修复后，正式主 UI 的猎聘搜索首次读取即显示 22 卡。51JOB / BOSS 仍未完成真实列表验收，更多地区与长期稳定性继续核对。既有单岗成功样本、官网索引、审核入库工具或合成面板测试均不能替代它；执行端未启动、旧服务返回 `404`、门禁或布局不识别都不能解释为“该地区 0 个岗位”。最新范围见[卡片审核入库报告](reports/job-atlas-reviewed-cards-2026-10-19.md)与[四平台阶段记录](reports/job-atlas-platform-search-2026-10-18.md)。

### 核对卡片并加入统一搜索

1. 先连接本机岗位服务，勾选当前成功读取且有明确企业名称的卡片，或使用“全选本页可入库岗位”，点击“核对并加入所选…个岗位”。每批最多50个；也可继续使用单卡“核对并加入统一索引”。缺企业的卡片保留原文与回链，继续使用原有机会草稿核对流程。
2. 核对岗位名称、雇主、地点 / 薪资 / 发布时间原文，展开“核对实际卡片原文”，按需要打开原岗位链接。读取时间和发布时间分开显示。
3. 点击“预览入库变化”。预览只检查输入和当前索引版本，显示新岗位 / 已有岗位、来源和限制，不联网重抓或写入数据库。
4. 勾选“我已核对来源和卡片字段，确认以待核实摘要加入索引”，再点“确认加入统一索引”。成功后重新读取真实索引，后续关键词、企业和地点原文查询使用同一套岗位数据。
5. 回执丢失时使用“重试本次写入 · 核对回执”，沿用原内容、版本和幂等键。在当前工作区恢复原写入前，不能关闭核对面板、换卡片批次或切后端。若收到权威的版本变化拒绝，重新读取索引、预览并核对；已显示写入成功而页面刷新失败时，只需“重新读取索引”。恢复凭据仅在本页内存，刷新或离开整个工作区不能当作已恢复或撤销。

选择绑定本次成功捕获；重新读取、失败或结束会话会清空选择。同一捕获改选后，旧的预览和勾选确认不会用于新批次。批量审核仍需展开逐卡原文，不自动读取完整JD或补造地点。分页配置、真实公开探测与交互验证见[本批报告](reports/job-atlas-json-pagination-batch-2026-10-22.md)。

这条通路接受**用户提供并明确核对的证据**，不能认证输入一定来自受管浏览器，也不能据此证明岗位仍在招。记录保留原平台、搜索页、单岗稳定 ID、原文链接、逐字段证据和卡片摘录；来源元数据不安装采集权限，不能直接用于自动刷新。重复核对同一捕获中的不同卡片子集不会重复追加相同观察；内容变化保留新的观察。

卡片只以 `excerpt`、未核实状态入库；已有完整 JD 不会被卡片摘要替换。薪资保留原文，不推断币种、数值、周期或税制。发布时间不从“刚刚活跃”等状态或读取时间推造，相对日期和无时区原文保持原文。仅有“上海-浦东新区”等地点文字时不自动补国家、省市区事实或坐标，因此可能无法满足国内 / 国家 / 结构化地区筛选；可先在全球视图按关键词和地点原文查看，再按下节显式确认。缺坐标的岗位保持待定位，不产生办公室地图点或离家距离。

### 核对并保存岗位地区

此操作需要已连接的真实本机索引。打开岗位详情，在具体工作地点下点击“核对并保存地区”；当前机会库和合成演示不能借此修改本机岗位库。

1. 对照来源地点原文和原岗位页面，选择地点性质与国家。只知道工作地区时可保持“尚未确认性质”；远程资格范围不能选为办公室。
2. 中国大陆可按省 → 市 → 区县选择，海外可填写明确的地区、城市和区县。仅披露上级就停在该级，不补造下级；改变国家或上级会清除不兼容选择。直辖市使用实际名称，目录分组与镇街 / 功能区保留其原含义。
3. 填写“核对依据或说明”，点击“预览地区变更”，检查原始 / 当前 / 拟保存的地区与精度。预览不写库；修改输入后旧预览失效。
4. 勾选“我已核对原岗位，确认保存上述地区选择”，再点击“确认保存地区”。写入后重读索引，同一套国家和省市区条件即可筛选该岗位。原文与来源证据不改写，详情明确标为本人确认、待核实。
5. 需要恢复时，在该地点的核对面板填写说明，单独勾选撤销并点击“撤销当前地区确认”。撤销会恢复上一条有效选择；全部撤销后恢复原来源字段，可能再次被明确国内 / 地区条件排除。

地区确认只保存行政范围，不生成来源坐标或离家距离。本次投影会移除已有坐标，避免新地区继续使用旧点；原始坐标保存在来源层，全部撤销后恢复。另有独立的城市分布参考投影：明确国家与城市可离线唯一匹配时用于地图估算展示，不持久保存为办公坐标，规则见下节。

版本改变时重新预览；回执丢失时用“重试本次地点写入 · 核对回执”沿用原内容和幂等键。已经显示保存成功但页面刷新失败时，只需“重新读取索引”。关闭或取消等待不等于数据库回滚。来源刷新若仍是同一原地点，保留确认；原地点变化形成新身份后须重新核对。缺少来源证据或无法唯一确定来源归属的旧数据会拒绝写入，避免错误覆盖。

本轮已在真实猎聘岗位完成上海市 / 浦东新区确认、国内筛选与服务重启后的保留，再明确撤销恢复未知来源地点；这是一个来源地点的有限闭环，不能代替所有地区和地图精确地址验收。详见[地区确认报告](reports/job-atlas-location-confirmation-2026-10-19.md)。

### 城市分布参考与办公室坐标

连接真实本机索引后，页面按当前版本只读加载独立城市参考，显示加载动画，可取消或明确重试。明确国家内唯一匹配完整城市名／真实别名才生成参考；不根据原始地址猜国家，不自动采用歧义候选。已有来源坐标优先；完全远程岗位、远程资格范围、冲突或缺少城市的地点继续保留原因。

“地图可展示”按来源坐标与城市参考的岗位并集去重，下方分别列出两类数量。城市点、卡片与详情明确标记“城市分布参考／城市级估算”，并提供地名数据出处。双击可直接定位、高亮城市，相机不高于城市级 zoom 9；手动放大底图不会提升岗位地址精度。**城市参考不修改来源地点、不确认办公地址，也不参与离家距离。**

一次最多处理 1,000 个地点，超出会显示实际处理范围，其余仍待定位。参考绑定快照和完整地点指纹，地区或来源改变即失效。旧服务不支持接口时会提示更新并重启，岗位列表继续可用；失败不自动循环重试。详见[实现与验收报告](reports/job-atlas-city-references-2026-10-19.md)。

搜索面板下方“读取 / 收藏单个岗位”进入“机会与投递”。在“导入 JD”粘贴单个岗位链接、分享消息、正文或截图，按既有浏览器流程核对完整原文、链接、地点与源时间，再显式收藏。返回地图选择“当前机会库”，点“重新读取机会库”查看公共字段投影。未知发布时间不从抓取时间推算；截图、OCR 或模型整理仍需人工核对，不会自动投递。

## 核对来源薪资

在本机真实索引的岗位详情中选择“核对来源薪资”，先读取本条披露的来源依据与历史。金额、币种、周期、税前／税后、工资组成及保证计薪数量分别绑定原岗位已保存的观察或正文原句；填写核对说明后预览，另行勾选本人核对再提交。未披露字段保持未知，不能仅凭勾选或平台惯例补出税前、固定工资或保证13薪。

保存及撤销后重读索引，详情、覆盖数、薪资筛选、排序、分页和地图使用同一有效值；本人核对仍为待核实。缺保证月份的月薪不静默估算为12薪，奖金、股票及总包不当作固定税前年薪。外币保留原币，参考汇率快照管理已接入，见下文的薪资与距离说明。来源原文、JD和地点适用范围不被核对改写。

回执丢失时保留原内容和幂等键核对；保存已确认但索引读取失败时，只重新读取索引。来源变化会永久失效旧核对，A→B→A不复活。公共岗位JSON只有有效投影；保留核对历史和撤销能力须使用服务完整备份。操作示例、四工具和验收边界见 [薪资核对报告](reports/job-atlas-compensation-review-2026-10-21.md)。

## 连接本机来源服务

使用 Node.js 24.15.0 或更新的 24.x，或 Node.js 26+。先按根 README 启动 Web 工作台，再在仓库根目录运行：

```powershell
$atlasDataDirectory = Join-Path $env:LOCALAPPDATA 'BetterMe\job-atlas'
pnpm --filter @better-me/job-service start --data-dir $atlasDataDirectory --origin http://localhost:5173
```

选择仓库外的私有目录，并按[服务说明](../apps/job-service/README.md)限制 Windows NTFS 权限。已有数据库或目录锁应保留并核实归属；端口被占用时先检查监听进程，不通过删除锁或停止其他程序来强行启动。

本机网页默认由同源网关读取服务端令牌文件，无需在地图填写令牌。服务日志会显示实际地址、数据库与**令牌文件路径**；只有选择高级直连时，才从本机文件读取令牌并填入高级设置。默认服务地址为 `http://127.0.0.1:5178`，以实际日志为准；API 的 Host 校验不接受 `localhost`。

允许 Origin 必须与浏览器地址栏一致。例如 `http://localhost:5173`、`http://127.0.0.1:5173` 是两个不同 Origin。需要多个时重复 `--origin`；不能加路径、末尾 `/` 或通配符。Pages 的 Origin 是 `https://nanfengovo.github.io`，不含 `/better-me/`。公网 HTTPS 页面访问本机可能受到浏览器本地网络授权限制，本机网页优先。

只有本人明确连接且成功读取索引后，地址和访问令牌才写入当前标签页的 sessionStorage；同一标签页刷新会恢复该 loopback 根地址的连接，不写入永久 localStorage、网址、JSON 配置或 Git，也不传给招聘站、GitHub 或地图服务。这不是跨设备或关闭浏览器后的永久保存。切换“当前机会库”或“合成演示”会移除会话中的凭据并保留所选视图；“断开并清除会话连接”同时清空页面令牌。修改地址或令牌会使旧连接失效，需重新连接。损坏、未来版本或非本机地址的会话不会自动请求网络；浏览器禁止会话存储时，本次连接仍可使用并明确提示刷新需重连。恢复失败保留本机索引视图、显示错误和重试入口，不拿旧机会库冒充已读取索引。旧页面没有历史记录，升级后仍须先连接一次。本机客户端拒绝重定向，不携带浏览器 Cookie。家庭参照坐标由浏览器本地计算，不作为来源查询参数发给服务。

默认使用系统 DNS。只有确认 Fake-IP 等解析问题后，才显式添加 `--dns google-doh`；它仅影响该服务的受控请求，不修改系统 DNS 或代理。完整参数、认证 API 与故障说明见[岗位服务 README](../apps/job-service/README.md)。

早期本机有限索引的阶段记录为 **36 岗、revision 10**，其中腾讯 8、Duolingo 8、Linear 20。这里只公开来源与计数，不发布岗位全文、真实令牌或私人材料；它不是全市场覆盖，也不等于岗位已独立核验在招。早期 28 岗 / revision 5 的原始联调条件保留在[本机索引报告](reports/job-atlas-real-local-index-2026-10-18.md)，属于历史快照；本轮扩展后的49岗 / revision22、9个可搜索来源与C#13个文本命中 / 8家企业见下方来源目录段及召回报告。

## 使用官网 ATS 与 GitHub 通用工具

连接后打开“来源工具”。已安装适配器包括 Greenhouse、Lever、Ashby、腾讯招聘官网关键词查询、可配置 JSON 和 GitHub JSON 线索；同协议的新公司主要增加配置。它们不是每个平台或每家公司都支持的统一搜索接口。

1. **检查配置**：将 [config/sources/examples.json](../config/sources/examples.json) 中合适的完整来源 JSON 放入“来源 JSON 配置”，点“检查 JSON”。示例默认禁用；先核对公司 board、精确允许域名/路径、许可、使用范围、数量上限和启用状态。Lever 示例是官方演示，不能当真实招聘。数组必须逐项选择并保存。
2. **有限预览**：设置关注关键词、地区、公司与记录上限，点“预览一页 · 不写入”。同时查看上游读取数、返回数、本地命中数和上游实际应用的条件。某些 ATS 一次下载公司整个 board，再只解析有限记录；不能把“解析上限”当网络读取数量。
3. **手动刷新**：确认后点“手动刷新并更新地图”。每次新刷新从头开始，查看 run 状态和新增数量。`partial`、`failed`、限流或需登录均按原结果显示；一次有限刷新不代表完整覆盖，也不会把未出现的旧岗位全部关闭。
4. **发现来源**：选择已配置 `discover-sources` 能力和受控端点策略的来源，输入 GitHub 搜索条件，读取仓库候选。可有限检查候选文件，也可指定样本 URL；URL 仍受该来源的允许域名与路径约束。
5. **审核提案**：候选可生成禁用、待审核 JSON 提案，随后另行检查和显式保存。仓库、公司清单、校招活动、方向性线索不直接计为真实单岗；仓库活跃时间和代码许可证不等于岗位更新时间或正文再分发许可。

JSON 只描述配置，不能下载或执行陌生适配器代码。真实凭据应放在本机秘密存储并使用引用；不要填入公开 JSON。纯发现配置未提供列举端点或有效映射时，“预览/刷新岗位”保持不可用。

### 继续上次扫描

V8 后端为来源保存分批扫描位置，解决有限读取反复只覆盖清单前部的问题。在“来源工具”选择原来源，点“读取扫描进度”核对已保存关注条件、累计尝试数和处理页数；进度可继续且原任务已结束时，再点“继续上次扫描”。它继承原关键词、地区、企业及明确国家条件，只使用当前填写的本批记录／页数上限。修改关注条件后应明确从头刷新；继续不会偷偷采用新条件，也不会自动循环读取全部页面。

`ready` 表示还有下一页；`retry-page` 表示原页未完整读取，继续时会重读并按原身份去重。`truncated` 表示仍为部分覆盖、适配器没有可继续位置，不能当作已读完。`exhausted` 只表示适配器报告本次受审清单已到末尾。`invalidated` 表示原位置因来源配置、新扫描或清单变化永久失效，应核对后另行从头刷新；配置或清单后来恢复也不会复活旧位置。累计尝试包括重读和失败，不是新增岗位数或唯一命中数。

每批继续同样遵守原来源最小刷新间隔、速率、记录／页数和宿主请求／字节／时间预算；间隔内拒绝不代表没有岗位。JSON-LD 详情超时保留已读内容与原页起点，等待本人明确继续。停止等待或关闭面板不撤回已提交页面；响应未知时保留原 body／幂等键核对原回执，原任务仍在运行就继续等待，不新建任务。终态回执可信后，仅重读索引与进度。关闭面板、切换视图和工作区重挂仍保留同连接的内存恢复屏障；整页刷新或浏览器关闭不保证保留前端请求，后台耐久回执仍在。

旧服务缺进度／续读路由时会提示更新后端。已经取得可信终态回执和新索引后，即使进度接口不可用，也不重复写入；当前进度保持未知，不能当成扫描结束。V8 完整备份保存私有扫描历史与回执，公共岗位导出不包含这些信息。接口、升级和有限测试范围见[来源扫描续读报告](reports/job-atlas-scan-continuation-2026-10-22.md)；升级前按[服务说明](../apps/job-service/README.md#一致性备份与部署)完成完整备份与隔离验证，不能用旧代码直接打开 V8 库。

腾讯来源将每个岗位关键词分别传给官网固定 HTTPS Query 端点；地区、公司和明确国家条件在已读取记录中本地筛选。它的 `C#` 等符号关键词可能返回宽泛结果，界面中的本地命中数与上游 `Count` 应分开理解；未翻完的页数不代表全量覆盖。默认获取职责摘录；显式配置 `fetchDetails` 且允许官方详情端点后，可按上限补全要求，默认每页最多 2 个详情，其余保持未完整读取。有限详情优先用于已披露公司 / 地点符合范围、但要求尚未读且摘录未命中的候选；已知摘录命中排在其后，已披露地点不符的候选不占这些名额。返回列表仍保留原站顺序，详情保持原岗位身份与字段证据。

未补全的要求可能包含关键词。工具分别计数已命中、无法确认和明确排除的已读候选；无法确认不算正式关键词命中，警告会说明仍有多少摘录未能核对。完整详情也没有该词，才可在本轮已读内容范围内作排除。保留官网更新时间原文，`DateCreated` 语义未核，不用作岗位发布时间。只有源国家字段明确为中国才进入有证据的国内范围；没有薪资、坐标、控股方证据的筛选仍保持未知。有限真实请求和具体限制见[腾讯关键词验证报告](reports/job-atlas-tencent-search-2026-10-18.md)。

点“取消操作”或关闭来源面板会取消尚未完成的请求。切换工作区会保留面板状态，已明确发起的本机操作可能继续；需要停止时先取消或关闭面板。已提交到 SQLite 的部分结果可能仍保留，应重新读取快照核对；取消不是数据库回滚。来源工具修改的是本机采集索引，浏览器旧机会库继续保留自己的投递进度和材料。

### 企业官网招聘入口发现

在“来源工具”展开“企业官网招聘 · 查找入口与已有来源”，先读取本机搜索配置。未知、读取失败、未配置和已配置分别显示；“已配置”只表示设置，不代表网络可用。仅填企业名不需选择发现策略：先匹配已登记来源；没有已启用且 active 的匹配时，使用宿主显式启用的 SearXNG 或实验 DuckDuckGo HTML。默认未配置时，陌生企业会提示补充官网或配置搜索，不猜域名。

点击“查找企业招聘来源”才发起发现。结果分别显示搜索线索数和官网实际读取页数；线索不当岗位或已核实官网。已有匹配中至少一条已启用且 active 时，工具优先返回；界面还要求该来源具备 `list-jobs` 能力，才显示“使用此企业来源”。禁用、待核实或不可用匹配仍展示原状态，但不会阻断本次明确官网或受信搜索的受限发现。新候选需核对原链接、归属、使用条件和协议，“检查禁用配置”只预填审查流程，不注册或启用。普通 HTML 入口仍需配套解析器。

显式官网／seed需已启用且允许精确主机／路径的独立访问策略；GitHub策略不会因填写官网而扩权。可将[默认禁用示例](../config/sources/company-career-discovery.example.json)导入“来源JSON配置”，把占位主机／路径改为已核对的官网范围，明确设置enabled:true／status:active，检查JSON、勾选核对后保存；再在企业发现表单中选此访问范围。`discovery-policy@1`只声明`discover-sources`，不能预览／同步岗位，不会被算作企业招聘来源或加入批量岗位刷新。发现新招聘入口后仍须另行核对并登记真正的岗位适配器。

每次搜索只读一页，最多20条，保持覆盖不完整。关闭、编辑、取消、重读配置或改变服务身份会中止旧发现并拒绝迟到结果。验证、限流、网络和结构变化单独显示，不解释成零岗位；“未发现”只描述本次有限范围。

## 扩展可搜索来源

在“来源工具”展开“已保存发现线索”，可查询先前扫描实际保留的 GitHub 条目、公司目录或招聘批次。支持关键词、来源、类型与稳定分页；浏览本机记录不会重新访问外站。选择线索后，仅显示已启用、装有原页读取能力且链接范围匹配的独立原来源。

接续顺序为：核对线索 → 明确选择原来源 → 读取原岗位 → 对照标题、实际雇主、原编号、正文与字段证据 → 预览 → 勾选确认保存。当前使用线索保留的 `record.url`，不自动替换为申请入口或猜测官网链接。本版支持配置过的 JSON-LD 与 SmartRecruiters 原页；没有可用来源时先审核配置，仅有首页／招聘活动线索、返回多个岗位或缺少原身份时，仍需继续核对；必须另读到唯一完整 JobPosting 才能预览入库。四平台人工登录／验证读取保留原流程。

确认后使用原来源的岗位身份去重，同时保留发现链；线索不会消失，也不计入正式岗位。接续记录包含历史，不能等同当前链接已重新核实。“查看规范岗位 · 清除地图筛选”是独立操作，明确清除旧筛选再选中统一索引中的岗位；仅有城市或来源地址时仍按其真实精度展示，不自动变成已确认办公室。

若保存响应丢失，面板关闭或切换视图仍保留原请求，使用“核对原保存回执”恢复；未核对前会阻止新采集与更换连接。成功回执已知、只有索引同步失败时，使用“重新读取已保存索引”，不会再写一次。恢复信息只存当前网页内存，整页刷新前请完成核对。服务进程重启会使未提交预览失效；已提交回执可按原 body 和幂等键恢复。

本机网页会自动通过同源后端读取服务，打开“来源工具 → 扩展可搜索来源”即可使用；静态托管页面需先在高级直连中配置服务。按名称、C#、.NET、远程等筛选目录并明确选择，然后点击“添加并启用所选来源”。此操作只保存配置，获取岗位仍由主搜索明确发起；已有相同来源 ID 或规范化端点的配置不会被覆盖，包括已有禁用配置。

目录由 [config/sources/catalog.json](../config/sources/catalog.json) 管理，含 Remotive、Arbeitnow、Remote OK 三个多公司公开 feed，以及 Hudl、LaunchDarkly、Sentry、Temporal 四家官网 ATS。配置保留实际核对时间、官方证据链接、每轮额度和刷新间隔。新增同类来源主要增加配置；自定义 JSON 和企业官网发现继续可用。目录技术标签代表曾在文本中观察到关键词，公司介绍提及不等于任职要求匹配。

公开 feed 只读取当前窗口，并标记部分覆盖；Arbeitnow 显式以 Unix 秒解析发布时间，Remote OK 首项条款不当成岗位。Remotive 仅提供延迟的有限远程岗位窗口，官方建议每天最多读取4次、每分钟不超过2次；本地强制 UTC 日切的每日4次、6小时间隔与每分钟2次限制，失败或取消的已启动读取也占额度，同一幂等任务回放不重复计数。Remotive 要求突出标注来源并保留原岗位链接，禁止转交第三方招聘站或在岗位站收集注册／邮箱线索。`candidate_required_location` 是候选人申请资格范围，不是办公室或地图坐标；工资、未带时区的发布时间保留原文。来源默认关闭待审核，启用后只按明确刷新请求读取。原始职位链接与来源标识保留；Remote OK 原链接遵守其 follow 回链说明，不使用其 Logo。

每个来源独立遵守配置刷新间隔。间隔内重复刷新会显示限制，已收录岗位仍可直接筛选；不应反复发请求或把拒绝当成“没有岗位”。网络中断后，原请求身份和已提交数据继续保留，重读索引核对即可。

## 颜色、来源与时间

每个 listing 分别显示**来源颜色标签 + 发布时间标签**。同一岗位有多个来源时不会借用另一来源的发布时间。来源配色按 `sourceId → adapterId → 平台名称 → 稳定备用色` 匹配，配置在 [presentation.json](../apps/web/src/components/atlas/presentation.json)。

发布时间默认按 `Asia/Shanghai` 显示：近期显示小时/天数，满一个**日历月**后显示具体日期，月底按下一月末日处理。仅日期保留“仅日期”精度；相对原文、无时区原文继续作为原文展示；缺失为未知，未来、无效或冲突时间提示待核对。抓取时间、平台刷新时间、核验时间和仓库更新时间都不代替岗位发布时间。

地图上的企业颜色是另一套配置，依据有证据的最终控股方来源，不能用办公地点推定企业归属。“配置颜色”可调整并保存到当前浏览器；未知或冲突保持待核实。简历主题和工作台浅色/深色外观各自独立。

薪资默认比较人民币税前固定年薪，可切原币显示；奖金、股票和税制未知值不会混入。参考汇率管理支持受控读取、原文预览、明确保存／启用和停用，网页与后端共用同版汇率；原文、出处、读取时间和内容哈希可查。没有明确薪资或有效汇率时放到不可比较项，汇率不能补造税前依据或保证月份。操作与备份边界见[参考汇率说明](reports/job-atlas-fx-context-2026-10-21.md)。离家距离使用 WGS84 直线距离，家庭参照点只在当前页面内存；城市中心距离标为估算，通勤路线尚未接入。

## 地图精度与部署边界

全球点阵地球和国内地图使用同一查询，可以连续缩放到底图街道。地图统计按岗位去重，多地点岗位可有多个标记。“显示更多岗位”沿查询游标加载列表，地图桶与统计保持该查询的完整范围。

### 多个地图标记重叠时

点击当前视角下重叠的多个标记，会展开地点组选择面板。可选择某一组，也可点“查看全部…个岗位”，查看这些组对应岗位的去重并集。同一岗位出现在多个地点组时，列表只显示一次；已有关键词、地区、排序和“显示更多岗位”继续适用，地图与统计保留原查询的完整范围。

每组分别显示名称、岗位数、WGS84坐标和“城市分布参考／来源地点组”。**屏幕上重叠不代表同一办公室**，查看全部不会合并地点、生成共同坐标或提高精度。缩放从城市分组切换为地点分组时，选中岗位保持，地图高亮按当前分组重新对应。城市参考失效或切换查询范围时，不沿用过期地点选择。

面板使用普通按钮，可用Tab选择；打开后焦点进入关闭按钮，Esc或关闭将焦点交回地图。打开选择时停止当前相机移动和待恢复的自转；拖动、缩放、定位其他岗位或切换地图模式后关闭旧面板，不在返回原视角时复活。它不是阻断整个页面的模态窗口。实现、合成交互与验收范围见[重叠标记与地址补全报告](reports/job-atlas-overlap-address-fallback-2026-10-22.md)。

### 查看岗位与地图定位

单击岗位卡片打开独立阅读侧栏，查看醒目的“打开岗位原文”、各来源与时间标签、薪资原文、地点及职责 / 要求；如果当前查询为该岗位生成了地图分组，地图同步高亮该分组。高亮表示分组成员，不证明城市参考点是办公地址，也不会为无坐标岗位创建地图标记。原文链接使用当前岗位 listing 的已校验地址；来源未提供链接时明确提示。来源摘录和已读取正文分别标注，卡片出现不代表完整要求已经读到。可通过关闭按钮或 Esc 关闭；收藏、JD 分析继续走既有机会流程，演示数据不能进入这些动作。

双击卡片打开详情并尝试在地图中定位、高亮；详情中也可逐个工作地点点击“地图定位”。存在有效 WGS84 坐标时才直接飞到该位置，缩放上限受国家、地区、城市、街道或地址精度限制。重复定位同一岗位仍可触发，切换岗位会清除上一岗位高亮。动态过渡采用可中断的相机移动和短暂位置提示，减少动态效果设置下直接到达目标。

只有“深圳”等原文且没有坐标时，先连接本机服务查找离线地名候选，由本人选择城市参考点；候选始终标为“城市估算 · 非办公地址”。本次选择只用于地图浏览，不写回岗位地址、坐标、位置精度或核实状态。国家范围与办公室身份保持绑定，同名城市不能自动确认；远程资格范围不能当办公地点定位。Google 地图外链可以使用已有坐标或地点原文，不代表已从 Google 获取或核实办公地址。

**放大地图不会提升岗位地点证据。** 只有原文城市且没有坐标时保持待定位；有城市中心坐标时明确标为城市估算；只有来源或人工确认的办公地址坐标才展示相应精度。远程允许地区不是办公室。待定位岗位仍可在列表中查看；未知位置不能按离家距离编造排序。

“地图服务”可切 OpenFreeMap 矢量底图、OpenStreetMap 标准街道或本地概览。道路、建筑和门牌取决于提供方覆盖；视图允许放大不代表每一层都有新的原生数据。网络底图会访问其提供方，离线概览只保留本地边界与点阵。国内概略分组仅用于展示，不用于正式测绘。

Google 地图当前提供**官方外链**，没有内嵌 Google Maps；内嵌需要个人 Key、服务权限及计费配置。放大到城市中心也不会因此成为真实办公地址。

GitHub Pages 和现有 Docker 镜像提供静态网页及浏览器本地数据能力，**不内置岗位采集后台、SQLite 或 Windows 招聘浏览器**。Docker 的同源 `/api/*` 仍明确返回静态版提示。官网来源、企业入口发现和索引需要显式连接独立本机服务；四平台 `/api/jd/search-session` 属于成功运行的本机 Vite 开发宿主，`vite preview` 仅检查静态构建，不提供这些岗位浏览器 API。独立岗位服务尚未接入对应 browser companion，不能仅连接索引服务就认为静态版已能控制浏览器。

新增服务端代码后需确认实际运行的是更新后的宿主；旧页面刷新不会给旧进程增加接口。此前暴露的 Vite / Node 搜索契约模块加载问题已增加纯搜索入口修复，但真实四站列表仍需逐站核对。`404`、模块加载失败或请求失败都按服务故障处理，不补成空岗位。历史 1692 项全仓检查及随后各组定向测试属于不同源码时点，不能相加或替代新版最终全仓检查、浏览器交互与实际来源验证。部署与 CI/CD 见[部署说明](deployment.md)，新一轮范围见[聚合与交互报告](reports/job-atlas-aggregation-interaction-2026-10-19.md)。

## 跨来源岗位核对与撤销

仅在已连接的“本机采集索引”提供“重复岗位核对”入口；打开面板不发起读取。点击“读取候选与记录”后，选择候选或手动选两岗，明确“保留摘要的目标岗位”和“并入的来源岗位”，填写依据并预览。彩色来源标签与安全原文链接、强弱线索、字段差异摘要一起显示。相同企业名／标题不能自动证明同岗，企业身份必要时单独确认。

阅读预览、勾选后可确认合并或记录暂不合并。改变说明、方向、企业确认或索引版本后须重新预览。目标提供标题／正文／公司／状态摘要，各来源、地点与薪资分项保留，不混成最高工资或补造核实状态。历史记录中撤销时，先预览当前实际相关岗位组的前后变化；只撤所选决定，其他有效关联和来源最新贡献保留。

写入回执不明时保留面板，使用“重试本次处理 · 核对回执”，沿原输入、版本、指纹与幂等键读取结果。收到成功回执但索引读取失败时，只重新读取索引。当前未确定命令仅在面板内存，关闭／刷新不保证恢复它。候选有扫描上限，没有候选或truncated=false都不表示没有重复。完整工具、验收和限制见[归并报告](reports/job-atlas-reconciliation-2026-10-19.md)。


## 官网结构化岗位与已登记企业

“来源工具”可选择默认禁用的 ABB 官网配置，核对并显式添加后使用原有预览／刷新工具。新增的是通用 `jobposting-jsonld@1` 协议：受审叶子 sitemap 或静态HTML清单 → 有界同源详情 → 实际 JobPosting JSON-LD → 统一索引；新增企业主要配置清单、路径、名称与额度，不写品牌分支。企业名称只用于来源关联，实际岗位的雇主、国家、正文和日期必须来自页面。

候选链接不等于已读取岗位，也不表示全市场覆盖。当前采样每次仍从有限队首开始；目录里的C#优先链接必须本次真实出现在清单中，关键词筛选只作用于已读详情。请在“本机采集索引 · 真实来源”中重新读取，旧“当前机会库”保持独立。默认关闭的陌生企业网页搜索、动态页／验证和未接通平台不会因此自动可用。配置、真实来源／时间证据和明确计数见[本批报告](reports/job-atlas-jsonld-sources-2026-10-19.md)。

## 桌面三栏与具体办公地址

电脑工作区宽度至少900px时地图、列表、详情并排；中等宽度详情在下一行，小屏才使用底部面板。单击卡片查看详情，双击定位；多办公地点先选本次位置。卡片与详情优先展示完整地址／街址，其次是城市。远程资格和完全远程岗位不当办公室；缺地址继续明确显示城市级估算或待定位。

连接本机索引后，详情的“核对办公地址”支持输入来源街道、门牌、楼宇或园区查询，候选仅填表；或手工填写WGS84、真实国家、坐标对应楼宇／入口／园区、出处与核对说明。先预览，独立勾选后保存。来源原文和证据不变，本人覆盖清楚标为待核实。确认保存后按同版当前筛选验证岗位并自动定位，即使来自“加载更多”的后续页也可恢复。来源变化后旧确认失效；撤销当前确认需要说明和独立勾选，可恢复上一有效确认或原来源／行政位置。

已核对地址点双击飞入16.5级并高亮，城市分布参考保持9级；本人点参与直线距离时仍为估算。Google地图入口只打开查询，尚未内嵌Google SDK。地址查询默认关闭，宿主可启用`--office-geocoder nominatim`或`--office-geocoder photon`；仅明确查询时请求固定服务，最多5候选，不自动补全或批量查询。覆盖不足时不猜雇主总部，也不将城市坐标当办公点。详细边界及本轮实证见[桌面与办公地址报告](reports/job-atlas-desktop-office-address-2026-10-19.md)。

地址查询连通与匹配精度分开验收：本机配置已完成一次Nominatim真实HTTP200，但返回门牌位于其他城镇，不能据此认定目标岗位办公地址。候选仅填表，先核对城市、邮编、街址及岗位关系，再预览和明确保存。门牌格式修复与真实索引字段范围见[地址提供方实证](reports/job-atlas-office-provider-real-2026-10-19.md)。

### 电脑即时阅读与地址查询约束

工作区至少900px时始终预留三栏，未选岗位显示阅读提示。鼠标单击立即阅读，双击进入地图；地图已经可见时保持滚动位置。来源已有街址但缺精确点时先进入办公地址核对，避免城市参考截获。候选查询可填写独立城市／邮编，默认空；只在点击查询后发送。城市请按地图名称填写，跨语言名称不做猜测，邮编保留前导零。任一条件不符或缺失时结果拒绝，修改查询条件后需重新查询。该约束不能补造来源缺少的办公地址。真实与合成验证见[本批报告](reports/job-atlas-desktop-precision-2026-10-19.md)。

## 逐岗补全办公地点与桌面交互

空机会库显示连接本机索引、读取与收藏岗位的入口，不保留整块空详情栏。工作页默认自动连接本机采集索引，先确认后端状态、数据视图和版本；关键词筛选只查询已有索引，获取新岗位仍需来源搜索/同步。隔离合成验收页用于测试，不是私人索引。

在真实索引已有结果时选择“补全当前结果办公地点”，核对本次明确列出的岗位，点击读取后才访问外部。每批最多50个已加载岗位、并发2；原来源街址优先查询受配置地址服务，再读取同平台原岗和已关联的可用官网来源。官网缺失时发现企业招聘入口；未知或验证失败逐项显示，不把公司总部或城市中心补成办公室。某岗位一个地点已定位时，其余pending地点仍会检查。

是否继续官网读取按本次各待补地点**实际获得地址候选**判断。已有街址但地址服务返回0候选、未配置、请求失败，或只有部分地点获得候选时，仍接续既有同岗位详情／官网及入口发现流程；不会因“有街址”而提前结束。每岗最多查询两个来源街址，未查询的其他待补地点也不会被算作已覆盖。全部待补地点已有候选时不再作较弱的查找；已经读取到有效同岗地址证据时，先保留本人审核入口。候选和官网入口线索均不自动确认办公室，详见[本批报告](reports/job-atlas-overlap-address-fallback-2026-10-22.md#来源街址无候选时继续官网读取)。

平台同岗结构化街址可以预览并独立勾选保存，随后继续“核对办公地址”，查看来源与地址候选并确认坐标。官网同岗线索目前只展示供核对，不直接写成平台来源地址。每项保存都有版本与回执，失败保留已成功部分；未知写入结果可在同一页面重新打开相同范围核对原请求，刷新前应完成回执恢复。办公地址保存后重新核对当前筛选并定位到相应job/location；换岗、关闭、换身份会中止旧定位。Esc先返回批量结果，再次Esc关闭面板。

地图保留连续街道缩放；只有点位变化才上传几何数据，相机运动时暂停悬停要素查询，手势结束后延迟恢复自转。城市参考与真正办公点分开标注；无可靠办公坐标的岗位不会计为精确定位，也不参与离家距离。完整验证与真实数据缺口见[办公地点与性能报告](reports/job-atlas-detail-address-review-2026-10-19.md)。

## 企业最终控股证据核对

本机岗位详情新增企业控股核对入口：先读取当前来源公司与历史，填写公开材料的原文链接、实际读取时间和原文，再逐字段引用实际雇主法定名称、可选母公司关系、最终控制方名称／性质／控制关系及可选来源国家。预览受影响的同公司岗位，独立勾选本人已核对后才保存。打开面板、读取、预览和保存均不会自动访问材料链接。

“本人核对”表示本人对引用原文的解释，不是发布机构或监管认证。系统校验原句存在、引用对应、哈希、版本与关系结构，不自动认证原文法律含义。每个最终控制方都要有实际控制雇主的关系引用；品牌、注册地、母公司名称或办公室地点不能自动成为最终控股国别。

单一控制保留一个最终控制方；共同控制逐个保留多方及其国别，使用独立配色规则；“无实际控制人”明确保留空控制方和空控股来源国，不用上市集团名称代替控制人。待核实和冲突可以显式保存，不因此成为私企／国企／外企事实。缺国别时不会满足需要完整国别依据的颜色规则。

核对只作用确切 `companyId`，不合并同名企业。普通 JD／薪资刷新、新增别名和同公司岗位保留有效核对；雇主身份、控制关系或绑定证据变化会永久失效旧核对，原文后来恢复也要重新审阅。保存后列表、筛选、统计、分页和地图颜色共用新索引版本；撤销保留历史，可恢复仍有效的上一核对或来源值。

响应未知时保留原请求和幂等键核对回执；已保存但新索引读取失败时只重读索引。关闭面板、切换视图或工作区重挂仍保留同连接的内存恢复屏障，整页刷新／浏览器关闭不保证保留该前端状态。V7 完整备份保存全部原文与历史；公共快照只携带当前有效引用材料的企业目录观察，不增加岗位或 JD，不能代替完整备份。
