# 本地模型编码实验台

入口：职业自动化 Studio → 沙箱应用工坊 → 本地模型编码实验台。它与同页的四个内置微应用预设分开。实验台要求本机 Agent Host 及已安装的本地 Ollama 模型，静态版或宿主失联时不伪造结果。

## 一次小任务

1. 输入通用目标，例如「返回输入对象的整数 value 的绝对值」，指定本机模型标签，给出合成用例，例如 `[{"id":"positive","input":{"value":4},"expected":4},{"id":"negative","input":{"value":-3},"expected":3}]`。不要填写真实简历、第三方材料、凭据或文件路径。
2. 确认目标、模型、用例和额度后创建任务。这一步只检查本机模型元数据并冻结清单，不生成代码。使用真实用户数据不是这一版的功能。
3. 可手动推进一轮，或**一次授权连续修复到待审**。每轮最多发出一条生成请求，针对一个未通过的用例，带入此前的受限源码和检查结果。首次须返回完整函数；修复时也可提交单处精确替换，宿主只接受能在该版本的已展示代码中唯一定位的旧片段，歧义就拒绝。Host 独立运行**全部**用例；修好一例但破坏原有通过项时，不替换此前保留的候选。
4. 全部通过后只到「待审」。可以检查/复制源代码，核对各轮历史和源码摘要。这是对给定样例的检验，不是对任意输入、通用软件安全或业务结果的保证。实验台没有安装、发布、投递、访问工作区或修改 FactBase 的命令。

连续修复只在本次 Host 的活授权内有效：关页面不会新建执行器，也不会撤销已授权的连续执行；人工暂停、换号、授权失效、模型变更、额度耗尽或到达待审都会停。Host 重启后可以读回之前的工作，但必须手动授权才会继续。查看历史、刷新页面或复制代码都不消耗模型请求。

## 哪些机制来自文章，哪些是 BetterMe 自己的约束

[Anthropic 关于长时间运行 Agent 的文章](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)把环境初始化、逐项实现、可接手的工作记录和可重复测试组合起来。它不是操作系统沙箱规范。这里用 Host 冻结的用例清单、固定模型摘要、逐轮检查记录、保留候选与私有 SQLite 检查点替代文章示例中的项目目录和 Git；不需要让模型写裁判、修改仓库或运行 shell。对于浏览器应用，真实 UI 验证仍应另做；函数用例并不代替 UI 验收。

| 层 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| 本机 Ollama | 在固定 loopback 地址核对所选标签的摘要，再查该模型的详情；没有远端标记且有可识别的本地 GGUF 权重元数据才发送任务 | 不下载权重，不换供应商，不把失败交给云端；未知格式从严拒绝。宿主相信自己连接的本机 Ollama 及其模型清单，这不是对恶意 daemon 的网络隔离 |
| QuickJS/WASM | 对每条输入使用全新、限时限内存的运行器，只返回 JSON；Host 依据冻结的期望值比较 | 无 shell、npm、文件、网络、数据库、浏览器 DOM 或继承的凭据；不在 Node 主进程 eval 候选 |
| 任务 Host | 归属当前账户，先记本轮预算再调用；带修订号拒绝重复推进；换号/撤权丢弃迟到结果 | 查看不生成；宿主重启不自动重派不明结果；不把等待用户的时间算成推理；没有无限修复预算 |
| 旧内置预设入口 | 仅编译完整内容与发布时摘要一致的四套内置 UI；独立请求批准打开一次或固定 | 自定义代码或更改权限的模板不能借此进入宿主；断线/旧回执不能据此安装；一次预览不覆盖已有安装 |

本机 HTTP 端点不等于机器已断网。若部署要求进程级的「绝不出网」，还应由操作者在受控 Ollama 服务上禁用云功能并实施网络出口策略；这个实验台不修改系统防火墙或 Ollama 配置，也不把预检、事后摘要比较当成防恶意守护进程的手段。参见 [Ollama 对本地与云端处理的说明](https://docs.ollama.com/cloud)。

目前放行的本地生成协议是 Ollama **0.40.15**。界面选择的是原始标签（例如 `gemma4:e2b-it-qat`）；真正发送给 `/api/chat` 的名字还要加 daemon 识别的 `:local` 来源限制。这样模型别名即使在检查后改指远端，daemon 也应拒绝，而不是把提示转发出去。未知协议版本、远端回包或缺失证据均停止；不重试裸标签。新增兼容版本须先核对并回归：[来源限定解析](https://github.com/ollama/ollama/blob/02480ca2a47153e1f9c31cbe1e05536da97ce1ba/internal/modelref/modelref.go#L94-L107) · [daemon 转发前的检查](https://github.com/ollama/ollama/blob/02480ca2a47153e1f9c31cbe1e05536da97ce1ba/server/routes.go#L2898-L2921)。

任务默认 3 次生成、180 秒累计活跃额度；可配置至最多 8 次、300 秒。执行中断后已经开始的一轮不退款。若进程硬退出、不知道精确用时，就保守计入已预留的一轮上限，以免崩溃绕过预算。每次请求留存的是用户批准的任务数据、源码与检验记录，不是模型私有推理。达到额度时可读回部分成果；不会把它标为通过。

这是从工坊独立创建的编码实验，不是后台为某个简历任务偷偷新开的子任务。它不消耗或重置已有简历任务的预算，也不能从这些任务继承材料或授权。将来若接为父 Agent 的自动工具，须先把模型请求、工具读取、活跃时间接入同一个父任务账本，取父任务剩余额度与实验限制的较小值；不能叠加两份额度。

### 面板为什么会停

- **不能确认是本地模型**：请核对已安装的确切模型标签和服务支持的元数据。实验台不会替你下载模型、换供应商，或把目标转给其他 CLI。
- **用例仍失败或出现回归**：看「逐轮记录」与「保留版本」，它们可以是不同版本。最近一次尝试不是最好的证明；尚未全过不能安装，也不能记为完成。
- **预算耗尽**：保留当前候选和逐例结果供审阅。这个版本没有原任务的扩额命令，重新打开不会补发或返还额度。
- **中断或切换账号**：回到原账号后重新打开任务、核对模型和剩余额度，再手动选择继续。只有显式连续授权才会让 Host 继续工作；读取任务本身不会运行代码。

## 重现验收

2026-11-10 的隔离 Chromium 验收使用私有临时账号和两条虚构整数用例。创建后显示 `0/3`；实际点击一次「授权连续修复至待审」，第一轮为 `1/2`、第二轮为 `2/2`，最终显示完整源码和两条历史记录，没有安装。这里使用脚本化模型，账号校验、HTTP、SQLite、QuickJS 以及浏览器交互均为真实路径；这不是 Gemma 推理成功或真实项目编码通过率的证据。

此工作树对应的本机 `BetterMe.app` 依赖相邻源码与加载器，并非新发布的独立安装包。桌面启动时优先使用带 SQLite 的兼容内置 Node；这台 Mac 的 Electron 34 自带 Node 20，故只在受检的固定 Homebrew 位置选择兼容 Node，绝不从任意 `PATH` 拿一个程序执行。隔离启动验证了 Electron 34 → 本机 Node 26 → 新 Host 健康响应、未登录任务返回 401；桌面渲染另用私有测试 profile 验证，不复用用户窗口。

冻结后的验收：沙箱、能力、任务 HTTP 和 Web 相邻回归共 **135/135**，桌面运行时/隔离/生命周期 **14/14**；仓库类型检查 **13/13**，lint 和 `pnpm desktop:build` 通过。不是全仓业务测试或真实模型成功率。未提交、推送或发布安装包。

离线回归使用脚本化模型和真的 QuickJS；认证、SQLite、切号、崩溃接手与编译不是假回执。可在仓库根运行：

```sh
pnpm exec tsx --tsconfig apps/web/tsconfig.json --test apps/agent-host/tests/sandbox-coding*.test.ts apps/agent-host/tests/sandbox-reviewed-build.test.ts apps/web/tests/sandbox*.test.*
```

**可选真实推理**：先在本机确认允许发送下面脚本内置的「正整数求和」虚构样例，并选一个已安装的确切本地模型，再运行：

```sh
pnpm exec tsx apps/agent-host/scripts/verify-sandbox-coding.ts --model gemma4:e2b-it-qat --consent-synthetic
```

该命令限两次生成、150 秒任务活跃额度；仅用临时私有目录，退出后清理。未安装、不支持、超时或用例失败都如实失败；不会暗中拉取或切模型。输出并排给出首轮（`firstPass`）与最终保留版本（`retained`）在三个公开功能例、两个不送给模型的留出例上的成绩，以及模型/源码摘要、尝试次数、回归次数及活跃用时；留出题及判分不参与修复。不打印源码或提示。一次跑通不代表任意编码任务通过率提升。比较模型或策略时应固定任务、模型摘要与预算，分别报告留出通过率、回归数、模型请求数和耗时。
